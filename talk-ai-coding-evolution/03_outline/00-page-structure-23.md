# Talk 页面结构（现场版 v1.6 · 23 页 · 45 min）

> 本版已与 V7 成稿对齐。五层是 **attention stacking**，不是严格运行时层级；Harness 是可靠运行边界，Loop 与 Graph 是按任务需要叠加的组织方式。

## 开场（3.5 min）

| 页 | 页面结论 | 时间 | 必讲要点 |
|---|---|---:|---|
| P1 | OPC 航海指南 | 0.5 | 题目、Ethan Jiang、问题：一个人要把 AI Coding 掌握到多深？ |
| P2 | 五个角色，已经分别有人替你命名 | 1.5 | Boris Cherny 讲 Loop；Böckeler 定义 Harness；Steinberger 讲 State Graph；人从写一句话转为设计系统怎么工作。 |
| P3 | 能力越强，边界越重要 | 1.5 | 信息怎样形成行动？行动怎样可靠并被 Loop / Graph 组织？边界进入业务后，哪些可借、哪些必须自己决定？ |

## 第一幕：五层不是五个新词（12 min）

| 页 | 页面结论 | 时间 | 必讲要点 |
|---|---|---:|---|
| P4 | 同一台发动机，把人的动作一格格往上推 | 2 | 模型能力增强 -> 单次交互边际收益下降 -> 杠杆点上移；METR 与 Anthropic 是两条证据；叠加，不是替代。 |
| P5 | Prompt 管表达，Context 管模型此刻所见 | 3 | Prompt 不是系统；Context 不是越多越好；context rot；两者解决不了执行边界。 |
| P6 | 能行动之后，问题变成：它在哪个受控环境里行动 | 2.5 | Harness = 权限、工具、验证、记录；Agent = Model + Harness；这是每次动作的运行与治理边界。 |
| P7 | Loop 管时间上的反馈；Graph 管空间上的协作 | 2.5 | Loop 的黄金法则；Graph 的显式节点、边、状态；Graph 可在部分节点使用 Loop；两者均是新兴、低置信度。 |
| P8 | 五层同时活着，但不是一座从小到大的金字塔 | 2 | 关系图：Prompt/Context 服务一次模型调用；Harness 保障每次执行；Loop 跨运行；Graph 跨节点组织；今天重仓成熟的前三层。 |

## 第二幕：为什么答案停在 Harness（10 min）

| 页 | 页面结论 | 时间 | 必讲要点 |
|---|---|---:|---|
| P9 | 每一次真实动作，都要经过一个可靠性边界 | 1 | 这是“Harness 最关键”的推断，不冒充为报告原话；从 P8 的关系图推出。 |
| P10 | 模型决定能力上限，Harness 决定交付底线 | 1.5 | Harness 不替模型思考；它把权限、验证与记录变成系统行为。同一模型换一圈运行边界，就是两个交付系统。 |
| P11 | Harness 同时在行动前引导、行动后反馈 | 3 | Guides / Sensors；computational / inferential；确定性优先。 |
| P12 | Harness 先保证可靠，再承载专业知识 | 2.5 | 圈住 / 拦住 / 看清是三项可靠性控制；Knowledge Map 在可靠边界上帮助模型找到归属与正确路径。 |
| P13 | Loop 与 Graph 开始之前，先过确定性门禁 | 1 | Harness 在执行前独立授权、检查、记录；模型可以提议工作图，但确定性 checker 决定放行或拒绝。 |
| P14 | 2026 的教训：在生成时相信模型，不等于在执行时授权 | 1 | 工具调用形状被伪造/绕过 -> 执行端缺少独立授权 -> 操作发生；修复是 authorize at execution；结尾提出“边界有人负责，不等于人人自建”。 |

## 叙事检查

1. P2 提出“人被模型推上去”；P4 解释为什么会发生。
2. P5-P8 给出五个不同工程对象与正确关系；P9 自然提出“每次动作靠什么可靠”。
3. P10-P14 从定义、机制、能力、依赖、事故完整回答“为什么是 Harness”。
4. P14 提出“边界必须有人负责”，P15 给出何时值得自己掌握的判断标准，P16 保住“先借现成”的默认答案。
5. P17-P18 说明 DSH 的注意力爆发和 OPC 收益；P19 定位 runtime；P20 提出责任问题；P21 用 owner final say 回答；P22 直接回答封面。

## 口径红线

- 前三层成熟，Loop / Graph 是新兴观察对象，不讲成既定生产范式。
- Graph 可以编排 Loop，也可以包含工具、验证器或其它节点；不能把所有 Graph 节点画成 Loop。
- Harness 是可靠性边界，不等于一定在几何上“包住”所有分布式节点；P8 的图只表达 talk 的治理关系，不宣称严格运行时包含。
- DSH 的原生机制不是 MCP；说 `ctx.llm`、`ctx.tools`、capability seam、plugin。
- DSH GitHub star 与 2,286 条生态数据都是 2026-08-27 的快照；只能说明 attention / 扩展面，不能讲成产品成熟、插件可信或持续增长曲线。
- CVE 只讲执行时授权缺失的因果链，不把厂商名、编号堆成画面主体。
