# 第三幕：一人公司看见 DSH 的爆发与收益（v1.4）

> 本幕不把“固定”说成落后，也不把“灵活”说成从零造。它讨论的是：当任务越过现成产品公开的扩展合同，谁能改变运行边界。

## P15 问题不是自建与否，而是边界由谁定义（1 min）

**上屏**：固定 vs 灵活，不是成品 vs 自研。

**判断问题**：我是否需要改变模型、工具、执行世界、门禁或项目知识组织？如果不需要，现成系统就是正确选择。

**讲点**：精装公寓的价值不是低，标准化降低了大量成本；真正的差异在于改造权和扩展合同。把“一人公司该自己写 harness 吗”的假问题，改为“什么时候需要拥有改变边界的能力”。

## P16 绝大多数场景，先借现成 Harness（2 min）

**上屏**：沙箱、权限、可观测性、provenance 与 CI 已能随产品交付。

**讲点**：Harness 的民主化使人不再需要自己写 bash 编排。固定产品在成熟、常见任务上提供了大量可靠性组件，正确的默认策略是 `Start with the simplest viable system`。这也是 OPC 稀缺注意力的正确用法。

## P17 14 天，DSH 已在 GitHub 成为近 20 万 star 的扩展入口（3 min）

**上屏**：公开后约 14 天，GitHub **199,846 stars**；同一生态快照 **2,286** 条条目。

**三类正在涌入的东西**：桥（接外部能力）、渠（占分发入口）、窗（在对话驾驶舱上做增强）。

**讲点**：这是 attention 和扩展面快速聚集的证据，不是“插件生态已经成熟”的证据。星标、条目数、可安装性都不能替代质量与可信度；这页的任务是让听众意识到：DSH 已成为一个正在被围绕着扩展的入口。

**转场**：大家为什么涌进来，和 OPC 为什么需要它，是两件不同的事。

## P18 对 OPC，价值不在装得多，而在少盯、敢放、能复制（2.5 min）

**上屏**：
- **省手**：装好即用；换本地 / 云端执行底座，不重写调用。
- **敢放手**：危险动作要签字；没有答复就 fail-closed；发生过的事可重建。
- **可复用**：把验证过的组合带到下个项目，或带给自己的小团队。

**讲点**：对自用 owner，生态的意义是“别人替你踩过的路”，不是自己去开商店。真正的生产力不在装了多少插件，而在你是否少回到手工、是否敢把夜里或批量的真活交出去、是否能把验证过的做法复制。

**转场**：但这里出现一个定位问题：这些插件到底围绕着什么工作？DSH 是商店、Agent 产品，还是别的东西？
