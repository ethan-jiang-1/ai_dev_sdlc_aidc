# 开场 + 第一幕：五层演变（v1.3）

> 这八页只完成一件事：让听众知道人为什么被推向更高粒度的工程工作，并建立五个工程对象的正确关系。不要在这里先论证“harness 最重要”。

## P1 封面（0.5 min）

**上屏**：OPC 航海指南；OPC 与 Harness，AI 协作之道；一个人，AI Coding 要掌握到多深？；Ethan Jiang。

**讲点**：不讲工具清单，而是讲人从“亲手做”变成“设计模型怎么做”的路线；最终要回答 OPC 在哪里该借现成、哪里要拥有改变能力。

## P2 五个角色，已经分别有人替你命名（1.5 min）

**上屏**：说话者 -> 策展者 -> 环境工程师 -> 控制流作者 -> 编排者。

**三处锚点**：
- Birgitta Böckeler：`Agent = Model + Harness`。
- Boris Cherny：`My job is to write loops.`
- Peter Steinberger：`Build agents as state graphs.`

**讲点**：不是每个人都要立刻构建 graph；这三句话共同说明人的动作粒度在变。转场：是什么把人一步步推到这里？

## P3 今天只回答三个问题（1.5 min）

**上屏**：
1. 为什么工程注意力从一句 prompt 上移到系统设计？
2. 为什么可靠性交付最终要落在 harness？
3. OPC 怎样从现成开始，又不被现成的边界锁住？

**讲点**：这是问题地图，不是目录。后文的五层、DSH 都只服务这三问。

## P4 同一台发动机，把人的动作一格格往上推（2 min）

**上屏**：模型能力更强 -> 单次交互的边际工程收益更低 -> 工程杠杆点上移。

**证据**：METR：50% 可靠性任务长度约每 7 个月翻倍；Anthropic：prompt 的精确措辞越来越不重要。

**讲点**：五层不是五种潮流，而是一台发动机的五次换挡。能力到位后，原来由人手工承担的动作上移到新的工程对象。强调：上移不等于替代。

## P5 Prompt 管表达，Context 管模型此刻所见（3 min）

**上屏**：
- Prompt：我怎样表达任务、约束和格式？
- Context：模型此刻应该看到哪些仓库事实、状态与证据？
- `更多 context != 更好回忆`。

**讲点**：Prompt 是一次交互的表达，不是系统控制面；Context 负责选择，而不是无限塞入。context rot 说明“看得更多”不等于“想得更对”。二者仍解决不了：模型能否在正确权限、正确工具与正确验证中行动？

## P6 能行动之后，问题变成：它在哪个受控环境里行动（2.5 min）

**上屏**：`Agent = Model + Harness`；Harness = 权限、沙箱、工具、验证、trace、CI。

**讲点**：Harness 工程化的不是模型能力，而是一次动作发生时的条件和后果：能做什么、谁来检查、如何留下记录。它是运行与治理边界。转场：一次动作可靠后，才会出现“何时再来一次、谁和谁协作”的新问题。

## P7 Loop 管时间上的反馈；Graph 管空间上的协作（2.5 min）

**上屏**：
- Loop：上一次结果改变下一次动作，才叫 loop。
- Graph：用显式节点、边和状态安排多个任务或 agent 的依赖、分支、并行与合并。
- 二者都是新兴方向，不是成熟定论。

**讲点**：Loop 是一条时间上的闭环，核心是 trigger、verification、stop rule、memory；Graph 是一张空间上的拓扑，核心是节点责任、数据/控制边和路由。Graph 可编排部分 Loop，也可编排工具、验证器和其它一次性节点。不要把两种图画成同一条线。

## P8 五层同时活着，但不是一座从小到大的金字塔（2 min）

**上屏**：关系图，而非层级塔。
- Prompt / Context：服务一次模型调用。
- Harness：让每次可执行动作可授权、可验证、可追溯。
- Loop：把反馈跨运行连起来。
- Graph：把多个节点组织为显式系统；部分节点可采用 Loop。

**讲点**：图的重点不是面积或高低，而是职责与依赖。五层是 attention stacking；今天重仓 Prompt、Context、Harness 三个成熟层，Loop/Graph 低成本试点、持续观察。转场：既然所有真实动作都要经过 Harness，可靠性到底在这里怎么产生？
