# 核心论点与立场（v1.5 摘要）

> 详细论证与证据分布见 [`00-storyline-map.md`](./00-storyline-map.md)（各幕要点）与 `../02_evidence/00-absorption-plan.md`（故事线资产 §一）。

1. **叠加上升观**：五层不是换代，是叠加——每一层都还踩着下面。论据：扳手/螺丝刀比喻（06 章）。
2. **成熟度标尺**：前三层（Prompt / Context / Harness）成熟可信；后两层（Loop / Graph）叙事期、低置信度——"火六周就被接棒"本身就是证据。
3. **harness 是承重墙**：这是**我们的判断**，不是报告背书（报告把 Context 与 Harness 并列）。用三线撑：结构线（loop/graph 实例化 harness）、哲学线（反馈同源 + 验证梯渗透 + GraphARC 门禁）、风险线（2026 CVE）。**三层同一件事**：harness 单次反馈 → loop 反馈连成循环 → graph 编排 + 门禁，本质都是"用反馈 + 确定性约束模型，换可靠结果"。
4. **可靠性是系统的属性**：模型给能力，harness 给可靠性；确定性优先（computational > inferential）。
5. **固定 vs 灵活（不绝对）**：不是"别用现成"，是先借成熟部件，同时保有改变运行边界的能力。
6. **DSH 的爆发与定位**：GitHub 关注度和插件涌现证明它成为扩展入口，不证明成熟或可信。DSH 的定位是可组合的 Harness runtime，而非插件商店或更强 Loop。
7. **Harness 最终控制权在手**：不等于自建全部部件；owner 必须能决定接入、替换、放行与重建事实，才能把生态能力放进真实执行路径。带走原则：**部件可借，边界自己定。**

## 一句话主线（源自 00-storyline-map）

模型越强，人机互动行为越变——人从"亲手做"被推成"设计模型怎么做"；一人公司要掌握到 **harness 这一层**：不用从零造，但要把最终控制权握在手里。
