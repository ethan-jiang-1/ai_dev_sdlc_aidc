## P7 · Loop Engineering + Graph Engineering

- 标题：从"迭代"到"编排"
- 副题：第四五层 Loop Engineering 与 Graph Engineering：刚冒头，是方向，不是定论
- 正文：
  - Loop Engineering = 反馈驱动迭代：模型越强越能"知错改错"——反馈得当，就不断输出更好结果
  - 黄金法则：只有上次结果改变下次行动，才算 loop
  - "A loop can be wrong in ways that are subtle, expensive, and hard to detect."
  - Graph Engineering = 编排：用 workflow / DAG 把多 agent 的乱发挥收进显式流程（谁先做、何时分支、何时停）
  - 有道理，但只解决特定的事，还在发展——是方向，不是定论
- 金句：**叙事期：火六周就被接棒**
- 候选上屏素材（以下内容可以考虑进入 PPT 页面，按版面选用）：
  - Loop Engineering 侧金句："Loop engineering is replacing yourself as the person who prompts the agent." —— Osmani
  - Loop Engineering 侧反转：blast radius——loop 错起来更贵（一次错、反复错、放大错）
  - Graph Engineering 侧双源定义：state graphs / "From Individual to System Intelligence"
  - Graph Engineering 侧：机制不新、诉求新——LangGraph 2024 就有 workflow / DAG
  - Graph Engineering 侧：命名先于沉淀——260 万浏览、无框架发布

> **背景（不上屏，仅供你理解本页后排版）**
> - 定位：后两层合并页（控制流作者 + 编排者）。
> - 意图：讲清 Loop Engineering 和 Graph Engineering——Loop Engineering 的引擎是"模型越强越能知错改错、反馈得当就越迭代越好"（与 harness 的 Sensors 同源：harness 是单次反馈，loop 是把它连成循环）；Graph Engineering 的核心是编排（orchestration）：用 workflow/DAG 控制模型的乱发挥、换可靠结果。定位这两层：有道理（是 harness 的延伸，主线在加强），但只解决特定的事（Loop Engineering 管迭代、Graph Engineering 管编排），机制不新、诉求新（LangGraph 2024 就有 workflow/DAG）、命名先于沉淀（260 万、无框架发布）——还在发展，是方向，不是定论。
> - 上下文：这两层都"站在 harness 上"（为 P9 承重墙铺垫）。
> - 布局提示：上半 Loop Engineering（循环箭头图）+ 黄金法则；下半 Graph Engineering（节点网络图）+ 两点校准；底部结论条"叙事期：火六周就被接棒"。
> - 别写错：口径——260 万浏览（不是 2.6 亿）；Woliveiras 那句英文引文别译。

## P11 · 两套控制 + 确定/概率

- 标题：两套控制，一档分野
- 副题：Guides 管事前，Sensors 管事后；能确定的，别靠模型猜
- 正文：
  - **Guides**（前馈）：行动前约束——按这个样式 / 必须过 lint / 只能用这些工具
  - **Sensors**（反馈）：行动后喂回——测试挂了 / 用户拒绝 / 退出码非零
  - **computational**（确定性）：测试 / lint / 类型——可复现，可审计
  - **inferential**（概率性）：AI review——意见本身可能错
  - Loop Engineering 五级验证梯：同一哲学
- 金句：**能交给确定性的，绝不靠概率性的**
- 候选上屏素材（以下内容可以考虑进入 PPT 页面，按版面选用）：
  - 通俗比喻：Guides = 事前规矩（先洗手、火别开大）；Sensors = 事后纠正（尝一口、咸了加水）
  - 通俗对比：npm test 全绿可直接信；AI 说"代码不错"不敢直接信
  - 渗透句：同一哲学，往上渗透到 Loop Engineering 五级验证梯

> **背景（不上屏，仅供你理解本页后排版）**
> - 定位：全篇最长页（3 分钟），harness 内部机制的核心。
> - 意图：讲清 harness 里头到底在干什么——两套控制（Guides/Sensors）+ 一档分野（computational/inferential）+ 原则（确定性优先）。
> - 上下文：这是"harness 里头干啥"的核心页，别压缩、别删内容。
> - 布局提示：闭环图（Guides 前馈箭头进 / Sensors 反馈箭头出）；下方 comp/infer 两档对比；原则句底部最大字。
