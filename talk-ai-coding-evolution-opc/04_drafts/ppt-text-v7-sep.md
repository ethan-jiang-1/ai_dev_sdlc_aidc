## P2
- AI Coding 的五个 Engineering，先看全貌
- 说清任务 → 让动作可靠 → 把工作组织起来
---
## P3
- 今天只沿一条主线：能力越强，边界越重要
- 从信息、执行、组织，一路走到 OPC 的最终选择
- 模型怎样说清、看对，形成一次行动？
- 行动怎样可靠，并被 Loop / Graph 放大与组织？
- 当边界进入业务，哪些可借，哪些必须自己决定？
- 最后用 DSH 回答：可组合能力，如何仍由 owner 控制运行边界
---
## P4
- 模型越强，工程对象越从一句话往系统上移
- 模型能力更强 → 单次措辞优化收益递减 → 工程杠杆向上移
---
## P5
- Prompt Engineering 与 Context Engineering：先说清，再看对
- 说对、看对之后，下一问是：它究竟能在什么边界里行动？
---
## P6
- Harness Engineering：为每一次行动设下可靠边界
- Agent = Model + Harness
- 权限 / 沙箱 / 工具 / 验证 / 执行记录 / CI
---
## P7
- Loop Engineering 与 Graph Engineering：让可靠行动持续发生
- 先有可靠的单次行动，Loop 才不会放大失败，Graph 才不会组织混乱
---
## P8
- 五个 Engineering 同时活着，但各自回答不同的问题
- 每一次真实动作都要经过 Harness 的执行边界
---
## P9
- 最值得看懂的不是最高层，而是真实动作穿过的边界
- 可靠性不是模型单独拥有的属性，而是 Model + Harness 的属性
---
## P10
- 模型决定能力上限，Harness 决定交付底线
- 同一个模型，换一圈运行边界，能否交付就是两个系统
- 能力上限：Model + 交付底线：Harness
- Harness 不替模型思考；它把权限、验证和记录变成系统行为
---
## P11
- 可靠性发生在两次：行动前约束，行动后反馈
- 确定的事交给系统；需要理解语义时，才交给模型或人
---
## P12
- Harness 先把行动变可靠，再把专业知识放进去
- 圈住：沙箱 + 权限；限制伤害范围
- 拦住：验证门禁；错误出现就停止
- 看清：Trace + 来源记录；还原发生过的事
- Knowledge Map：把事实归属、正确路径和项目地图放进边界内
---
## P13
- Loop 与 Graph 开始之前，先过确定性门禁
- 模型可以提议工作图；确定性检查器决定放行还是拒绝
---
## P14
- 真实事故：伪造工具调用，无需模型也能触发真实动作
- authorize at execution, not at generation
- 边界必须有人负责；但这不等于每个 OPC 都要自己造 Harness
---
## P15
- 什么时候值得自己掌握边界？看它是否已经进入业务
- 工具多，不是理由；边界变成业务，才是理由
- 当标准边界开始限制真实交付，才需要灵活 Harness
---
## P16
- Codex、Claude Code 已经很强：大多数 OPC 应直接借用
- 默认答案仍是借现成；只有边界成为业务，才寻找可组合 Harness
- DSH 不是替代成熟产品，而是让边界可改
---
## P17
- 公开 14 天，DeepSeek Harness 接近 20 万 GitHub stars
- 这股注意力，迅速聚到一套可扩展的 Harness 边界
- 199,846 stars / 22,820 forks / 2,286 条生态快照
- 这是“边界可扩展”需求爆发的信号，不是质量认证
---
## P18
- 对 OPC，价值不在装得多，而在少盯、敢放、能复用
- 省手 / 敢放手 / 可复用
- 先验证，再借力；少回手工，敢交真活
---
## P19
- DSH 不是插件商店；它是一套可组合的 Harness runtime
- 插件扩展 Harness；Harness 负责运行合同与事实记录
---
## P20
- 插件进入执行链后，真正的问题变成：谁说了算？
- 谁允许它进来？· registry
- 谁能换实现？· adapter + seam
- 谁在执行前签字？· gate
- 谁能还原事实？· session log
- 四问不是插件功能清单，而是运行边界的责任清单
---
## P21
- Harness 在手，不是都自己做，而是关键时刻你有 final say
- 我决定接什么 / 换什么 / 何时执行 / 如何追溯
- 部件可借，决定权不能外包
---
## P22
- 回答封面：OPC 要掌握到 Harness 这一层
- 掌握深度，不按工具数量算；按你对运行边界的责任算
- 会用成熟 Harness → 看懂运行边界 → 需要时握住 final say
- 部件可借，边界自己定
