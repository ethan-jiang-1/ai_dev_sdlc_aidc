# CONTEXT.md —— 本 talk 的术语权威

> 本目录里**词义只在本文定义**。`AGENTS.md` 管流程，其他文件消费这些词，不重复定义、不悄悄改义。
> 用户使用含混或与本文冲突的词时，先指出可能对应的已定义概念，确认后再更新本文。

## 一、核心对象

| 术语 | 定义 | 不要混用成 |
|---|---|---|
| **harness** | 模型之外的一切运行与治理条件：权限、沙箱、工具、验证门禁、执行记录、CI。`Agent = Model + Harness` | 不要写成"框架""平台""中间件"；也不要写成"最高层" |
| **五层工程** | Prompt → Context → Harness → Loop → Graph 这五层工程，简称"五层"。是**注意力与控制面**的叠加，不是运行时大小或严格包容关系。**量词固定用"层"**——说"五层工程""第三层""每上一层" | 不要画成金字塔、不要写成"五代产品"；**不要说"五门工程"**（量词不对，且"门"会被听成课程） |
| **固定 harness（Product First）** | 成品 agent 产品随产品交付的既有运行环境，扩展边界由产品定义 | 不要写成"封闭的""不好的" |
| **可组合 harness（Framework First）** | 运行时的每一层都可以装配与替换的 harness runtime | 不要写成"自研框架"或"更高级的 harness" |
| **运行边界** | 一次动作能不能发生、由谁授权、在什么环境里发生、留下什么记录 | 不要写成"安全边界"（太窄）或"架构边界"（太泛）；**也不要写成"执行边界"**（同一概念，全库统一用"运行边界"） |

## 二、第二幕的机制词（只在这一幕使用）

| 术语 | 定义 |
|---|---|
| **Guides（前馈）** | 行动**前**的约束：样式、必须通过的检查、可用工具白名单 |
| **Sensors（反馈）** | 行动**后**回传的信号：测试失败、类型错误、非零退出码 |
| **computational（确定性）** | 可复现、可审计的判定：测试 / lint / 类型 / schema |
| **inferential（概率性）** | 不可审计的判定：AI review / LLM-as-judge |
| **圈住 bound** | 沙箱 + 权限：限制碰得到的文件、网络与操作 |
| **拦住 gate** | 工具协议 + 验证门禁：把对错变成机器可判的关卡 |
| **看清 see** | 可观测性 + provenance + CI：还原每一步决策与产物来源 |
| **提出权 / 执行权** | 提议下一步动作（可交给模型）与决定这一步能否发生（必须留在 harness） |

**固定搭配**：`authorize at execution, not at generation`——授权必须在执行端发生，不能挂在生成侧。

## 三、叙事用词

| 术语 | 定义 |
|---|---|
| **生成 vs 交付** | 本场的问题分野：生成 = 能不能写出代码；交付 = 写出来的东西能不能上线 |
| **交付底线** | 由 harness 决定的质量下限：权限清楚、环境隔离、工具受控、结果可验、过程可追、失败即停 |
| **控制面** | 一层工程所实际管辖的东西。上屏只用既有词：提示词 / 上下文 / harness / loop（循环）/ 编排 |
| **一致性** | 团队版核心痛点：多人多套配置导致交付质量取决于执行者个人习惯 |
| **尾巴** | **内部用词**：第三幕 → 收尾（P19–P36，18 页 / 约 36.5 min）。**不得出现在上屏文字** |
| **引桥** | **内部用词**：开场 + 第一、二幕（P1–P18，18 页 / 约 40 min）。**不得出现在上屏文字**（与"尾巴"同性质） |
| **呼吸页（B1–B6）** | **内部用词**：插在结构接缝上的单句大字页，**不参与正文编号、屏幕上不显示页码**。作用是**切割 + 承接**：一句话里同时带上一段的结论与下一段的问题。与转场页（T，在幕边界）不是一回事 | 不要写成"停顿页"（只复述，不承接）；不要给它编 P 号 |
| **收束页自带呼吸** | P11 / P24 / P33 这类 1–1.5 min 的收束页，讲完停 3–5 秒即可，**不再额外插呼吸页** | 不要在同一处既给收束页又给呼吸页 |
| **自查五维** | 模型能否换 / 工具能否加 / 执行后端能否换 / 门禁能否自定 / 事实能否重建 |

## 四、证据强度标注（统一写法）

上屏与讲稿一律使用这四档，不发明新词：

| 标注 | 含义 |
|---|---|
| **一手** | 官方文档、官方仓库、官方发布，可核验 |
| **⚠️ 厂商自述** | 厂商 / 作者自述，未经独立审计 |
| **⚠️ 降级取证** | 网络受限下仅标题 / 摘要级核验，正文未读 |
| **趋势级** | 有来源但属论述、媒体或榜单级，无方法论支撑，只作趋势不作基准 |

配套规则：星数、插件数、成本数字一类会漂移的值，标注**观测日期**；口径不可比的两个数字**不合成一个**。

## 五、禁用词

| 禁用 | 原因 |
|---|---|
| OPC / 一人公司 / 姊妹项目引用 | 会造成困惑，且与本场对象不符 |
| 听众所属行业名与行业专属术语 | 换观众不用改稿；听众特征用通用描述承载 |
| "最高层""最底层最重要" | harness 是每次动作都绕不开的运行边界，不是层级高低 |
| "MCP 挂载"（讲 DSH 时） | DSH 的原生机制不是 MCP |
| "引桥""尾巴"（出现在上屏文字时） | 内部叙事用词，只在工作区文档里用，见第三节 |
| 自造的证据强度档位（如"厂商一手自述""媒体共识口径"） | 统一只用第四节四档，不发明新词 |
| CVE 编号堆叠 | 只讲因果链 |
| "框架""平台"（指 harness 时） | 词义漂移，改用 harness / runtime |
| **新造的中文对等词**（如"唯一真源""接缝""线束"） | 见第六节：找不到通行译法就保留英文 |

## 六、术语纪律：不新造中文词（2026-09-17 用户定）

> 用户原话：**"别新发明术语啊，实在找不到的话，其实网络上可以搜索的，别自己发明，毫无意义。
> 尤其是中文这边，实在找不到中文合理的翻译的时候，实际上你只要维护英文就行了。"**

**三条顺序**：

1. **先查既有译法**——业界已经这么说的，照用：`prompt` → 提示词；`context` → 上下文；
   `orchestration` → 编排；`append-only` → 只追加；`sandbox` → 沙箱；`gate` → 门禁。
2. **查不到通行译法的，保留英文**，不硬译，不生造。首次出现时可加一句白话解释，
   但**不造一个假中文词去"对应"它**。
3. **本 talk 自己定义的概念**（运行边界、圈住/拦住/看清、两类程序）不算临时自造，
   但必须**全文一致**，且首次出现时给一句话定义。

**全场保留英文的词**（括号内是可上屏的白话解释，不是译名）：

| 保留英文 | 为什么不译 | 白话解释 |
|---|---|---|
| **harness** | 无通行译名；"框架 / 平台 / 线束"都会跑偏 | 模型之外的一切运行条件 |
| **single source of truth** | "唯一真源""唯一事实来源"都是硬译 | 所有东西都以这一份为准 |
| **seam**（capability seam） | "接缝"是硬译 | 可以替换的地方 |
| **fail-closed / fail-safe** | 译名混乱，容易说反 | 失败时就拦住 / 失败时退回安全状态 |
| **projection** | 此处"投影"是硬译 | 同一份日志的不同看法 |
| **computational / inferential** | Böckeler 原词；"确定性 / 概率性"只是解释 | 能重跑的 / 换个时间可能换结论的 |
| **typed events** | — | 带类型的事件 |
| **in-process** | — | 在同一进程里 |
| **Goal / Ralph / workflow / Spawn-Fork** | DSH 模式名，译了反而认不出 | — |
