## 一句话主线

**AI 能写代码早就不是问题，AI 写出来的东西能不能上线才是问题。**
能不能上线，不取决于模型，取决于模型外面那圈东西——那圈东西叫 **harness**；
而在一个团队里，那圈东西最容易散。整场要证明的是：**harness 是变量，而且已经可以被替换。**

## 每一幕的要点

### 开场：生成不是瓶颈，交付才是

- **钩子（两句配一对）**：
  1. 断言——"AI 能写代码，早就不是问题了。AI 写出来的东西能不能上线，才是问题。"
  2. 追问——"你们团队里最会写 prompt 的那个人，和刚上手的新人，交出来的质量一样吗？应该不一样。但为什么不一样，你答得上来吗？"
- **承诺页（P3）**：不讲第六个新名词。只回答三件事——那圈东西是什么、它为什么决定交付稳不稳、它能不能换。
- **P4 本场地图**：五层 + harness + 两个可换的进展。

### 第一幕：五层演变（铺路，不是科普）

- **发动机**：模型越强 → 单次交互的边际工程收益越低 → 工程杠杆点上移。
- **Prompt 与 Context——只讲"为什么这层救不了你"**：这两层只在改"生成"，改不了"能不能上线"。
  Context 这层要讲深（听众容易自我感觉良好）：context rot、"更多 context ≠ 更好回忆"、最小脚手架。
- **Harness**：`Agent = Model + Harness`；harness = 模型之外的一切。只定义，不展开（展开留给第二幕）。
- **Loop 与 Graph**：Loop 是时间上的反馈闭环（黄金法则：上次结果不改变下次行动就不叫 loop；
  反转：没有门禁的 loop 只会更快地放大错误）。Graph 是空间上的依赖与协调（显式节点、边、状态；
  可编排部分 Loop，也可编排工具与验证器；不要画成金字塔）。
- **五层关系**：**叠加，不是替代**。Prompt/Context 服务一次模型调用；Harness 保障每次执行；
  Loop 跨运行；Graph 跨节点组织。成熟度标尺：前三层成熟，Loop/Graph 是 2026 才冒头的新兴叙事、低置信度。
- **团队版焊点**（替代个人视角）：五层是交付链上的**五个控制面**，在团队里它们往往散在不同人手上，或者根本没人管。
- **幕末转场**：前两层改不了"能不能上线"，Loop 和 Graph 只会放大结果——所以问题落回第三层。

### 第二幕：harness 里头到底干了什么（抓要害）

- **一句话**：**模型给能力，harness 给可靠性。** harness 不负责让模型变聪明，它负责让同一个模型每次都不掉链子。
- **两套控制**（Böckeler 框架）：
  - **Guides（前馈）**：行动前约束——按这个样式写、必须过这个 lint、只能用这些工具。
  - **Sensors（反馈）**：行动后回传——测试挂了、类型不过、exit code 非零。
  - 各分两档：**computational（确定性，可复现可审计）** vs **inferential（概率性，不可审计）**。
  - **原则：能交给确定性的，绝不靠概率性的。**
- **三个动词**：
  - **圈住（bound）**——沙箱 + 权限：只能碰该碰的文件、连该连的网、做被授权的操作。
  - **拦住（gate）**——工具协议 + 验证门禁：把"对错"变成机器可判的关卡，在离源头最近的地方拦下。
  - **看清（see）**——可观测性 + provenance + CI：trace / metrics / logs 记下每一步，产物可追溯。
- **团队映射**（本 talk 新增，见 `06-harness-internals.md`）：
  | 团队已有的纪律 | harness 动词 | 要补的一步 |
  |---|---|---|
  | 生产不是谁都能碰、环境隔离 | 圈住 | 把 agent 圈进同一圈边界（沙箱、权限） |
  | 变更要审批、要有人复核 | 拦住 | 让 agent 的动作过同一道门禁，不靠它自觉 |
  | 操作要留痕、出事能还原 | 看清 | 把 agent 每一步写进那份日志（trace、provenance） |
- **提议权与执行权分开**：模型 / Loop / Graph 提议下一步 → 权限与确定性门禁**独立**检查 → 放行或拒绝并记录。
  **提议权可以交给模型；执行权必须留在 harness。**
- **反面证据（2026）**：工具调用形状可被伪造——护栏若建立在"模型会发出合法调用"上，整条链失效。
  修复口径：**`authorize at execution, not at generation`**。对团队的讲法：审批不能挂在"它说它会怎么干"上。
- **幕末转场**：可靠性只解释了"为什么它不翻车"，还没解释"为什么它更强"。

### 第三幕：harness 才是变量（转折，本 talk 新写）

- **转折句**：同一个模型，换一圈 harness，就是两套交付系统。
- **证据一（⚠️ 厂商自述）**：Codex Harness 开源（Apache-2.0，2026-08-20）后，同一个模型在
  ARC-AGI-3 从 13.3% → 38.3%，输出 token 降到 1/6。**模型没换，换的是 harness。**
- **证据二（⚠️ 趋势级，无方法论）**：第三方 8-harness 对照实测，同一批模型下成功率与成本明显分层。
  只作方向性信号，**不作基准**。
- **你们手上跑的是什么**：现在主流的几条固定 harness，各自把沙箱、审批、事件流、长程记忆做进去了；
  开箱即用，治理默认内建。
- **它们的天花板**：扩展边界由产品定义。五个自查维度——**模型能不能换 / 工具能不能加 /
  执行后端能不能换 / 门禁能不能自己定 / 事实能不能重建**。
- **幕末收束**：所以 harness 是变量。而变量意味着——**它可以换。**

### 第四幕：两个进展——Pi 与 DSH（给出可换的答案）

- **两条路线的分野**：`Product First`（引擎即用、产品接入路径短）vs `Framework First`（可完全私有化、模型无关、架构修改权最大）。
- **DSH 是主线**：Everything is a Plugin（Cordis 元框架，**无特权核心**）；
  四种运行模式 = 四套默认插件集；会话是**类型化只追加 SessionEvent 日志（唯一真源）**，
  模型所见即被记录 → replay / resume / fork / audit 都是同一事件流的投影；
  长程不是单一 Loop（Goal / Ralph / workflow / Spawn-Fork 并存）。
- **Pi 讲"轻量路线的代价"**：minimal terminal harness；结构上做对了三层同心接缝（operations / tool / extension）、统一注入点、分发闭环、
  以及"进程内跑陌生代码"的护栏（两阶段绑定、stale 保护、**fail-close**）；
  但有四条短板——**无默认沙箱**、无 MCP/ACP、内层 AgentLane 半成品、无扩展 API 版本契约。
  → **正确口径**：不是"Pi 不安全"，而是 **"Pi 把信任放在『谁装了它』，而不是『它是什么代码』上"**。
  在质量门槛高的环境里，这意味着它需要自己补上组装件，不能直接上生产。
- **共同点（本幕落点）**：这两条路线把 harness 从"产品的一部分"变成"**你可以改的东西**"。
- **诚实边界（必须同屏）**：DSH 官方插件市场未上线、插件治理与白名单要自建、v0.1 接口仍在快变、
  二次开发量明显高于 Product First。Pi 与 DSH 都必须对称地讲代价。

### 第五幕：怎么判断

- **第一句**：harness 才是真正的变量——模型大家都在用同一个，差距在底下那圈。
- **第二句**：先看清你手上 harness 的边界——用第三幕那五个自查维度过一遍。
- **第三句**：值不值得换——什么条件下值得，什么条件下**先用好手上的**（大多数团队的默认答案仍是这个）。
- **反软广纪律**：本幕必须包含"什么时候别折腾"，否则第四幕会变成产品推荐。

### 收尾

- 三句话合成一句带走的话（候选见 `04-open-questions.md`）。
- 收束回到开头那个追问：为什么同一个模型，交出来的东西不一样。

## 口径红线

1. **前两层成熟，Loop / Graph 是新兴观察对象**，不讲成既定生产范式。
2. **Graph 可以编排 Loop**，也可包含工具、验证器或一次性节点；不能把所有 Graph 节点画成 Loop。
3. **harness 是可靠性边界**，不等于几何上"包住"所有节点；关系图只表达治理关系，不宣称严格运行时包含。
4. **"harness 才是变量"是本 talk 的解释性结论**，不是上游报告的结论；引用时必须区分。
5. **DSH 的原生机制不是 MCP**：说 `ctx.llm`、`ctx.tools`、capability seam、plugin。
6. 外部数字一律带证据强度标注（见 `../02_evidence/00-absorption-plan.md` 第三节），
   星数/插件数/成本数字标观测日期，只作趋势不作基准。
7. **不出现 OPC / 一人公司 / 姊妹项目的任何引用**；不点听众所属行业，不用行业专属术语。
8. 安全事件的讲法是**因果链**（授权为何必须在执行端），不是厂商名单或编号表。
