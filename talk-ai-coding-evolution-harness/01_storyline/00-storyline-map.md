## 题目

**AI Coding 演变指南：从 Prompt Engineering 到 Harness Engineering**

开场追问（副标题候选）：**这次改动，凭什么可以上线？**

## 一句话主线

**AI 能写代码早就不是问题，AI 写的改动能不能上线才是问题。
而当你写的不再是程序、而是智能体时，让它跑起来的那圈东西，必须在你自己手上。**

（前半句是 v0.1 的，仍然成立；**后半句是 v2 新增的**，它把全场从"用 AI 写代码"翻到"你要造 agent"。）

---

## 全场主轴：只追一个问题

**这次改动，凭什么可以上线？**

听众的流程本来就在答这题——**谁批 / 在哪个环境跑 / 留下什么记录**。这三道关是他们已有的纪律，
不是讲者教的新东西。所以开场不是"我给你们一个新概念"，而是"我拿你们自己的三道关，去问 AI 的改动"。

选这题的三个理由：

1. **听众自己已经有答案** → 开场让他们先说出来，后面的东西才有地方挂。
2. **这三个问号天然就是 圈住 / 拦住 / 看清**，不是硬塞的三分法——是那三道关本来就这么问。
3. **命名被迫后置**：追到"这一步是谁放行的"发现没人放行 → 那这个"放行能力"一直在哪 →
   在模型外面那圈 → 它叫什么 → harness。**先有动机，后有词**，不讲"第六个新名词"。

## 第一幕的骨架：五层工程 = 同一个问题的五轮答案

> **不要讲成"五个新名词"。** 每层讲清三件事：把答案放在哪 / 它默认了什么前提 / 这个前提什么时候不成立。
> 这样**反转句自动变成条件句**，不需要"更多 context ≠ 更好回忆"那种句式。

| 层 | 管什么 | 答案放在哪 | 它默认的前提 | 这个前提什么时候不成立 |
|---|---|---|---|---|
| Prompt Engineering | 提示词 | 把规矩写进话里 | 模型会照做 | 措辞的边际收益已经很低（Anthropic 2025-09-29，**定性判断**） |
| Context Engineering | 上下文 | 把事实塞进上下文 | 塞进去它就用得到 | 上下文超过一定长度后，对中段的召回下降（Chroma《Context Rot》2025-07，⚠️ 厂商自建评测）；**最小脚手架也能跑出结果**（Anthropic 2024-10-30 原句） |
| Harness Engineering | harness | 权限、沙箱、工具、验证门禁、执行记录、CI | 这一圈是存在的 | 存在，但**边界由产品定义**（留给第三幕） |
| Loop Engineering | 怎么回头 | 让上次结果改变下次行动 | 单次运行是受控的 | 停止条件不依赖上次结果时，那叫重试，不叫 loop；单次运行不受控时，loop 只是把错误复制得更快 |
| Graph Engineering | 怎么分工 | 跨节点协调与状态 | 单个 agent 是受控的 | 节点各自失控时，编排只是放大 |

**每上一层，都对下一层做了一个前提**：
`Prompt→Context` 默认"模型能吃上下文"；`Context→Harness` 默认"环境是受控的"；
`Harness→Loop` 默认"单次运行受控"；`Loop→Graph` 默认"单 agent 受控"。
**前提不成立的地方，就是这一层管不到的地方**——这一句是第一幕的组织方式，不是一句金句。

**公式 `Agent = Model + Harness` 在五层过完之后才给**（第一幕收束）。
harness 这个名字在第三层自然出现，不是凭空冒出来的第六个词。

## 第四幕的骨架：你今后要写两类程序

> **这一幕是本场的赌注。** 前三幕讲的都是"用 AI 写代码"，听众的处境是**用**；
> 从这一幕起，处境变成**造**——而造 agent 时，harness 的性质完全不同。
> **没有这一翻，第四幕就是讲者的兴趣；有了这一翻，它是听众明年就会遇到的处境。**

| | 传统程序 | 智能体 |
|---|---|---|
| 行为在什么时候确定 | 写的时候 / 编译的时候就定了 | **运行时才被决定** |
| **写** | 现成 coding harness（Codex、Claude Code）已经把沙箱、审批、事件流做进去了 | 智能体的代码也是代码，**写**的过程同样可以放在这些工具里 |
| **跑** | 目标环境你们本来就有 | **需要一套真正能运行 agent 的 harness 环境**——谁来给它权限、谁来记它的每一步、失败停在哪 |
| 那圈东西归谁 | 工具的一部分，用就好 | **你产品的一部分，边界必须由你定** |
| 结论 | **这条路不用你们自己造** | **harness 得在你自己手上** |

**造 agent 的 harness，两条路**：

| | 自己组装 | 可组合运行时（DSH） |
|---|---|---|
| 入手方式 | 执行后端 / 工具集 / 门禁 / 事件流，四样自己拼 | 通过插件把能力装进去 |
| 修改权 | 最大，全在自己手里 | 每一层都能替换 |
| 治理 | 全部自建 | 白名单与逐件审计要自己建 |
| 价格 | 从零开始的工作量 | 二次开发量明显高于成品路线；官方市场未上线、接口还在快变 |
| 轻量样本 | **Pi**：三层 seam（执行后端 / 工具集 / 行为组合）做对了，统一注入点，in-process 护栏（two-phase binding · fail-safe · fail-closed）；但**没有默认沙箱、没有 MCP/ACP、没有扩展 API 版本契约** → 正确口径：**不是说它不安全，是说 Pi 把信任放在"谁装了它"，而不是"它是什么代码"上** | — |

**DSH 展开三页**（第四幕主体）：
① **没有特权核心**——Cordis 元框架，所有能力都是插件，不存在必须改源码才能动的东西；
四种运行模式本质是四套默认插件集；长程不是单一 loop（Goal / Ralph / workflow / Spawn-Fork 并存）。
② **会话日志是 single source of truth**——typed、append-only 的事件日志；模型看到什么，就被记下什么；
回放 / 恢复 / 分叉 / 审计，用的是同一份日志，只是四种看法 → **审计不是事后补的，是架构自带的**。
③ **代价**——市场没上线、治理要自建、接口还在快变。落点：这些不是缺陷，
是**"你拥有整个运行时"这件事本身的价格**。

**两边都还没解决的那件事**：对陌生插件的安全，两条路都还没有答案——一条没有沙箱，
另一条**插件化不等于安全**。所以这两条都不是"更先进的选择"，是**正在演进的路线**。
**这一页是全场可信度的关键，不能省。**

## 节奏：讲一段，停一下（★ 2026-09-17 复核：10 张 → 6 张）

> 用户的原话：**"开起始页，中间的呼吸页，一张一张讲下去，到结束页，我们用有节奏的办法。
> 毕竟要讲这么多东西，一口气全部讲，中间没有停顿，这个节奏把握得不好，听的人可能也很累。"**
> 复核时用户的追加意见：**"我们中间停下来继续的这个呼吸页好像还没达到这么多吧，搞得有点多了"**——
> 所以 10 张压到 **6 张**，并且每一张必须**同时收上一段、启下一段**。

**放置判据（只有满足其一才设呼吸页）**：

1. **结构接缝**——一幕结束、下一幕换话题，听众需要把上一幕卸下来。
2. **段内超 10 分钟**——同一条线上连讲超过 10 分钟，中间切一刀。
3. **需要听众自己先答**——前提已经给全，只差一步推导（检查点）。

**同时规定**：P11 / P24 / P33 这类 1–1.5 min 的**收束页自带呼吸**（讲完停 3–5 秒），
**不再额外插页**——否则同一处停两次，节奏反而拖。

**六张呼吸页的分布**：

| 代号 | 位置 | 这一段 | 大字（上屏唯一内容） | 收什么 | 启什么 |
|---|---|---:|---|---|---|
| B1 | P3 后 | 开场 6 min | 这三道关，你们本来就有答案。**AI 写的改动，谁来答？** | 开场三问 | 第一幕"我们答过五轮" |
| B2 | P7 后 | P4–P7 · 9.5 min | 前两层改的是它说什么。**能不能上线，谁说了算？** | 前两层都管生成 | 后两层都建在第三层上 |
| B3 | P15 后 | P8–P15 · 17 min | 圈住、拦住、看清——**都不是为 AI 新发明的** | 三道关 | 下面拿一次真实执行问一遍 |
| B4 | P18 后 | P16–P18 · 7 min | 刚才那一步，**谁批的？** | 演示后的缺口 | 第三幕"它是变量吗" |
| B5 | P21 后 | P19–P21 · 8 min | 模型没换。**换的是外面那一圈。** | 两条证据 | 这圈能不能改 |
| B6 | P27 后 | P22–P27 · 12 min | **写**，有人管了。**跑**，谁来管？ | 两类程序的分界 | 两条路 |

**为什么这几处之外不再设**：

- **P11 / P24 / P33** 是收束页，自带呼吸，不重复插。
- **P25**（分野）与 **P30**（DSH 第一页）都是**新话题的入口页**，开场本身就有停顿感。
- **P28–P33**（11.5 min）是唯一超过 10 分钟的一段，但它是**一条路连着讲完**（路一 → 路二三页 → 两边都没解决），
  DSH 那三页切开就散了，所以整体保留。

**规格**：纸白满底 · 一句大字 · 留白 ≥60% · 不用语义色 · **不显示页码**。
讲法：念完就闭嘴，静默 5–8 秒时**看听众，不看屏幕**；不补例子，哪怕当场想起一个特别好的。

## 口径红线

1. **前两层成熟，Loop / Graph Engineering 是新兴观察对象**，不讲成既定生产范式。
2. **Graph 可以编排 Loop**，也可包含工具、验证器；不能把所有节点画成 Loop。
3. **harness 是运行边界**，不等于几何上"包住"所有节点；不是"最高层"也不是"最底层"。
4. **"harness 是变量"与"你要自己握住那圈东西"都是本 talk 的解释性结论**，不是上游报告的结论；讲述时必须认领。
5. **DSH 的原生机制不是 MCP**：说 `ctx.llm`、`ctx.tools`、capability seam、plugin。
6. 外部数字一律带证据强度标注（`../CONTEXT.md` 四档，不发明新词）；星数 / 插件数 / 成本标观测日期，只作趋势不作基准。
7. **不出现 OPC / 一人公司 / 姊妹项目的任何引用**；不点听众所属行业，不用行业专属术语。
8. 安全事件讲**因果链**（授权为何必须在执行端），不是厂商名单或编号表。
9. **（v2 新增）语域是教学 / 推导，不是市场营销。** 句类用**前提 / 推导 / 结论 / 边界**，
   不用**钩子 / 转场 / 金句 / 反转**（`02-turning-points.md` v1 的分类法已废）。
10. **（v2 新增）大题字只能是这一页的论点本身**，且底下必须压着对照项。
    已废除 76 / 88 两档字号；现存两档：论点数字 104（限 ≤4 页）、论点句 56。
    反面样本（v1 用过、不得恢复）：`7` `3` `反` `散` `0` `02` `五问`。
11. **（v2 新增）每一页必须让听众拿走一个东西。** 拿不到的页 = 零增量页，删或合并。
12. **（v2 新增）讲者时间表不上屏**（前 42 min / 后 42 min / 幕级分钟数，全部下屏）。
