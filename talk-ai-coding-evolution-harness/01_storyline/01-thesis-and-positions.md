# 核心论点与立场

> 本文件回答：这场 talk 主张什么、每条主张靠什么撑、哪些是**本 talk 的推断**而不是素材的结论。

## 中心结论

**AI Coding 的瓶颈已经从"生成"移到"交付"。**
决定交付的是模型外面那圈东西——**harness**；它是交付质量的真实变量，
而且已经出现把 harness 做成**可替换件**的路线。团队的默认动作应该先是"用好手上的"，
但当运行边界开始限制真实交付时，值得认真评估换一个。

## 立场与边界

1. **不做产品推荐。** 讲 Pi 与 DSH 是因为它们代表两条**路线**（轻量组装 / 框架优先），
   不是因为它们比谁好。第四幕必须包含 DSH 与 Pi 各自的代价，第五幕必须包含"什么时候别折腾"。
2. **不宣称 harness "最高"或"最大"。** 它是每次动作都绕不开的**执行边界**，
   五层之间是注意力与责任的叠加，不是大小或包含关系。
3. **区分素材结论与本 talk 判断。** A1、A3、A6、A7 是本 talk 的解释性结论，
   页面上要能说清"这是我的判断，我靠这几条撑"，而不是假借报告背书。
4. **主动打折。** 涉及厂商自述、趋势级、口径不可比的数字，同屏标注证据强度。
   这是本场可信度的一部分，不是脚注。
5. **不滑向安全 / 合规叙事。** 圈住 / 拦住 / 看清借用听众已有的纪律感，
   但目的是解释 harness 是什么，不是讲治理。

## 一句话立场

**先用好手上的；当那圈东西开始限制真实交付时，记住它是可以换的。**
