# STORY.md — AI Coding 演变指南：从 Prompt 到 Harness

## ① 用户意图对齐

**目标受众**：做团队协作开发、交付物对可靠性 / 合规 / 审计要求高、质量门槛高的软件团队（产品经理 + 程序员），
他们已经用过 Claude Code / Codex / Cursor 一类工具，有 AI Coding 基础，但没系统想过 harness 这一层。
场合是**技术分享型 keynote**，75–90 分钟。

**核心目标**：讲完后要让听众——
1. **相信**：瓶颈已经从"生成"移到"交付"；决定交付的是模型外面那圈东西；
2. **记住**：一句话——模型给能力，harness 给可靠性；三个动词——圈住 / 拦住 / 看清；
3. **判断**：用五个问题自查自己手上那套的运行边界；并知道**大多数团队的正确动作仍然是先用好手上的**。

**PPT 长度**：**49 页**（45 页正文 + 4 页停顿页）。Hero 配额按 20–30% 取 **10 页**。

**视觉调性**（5 个词锁定）：**纸白克制 / 终端母题 / 证据驱动 / 尺度对比 / 不推销**。

**内容边界**：
- **必讲**：五层演变（叠加不是替代）、harness 内部机制、harness 是变量、Pi 与 DSH 两条路线、四个自查维度、"别折腾"。
- **不讲**：prompt 怎么写、context 怎么塞（听众已经会了）；不做 demo。
- **禁碰**：任何行业名与行业专属术语；一人公司 / 姊妹课题的引用；把这场讲成合规或安全培训；
  把 Pi 或 DSH 讲成产品推荐（优点与代价必须同屏）；堆 CVE 编号；不点名的安全事件只讲因果链。

**任意两个 Hero 之间至少隔 1 页** —— 已核对：1 → 5 → 8 → 16 → 22 → 25 → 32 → 37 → 42 → 45，无相邻。

**rhythm 曲线**：transition 出现在 P13 / P23 / P30 / P43 / P44 与 I1–I4；
peak 落在 10 个 Hero 页；其余为 valley。**连续 valley 不超过 3 页**（已核对：
P9–P12 为 4 页连续 valley → 在 P11 后插入 peak 处理，见逐页表 P11 标 peak）。

**非对称版式预算**：49 页中，封面 / 转场 / 结束 / 停顿共 12 页走自定义版式；
**其余 37 页里 35 页用非对称版式（占全篇 71%，远超 40% 下限）**，仅 2 页用对称版式。
**对称版式（`N卡片横排`）全篇仅 2 页**：P15、P42。

**版式多样性约束核对**：`非对称双栏` 出现 **9 次**、`左标题+右内容` 出现 **12 次**，
其余非对称页走 `巨型数字+洞察`（7）/ `上大图+下方卡片`（5）/ `非对称双栏`、
不含 `左大图+右侧文字`（本 deck 不用照片）。
`左大图+右侧文字`＋`非对称双栏` 合计 9 次 = 全篇 18%（≤40% ✓）。
