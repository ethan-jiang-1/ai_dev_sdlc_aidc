# AI Coding 演变指南 —— 全页内容交付稿

> **这是什么**：一场 75–90 分钟技术演讲的**全部页面内容，自包含**。
> 每页的「上屏文字」「这一页在答哪一步」「讲法」「推导句」「证据与口径」都在这里，
> **不依赖任何其他文件**。拿去任何 PPT 工具 / agent 里都能直接开工。
>
> **规模**：**42 张** = 正文 **37 页（P1–P37）** + 停顿页 **5 张（B1–B5）**。
> 正文 78 min + 停顿约 1.7 min ≈ **80 min**（75–90 区间内，留约 5 min 现场缓冲）。
>
> **分隔约定**：**每一页都以一条 `---` 开头**（含 P1 之前那一条）。本文件里的 `---`
> **只出现在页面边界上**，别处一律不用。按 `^---$` 切分即可：
> **第 1 段是前面的说明与附录，第 2 段起依次就是 42 页**（P1, P2, P3, B1, P4, …, P37）。
> 页块标题形如 `## P4 · …` / `## B2 · …`；页面按**实际放映顺序**排列
> （停顿页就插在它该出现的位置），不是「正文一组、停顿页一组」。
>
> **字段约定**：标了**「不上屏」**的内容是给讲者 / 给你理解用的，**不要放上页面**。
> 其余字段（L1 / L2 / L3 / L4）才是上屏内容。


## 0. 先读这一节：这份稿怎么用

三件事决定了这页为什么长这样，改稿前请先接受它们：

1. **这是教学稿，不是营销稿。** 每一页都必须同时具备一条〔前提〕和一条〔边界〕
   —— 也就是「它成立要依赖什么」和「它在什么条件下不成立」。
   只有结论、没有前提和边界的页，会被判定为广告页，需要回炉。
2. **大字是论点本身，不是节奏工具。** 全场只有 **P21 / P22** 两页用超大字（104px），
   且这两页的大字底下都**必须压着一个对照项**（`38.3%` 底下压「换之前 13.3%」；
   `76%` 底下压「只剩 53%」）。其余论点句用 56px。**不允许**把单个汉字、孤立数字
   （`7` `3` `反` `散`）放大当锚点——这是上一版失败的主因。
3. **证据必须与数字同屏。** 每一个外部数字都要当场标出证据强度（四档见 §1.4），
   **P21 / P22 两页要当场「降档」**，而且两页的降档说法必须不同。

另外三条硬纪律：

- **讲者分钟数一律不上屏**（连幕级分钟数也不上）。本稿里的时长只给你排节奏用。
- **上屏文字不出现内部用词**「引桥」「尾巴」。
- **harness 在 P8 之前不给名**；`Agent = Model + Harness` 只在 P12 出现。


## 1. 全场硬约束（改稿前必读）

### 1.1 主轴与叙事脊柱

**全场主轴（只追一个问题）**：**这次改动，凭什么可以上线？**

听众的流程本来就在答这题 —— **谁批 / 在哪个环境跑 / 留下什么记录**。
这三道关是他们**已有的纪律**，不是讲者教的新东西。
所以开场不是「我给你们一个新概念」，而是「我拿你们自己的三道关，去问 AI 的改动」。

**一句话主线**：AI 能写代码早就不是问题，**AI 写的改动能不能上线**才是问题。
而当你写的不再是程序、而是智能体时，让它跑起来的那圈东西，**必须在你自己手上**。

**叙事脊柱（六步，全场只走这一条线）**：

| # | 一步 | 作用 | 落在 |
|---|---|---|---|
| 1 | 一次改动上线前，你们本来就要过三道关 | 让听众**先说出答案** | 开场 |
| 2 | 同一个问题去问 AI 的改动，三道关答不上来 | 立起本场的问题 | 开场 |
| 3 | 这问题我们答过五轮（五层工程），每轮把答案放在不同地方，每轮都默认了一个会失效的前提 | 逐个排除，推导到那圈东西 | 第一幕（**先给桥页**） |
| 4 | 追责链断在哪一步：圈住 / 拦住 / 看清 | 拆开那圈东西 | 第二幕 |
| 5 | 它是变量：同一个模型换一圈，就是两套系统 | 从「它是什么」推到「它能改」 | 第三幕 |
| 6 | 你今后要写两类程序；写智能体时，那圈东西得在你自己手上 | **本场落点** | 第四幕 → 收尾 |

**节奏机制**：讲一段、停一下。全场 **5 张停顿页 + 3 处收束页短停 = 8 次停顿**。
停顿页只放在**结构接缝**或**段内超 10 分钟**处；**连续推导中途不插停顿页**
（五层 P6–P10 就是一条线连着推，中间切开就散成五个概念）。
**悬念式转场禁用**（「另一条呢？」这类不给线索的纯吊胃口）；
检查点式提问可用（「你已经知道 A 不行、B 不行，那 C 呢？」）。

### 1.2 对象红线

听众是**做团队协作开发、交付物对可靠性 / 合规 / 审计要求高、质量门槛高**的软件团队
（产品经理 + 程序员）。他们已经有 AI Coding 基础，**不需要科普 prompt 和 context**。

- 论证必须落在**一致性 / 门禁 / 责任归属 / 交付可追溯**，**不要滑向个人技能进阶**。
- 全场 audience-facing 文字**不出现 OPC / 一人公司 / 姊妹项目引用**。
- **不点听众所属行业名，不用行业专属术语** —— 听众特征一律用通用描述承载
  （「团队协作、质量要求高、要过审、要能查、要能还原」），换观众不用改稿。
- **不把这场讲成合规或安全培训。** 圈住 / 拦住 / 看清是桥，不是终点。

### 1.3 术语纪律

**量词固定用「层」**：说「五层工程」「第三层」「每上一层」，
**不要说「五门工程」**（量词不对，且「门」会被听成课程）。
**不要画成金字塔、不要写成「五代产品」** —— 五层是**注意力与控制面的叠加**，不是层级高低。

**核心词定义**（全场统一，不要换说法）：

| 术语 | 定义 | 不要写成 |
|---|---|---|
| **harness** | 模型之外的一切运行与治理条件：权限、沙箱、工具、验证门禁、执行记录、CI。`Agent = Model + Harness` | 「框架」「平台」「中间件」「最高层」 |
| **运行边界** | 一次动作能不能发生、由谁授权、在什么环境里发生、留下什么记录 | 「安全边界」（太窄）、「架构边界」（太泛）、**「执行边界」**（同一概念，全库统一用「运行边界」） |
| **圈住 / 拦住 / 看清** | 沙箱+权限 ／ 工具协议+验证门禁 ／ 可观测性+provenance+CI | — |
| **提出权 / 执行权** | 提议下一步动作（可交给模型）／ 决定这一步能否发生（**必须留在 harness**） | — |
| **固定 harness** | 成品 agent 产品随产品交付的既有运行环境，扩展边界由产品定义 | 「封闭的」「不好的」 |
| **可组合 harness** | 运行时每一层都可装配与替换的 harness runtime | 「自研框架」「更高级的 harness」 |

**不新造中文词**：查不到通行译法的一律**保留英文**，只加一句白话解释，不硬译、不生造。
**全场保留英文的词**：

| 保留英文 | 白话解释（不是译名） |
|---|---|
| harness | 模型之外的一切运行条件 |
| single source of truth | 所有东西都以这一份为准 |
| seam（capability seam） | 可以替换的地方 |
| fail-closed / fail-safe | 失败时就拦住 / 失败时退回安全状态 |
| computational / inferential | 能重跑的 / 换个时间可能换结论的 |
| typed events | 带类型的事件 |
| append-only | 只追加 |
| in-process | 在同一进程里 |
| projection | 同一份日志的不同看法 |
| Goal / Ralph / workflow / Spawn-Fork | DSH 的模式名，译了反而认不出 |

**固定搭配（原文照用）**：`authorize at execution, not at generation`

**禁用词**：OPC / 一人公司 / 姊妹项目引用；行业名与行业专属术语；
「最高层」「最底层最重要」；讲 DSH 时说「MCP 挂载」（**DSH 的原生机制不是 MCP**）；
自造的证据强度档位；CVE 编号堆叠；指 harness 时说「框架」「平台」；
新造的中文对等词（如「唯一真源」「接缝」「线束」）。

### 1.4 证据强度四档（统一写法，不发明新词）

| 标注 | 含义 |
|---|---|
| **一手** | 官方文档、官方仓库、官方发布，可核验 |
| **⚠️ 厂商自述** | 厂商 / 作者自述，未经独立审计 |
| **⚠️ 降级取证** | 网络受限下仅标题 / 摘要级核验，正文未读 |
| **趋势级** | 有来源但属论述、媒体或榜单级，无方法论支撑，只作趋势不作基准 |

配套规则：星数、插件数、成本数字一类会漂移的值，标注**观测日期**；
口径不可比的两个数字**不合成一个**。

**关键口径红线（引用前必查，最容易说错的几条）**：

| # | 事项 | 正确口径 |
|---|---|---|
| 1 | Codex 的能力提升数字 | ⚠️ **厂商自述**，无第三方审计；ARC-AGI-3 **13.3% → 38.3%**；一手表述是「**输出** token 少 6 倍」，**不要说成「同任务 token 降 1/6」**。同屏必须标「厂商自述」 |
| 2 | 8-harness 对照实测 | ⚠️ **趋势级**：快讯 / news 类来源、无方法论文档。只作方向性信号，**不作基准结论** |
| 3 | Pi 的 GitHub star | **趋势值**，随文章日期漂移（同期 86k–98k 浮动），观测 2026-09-06。**不画增长曲线** |
| 4 | DSH 插件数量 | 约 300 → 约 3000（媒体口径）；第三方商店 2000+ / 3000+ **口径互不可比，不合成一个数字** |
| 5 | DSH 的原生机制 | **不是 MCP**。说 `ctx.llm` adapter、`ctx.tools`、capability seam、plugin |
| 6 | Pi 的安全通告 | 讲**因果与后果**（无内置权限模型 + 项目本地扩展加载边界），**不堆 CVE 编号**，不复述具体版本区间 |
| 7 | 五层的成熟度 | 前三层成熟可信；**Loop / Graph 是 2026 夏才冒头的新兴叙事、低置信度**，不讲成既定生产范式 |
| 8 | Graph 与 Loop 的关系 | Graph **可以**编排 Loop，也可包含工具、验证器；**不能把所有 Graph 节点画成 Loop** |
| 9 | **Pi 有没有 MCP**（两份素材冲突） | 选型研究引 PR #3774，而源码级核对结论是**没有 MCP/ACP 实现**。→ **采信有源码锚点的一方**：讲「没有 MCP/ACP 实现，生态锁在自家 extension API，外部工具要付适配层税」，**不要把该 PR 当成已 GA** |
| 10 | Pi 的「无沙箱」怎么说 | **不能说成「Pi 不安全」**。正确口径：**「Pi 把信任放在『谁装了它』，而不是『它是什么代码』上」**。且要区分：Pi 有「沙箱执行工具」的思路，**没有「沙箱运行扩展代码」的机制** |
| 11 | harness 评价类素材 | 是**评价文档**，硬事实 / 解释 / 推测分开标；引用时必须保留这个分层，不要把评价写成源码事实 |

### 1.5 中文编辑门（上屏文字与讲稿都要过）

这是一场**中文演讲**。中文负责叙述和推理，英文只负责标识确实需要保留的术语、产品名与代码。

1. **从意思出发重写**：先确定这句话要说清的判断，再用中文重新组织主语、动作和结果；不逐词搬运英文句法。
2. **标题能直接讲出口**：优先使用完整判断或自然提问；避免名词连续堆叠、斜杠串词、箭头代替因果。
3. **术语中文先行**：正文统一使用「运行边界、门禁、执行记录、交付底线」这类说法；
   `harness`、`runtime`、`skill`、`plugin`、`gate` 等没有稳定等价词或承担精确机制含义的词可以保留，
   但必须嵌进自然中文句子，**不能充当中文谓语**。
4. **一句只推进一个判断**：先给结论，再补条件、证据或例外。
5. **完成前朗读**：逐页朗读标题、上屏文字与关键转场。凡是需要倒回去才能读懂、
   或离开英文词就说不清的句子，继续改写。


## 2. 视觉方向（原方案；你可以换，但换了要知道放弃了什么）

**一句话视觉判断**：纸白底 + **代码终端母题**。等宽字体承担代码 / 命令 / 日志 / 指标；
深墨承担标题与结构线；语义色只做强调。

上一版的失败原因是**所有元素都趋近中间大小**（标题 27px、正文 13.5px、无巨型锚点、大量 50:50 等分）。
本版三条硬修正：**① 字号阶梯拉开；② 每页必有一个视觉锚点；③ 除 2 页外全部走非对称版式。**

### 2.1 色板（4 个 hex + 画布）

| 角色 | hex | 用途 | 面积占比 |
|---|---|---|---|
| **画布** | `#FAFAF7` | 全篇统一底色（纸白） | 铺满 |
| **主色** | `#1C1F23` | 标题、正文主文本、结构线、图表主轴 | ≤ 55% |
| **辅色** | `#0F6E56` | active path / 反馈 / 正面锚点 / 巨型数字 | ≤ 25% |
| **强调色 A** | `#A32D2D` | 门禁 / 风险 / 缺口 / 未护栏处 | ≤ 8% |
| **强调色 B** | `#8A5A00` | 证据 / 提示 / 已提交工件 / 趋势级标注 | ≤ 8% |
| 中性 | `rgba(28,31,35,0.04 / 0.10 / 0.18 / 0.40)` | 卡片底、分隔线、次级文字 | 剩余 |

**派生规则**：浅色底一律由主色 rgba 派生，**不引入新的 hex**。

**色彩节奏**（每页落在下表模式之一，禁止全篇雷同）：

| 模式 | 适用 | 强调色占比 |
|---|---|---|
| **A · 克制** | 常规内容页 | 强调色 ≤ 5%，辅色 ≤ 10% |
| **B · 聚焦** | Hero 页（含 P21 / P22 两页大字） | 强调色 15–20%，只出现在锚点元素上 |
| **C · 留白** | 转场 / 停顿 / 结束 | 强调色 ≤ 3%，几乎只有墨色 |

**禁忌**：同一页出现 ≥ 2 套主色板；青绿与朱红同页都做大面积（只允许一个当焦点）；
全篇每页颜色分配比例差异 < 10%；**Emoji 一律禁用**；**禁用渐变与投影**
（层级只靠 ① rgba 半透明层次 ② 1px 结构线 ③ 尺度对比 三件事建立）；
**不使用整页黑底章节或深浅交替**。

### 2.2 字体与字号

| 用途 | 字体 |
|---|---|
| 中文全部 | **`PingFang SC`** |
| 西文 / 数字 / 代码 / 眉题 / 页码 / 指标 | **`SF Mono`**（回退 `Menlo`） |

**字号只有两档承担论点**：**104**（论点数字，全场仅 P21 / P22）与 **56**（论点句）。
其余：封面 64 / 主标题 36 / 正文 22 / 辅助 18 / 眉题页码 14。
**76 / 88 两档已废除**——它们此前全被用来放单个汉字或符号，正是「一惊一乍」的来源。

### 2.3 密度与锚点

- **每页强制 ≥ 1 个视觉锚点**（满足任一）：字号 ≥ 64px 的文字元素；
  占内容区 ≥ 40% 的结构图；面积 ≥ 280×200 的平色块。
  **禁止**一页里所有元素都落在 18–36px 这个区间。
- **抽掉标题后页面不能是空的** —— 只剩一两行字的页必须回炉。
- 卡片内容垂直占用 ≥ 容器高度 85%；同一行兄弟卡片的「标题块 / 正文块 / 尾部元素」三段 y 轴等高。
- **禁止「均匀稀薄」**：留白必须围绕焦点，不是每两个元素之间都差不多。
- 停顿页走**反向标准**：留白 ≥ 60%，越空越好 —— 正文页求「不空」，停顿页求「空」，两套标准别互相套用。

### 2.4 图源策略

**全原生矢量，不使用照片 / AI 生图。** 信息结构图、五层关系图、对照表、时间线、代码块、
终端构件一律用可编辑图元绘制 —— 清晰、零错字、投影稳。
图标克制使用（统一线性风格、32×32，全篇最多 6 处），只用在三个动词上：
`shield`（圈住）／`check-circle`（拦住）／`eye`（看清），外加 `exclamation-circle`（证据强度提示）。
**严禁编造图标名，严禁 Emoji。**
**不套第三方模板、不引入活动方视觉元素。**
