## P5 · 发动机
**上屏**
- 模型越强，工程杠杆点越往上移
- 模型能力更强 → 单次交互的边际工程收益更低 → 杠杆点上移
- 上移不等于替代

**讲点** 五层不是五种潮流，是一台发动机的五次换挡。能力到位后，原来由人手工承担的动作上移到新的工程对象。
**证据** METR「50% 可靠性任务长度约每 7 个月翻倍」；Anthropic 关于 prompt 措辞重要性下降的观察（一手/官方工程文）— 源 `rawdata_ai-coding-evolution-final` 01/02 章

## P6 · Prompt
**上屏**
- Prompt 管表达 —— 但它已经不再是你的杠杆
- 两年前你花三小时调措辞；现在调不调，差别已经不大了
- 不是你变强了，是这层被吃掉了

**讲点** 这层不是不重要，是**已经变成默认能力**了——不值得再当主战场。
**证据** 报告 01 章。⚠️ 该章部分量化口径需回源核对后再上屏（见 open-questions 待办）

## P7 · Context
**上屏**
- Context 管模型此刻所见 —— 不是越多越好
- 更多上下文 ≠ 更好回忆
- 最小脚手架也能跑出结果

**讲点** 这是听众最容易自我感觉良好的一层（"我 AGENTS.md 写了 500 行""我挂了一堆工具"）。讲 context rot 打掉这个错觉：塞得越满，越可能看漏中间那段。
**证据** 报告 02 章（context rot / Lost in the Middle；最小脚手架表述）。**上屏前必须回源核对**

## P8 · Harness 定义
**上屏**
- `Agent = Model + Harness`
- 模型之外的一切，都是 harness

**讲点** 这一页只定义，不展开。展开留给下一幕。

## P9 · Loop
**上屏**
- Loop 管时间上的反馈
- 上次结果不改变下次行动，那叫重试，不叫 loop
- 没有门禁的 loop，只会更快地放大错误

**讲点** 前半句是黄金法则，后半句是反转。先让听众点头，再把风险给他们。
**证据** 报告 04 章

---

## P10 · Graph
**上屏**
- Graph 管空间上的协作
- 显式节点、边、状态
- 它可以编排一部分 loop，也可以编排工具和验证器

**讲点** 不要把两种图画成同一条线。Graph 的价值是**把依赖和路由显式化**，不是"更大的 loop"。
**证据** 报告 05 章

---

## P11 · 五层关系
**上屏**
- 五层是叠加，不是替代
- Prompt / Context 服务一次模型调用 · Harness 保障每一次执行 · Loop 跨运行 · Graph 跨节点
- 成熟度：前三层成熟；Loop / Graph 是新兴观察对象

**讲点** 图的重点不是面积或高低，是职责与依赖。今天重仓前三层。
**证据** 报告 06 章。**口径**：Loop / Graph 不讲成既定生产范式；Graph 不能把所有节点画成 Loop

## P12 · 团队焊点
**上屏**
- 五层是交付链上的五个控制面
- 在团队里，它们往往散在不同人手上 —— 或者根本没人管

**讲点** 这是团队版的独有问题：不是"我不会"，是"我们不一致"。
**证据** —（本 talk 的观察）

## P13 · 转场
**上屏**
- 前两层改不了"能不能上线"
- 后两层只会放大结果
- 所以问题落回中间那一层

**讲点** **口径**：这是本 talk 的推断，不是上游报告的结论。讲的时候要认领（"我的判断是……"）。
**证据** 结构线 + 哲学线 + 风险线三条支撑，见 `01-thesis-and-positions.md` A3

## P14 · harness 是必经
**上屏**
- 每一次真实动作，都要经过 harness
- 每个可执行节点最终都落到一次真实执行
- 上层不会自动修复底层的缺口

**讲点** Loop 每次迭代实例化一个 harness；Graph 的每个节点跑在自己的 harness 里。
**证据** 报告 04/05/06 章

## P15 · 一句话
**上屏**
- 模型给能力，harness 给可靠性
- 它不负责让模型变聪明
- 它负责让同一个模型每次都不掉链子

**讲点** 全场最需要被记住的一句。
**证据** Böckeler 框架 + 本 talk 的表述

## P16 · 两套控制
**上屏**
- 可靠性发生在两次：行动前约束，行动后反馈
- Guides：按这个样式写 · 必须过这个检查 · 只能用这些工具
- Sensors：测试挂了 · 类型不过 · 退出码非零

**讲点** 用"教人做菜"说明：先说规则，再尝结果。
**证据** Böckeler Guides / Sensors 框架 — 报告 03 章

---

## P17 · 确定性优先
**上屏**
- 能交给确定性判的，绝不靠模型自觉
- 可复现、可审计：测试 / lint / 类型 / schema
- 不可审计：AI review、模型判断

**讲点** 原则一句话：能交给机器门禁的，绝不靠模型自觉。模型判断只做兜底。
**证据** 同上（computational vs inferential）

## P18 · 圈住
**上屏**
- 圈住：让它只能碰该碰的
- 沙箱 + 权限
- 把 agent 圈进你们已经在用的那圈边界

**讲点** 这一页的关键动作是"对号入座"：你们对生产环境本来就有一圈边界，现在把 agent 也圈进去。
**证据** 报告 03 章 + `01_storyline/06-harness-internals.md` 团队映射

## P19 · 拦住
**上屏**
- 拦住：把对错变成机器能判的关卡
- 工具协议 + 验证门禁
- 在离源头最近的地方就地拦下

**讲点** 你们本来就有的那道变更门禁，现在让 agent 的动作也走同一道。
**证据** 同上

## P20 · 看清
**上屏**
- 看清：每一步都留下痕迹

- 接进 CI，每次交付可审计

**讲点** 这一页最容易被听众接住——"出事要能还原"是他们本来就认的事。
**证据** 同上

## P21 · 提议权与执行权
**上屏**
- 提议权可以交给模型，执行权必须留在 harness
- 提议 → 独立检查 → 放行 / 拒绝并记录

**讲点** Loop 和 Graph 负责安排下一步，harness 决定这一步能不能发生。**检查必须是独立的**。
**证据** 报告 04/05/06 章（plan → check → execute 的实例）

---

## P22 · 执行时授权
**上屏**
- 授权要在执行那一刻发生
- 审批不能挂在"它说它会怎么干"上

**讲点** 讲因果链，不点名、不堆编号：工具调用的形状可以被伪造 → 执行端若只相信"这看起来像一次合法调用"，独立授权就缺失 → 动作仍然会发生。修复口径：`authorize at execution, not at generation`。
**证据** 报告 03 章第六节。**口径**：只讲因果，不把厂商名或编号堆成画面主体

## P31 ★ · 两条路线
**上屏**
- 两条路线的分野：引擎即用 vs 你拥有整个运行时

## P32 ★ · DSH：没有特权核心
**上屏**
- 没有特权核心 —— 所有能力都是插件
- 不存在必须改源码才能动的东西
- 四种运行模式，本质是四套默认插件集

**讲点** 顺带提一句：它的长程也不是单一 loop，是几种接力方式并存（Goal / Ralph / workflow / Spawn-Fork）。**不必展开**，只让听众知道这不是又一个循环。

## P33 ★ · DSH：会话日志
**上屏**

## P35 ★ · Pi：结构做对了什么
**上屏**
- 三层同心接缝：执行后端 / 工具集 / 行为组合
- 所有能力走同一个注入点
- 进程内护栏：两阶段绑定、失效保护、**失败即拦**

**讲点** 它把接缝放在"会变的地方"，而不是随手按类名切——所以换执行后端、加工具、改行为组合，是三条清晰的变化轴。
**证据** `rawdata_pi-digested/harness/01-Architecture/`（1.1–1.4，**带源码锚点**）

---

## P36 ★ · Pi 的代价
**上屏**
- 没有默认沙箱：扩展 = 宿主进程同等权限
- 装一个陌生包，约等于执行它的任意代码
- 也没有 MCP/ACP：外部工具要付适配层税

**讲点** 关键口径：**不是说它不安全**，而是——**它把信任放在"谁装了它"，而不是"它是什么代码"上**。在质量门槛高的环境里，这意味着护栏要你自己补。
**证据** `rawdata_pi-digested/harness/02-Boundaries/`（2.1–2.4，**带源码锚点**）。
**口径**：区分"沙箱执行工具"（有思路）与"沙箱运行扩展代码"（无机制）；MCP 状态采信有源码锚点的一方（红线 13）
