## P4 · 答不上来，不等于没人答过 · 1.5 min
**L1** 这三道关不是没人想过 —— 每答一轮，答案就往外挪一层
**L2** A — 一条横向位移带：左段"模型里面"放 ① ②，右段"模型外面"放 ③ ④ ⑤；每个点下面一行"答案放在哪"
**L3**
- 五轮答的是同一道题：**这次改动，凭什么可以上线**
- 前两轮的答案在**模型里面**：① 把规矩写进话里 ② 把事实塞进上下文
- 从第三轮起，答案挪到了**模型外面**：③ harness ④ 循环 ⑤ 编排
- 底部：**里面那两轮改的是它说什么、看到什么；只有挪到外面，才第一次碰到"这一步能不能发生"**
**讲法**（不上屏）**这一页是开场到第一幕的桥，不是又一张总览。**
它只做一件事：把 P3 那三个问号接住——"不是没人想过，是想过五轮，只是每轮都把答案放在了更外面一层"。

**L2** A — 五层叠加带（**不是金字塔**），中间一条**模型里面 / 外面**的分界线；每层标：层名 / 管什么
**L3**
- Prompt Engineering —— 管**提示词** ｜ Context Engineering —— 管**上下文**

## P6 · ① Prompt Engineering · 2 min
**L1** 把规矩写进话里 —— 前提是模型会照做
**L2** B — 两列：两年前 / 现在
**L3**
- 两年前：三小时调措辞，效果立竿见影；模板、few-shot、角色设定各有讲究
- 现在：调不调，差别已经不大了
- 落点（与"两年前"并置，不单独下结论）：**它还在，但不是杠杆了**
- 〔边界〕**措辞的边际收益已经很低**——这是 Anthropic 的**定性判断**，不是量化结论
- 但那套东西没白学：它变成了默认值，只是不再是你的杠杆
**讲法**（不上屏）**与 P5 的咬合**（v3.3）：P5 说"五层都还在"，这一页说"它还在，但不是杠杆了"——
**存在 ≠ 是杠杆**。两句话要在同一口气里说出来，否则听众会以为你在自相矛盾。
**讲法**（不上屏）**先认账再换地方**：你们当年学的提示词技巧全都还有用，只是模型把它吃成了默认能力。
这一页不是宣布"你们白学了"，是说**力气该换地方**——否则听众会带着被否定的情绪听后面 70 分钟。

"the exact formatting of prompts is likely becoming less important as models become more capable"。

## P7 · ② Context Engineering · 3 min
**L1** 把事实塞进上下文 —— 前提是塞进去它就用得到
**L2** A — 上下文窗口示意，中段标出塌陷区；右下角一个"最小脚手架"小图
**L3**
- 〔边界〕上下文超过一定长度后，**模型对中段的召回会下降**
- 〔边界〕反过来也成立：**最小脚手架照样跑得出结果**——一个提示词、一个 Bash、一个 Edit
- 所以"最好的上下文工程"往往是"少放"，不是"多放"
- 这一层改的仍然是**它能看到什么**，不是**能不能上线**
**讲法**（不上屏）"最小脚手架"有一字不差的一手原文可引：Anthropic 公布 SWE-bench Verified 49% 时写的是
"keep the scaffolding minimal. **The agent has a prompt, a Bash Tool, and an Edit Tool.**"（2024-10-30）。
**口径**：context rot 的独立量化来自 Chroma《Context Rot》2025-07，它是**向量数据库厂商自建的可复现评测**——
比只引 Anthropic 一家强，但**不是中立第三方**；上屏只能说"有独立复现"，不能说"第三方审计"。
**L4** 一手：Anthropic 2025-09-29（命名 context rot）｜独立量化：Chroma《Context Rot》2025-07（⚠️ 厂商自建评测）｜最小脚手架：Anthropic 2024-10-30 · 7 / 37

## P8 · ③ Harness Engineering · 2.5 min
**L1** 前两层改的都是"生成" —— 那谁能改"能不能上线"
**L2** A — 中心一个模型块，外面一圈边界带；左侧两个箭头从 Prompt / Context 指过来，都被边界挡住
**L3**
- 前两层都在改**模型说什么**，改不了**这一步能不能发生**
- 答案在模型外面那一圈：权限 · 沙箱 · 工具 · 验证门禁 · 执行记录 · CI
- 这一圈叫 **harness**；这一层叫 **Harness Engineering**
- 〔边界〕它默认的前提是"**这一圈是存在的**"——而这恰恰是很多团队没有的
**讲法**（不上屏）**命名发生在这里，动机已在 P6 / P7 建立**（先有问题，后有词）。
说完定义立刻往前走，不要在这一页展开机制——展开是第二幕的事。

## P9 · ④ Loop Engineering · 2.5 min
**L1** 让上一轮的结果改变下一轮 —— 前提是单次运行是受控的
**L2** D + A — 左侧一段伪码（触发 / 验证 / 停止条件 / 记忆），右侧一条条件带
**L3**
- 四要素：**触发 · 验证 · 停止条件 · 记忆**
- 〔边界〕**如果停止条件不看上一轮的结果，那叫重试，不叫循环**
- 〔边界〕单次运行不受控时，循环只是把错误复制得更快
- 所以这一层建在第三层之上：先有受控的单次运行，才有可靠的循环
**L4** 报告 04 章 · finding W4F-204（loop 的爆炸半径）· 9 / 37

## P10 · ⑤ Graph Engineering · 2.5 min
**L1** 几个环节之间怎么串 —— 前提是单个 agent 是受控的
**L2** A — 一张 DAG：显式节点、显式边、显式状态；其中一个节点内嵌一个小循环
**L3**

## P11 · 每上一层，都对下一层默认了一个前提 · 2 min
**L1** 这个前提不成立的地方，就是这一层管不到的地方
**L2** E — 五条前提链，每条：从 → 到 → 默认了什么 → 什么时候不成立
**L3**
- `Prompt → Context`：默认"**模型能吃下上下文**"（所以别再往提示词里塞事实）
- `Context → Harness`：默认"**环境是受控的**"（所以别再往上下文里写规矩）
- `Harness → Loop`：默认"**单次运行受控**"（所以不用人手动决定要不要再来一轮）
- `Loop → Graph`：默认"**单个 agent 受控**"（所以不用人手动拆任务）
- 四条前提**到极限处都会不成立**——这是 P8 命名那一步的伏笔，也是全场的种子
**讲法**（不上屏）这一页是第一幕的**枢纽**，不要讲成一张概念表。
四条前提要能当场说出来，每条配一句"所以……"（所以别再往那一层使劲）。

## P15 · 拦住 · 2.5 min
**L1** 把"对错"变成机器能判的关卡
**L2** A — 门禁序列：工具调用 → 协议检查 → 验证门禁 → 放行 / 拒绝
**L3**
- 位置原则：**在错误离源头最近的地方就地拦下**
- **把测试当成可以执行的契约**——写了测试，"对错"就从讨论变成了运行
