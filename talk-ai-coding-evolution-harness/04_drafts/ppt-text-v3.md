## P6 · ② Context Engineering · 3 min
**L1** 把事实塞进上下文 —— 前提是塞进去它就用得到
**L2** A — 上下文窗口示意，中段标出塌陷区；右下角一个"最小脚手架"小图
**L3**
- 〔边界〕上下文超过一定长度后，**模型对中段的召回会下降**
- 〔边界〕反过来也成立：**最小脚手架照样跑得出结果**——一个提示词、一个 Bash、一个 Edit
- 所以"最好的上下文工程"往往是"少放"，不是"多放"
- 这一层改的仍然是**它能看到什么**，不是**能不能上线**
**讲法**（不上屏）"最小脚手架"有一字不差的一手原文可引：Anthropic 公布 SWE-bench Verified 49% 时写的是
"keep the scaffolding minimal. **The agent has a prompt, a Bash Tool, and an Edit Tool.**"（2024-10-30）。
**口径**：context rot 的独立量化来自 Chroma《Context Rot》2025-07，它是**向量数据库厂商自建的可复现评测**——
比只引 Anthropic 一家强，但**不是中立第三方**；上屏只能说"有独立复现"，不能说"第三方审计"。
**L4** 一手：Anthropic 2025-09-29（命名 context rot）｜独立量化：Chroma《Context Rot》2025-07（⚠️ 厂商自建评测）｜最小脚手架：Anthropic 2024-10-30 · 6 / 36

## P7 · ③ Harness Engineering · 2.5 min
**L1** 前两层改的都是"生成" —— 那谁能改"能不能上线"
**L2** A — 中心一个模型块，外面一圈边界带；左侧两个箭头从 Prompt / Context 指过来，都被边界挡住
**L3**
- 前两层都在改**模型说什么**，改不了**这一步能不能发生**
- 答案在模型外面那一圈：权限 · 沙箱 · 工具 · 验证门禁 · 执行记录 · CI
- 这一圈叫 **harness**；这一层叫 **Harness Engineering**
- 〔边界〕它默认的前提是"**这一圈是存在的**"——而这恰恰是很多团队没有的
**讲法**（不上屏）**命名发生在这里，动机已在 P5 / P6 建立**（先有问题，后有词）。
说完定义立刻往前走，不要在这一页展开机制——展开是第二幕的事。

## P8 · ④ Loop Engineering · 2.5 min
**L1** 让上一轮的结果改变下一轮 —— 前提是单次运行是受控的
**L2** D + A — 左侧一段伪码（触发 / 验证 / 停止条件 / 记忆），右侧一条条件带
**L3**
- 四要素：**触发 · 验证 · 停止条件 · 记忆**
- 〔边界〕**如果停止条件不看上一轮的结果，那叫重试，不叫循环**
- 〔边界〕单次运行不受控时，循环只是把错误复制得更快
- 所以这一层建在第三层之上：先有受控的单次运行，才有可靠的循环
**L4** 报告 04 章 · finding W4F-204（loop 的爆炸半径）· 8 / 36

## P9 · ⑤ Graph Engineering · 2.5 min
**L1** 几个环节之间怎么串 —— 前提是单个 agent 是受控的
**L2** A — 一张 DAG：显式节点、显式边、显式状态；其中一个节点内嵌一个小循环
**L3**
- 显式节点 / 显式边 / 显式状态
- 图**可以**编排循环，也可以编排工具与验证器——**不要把两种图画成同一条线**
- 〔边界〕**每个环节各自失控时，编排只是把错误放大**
- 成熟度：这一层与循环都是 2026 才冒头的新兴叙事，**不是既定范式**

## P10 · 每上一层，都对下一层默认了一个前提 · 2 min
**L1** 这个前提不成立的地方，就是这一层管不到的地方
**L2** E — 五条前提链，每条：从 → 到 → 默认了什么 → 什么时候不成立
**L3**
- `Prompt → Context`：默认"**模型能吃下上下文**"（所以别再往提示词里塞事实）
- `Context → Harness`：默认"**环境是受控的**"（所以别再往上下文里写规矩）
- `Harness → Loop`：默认"**单次运行受控**"（所以不用人手动决定要不要再来一轮）
- `Loop → Graph`：默认"**单个 agent 受控**"（所以不用人手动拆任务）
- 四条前提**到极限处都会不成立**——这是 P7 命名那一步的伏笔，也是全场的种子
**讲法**（不上屏）这一页是第一幕的**枢纽**，不要讲成一张概念表。
四条前提要能当场说出来，每条配一句"所以……"（所以别再往那一层使劲）。

## P18 ★ · 现场看一次：一次被拦下来的执行 · 2.5 min
**L1** 拿一次真实执行，把这三道关问一遍
**L2** D — 一屏真实执行记录（终端 / trace），三个位置各挂一个问号标注
**L3**
- 指向第 1 步：**这一步谁批的？**
- 指向第 2 步：**它在哪台机器上跑的？**
- 指向第 3 步：**这一步记下来了吗？**
- 三问答不上来 → 这就是它上不了线的原因
- 因果链：工具调用的形状可以被伪造，绕过模型回合；**如果执行端只相信"这看起来像一次合法调用"，
  独立授权就缺失了——而动作仍然会发生**
- 怎么修（mono）：`authorize at execution, not at generation`
**讲法**（不上屏）**全场唯一一次演示，不可替代。**
这一页的讲法是"指"：屏幕上有一次真实执行，你指着它问三遍，每问一遍停一下。
三问答不上来之后，再给"授权必须在执行端"的因果链——**先让他们感到缺口，再给原理**。
**只讲因果链，不点名厂商、不堆 CVE 编号。**
