# 页面结构 v3.3（正文 37 页 + 停顿页 B1–B5 = 42 张 · 约 80 min）

> **本文件取代 `00-page-structure-45.md`（v2，45 页）。** v2 **已移出本目录**，归档在
> 仓库根 `.tmp-harness-talk-archive-20260917/`（不入库，仅供回查），不再是生产依据。
>
> **v3 的两处根本变化**：
> 1. **组织原则换了。** v2 按"素材有什么"分幕（五层 / 机制清单 / 两个产品 / 三句话）→
>    页与页是并列，只能靠修辞制造动量。v3 按**听众要解决什么**分幕：全场只追一个问题，
>    每一幕是这个问题的一步推导。
> 2. **终点换了。** v2 收在"两个开源仓库的架构对照"（Pi vs DSH 平权）。
>    v3 收在**你今后要写两类程序**——写传统程序，现成 harness 已经够用；
>    写智能体，**写**可以在现成工具里写，**跑**却必须要有一套 harness 环境。
>    这一条把第四幕从"讲者的兴趣"变成"听众自己的处境"。
>
> **全场主轴**：**这次改动，凭什么可以上线？**
> 听众的流程本来就在答这题——谁批 / 在哪个环境跑 / 留下什么记录。
> 这三个问号天然挂住 圈住 / 拦住 / 看清，不是硬塞的三分法。

## 第一幕：这问题我们答过五轮（9 页 / 19.5 min）

> **本幕的组织方式**：五层工程 = 同一个问题的五轮答案。每轮讲清三件事——
> 答案放在哪 / 它默认了什么前提 / 这个前提什么时候不成立。
> **反转句在这里自动消失**，因为每一句都是条件句。
>
> **P4 是桥，P5 是总览，两页不重复**（v3.3）：P4 讲**答案在往哪挪**，P5 讲**那五层叫什么**。
> **P6–P10 五层必须连续**，中间不插停顿页。

| 页 | 这一页在答什么 | min | 必讲要点 |
|---|---|---:|---|
| P4 | **桥**：这三道关不是没人想过，每答一轮答案就往外挪一层 | 1.5 | ① ② 在模型里面，③ ④ ⑤ 在模型外面；里面那两轮改的是它说什么、看到什么，**只有挪到外面才第一次碰到「这一步能不能发生」**。**五层只出编号不出细节**，细节留给 P6–P10 |
| P5 | 那五轮分别把答案放在了哪 | 2 | 五层各管什么（提示词 / 上下文 / harness / 循环 / 编排），中间一条**模型里面 / 外面**的分界线（与 P4 同一条）。底部：**五层都还在，但杠杆不在同一层**（不是"是叠加不是替代"——那句会和下一页的"边际收益低"打架）。不画金字塔、不讲"五代产品"。**本幕问法在这一页上屏一次**：答案放在哪 / 默认了什么 / 什么时候不成立 |
| P6 | ① Prompt Engineering 管提示词 | 2 | 答案：把规矩写进话里 ｜ 前提：模型会照做 ｜ 不成立：措辞的边际收益已经很低（Anthropic 2025-09-29，**定性判断**）。**先认账**：那套东西没白学，它变成了默认值，只是不再是杠杆 |
| P7 | ② Context Engineering 管上下文 | 3 | 答案：把事实塞进上下文 ｜ 前提：塞进去它就用得到 ｜ 不成立：上下文超过一定长度后，模型对中段的召回下降（Chroma《Context Rot》2025-07，⚠️ 厂商自建评测）；**最小脚手架也能跑出结果**（Anthropic 2024-10-30 原句） |
| P8 | ③ Harness Engineering 管 harness | 2.5 | 前两层都管的是"生成"，管不了"能不能上线"。**谁管？** → 在模型外面那圈：权限、沙箱、工具、验证门禁、执行记录、CI。**命名发生在这里**，动机已在 P6/P7 建立 |
| P9 | ④ Loop Engineering 管循环 | 2.5 | 答案：让上次结果改变下次行动 ｜ 前提：单次运行是受控的 ｜ 不成立：**如果停止条件不依赖上次结果，那叫重试，不叫 loop**；单次运行不受控时，loop 只是把错误更快地复制一遍 |
| P10 | ⑤ Graph Engineering 管编排 | 2.5 | 答案：跨节点协调 ｜ 前提：单个 agent 是受控的 ｜ 不成立：节点各自失控时，编排只是放大。Graph **可以**编排 Loop，也可编排工具与验证器；**不能把所有节点画成 Loop** |
| P11 | 每上一层，都对下一层默认了一个前提 | 2 | Prompt→Context 默认"模型能吃上下文"；Context→Harness 默认"环境是受控的"；Harness→Loop 默认"单次运行受控"；Loop→Graph 默认"单 agent 受控"。**这个前提不成立的地方，就是这一层管不到的地方** |
| P12 | 收束：`Agent = Model + Harness` | 1.5 | 五层过完，公式才给。成熟度：前三层实，后两层虚（Loop / Graph 是 2026 才冒头的新兴叙事，低置信度，**不讲成既定范式**）。**收束页自带停顿**，讲完停 3–5 秒 |

## 第二幕：那圈东西里到底有什么（7 页 / 16 min）

> **本幕的组织方式变了**：v2 按"机制清单"讲（Guides/Sensors → 三个动词 → 提出权 → 授权），
> 是并列的功能介绍。v3 按**追责链**讲：一次动作从提议到落地要过三道关，
> 每一道都挂回 P2 听众自己说的那三句话。

| 页 | 这一页在答什么 | min | 必讲要点 |
|---|---|---:|---|
| P13 | 一次动作从提议到落地，要过哪三道 | 2 | 它能碰到什么 / 它做得对不对由谁判 / 事后能不能还原。**把 P2 的三道关映射进来** |
| P14 | 第一道：圈住 | 2.5 | 沙箱 + 权限。边界内：项目目录读写、构建与测试命令、本地依赖；边界外：生产配置、凭据、任意外网。落点：**你们本来就有一圈边界，现在把 agent 也圈进去** |
| P15 | 第二道：拦住 | 2.5 | 工具协议 + 验证门禁。**把测试当成可执行契约**——写了测试，"对错"就从讨论变成运行。位置原则：在错误离源头最近的地方就地拦下 |
| P16 | 判据也分档次 | 2 | 确定性（测试 / lint / 类型 / schema，可复现可审计）vs 概率性（AI review / LLM-as-judge，换个时间可能换结论）。**能交给确定性的，不交给概率性的**；模型判断只做兜底，不做门禁 |
| P17 | 第三道：看清 | 2.5 | trace / metrics / logs + provenance + 接进 CI。落点：你们本来就要求"出事能还原"，现在把它也套上 |
| P18 | 三道关的分界在哪 | 2 | 提出权可以给模型 / Loop / Graph；**执行权必须留在 harness**。关键在"独立"两个字——检查方不能是提议方 |
| P19 | **现场看一次：一次被拦下来的执行** ★ | 2.5 | **全场唯一一次演示**。放一次真实执行，指着它问三遍：这一步谁批的？在哪跑的？记了什么？→ 三问答不上来。再给因果链：工具调用的形状可以被伪造，绕过模型回合；如果执行端只相信"这看起来像一次合法调用"，独立授权就缺失了，而动作仍然会发生 → `authorize at execution, not at generation`。**审批不能挂在"它说它会怎么干"上** |

## 第四幕：你今后要写两类程序（9 页 / 17.5 min）★ v3 新增主幕

> **这一幕是 v3 的赌注。** 理由：前 23 页都在讲"用 AI 写代码"，听众的处境是**用**；
> 从这一幕起，他们的处境变成**造**——而造 agent 时，harness 的性质完全不同。

| 页 | 这一页在答什么 | min | 必讲要点 |
|---|---|---:|---|
| P26 | 你今后要写的程序有两类 | 2 | 一类是**传统程序**，一类是**智能体**。分界不是语言、不是框架，是**它的行为在运行时才被决定** |
| P27 | 写传统程序：现成的已经够好 | 2 | Codex、Claude Code 这类 coding harness 已经把沙箱、审批、事件流做进去了。**只要项目本身的配置不是太离谱，写传统程序这件事问题不大**——这一页要给的结论是"这条路不用你们自己造" |
| P28 | 写智能体：写可以，跑呢 | 2 | 智能体的代码也是代码，**写**的过程当然可以放在 Codex / Claude Code 里。**但跑呢？** 你总得有一个能真正运行 agent 的 harness 环境——谁来给它权限、谁来记它的每一步、它失败了停在哪 |
| P29 | 所以那圈东西得在你自己手上 | 2 | 当你的**产物本身**是 agent 时，harness 不再是你工具的一部分，它是**你产品的一部分**。边界由谁定，就得由谁承担。**两条路**：① 自己组装；② 用一个可组合的运行时 |
| P30 | 路一：自己组装（简单介绍） | 2 | 从零搭：执行后端、工具集、门禁、事件流，四样自己拼。**能轻到什么程度**——Pi 是这条路上一个可看的样本：三层 seam（执行后端 / 工具集 / 行为组合）做对了，统一注入点，in-process 护栏（two-phase binding · fail-safe · fail-closed）；但**它没有默认沙箱、没有 MCP/ACP、没有扩展 API 版本契约** → 正确口径：不是说它不安全，是说 **Pi 把信任放在"谁装了它"，而不是"它是什么代码"上** |
| P31 | 路二 DSH（一）：没有特权核心 | 2.5 | Cordis 元框架；**所有能力都是插件**，不存在必须改源码才能动的东西；四种运行模式本质是四套默认插件集；长程不是单一 loop（Goal / Ralph / workflow / Spawn-Fork 并存） |
| P32 | 路二 DSH（二）：会话日志是 single source of truth | 2.5 | 会话是 **typed、append-only** 的事件日志；模型看到什么，就被记下什么；**回放 / 恢复 / 分叉 / 审计，用的是同一份日志，只是四种看法**。审计不是事后补的，是**架构自带的** |
| P33 | 路二 DSH（三）：代价 | 2 | 官方插件市场还没上线；白名单与逐件审计要自己建；接口还在快变，二次开发量明显高于成品路线。落点：这些不是它的缺陷，是**"你拥有整个运行时"这件事本身的价格** |
| P34 | 两边都还没解决的那件事 | 1.5 | 对陌生插件的安全，两条路都还没有答案：一条没有沙箱，另一条**插件化不等于安全**。所以这两条都不是"更先进的选择"，是**正在演进的路线**。这一页是全场可信度的关键，不能省 |

## 停顿页（B1–B5 · 不参与正文编号）★ 全场节奏机制

> **v3.2 两处改动**（2026-09-17 用户二次复核）：
> ① **不再叫"呼吸页"**——"呼吸"是讲者行话，多数听众不知道在说什么。内部统称**停顿页**。
> ② **每张必须让听众有反应**，三选一：
>
> | 型 | 让听众发生什么 | 标点纪律 | 例子 |
> |---|---|---|---|
> | **反思** | 前提已经给全，把问题抛回给他 | 以**问号**收尾 | 「刚才那一步，**谁批的？**」 |
> | **顿悟** | 让他自己把两件事并起来 | 用**顿号**并列 | 「圈住、拦住、看清」 |
> | **迷惑** | 把矛盾摆上台面，让他先别扭一下 | 用 **?! / !?** | 「写，有人管了。跑呢？！」 |
>
> **大字说不清就加小字**：大字给冲击（56px 墨色），小字给前提（28px 灰）。
> 只用一句大字讲不清的，一律补小字，**不要硬压成一句**。
>
> **放置判据（只有满足其一才设停顿页）**：
> 1. **结构接缝**——一幕结束、下一幕换话题，听众需要把上一幕卸下来。
> 2. **段内超 10 分钟**——同一条线上连讲超过 10 分钟，中间切一刀。
>
> **收束页自带停顿**：P12 / P25 / P34 讲完停 3–5 秒，**不再额外插页**——同一处停两次，节奏反而拖。
> **每张必须同时收上一段、启下一段**；只复述上一页的一律删。
> **悬念仍然禁用**："另一条呢？"这种不给线索的纯吊胃口，一律不用。
>
> **规格**：纸白满底 · 大字 + 小字 · 留白 ≥60% · 不用语义色 · **不显示页码**。
> **讲法**：念完就闭嘴，静默 5–8 秒时**看听众，不看屏幕**；不补例子，哪怕当场想起一个特别好的。

|---|---|---|---:|---|---|---|:---:|---:|

## 叙事检查（v3）

1. **全场只有一条因果链**：P2 立问题 → P3 三个问号 → **P4 桥（答案在往外挪）** → P5 总览 → P6–P10 五层逐个排除 → P11 前提链 → P12 收束 → P13–P19 追责链三道关 →
   P20–P25 它是变量 → P26–P34 你今后写哪类程序 → P35–P37 回到你自己的三道关。
   每一页都是上一页的**下一步**，不是"还有一个"。
2. **命名时序**：harness 在 P8 给名（动机已在 P6/P7 建立）；`Agent = Model + Harness` 在 P12 才给。
   **不允许任何一页在动机之前给词。**
3. **P19 是全场唯一的演示页**，不可替代。要可靠性 / 可追溯的团队要看到**一次被拦下的执行**，
   不是 36 个结论句。
4. **第四幕的逻辑责任**：前三幕讲的是"用 AI 写代码"，第四幕翻成"你要造 agent"。
   没有这一翻，第四幕就是讲者的兴趣；有了这一翻，它是听众明年就会遇到的处境。
5. **反软广纪律**：P33（DSH 代价）与 P34（两边都没解决）缺一不可。没有这两页，
   P31 / P32 就是产品推荐。
6. **P27 必须真的给"不用你自己造"这个结论**，否则听众会误以为连写传统程序都得自建 harness，
   整场就变成了吓唬人。

## 时间与节奏

- **正文 78 min + 停顿页约 1.7 min ≈ 80 min**，落在 75–90 区间内（仍留约 5 min 现场缓冲）。
- 停顿：5 张停顿页 + 3 处收束页短停 = **8 次停顿**，从开场页贯穿到结束页。
- **不再用"单块不超过 10 分钟"当硬指标**——它逼着把每个 10 分钟都切一刀，结果就是停顿页泛滥。
  现在的口径是：**只在结构接缝和实在太长的地方停**（P29–P34 那 11.5 min 是因为一条路要连着讲完）。
- P21 / P22 的降档是全场建立可信度的关键动作，**两处说法必须不同**。
- **P24 的 10 秒留白与 P37 的收场，是正文页里仅有的两次留白**，其余页停顿不超过 2 秒。
