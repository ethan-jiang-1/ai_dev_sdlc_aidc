## 第一幕：五层演变（17 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P5 | 模型越强，工程杠杆点越往上移 | 2 | 上移不等于替代；工程对象从"一句话"移到"系统"。**最锋利的一句是"每层对下层做了一个假设"**——Prompt→Context"模型能吃上下文"／Context→Harness"环境受控"／Harness→Loop"单次运行受控"／Loop→Graph"单 agent 受控"，**每个假设在极限处都可能失效**（这是 P13"问题落回中间那层"的伏笔） |
| P6 | Prompt 管表达——但它已经不再是你的杠杆 | 2 | 措辞越来越不重要；这层被吃掉了，不是你变强了。**先认账再换地方**：那套东西没白学，它变成了默认值——不然听众会带着被否定的情绪听后面 40 分钟 |
| P7 | Context 管模型此刻所见，不是越多越好 | 3 | context rot；"更多 context ≠ 更好回忆"；最小脚手架也够用 |
| P8 | Harness：`Agent = Model + Harness` | 2 | 只定义；harness = 模型之外的一切；展开留给第二幕 |
| P9 | Loop 管时间上的反馈 | 2 | 黄金法则；反转：没有门禁的 loop 只会更快放大错误 |
| P10 | Graph 管空间上的协作 | 2 | 显式节点、边、状态；可编排部分 Loop；不要画成金字塔 |
| P11 | 五层是叠加，不是替代 | 2 | 关系图 + 成熟度标尺：前三层成熟，Loop/Graph 是新兴观察对象 |
| P12 | 五层是交付链上的五个控制面 | 1.5 | 团队版焊点：它们往往散在不同人手上，或者根本没人管。**横向讲"人跟人不一样"**（画面：十个人十套配置）；本页**不用"两个团队"的画面**——那个留给 P24 讲纵向后果。**新增外部依据**（W4F-203 组织含义段）：只用最上层、忽略权限的团队"会被 agent 违规惩罚"，成熟组织五层都用、每层有显式验证门——这条把 A7 从"我的观察"往"有依据"推了一格 |
| P13 | 前两层改不了"能不能上线"，后两层只放大结果 | 0.5 | 转场到第二幕 |

## 第二幕：harness 里头到底干了什么（20 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P14 | 所有真实动作都要经过 harness | 1.5 | 每个可执行节点最终落到一次真实执行，上层不会自动修复底层缺口 |
| P15 | 模型给能力，harness 给可靠性 | 2 | 一句话定义；harness 不负责让模型变聪明。**L1 有一手原句做底**：Böckeler 的 `Reliability is a property of the model-plus-harness system`（《Harness engineering for coding agent users》，2026-02-17 memo / 2026-04-02 全文）；被追问出处就报这一句 |
| P16 | 可靠性发生在两次：行动前约束，行动后反馈 | 2.5 | Guides / Sensors 两套控制 |
| P17 | 能交给确定性判的，绝不靠模型自觉 | 2.5 | computational vs inferential；确定性优先 |
| P18 | 圈住：让它只能碰该碰的 | 2 | 沙箱 + 权限；团队映射第一行 |
| P19 | 拦住：把对错变成机器能判的关卡 | 2 | 工具协议 + 验证门禁；在离源头最近的地方拦下 |
| P20 | 看清：每一步都留下痕迹 | 2 | 可观测性 + provenance + CI；团队映射第三行 |
| P21 | 提议权可以交给模型，执行权必须留在 harness | 2 | 提议 → 独立检查 → 放行/拒绝并记录 |
| P22 | 授权要在执行那一刻发生 | 2 | 2026 事故的因果链；审批不能挂在"它说它会怎么干"上 |
| P23 | 可靠性解释了"不翻车"，没解释"为什么更强" | 1.5 | 转场到第三幕。**必须点明"下限 / 上限"**：前面讲的是下限（不掉链子），接下来讲上限（同一个模型能做成什么）。**这两句不点明，听众会觉得 P15 与 P24 前后打架**——这是全场最需要防的一处自相矛盾 |

## ★ 第三幕：harness 才是变量（13 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P24 ★ | 同一个模型，换一圈 harness 就是两套交付系统 | 2 | 本幕命题；承接 P23 |
| P25 ★ | 模型没换，换的是 harness，结果差了将近三倍 | 2.5 | ⚠️ **厂商自述**：ARC-AGI-3 13.3% → 38.3%、输出 token 降至 1/6；同屏标注证据强度。**口径要点**：这条证的是**能力层**，交付层由 P27–P29 承接，别混 |
| P26 ★ | 同一批模型换 harness 会分层——这条只能当信号 | 2 | ⚠️ **趋势级、无方法论，不作基准**。源头是**快讯＋标题级捕获**，其标题级结论**偏袒轻量路线**——正因如此更要当面打折。它证的是**现象**（分层真实存在），不是**数字**。落到可迁移判据：**能当基准 vs 只能当信号**（旁证：ICSE 2026《SWE-Bench Illusion》，76% → 53%）。**最后一页必讲"诚实交代"**：本幕三条证据没一条够格当基准，结论靠它们**指向同一方向**——与其被问，不如自己先说 |
| P27 ★ | 你现在跑的那套，是把治理内建好的成品 | 2 | 主流固定 harness 的共同特征：沙箱、审批、事件流、长程记忆开箱即用。**顺序纪律：先把好话说足**，否则下一页会被听成挑刺。本页兼第三幕**第三条证据**——不是一家厂商的自述，是整个品类在投票 |
| P28 ★ | 但它的扩展边界，由产品定义 | 2 | 五个自查维度（上半）：模型能不能换 / 工具能不能加。**必须认领**：这是本 talk 从评分卡"可部署 / 合规"两维拆出来的，**不是行业标准** |
| P29 ★ | 改不动的地方，就是你的天花板 | 2 | 五个自查维度（下半）：执行后端能不能换 / 门禁能不能自己定 / 事实能不能重建。**留 10 秒安静**让听众自己算，不要替他们下结论 |
| P30 ★ | 所以 harness 是变量——而变量意味着它可以换 | 0.5 | 转场到第四幕；**一句带过，不在这里展开下一幕** |

## ★ 第四幕：两个进展——Pi 与 DSH（16 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P31 ★ | 两条路线的分野：引擎即用 vs 你拥有整个运行时 | 1.5 | `Product First` vs `Framework First`；两边素材等厚，平权讲 |
| P32 ★ | DSH：没有特权核心，所有能力都是插件 | 2.5 | Cordis 元框架；不存在必须改源码才能动的东西；四种运行模式本质是四套默认插件集；长程不是单一 loop（Goal / Ralph / workflow / Spawn-Fork） |
| P33 ★ | DSH：会话日志是唯一真源 | 2.5 | append-only SessionEvent；模型所见即被记录；回放 / 恢复 / 分叉 / 审计都是同一份日志的投影 |
| P34 ★ | DSH 的代价：市场未上线、治理要自建、接口还在快变 | 2 | 官方插件市场未上线；白名单与逐件审计要自建；v0.1 接口快变；二次开发量高于 Product First。**第四幕第一次结论升级**：把"代价"重述成"**自由的价钱**"，把听众从"哪个更好"拨到"你愿意付哪种成本" |
| P35 ★ | Pi：结构上做对了什么 | 2.5 | 三层同心接缝（operations / tool / extension）按"变化轴"裁接口；统一注入点；进程内护栏（两阶段绑定、stale 保护、**fail-close**） |
| P36 ★ | Pi 的代价：信任放在"谁装的"上 | 2 | 无默认沙箱——扩展 = 宿主进程同等权限，`install` 陌生包 ≈ 执行任意代码；无 MCP/ACP——外部工具付适配层税；无扩展 API 版本契约 |
| P37 ★ | 两边都还没解决的那件事 | 1.5 | 对陌生插件，两条路线都还没有安全答案（Pi 无沙箱；DSH 插件化 ≠ 安全）。**这一页是全场可信度的关键** |
| P38 ★ | 共同点：harness 从"产品的一部分"变成"你可以改的东西" | 1.5 | 本幕落点 |

## 停顿页（I1–I4 · 不参与正文编号）

> **为什么需要**：正文里最长的两段密集机制区——第一幕 P5–P12（17 min）与第二幕 P14–P22（20 min）——
> 中间**一次呼吸都没有**，全部是"结论 + 机制"往前推。产品经理在这两段最容易掉。
> 停顿页的作用不是装饰：**一块信息讲完，让听众自己把它压成一句话，再进下一块**。
>
> **为什么不编号**：正文 45 页的编号不变，所有既有引用（尾巴 P24–P45、P31–P38、P25/P26 降档、
> P37 可信度关键页、P42 别折腾）**全部保持有效**，避免全库页号重排带来的过期引用。
> 停顿页在屏幕上**不显示页码**（页脚只有眉题），视觉上就是一次呼吸。
>
> **规格**：纸白满底 · 只有一句大字（28–36px 墨色）· 留白 ≥60% · 不用语义色 · 时长 20–30 秒。

| **代号** | **位置** | **眉题** | **大字（上屏唯一内容）** | **静默** | **承接下一页** | **它解决什么** |
|---|---|---|---:|---|---|---|
| **I1** | P8 之后 | 第一幕 · 五层演变 | 模型越强，你能在 Prompt 和 Context 上使的劲就越小 | 6 秒 | P9 · Loop | 它压缩的是 **P5–P7**（发动机 + Prompt + Context），不是只看后两页。刚才那三页说了两件事——杠杆点上移、前两层的边际收益已经很低；这一句把它们并成一句，听众才带着"**那劲该往哪使**"进下一个块 |
| **I2** | P17 之后 | 第二幕 · harness 里头 | 可靠性发生在两次：**行动前约束，行动后反馈** | 6 秒 | P18 · 圈住 | 第二幕前半（是什么 + 两套控制）共 8.5 分钟，信息密度全场最高。这一句是那 8.5 分钟的**唯一出口**；听众带着它进三个动词，后面 P18–P20 就不用再回头解释"为什么要前后两次" |
| **I3** | P20 之后 | 第二幕 · harness 里头 | **圈住 · 拦住 · 看清** | 8 秒 | P21 · 提议权与执行权 | 六个机制构件讲完，听众手里是一堆零件。这一页把它压成 **3 个动词**——全场最需要"落地"的一刻，也是听众唯一有机会记下来的地方 |
| **I4** | P34 之后 | 第四幕 · 两条路线 | 这是**一条路线的价钱**。另一条呢？ | 5 秒 | P35 · Pi 的结构 | 第四幕平权的分界线：DSH 段结束、Pi 段开始。上一页刚把代价重述成"自由的价钱"，这一句用**悬念**把听众带进另一条路线 |

**停顿页的讲法纪律（写进 `talk-v1.md`）**：
1. 上屏的那句话**要说出口**，说完**立刻闭嘴**——停顿页上的 20–30 秒不承担任何新信息。
2. **不要在这 20 秒里补充解释**。哪怕想起一个特别好的例子，也留到下一页。
3. 静默时**看着听众**，不看屏幕；屏幕上的字就是给他们的。
4. 停顿页**不写讲稿正文**，讲稿里只记两句：念哪一句、停多久。

**呼吸节奏**：加上原有的 5 张转场页（P13 / P23 / P30 / P43 / P44），全场共 **9 次呼吸**，
平均每 **9.4 分钟**一次。第二幕最长的那一段（P14–P22，20 min）被 I2、I3 切成 8.5 / 6 / 5.5 分钟三节。

## 叙事检查

1. P2 立问题（生成 vs 交付）→ P5–P12 解释"控制面一直在换" → P13 逼出"问题落回第三层"。
2. P14–P22 完成 harness 内部的完整定义（两套控制 → 三个动词 → 提议权与执行权分开 → 执行时授权），
   每页一个机制，不重复喊口号。
3. P23 是全场最关键的一次转场：把"可靠性"升级为"能力天花板"，否则第三幕无立论基础。
   **这一页必须点明"下限 / 上限"的分野**——P15 讲的是"不掉链子"（下限），P24 起讲的是
   "同一个模型能做成什么"（上限）；两者不是矛盾，是升级关系。讲不清，听众会觉得前后打架。
4. P24–P29 用证据 + 五个自查维度把"harness 是变量"落到实处；P30 才允许说"可以换"。
   **第三幕是三条证据合撑一条判断**：P25（一家厂商自述的历史对比）+ P26（现象：跨 harness 会分层）
   + P27（品类共识：所有成品都把治理当卖点）。**缺任何一条，P24 的判断就只剩孤证。**
5. P31–P38 两条路线**平权讲**：**DSH 三页（P32–P34：无特权核心 / 会话日志 / 代价）+
   Pi 两页（P35 结构 / P36 代价）**，中间夹一页 **P37「两边都还没解决的那件事」**（两边共用）。
   净页数 3 : 2，但 Pi 两页的承载与 DSH 三页同量（L3 各 4–5 条），素材厚度也是等量（Pi 154 篇 / DSH 173 篇）。
   ——这页不加，第四幕就是产品推荐；加了，它才是工程判断。
6. **第四幕的升级节拍**（八页不能平铺）：P33 会话日志落点＝翻转一（审计是架构级属性）→
   P34 代价＝翻转二（代价是自由的价钱）→ P36 标题＝翻转三（信任放在"谁装了它"上）→
   P37＝总升级（两条路线都还没解决）。相邻两次升级的间隔不超过 4 页。
7. P39–P42 三句落点 + 一页"别折腾"，防止变成推荐会；**P41 必须补掉"那换哪条"这个缺口**。
8. P43–P45 回到 P2 的追问，闭合全场。
9. **9 次呼吸把全场切成 11 个信息块**，每块不超过 10 分钟：
   ① 开场 P1–P4（5 min）｜ **I1** ｜ ② 前三层 P5–P8（9）｜ ③ 后两层 P9–P12（7.5）｜ **P13 转场** ｜

## 时间与节奏约束

- 前 23 页（开场 + 第一、二幕）必须控制在 **42 分钟**内，否则尾巴被压缩。
- **但讲稿字数按更紧的口径写**：引桥按 **39 min**、尾巴按 **42 min** 折算
  （引桥约 6,860 字 / 尾巴约 7,400 字），多出的约 3 分钟作为现场缓冲——开场最容易超时，
  第二幕机制页最容易讲开。**页面时长账目不动，只收紧讲稿的字数预算。**
- **停顿页另计时间，不吃正文预算**：4 张 × 20–30 秒 ≈ **1.5–2 分钟**。
  总时长因此从 84 min 变为约 **85.5 min**（75–90 区间内，安全）。
  停顿页字数极小（一句话），所以**讲稿字数预算不变**——
  引桥 = 39 min 口播 + 1.5 min 停顿 ≈ 40.5 min，仍在 42 min 红线内。
- **呼吸节奏（硬约束）**：**每个信息块结束后要有一次呼吸**——停顿页 I1–I4，或转场页 P13 / P23 / P30 / P43 / P44。
  **单个信息块不超过 10 分钟**；超过 10 分钟的块必须在块内自带留白（P29 的 10 秒是唯一样板）。
  全场 9 次呼吸、平均 9.4 分钟一次。**加页面、删页面或改时长之前，先看这一条。**
- 每 4–5 页必须有一次"结论升级"，避免连续机制页造成疲劳。
- **停顿页 ≠ 随处可停**：只有这 4 处。其余页面的停顿不超过 2 秒，
  否则 85 分钟会被停顿吃掉。**P29（五问之后 10 秒）与 P45（收场）是正文页里仅有的两次留白。**
- P25、P26 的证据页必须有一次明显的**语气降档**（"这个数字来源是厂商自述 / 这个是趋势级"），
  这是本场建立可信度的关键动作，不能省。**两处不要用同一套说法，否则第二次就不像话了。**
