# 页面结构（45 页 · 84 min · v0.1 骨架）

> 本表定义**每一页的职责与结论**，不写上屏文案。上屏文案定稿在 `../04_drafts/`。
> 标注：★ = 尾巴（第三幕 → 收尾，22 页 / 约 42 min，本场赌注所在）。
> 口径：每页只承担一个叙事任务；标题即结论；证据与结论同屏咬合。

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P1 | AI Coding 演变指南：从 Prompt 到 Harness | 0.5 | 题目、讲者、副标题「生成不是瓶颈，交付才是」 |

## 第一幕：五层演变（17 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P5 | 模型越强，工程杠杆点越往上移 | 2 | 上移不等于替代；工程对象从"一句话"移到"系统" |
| P6 | Prompt 管表达——但它已经不再是你的杠杆 | 2 | 措辞越来越不重要；这层被吃掉了，不是你变强了 |
| P7 | Context 管模型此刻所见，不是越多越好 | 3 | context rot；"更多 context ≠ 更好回忆"；最小脚手架也够用 |
| P8 | Harness：`Agent = Model + Harness` | 2 | 只定义；harness = 模型之外的一切；展开留给第二幕 |
| P9 | Loop 管时间上的反馈 | 2 | 黄金法则；反转：没有门禁的 loop 只会更快放大错误 |
| P10 | Graph 管空间上的协作 | 2 | 显式节点、边、状态；可编排部分 Loop；不要画成金字塔 |
| P11 | 五层是叠加，不是替代 | 2 | 关系图 + 成熟度标尺：前三层成熟，Loop/Graph 是新兴观察对象 |
| P12 | 五层是交付链上的五个控制面 | 1.5 | 团队版焊点：它们往往散在不同人手上，或者根本没人管 |
| P13 | 前两层改不了"能不能上线"，后两层只放大结果 | 0.5 | 转场到第二幕 |

## 第二幕：harness 里头到底干了什么（20 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P14 | 所有真实动作都要经过 harness | 1.5 | 每个可执行节点最终落到一次真实执行，上层不会自动修复底层缺口 |
| P15 | 模型给能力，harness 给可靠性 | 2 | 一句话定义；harness 不负责让模型变聪明 |
| P16 | 可靠性发生在两次：行动前约束，行动后反馈 | 2.5 | Guides / Sensors 两套控制 |
| P17 | 能交给确定性判的，绝不靠模型自觉 | 2.5 | computational vs inferential；确定性优先 |
| P18 | 圈住：让它只能碰该碰的 | 2 | 沙箱 + 权限；团队映射第一行 |
| P19 | 拦住：把对错变成机器能判的关卡 | 2 | 工具协议 + 验证门禁；在离源头最近的地方拦下 |
| P20 | 看清：每一步都留下痕迹 | 2 | 可观测性 + provenance + CI；团队映射第三行 |
| P21 | 提议权可以交给模型，执行权必须留在 harness | 2 | 提议 → 独立检查 → 放行/拒绝并记录 |
| P22 | 授权要在执行那一刻发生 | 2 | 2026 事故的因果链；审批不能挂在"它说它会怎么干"上 |
| P23 | 可靠性解释了"不翻车"，没解释"为什么更强" | 1.5 | 转场到第三幕 |

## ★ 第三幕：harness 才是变量（13 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P24 ★ | 同一个模型，换一圈 harness 就是两套交付系统 | 2 | 本幕命题；承接 P23 |
| P25 ★ | 模型没换，换的是 harness，结果差了将近三倍 | 2.5 | ⚠️ 厂商一手自述：ARC-AGI-3 13.3% → 38.3%、输出 token 降至 1/6；同屏标注证据强度 |
| P26 ★ | 同一批模型，不同 harness 的成功率与成本明显分层 | 2 | ⚠️ 第三方对照实测，**趋势级、无方法论，不作基准**；只取方向性信号 |
| P27 ★ | 你现在跑的那套，是把治理内建好的成品 | 2 | 主流固定 harness 的共同特征：沙箱、审批、事件流、长程记忆开箱即用 |
| P28 ★ | 但它的扩展边界，由产品定义 | 2 | 五个自查维度（上半）：模型能不能换 / 工具能不能加 |
| P29 ★ | 改不动的地方，就是你的天花板 | 2 | 五个自查维度（下半）：执行后端能不能换 / 门禁能不能自己定 / 事实能不能重建 |
| P30 ★ | 所以 harness 是变量——而变量意味着它可以换 | 0.5 | 转场到第四幕 |

## ★ 第四幕：两个进展——Pi 与 DSH（16 min）

| 页 | 页面结论 | 时长 | 必讲要点 |
|---|---|---:|---|
| P31 ★ | 两条路线的分野：引擎即用 vs 你拥有整个运行时 | 1.5 | `Product First` vs `Framework First`；两边素材等厚，平权讲 |
| P32 ★ | DSH：没有特权核心，所有能力都是插件 | 2.5 | Cordis 元框架；不存在必须改源码才能动的东西；四种运行模式本质是四套默认插件集；长程不是单一 loop（Goal / Ralph / workflow / Spawn-Fork） |
| P33 ★ | DSH：会话日志是唯一真源 | 2.5 | append-only SessionEvent；模型所见即被记录；回放 / 恢复 / 分叉 / 审计都是同一份日志的投影 |
| P34 ★ | DSH 的代价：市场未上线、治理要自建、接口还在快变 | 2 | 官方插件市场未上线；白名单与逐件审计要自建；v0.1 接口快变；二次开发量高于 Product First |
| P35 ★ | Pi：结构上做对了什么 | 2.5 | 三层同心接缝（operations / tool / extension）按"变化轴"裁接口；统一注入点；进程内护栏（两阶段绑定、stale 保护、**fail-close**） |
| P36 ★ | Pi 的代价：信任放在"谁装的"上 | 2 | 无默认沙箱——扩展 = 宿主进程同等权限，`install` 陌生包 ≈ 执行任意代码；无 MCP/ACP——外部工具付适配层税；无扩展 API 版本契约 |
| P37 ★ | 两边都还没解决的那件事 | 1.5 | 对陌生插件，两条路线都还没有安全答案（Pi 无沙箱；DSH 插件化 ≠ 安全）。**这一页是全场可信度的关键** |
| P38 ★ | 共同点：harness 从"产品的一部分"变成"你可以改的东西" | 1.5 | 本幕落点 |

## 叙事检查

1. P2 立问题（生成 vs 交付）→ P5–P12 解释"控制面一直在换" → P13 逼出"问题落回第三层"。
2. P14–P22 完成 harness 内部的完整定义（两套控制 → 三个动词 → 提议权与执行权分开 → 执行时授权），
   每页一个机制，不重复喊口号。
3. P23 是全场最关键的一次转场：把"可靠性"升级为"能力天花板"，否则第三幕无立论基础。
4. P24–P29 用证据 + 五个自查维度把"harness 是变量"落到实处；P30 才允许说"可以换"。
5. P31–P38 两条路线**平权讲**：DSH 三页（无特权核心 / 会话日志 / 代价），Pi 三页（结构 / 代价），
   中间夹一页 **P37「两边都还没解决的那件事」**——这页不加，第四幕就是产品推荐；
   加了，它才是工程判断。P38 再把两条路线收成一句共同点。
6. P38 把两条路线收成一句共同点；P39–P42 三句落点 + 一页"别折腾"，防止变成推荐会。
7. P43–P45 回到 P2 的追问，闭合全场。

## 时间与节奏约束

- 前 23 页（开场 + 第一、二幕）必须控制在 **42 分钟**内，否则尾巴被压缩。
- 每 4–5 页必须有一次"结论升级"，避免连续机制页造成疲劳。
- P25、P26 的证据页必须有一次明显的**语气降档**（"这个数字来源是厂商自述 / 这个是趋势级"），
  这是本场建立可信度的关键动作，不能省。
