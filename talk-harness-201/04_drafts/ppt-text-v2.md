# PPT 上屏文案 v2 · 20 张（实战手册味：一页一个完整单元）

> **[INTERFACE]** 本文件是**本场唯一的上屏文案来源**，也是候选内容池。
> **v2 是 20 页版（用户定：只有 20 页资源）——取代 35 页的 v1**（v1 在 git 历史里，要恢复长版随时可取）。
>
> **怎么切页（下游请按这个来）**：
> 1. **页块 = 以 `### ` 开头的那一块**（`### P1`…`### P20`）——**共 20 个页块**；
> 2. **`## ` 开头的是分段**（开场／三条立场／道／分水岭／术／收尾），**不是页**；
> 3. **第一个页块之前的头部不是页**；
> 4. **页块之间必有 `---`**（一条不许删、不许合并、不许挪位置）。
>
> **优先级记号（本件只有这三个）**：`[必上]`＝缺了这一页就不成立；`[可选]`＝装得下就上；`[例]`＝优先上。
> 方括号里只放优先级记号，其他说明用圆括号。
>
> **20 页版的两条特殊纪律**：
> - **一页一个完整单元**（实战手册味）：每页自带"为什么→是什么→怎么算做到"，不靠翻页补全；
>   每页 ≈ 2.5 min，总计 ≈ 50 min。
> - **停顿已融入正文**：原 B1"现在，看你的仓库"＝P15 标题；原 B2"该我动手了"＝P19 标题。
>
> **英文与数字口径**：机制名与文件名＋精选 DSH 原话 7 句（页位见 03）可上屏；外部厂商数字与转述级引语不进本件。
> **序列纪律**：任何一页不得引用后面页面才引入的概念。**口播不进本件**（讲者材料在 03「讲法要点」列）。
>
> **字段表**：

### P3 · 两种结局与一个反转

- **L1 标题**：**coding agent 进大仓库：两种结局，一个反转**
- **L2 主视觉**：上半屏两栏对照（两种结局各拖着缺口清单），下半屏一杆秤压向"成本结构"
- **L3 支撑 [必上]**：
  - 结局一 **糊涂**：抓不住主线、读错、脑补——缺的是：**必须遵守什么／系统由什么组成／为什么这样设计**
  - 结局二 **乱发挥**：改错地方、绕过约束、自造设计——缺的是：**改动落在哪里／按什么流程／怎么算做对**
  - 第七个缺口：**交付怎样算完整**——代码先走、文档后补、声称的行为没有证据
  - DSH 把这句话反过来：**让「读对、改对」变成阻力最小的路径；让「读错、改错」在离错误源头最近的地方，被机器拒绝**
- **落点 [必上]**：**不赌聪明，赌成本结构——全场只讲这一件事。**

## 三条立场

### P4 · 立场①

- **L1 标题**：**立场一：agent 是一等参与者**
- **L2 主视觉**：三个"天然缺陷"箭头指向一条立场
- **L3 支撑 [必上]**：
  - 为什么被逼出来：开发主力**就是** agent——天然缺背景、会忘、会走捷径
  - 它**没有组织记忆**——自述没有约束力，"完成了"可能是没有证据的声称
  - 它听不到走廊对话——口头传统对它无效，它的"问"只能是读文件
  - → **知识必须外置——写进文件、摆到位，agent 找得到；不靠资深脑子与口口相传**
- **L3 支撑 [可选]**：
  - 写给 agent 读和写给人读，是**两种不同的纪律**——DSH 的每个机制，都是这条纪律的形状
- **落点 [必上]**：**它缺什么，仓库就得把什么摆到它看得见的地方。**
- **L4 页脚**：页码 4

### P5 · 立场②

- **L1 标题**：**立场二：规则是可执行的代码**
- **L2 主视觉**：左边一页没人看的贡献指南，右边一个红了的自检脚本
- **L3 支撑 [必上]**：
  - 为什么被逼出来：**写在贡献指南里靠自觉的规则，agent 不会当真**
  - 失败形态：**绿灯崇拜**——检查全绿，但没人验证过它真会拦人，绿灯成了仪式；自报完成 ≠ 验证过
  - **"Agents follow enforced gates far more reliably than prose conventions."**
    ——agent 听门禁的，远比听约定的可靠
  - → **每条可机械判断的规则，接成一个会拦人的检查（门禁）**
- **落点 [必上]**：**门禁和自觉是两种东西——换谁来干活，门禁都拦得住。**

### P6 · 立场③

- **L1 标题**：**立场三：一个事实，一个家**
- **L2 主视觉**：六个格子各贴一个标签——一处一个家；底下三条汇成一个骨架
- **L3 支撑 [必上]**：
  - 为什么被逼出来：agent **每次都是新来的**——读不到上个会话的聊天记录
  - 一处事实两个家，早晚分叉——改了 A 处忘了 B 处，错得无声无息
  - **负知识没家**："为什么不做 X"没地方读，它就把明确的缺席当遗漏，**反复提已否决的方案**
  - 现在与当初搅在一起：只读代码会重走已否定的路，只读历史会把过时实现当现行
  - → 意图、理由、现状、证据、交付状态——**各有各的家，一处一个权威，没有第二份**
  - 三条立场长成一个骨架：**变更闭环管时间／归属管事实去向／渐进披露管读取时机**——
    先走第一层，**拿一笔真实提交**
- **落点 [必上]**：**拿这三条当滤镜看 DSH，它就不神秘了。**
- **L4 页脚**：页码 6

### P7 · 变更闭环

- **L1 标题**：**一笔变更，不该只是一段代码**
- **L2 主视觉**：闭环环图（八环首尾相接），旁边三个失效形态的"病床卡"

### P10 · 归属

- **L1 标题**：**每个事实，住在负责它的那一层**
- **L2 主视觉**：一座带房契的小房子，几条链接箭头指进来——"别处只放链接"；旁边一张预算清单
- **L3 支撑 [必上]**：
  - 刚才那"三跳"，凭什么跳得对？——因为**每个事实都有家，链接才不断**
  - **"Each fact has one home: the tier whose job it is; elsewhere, link there."**
    ——每个事实住在负责它的那一层，别处只放链接
  - 四个失败来源：上下文有限／两处各写一版／人走知识走／现在与当初搅在一起
  - 实物一：根 AGENTS.md 每条常驻规则**只有一到三行，紧跟着一条链接**——根文件负责"有这条规则"，链接负责"怎么执行"
  - 实物二：字数预算不是建议，是**门禁**——`verify-doc-budgets` 逐文件卡上限，根文件 **≤ 1,950 词**
  - 实物三：`ln -s AGENTS.md CLAUDE.md`——不同工具认不同入口名，**事实只有一份**（仓库 4 处这么干）
  - 实物四：负知识也有家——**"为什么不做 X"写在明处**，不然 agent 反复提已否决的方案
- **落点 [必上]**：**"不糊涂"的度量：能不能便宜地找到那份最小且权威的材料。**
- **L4 页脚**：页码 10

### P11 · 决策记录

- **L1 标题**：**"为什么"和"现在"分家**
- **L2 主视觉**：四个状态文件夹（proposed／implemented／rejected／archived），旁边两笔变更的对比例卡
- **L3 支撑 [必上]**：
  - 上一页那笔变更，没写"为什么"的记录——**那什么时候必须写？**
  - 为什么：agent 没参与当时的讨论；**代码只回答"现在是什么"，从不回答"为什么不是别的"**
  - 这类记录有名字：**决策记录**——存"为什么"与取舍，不存"现在是什么"
  - 状态目录即状态机：proposed／implemented／rejected／archived——"已否决""已过时""现行"一眼可分
  - 两个对比例：模型选择器修补 → **不写**（无持久取舍）；进程竞态修复 → **再小十倍也必写**（有五条被否决的路线与接受的代价）
  - 取代纪律：**新增记录并交叉链接，不原地改写；完全取代前先吸收旧记录的全部独有内容**
- **落点 [必上]**：**判据一句话：改动大小无关，看有没有需要长期记住的取舍。**
- **L4 页脚**：页码 11

### P12 · 静与动

- **L1 标题**：**哪些东西稳，哪些东西每轮都在变**
- **L2 主视觉**：四层阶梯，越往下越"活"，每层挂一个实物标签
- **L3 支撑 [必上]**：
  - 为什么多出这一道：agent 的世界里多了两样东西——**每轮重新拼出来的上下文**（模型这轮看到什么，下轮重拼）
    和**跨轮存活的状态**；传统软件里"稳的归代码、活的归内存"有人替你担保，**这里没人管，界线得自己划**
  - 四层：**规则地图**（跨版本不变——AGENTS.md 里那些规矩）／**配置**（部署时定——settings 文件）／
    **事实源**（会话内只追加——像行车记录仪，只录不改：会话日志）／**派生**（每轮重算——这轮拼出来的提示词，丢了能重建）
  - 纪律：每一层只被上一层修改，**下层永远写不进上层**
  - **"Model-visible ⟺ logged."**——模型看到的任何东西，都能从会话日志重建；所以一次会话能**整段回放**
- **落点 [必上]**：**模型当时到底看到了什么，永远答得出来。**
- **L4 页脚**：页码 12

### P13 · 正确路径

- **L1 标题**：**改哪里有表可查；改动有多重，有梯可下**
- **L2 主视觉**：左半屏一张两列表（目标 → 机制），右半屏四级阶梯横着一支"影响半径"的箭头
- **L3 支撑 [必上]**：
  - 三个失败形态：在错误位置插代码／发明一套新接入方式／能用配置解决却动核心
  - 改哪里对照表原样三行：**目标 → 机制**——右边是**具体的注册动作**，不是"参考架构文档"
  - **"There is no privileged core to patch."**——没有特权核心可改：扩展＝挂插件，注册即归属，卸载即撤销
  - 参与阶梯：**L0 组合**（换配置）→ **L1 扩展点**（加工具、命令）→ **L2 seam**（给整块能力换实现留的口子）→ **L3 核心循环**（改驱动本身）
  - **阶梯按影响半径分层，不按价值排序**——乱发挥的典型：本可用 L0／L1 表达，却一路爬到 L3 改核心
- **L3 支撑 [可选]**：
  - 新行为依次问：只是换配置吗？现有扩展点够吗？需要可替换的完整能力吗？——都否，才论证改核心
- **落点 [必上]**：**影响半径最小的那层，就是首选的那层。**
- **L4 页脚**：页码 13

- **L2 主视觉**：三个齿轮咬合（标"本页属第一条链"）＋入口链骨架图

  - 文件态：`CLAUDE.md` 软链 `AGENTS.md`——**两个入口名，一份事实**；根文件只放**常驻规则＋布局＋命令**；
    大多数包只有 README，**是正确结果，不是缺口**
  - 会话态：**触达才注入**——注入＝放进模型这一轮看到的内容；首次只给基线，真读写到更深目录才给那一层；
    **maxBytes 限整条链**，没变的文件不重复注入；超预算**先丢整份更宽的，也不截断最具体的**
  - Skills 同理：**目录只给名字＋一句话说明（不超过 500 字符），选中才读全文**——摘要负责发现，正文才拥有指令
- **落点 [必上]**：**"按需"不是写作纪律，是运行时机制。**
- **L4 页脚**：页码 16

### P17 · 执行链与反馈

- **L1 标题**：**agent 做什么、错了谁拦：一条管线，六层反馈**
- **L2 主视觉**：上半屏一条管线图（动作过几道闸），下半屏六层反馈的金字塔
- **L3 支撑 [必上]**：
  - 执行三设计：**每个动作先落日志，再执行**（失败的调用也在场，事后查得到）／
    **策略全在工具体之外**（闸门统一一处——加一条权限规则只改**一个**文件）／
    **结果只有一条权威出口**（异常都归一化成 isError——模型永远看不到"部分成功"）
  - 反馈六层各查各的：编译／加载／局部／组装／运行时关系／语义——**每层只拥有自己能观察的性质，绿一层不代表别的层也绿**
  - **"A guard only guards if the regression fails it."**——门禁只有在回归上红过，才算门禁；
    新检查先做**负例控制**：引入回归 → 看红 → 还原
  - 本地按改动面选**最小可信证据**，CI 跑穷举——**hook 不是小号 CI**
- **L3 支撑 [可选]**：
  - 三条链合起来，还是开场那句反转：**读对改对阻力最小，读错改错最早被拒**
- **落点 [必上]**：**随便挑一个现有检查：说得出它最近一次为红，是什么回归吗？**
- **L4 页脚**：页码 17

### P18 · 披露与查询

- **L1 标题**：**给什么有预算，查状态不靠猜**
- **L2 主视觉**：五节管线图（组织→注入→组装→回收→隔离），旁边一面"查询"的镜子
- **L3 支撑 [必上]**：
  - 披露是一条管线：静态组织 → 按需注入 → 组装（这一轮模型实际看到什么）→
    **回收**（超预算压缩，**绝不拆散一个工具的调用与结果**——拆散了它就不知道自己刚才做对没有）→ **隔离**
  - **"Spawn supplies no history; fork supplies its balanced seed."**
    ——派生的子代理不带父对话——不会被父上下文的细节带偏
  - 查询：源码答得了"可能"，答不了"现在"——**给一条"查实际生效配置"的命令**，agent 就不用猜；
    接口清单（catalog）答"仓库声明了什么"，答不了"此刻在跑什么"
- **落点 [必上]**：**"按需"的"需"由谁、在什么时刻、以什么预算决定——这是写作纪律答不了的问题。**
- **L4 页脚**：页码 18
