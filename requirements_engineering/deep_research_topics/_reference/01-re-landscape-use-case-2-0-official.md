## 关键事实

1. IJI 官方页面直接把 Use-Case 2.0 定义为：
   - `The Agile Way of Doing Use Cases`
2. 页面明确写道：
   - Use-Case 2.0 `slices-up use cases` 以适应迭代敏捷开发
   - `use-case slices includes the equivalent of user stories for the backlog`
3. 同页还说明它的优势不止 backlog：
   - provides `test-driven design`
   - assists in designing `user experiences`
   - scales to `enterprise or product line level`
4. 官方还直接给出边界判断：
   - `In some cases user stories are enough`
   - 但当 user stories 数量增大，或场景是银行、保险、电信、国防等大型或受监管行业时，仅靠 stories 不够
5. e-book landing page 则再次强调：
   - use-case slices 支持增量、价值驱动、可增长而不是每次推倒重来

## 核心内容摘录

### 敏捷化用例

- 官方 service page 标题就是：`Use-Case 2.0 – The Agile Way of Doing Use Cases`

### 与 user stories 的边界

- service page 写道：
  - `Use-Case 2.0 with its use-case slices includes the equivalent of user stories for the backlog`
  - `In some cases user stories are enough, but not when the number of user stories begins to grow, or when you develop enterprise systems for banks, insurance, telecom operations, defense or other large scale or regulated industries.`

### 解决的问题

- 官方列出的痛点包括：
  - drowning under tiny stories
  - struggling to see the big picture and business value
  - difficult to manage test assets
  - difficult to maintain lightweight but accessible documentation
