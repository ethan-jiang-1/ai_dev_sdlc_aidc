## 当前可支撑的判断

1. Topic 04 里的“规约即代码 / spec-as-workflow”已经不是纯猜测，而是已出现明确产品与方法信号。
2. IDE-native specification primitive 已经出现雏形：
   - Kiro 把 specs 内建为 IDE workflow
   - Spec Kit 把 spec/plan/tasks 变成显式 artifact graph
3. 与此同时，治理方向也在推高 structured documentation 的价值：
   - AI RMF 把设计/开发/部署/使用全链条都纳入风险管理
   - EU AI Act 对技术文档、日志、人类监督提出明确要求
4. 趋势不是单向乐观：
   - Thoughtworks 也明确提醒 elaborate / opinionated / hard-to-review 的风险
   - 这意味着 spec-driven development 会继续演化，而不是已经定型
5. Topic 04 现在对多模态 / graph 两条轴可以更谨慎地下结论：
   - `multimodal-workflow-signal-supported`
   - `multimodal-beyond-single-product-supported`

   - `independent-empirical-multimodal-workflow-outcome-supported`

## 当前 deep-dive questions

1. 哪些团队已经把 spec-driven workflow 跑到 production，而不只是试验？
2. 多模态 / design-to-code requirements 现在已有 Figma + v0 两条官方 workflow signal、一个 Figma/Findable named app-shell deployment case、一个 Vercel/Stripe hosted outcome、一个 independent design-study outcome、AI4UI enterprise-grade benchmark，以及 UX Tools independent adoption census；下一步若继续增强，应找独立验证的 production outcome，而不是再补 vendor-hosted case 或泛 survey。
3. 未来监管会要求什么级别的可追踪 structured artifact，是否会间接推动 EARS/controlled natural language 的回潮？

## 风险与升级点

- 当前 starter pack 对 Spec-as-Code 很强；multimodal 轴现已有 Figma + v0 两条官方 workflow signal、一个 Figma/Findable named app-shell deployment case、一个 Vercel/Stripe hosted outcome、一个 independent design-study outcome、AI4UI enterprise-grade benchmark，以及 UX Tools independent adoption census；graph 轴现已有 RE-specific research signal、enterprise customer-requirements signal 与 BMW product-development case，但 multimodal production outcome 仍主要是 vendor-hosted / self-reported，独立验证仍待补。
- Thoughtworks Radar 是 trend signal，不是 adoption census。
- Topic 04 仍不应把这些轴写成“已成行业主流”；更稳的是“工具与标准底座已出现，采用成熟度待补”。
