## 背景：一只手打着石膏做了两个月

Erik 手骨折打了两个月石膏，被迫把所有编码工作交给 Claude。这段经历让他"被迫 vibe code"，并从中提炼出一套系统方法论。

---

## 核心框架：四大支柱

| # | 策略 | 一句话 |
|---|---|---|
| 1 | **做 Claude 的 PM** | 花 15-20 分钟帮 Claude 探索代码库、共写执行计划，压缩成一条 prompt，然后放手让它跑 |
| 2 | **Leaf Nodes 策略** | AI 只改叶子节点（不被其他模块依赖的终端模块），核心架构保持人类深度掌控 |
| 3 | **核心逻辑必须人工审查** | 触碰系统主干的部分，人类逐行审查不可妥协 |
| 4 | **可验证的检查点** | 设计长跑压力测试 + 人类可验证的输入输出标准，不需要逐行读代码也能判断对错 |

---

## 支柱一：做 Claude 的 PM — 15 分钟前置仪式

> *"不要问 Claude 能为你做什么，问你能为 Claude 做什么。"*

**四步前置流程：**

1. 让 Claude **探索代码库**，找出相关文件和模式
2. 与 Claude **共创执行计划**
3. 把探索结果 + 计划 **合并成一条 prompt**
4. **放手**让 Claude 执行

**效果**：任务成功率指数级提升。计划本身作为工件保存，后续对话可以直接引用。

---

## 支柱二：Leaf Nodes 策略

> *"Leaf Nodes 可以烂一点，因为它们几乎不改，也不阻塞下游。核心架构不行。"*

```
系统主干（人类深度保护，可扩展性优先）
    ├── Leaf Node A（AI 生成，可接受一定技术债）
    ├── Leaf Node B（AI 生成，可接受一定技术债）
    └── Leaf Node C（AI 生成，可接受一定技术债）
```

动态边界：随着模型能力提升，"叶子节点"的边界会向下移动。核心架构的信任范围在缓慢扩大，但不能急。

---

## 支柱三：核心逻辑人工审查

触碰系统主干的部分 → 人类逐行审查，不可妥协。

Erik 的界定标准：
- **必须审**：涉及数据模型变更、权限边界、跨服务协议
- **可跳过**：UI 布局调整、纯增量的叶子节点功能、文档更新

---

## 支柱四：可验证的检查点

> *"忘掉代码存在，但永远别忘了产品存在。"*

- 设计**长跑压力测试**和 I/O 标准
- 人类验证**产品行为**而不是代码行
- 像 CTO 用验收测试、PM 用产品、CEO 做抽查 — 找到你自己的验证层

---

## 22000 行案例

Anthropic 内部强化学习代码库，一次变更 +22,160 行 / -0 行，**一天内合并**。同样的工作人类工程师需要**两周**。

四条支柱同时施加，缺一不可：前置几天的人类规划 → 严格 leaf node 范围约束 → 核心人工审查 → 压力测试验证。

## 实战锦囊

| 话题 | 他的做法 |
|---|---|
| **TDD × Vibe Coding** | 强制 Claude 只写 **3 个 E2E 测试**（1 happy path + 2 error）。他读的唯一代码就是测试 |
| **上下文压缩** | 在自然"午饭断点"时压缩。让 Claude 把计划写进文档，然后立即 compact，~10 万 token → ~几千 |
| **工具组合** | Claude Code 做重型框架搭建，VS Code/Cursor 做 review 和精确小修 |
| **学习加速** | 问 Claude *"你为什么选这个库？说说它。"* 架构决策验证从 2 年变 6 个月 |
| **上下文丢失** | 当 Claude 偏离计划，用 git diff 提取关键决策，新对话贴进去 |

## 核心教训

> **"当模型 7 个月翻一倍能力时，人类逐行 code review 会成为瓶颈。你必须找到不读代码也能验证的抽象层。"**
>
> **"AI 任务能力每周都在变。Leaf node 边界也在变。唯一不变的是：你仍然需要人类判断力来决定把边界画在哪。**
