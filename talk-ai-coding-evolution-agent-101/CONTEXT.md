# CONTEXT.md —— 本 talk 的术语与红线（唯一权威）

> 本目录里**词义与禁用词只在本文定义**。其他文件消费这些词，不重复定义、不悄悄改义。
> **本场的红线是本场自己的**——不套用其他 talk 的禁用词表（各场对象不同，红线各自成立）。

## 一、四个档位

**上屏名（用这个）** vs **内部工作名** vs 用户原说法：

| 档 | 上屏名 | 内部名 | 用户原说法 | 下一步谁定 | 有几个在跑 | **这一圈归谁** |
|---|---|---|---|---|---|---|
| **第 1 档** | **你问一句，它答一句** | 一问一答 | 简单智能体 | 你 | 一个 | **现成的**（你自己就是那一圈） |
| **第 2 档** | **你定好步骤，它照着走** | 固定流程 | 简单工作流 | 你（事先排好） | 多个步骤 | **现成的**（步骤与检查要你写进去） |
| **第 3 档** | **你给个目标，它自己跑** | 自己跑 | 复杂智能体 | 它自己 | 一个 | **你自己搭** |
| **第 4 档** | **你定好分工，它们自己配合** | 多条线 | 复杂工作流 | 结构（谁先谁后是你排的） | 多个 | **你自己搭，还要定谁验收** |

**编号纪律（三套编号不许撞车）**：

| 指什么 | 用什么编号 |
|---|---|
| **五种症状 / 五件事** | `①②③④⑤`——**两者一一对应、同号同序** |
| **四档** | **第 N 档**——**不许用圈码**（避免与症状/五件事混淆） |

**为什么上屏不用「简单 / 复杂」**：这两个字自带褒义，听众会听成「复杂 = 高级 = 该上」。
四档回答的是**这一圈归谁**，不是先进程度——**大多数人日常 90% 的活在 第 1–2 档，停在 第 1 档 完全没问题**。

**内部名只用于本目录的工作文档**（storyline / 页表 / 提纲），**不上屏、不进讲稿**。
上屏与口播一律用上屏名，或直接说「第 1 档 / 第 2 档」。

## 二、核心词

### 2.1 失败面：糊涂（本场的敌人）

| 词 | 口语定义 | 上游出处 |
|---|---|---|
| **糊涂** | **本场对失败面的统称**：它不知道你要什么、不知道规矩、拿着旧资料当真、反复绕圈、说做完了其实没做完 | `backbone.md` §0.2 七缺口 |
| ~~乱来~~ | **本场不用这个词**。上游把失败分成两侧（糊涂 ①②③⑦ / 乱发挥 ④⑤⑥），本场**不展开分侧**，避免多一层术语 | `backbone.md` §0.2 |

**「糊涂」不是本场新造的框架**——它是听众自己的词。开场先让听众认领症状（第一段的五种），再给名字。
**上游的「乱发挥」在本场并入「糊涂」**：听众不需要知道这两侧的区别。

### 2.2 答案：harness（模型外面那一圈）

| 说法 | 用途 |
|---|---|
| **模型外面那一圈** | **全场的工作说法**——除下面两处外，一律用这个 |
| **harness** | **只在两处出现**：（a）P4 核心命题 `Agent = Model + Harness`（含原文 "If you're not the model, you're the harness."）；（b）P15 收尾正名 **harness engineering**。**其余各页出现即违规** |
| **`Agent = Model + Harness`** | 全场核心命题，**P4 给出**（动机已在 P2 建立）。**逐字使用，不拆开改写** |
| **harness engineering** | 收尾正名：搭这一圈是一门工程手艺。**不上屏定义**，一句话带过 |

**为什么给名（2026-09-21 用户定）**：给听众一个能带走的词，本场同时成为进阶内容的入口。
**为什么只给两次**：本场听众不靠这个词理解；给多了就变成术语课。

### 2.3 两个基础词

| 词 | 定义 | 一句话区分 |
|---|---|---|
| **智能体** | 能自己决定下一步的东西 | **下一步是谁定的** |
| **工作流** | 步骤被事先定好的东西 | （同上，就这一句） |

**这句区分句是四档的派生源**，四档全部由它派生。不要用「自主性」「agentic」这类词替代。

## 三、固定说法（全场一字不改）

| 概念 | 固定说法 | 不要写成 |
|---|---|---|
| 全场主轴 | **同一个模型，为什么在别人手里好用，在你手里糊涂？** | 「AI 智能体入门」「如何搭建智能体」 |
| 全场结论 | **模型你只能选；差别在模型外面那一圈——搭对了，它就不糊涂** | 「选对模型」「用好提示词」 |
| **五件事** | **看到什么 / 懂什么 / 会什么 / 怎么做 / 怎么验** | 宪法 / 工件 / 回路 / 节奏（母版内部词） |
| 五件事的顺序 | 先看到 → 再懂 → 再会 → 再按路走 → 最后被验证（**与五种症状一一对应，不许换序**） | 「五大支柱」「五层」「五个能力」 |
| 两句判据 | **错了赔得起吗？错了多久能发现？** | 「风险评估」「成本收益分析」 |
| 每件事的结论句 | **一句话** | **「判词」「金句」「slogan」——「判词」本场禁用**，与「判据」一字之差、含义完全不同 |
| 四档的关键句 | **这一圈是现成的，还是你自己搭** | 「自主性等级」「成熟度模型」 |
| 验证的可信度排序 | **它自己就能查的核对 > 你看一眼 > 它说它做好了** | 「验证闭环」「可观测性」 |
| 划圈怎么说（③） | **它能读什么、能对谁发东西、能不能花钱** | 沙箱 / 权限边界 |
| 核对怎么说（⑤） | **一个机器自己能查的检查** | 门禁 / CI / 断言 |
| 留痕怎么说（⑤） | **事后查得到它每一步做了什么、用了哪份数据** | trace / 可观测性 / provenance |
| **传统代码的角色** | **不是拿来干活的，是拿来做质量控制的** | 「脚本」「程序逻辑」「要学编程」 |
| 代码为什么能把关 | **它每次跑的结果都一样** | 确定性 / computational / deterministic |
| AI 判断的边界 | **AI 的判断每次可能不一样** | 概率性 / inferential / 「幻觉」 |
| 代码当检查怎么说 | **一段跑起来会给出明确对错的检查** | 测试 / 断言 / 门禁 / lint |
| **P10 的落点** | **能让代码查的，别让 AI 自己说** | 「确定性优先」「分层验证」 |
| 要不要会写 | **写不用你写；你要知道的是它能拿来把什么定死** | 「零基础也能学」「不用懂技术」 |

> **「判据」与「一句话」不许混用**（v3 质检修复）：
> **判据** = 那两句（错了赔得起吗 / 多久能发现），回答**"这一圈搭多厚"**，全场只有一处（P11）；
> **一句话** = 五件事各自的结论句，回答**"这件事记住什么"**，共五处（P6–P10）。
> 旧稿里的「判词」一词**已废**，见第四节禁用词。

## 四、禁用词（上屏与讲稿都不出现）

| 禁用 | 原因 |
|---|---|
| **harness**（P4 与 P15 之外） | 只在 P4 核心命题与 P15 正名出现**两次**（见第二节 2.2）。**其余各页一律说「模型外面那一圈」** |
| 沙箱 / 门禁 / CI / trace / prompt engineering / context engineering / 编排 / RAG / 工具调用 / 多智能体 / 幻觉 | **本场听众没有这些词，出现即劝退**；一律换成第三节的固定说法 |
| 具体产品名（平台 / 模型 / 工具） | 会过时，且会被听成推荐。口播可用「你们手上那些工具」泛指 |
| 「不学就被淘汰」「AI 要取代你」 | 焦虑营销。本场是**判断力场**，不是危机场 |
| 「简单 / 复杂」当档位名 | 自带褒义，暗示越复杂越好（见第一节） |
| 姊妹项目引用 / 内部代号 / 仓库路径 | 对外文字不泄露内部命名（仓库通用纪律） |
| 具体数字（百分比 / 倍数 / 版本号） | 本场原则上不引外部数字。**唯一例外：P4 的 Top 30→Top 5**，须同屏标 ⚠️ 厂商自述且**只写作者 + 年份**（红线见 `../02_evidence/00-sources.md` §5） |
| 「判词」 | 与「判据」一字之差、含义不同，容易混（见第三节末的辨析）。用「**一句话**」 |
| 公司名 / 产品名 / 工具名**上屏** | 上屏只留**作者或机构 + 年份**（如 "Trivedy, 2026"、"UC Berkeley 等, NeurIPS 2025"）；公司名只出现在本目录的工作文档里 |
| 编程术语（API / 接口 / 函数 / 变量 / JSON / 部署 / 服务器） | 听众不靠这些词理解。一律换成「它连的那个地址 / 它的钥匙 / 什么情况下它自己停下来」 |
| 「学编程」「零基础」类说法 | 本场不教编程，也不把不会写当门槛（见第五节第 6 条） |

## 五、讲法纪律（写稿时逐条过）

1. **五件事的每一件必须给四段：症状 → 它是什么 → 你要做什么 → 一句话。不给形容词。**
   写不出对应症状的那一件，说明它还没想清。
2. **开场先让听众认领症状，再给名字。** 五种症状（P2）念完必须停一下问「你中过哪一条」，
   不要念完就往下走——听众不认领，后面五件事就没有地方挂。
3. **症状与五件事必须一一对应、同序**：看到 → 懂 → 会 → 走 → 验。**不许换序，不许合并。**
4. **五件事连续讲完，中间不插停顿页**（P5–P10）。切开就散成五条孤立技巧。
5. **不教工具操作，也不教编程。** 不出现「点哪里、怎么配置」，也不出现语法、函数、部署。
   讲代码只讲一件事：**它是拿来把「对不对」这一步定死的**。
6. **不把「不会写代码」当门槛，也不当卖点。** 两句话都不说——「这你学不会」（劝退）和
   「零基础也能学会」（跑题，本场不是编程课）。正确说法：**写不用你写，你要知道的是该要求什么**。
7. **四档收着讲。** 第 3–4 档是听众最容易上头的地方，必须紧跟「什么时候别折腾」。
8. **P3 必须回答「等下一代模型不就行了」这个反驳**（v3 质检补）——这是听众最可能的抵抗点，
   也是本场唯一的趋势判断：**这一圈不会消失，只会移动**（每个组件都编码了一个"模型做不到"的假设）。
   **不回答它，整场的必要性就立不住。**
9. **每一页让听众拿走一个东西。** 拿不到的页 = 删或合并。
10. **任何一页都不许讲成「越复杂越高级」。** 四档是这一圈归谁，不是成熟度；停在 第 1 档 完全没问题。
11. **外部结论一律回 `../02_evidence/00-sources.md` 取**，不在稿里另行摘录；上屏只留作者 / 机构 + 年份。

## 六、证据强度四档（本场自用，与仓库统一口径一致）

| 标注 | 含义 |
|---|---|
| **一手** | 官方文档、官方仓库、同行评审论文，可核验 |
| **⚠️ 厂商自述** | 厂商 / 作者自述，未经独立审计 |
| **⚠️ 降级取证** | 网络受限下仅标题 / 摘要级核验，正文未读 |
| **趋势级** | 有来源但属论述、媒体或榜单级，无方法论支撑，只作趋势不作基准 |

**配套规则**：

- 会漂移的值（排名、星数、价格）标**观测日期**；口径不可比的两个数字**不合成一个**。
- **转引必须标转引**——本场未直接核验原文的（如经 Osmani 转引的 HumanLayer），要用先回源。
- **本场原则上不引数字**：MAST 的频率不上屏，只作症状排序的底稿；
  唯一例外与红线见 `../02_evidence/00-sources.md` §5。
