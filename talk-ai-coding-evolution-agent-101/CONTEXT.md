|---|---|---|---|---|---|---|

**内部名只用于本目录的工作文档**（storyline / 页表 / 提纲），**不上屏、不进讲稿**。

## 二、核心词

### 2.1 失败面：糊涂（本场的敌人）

| 词 | 口语定义 | 上游出处 |
|---|---|---|
| **糊涂** | **本场对失败面的统称**：它不知道你要什么、不知道规矩、拿着旧资料当真、反复绕圈、说做完了其实没做完 | `backbone.md` §0.2 七缺口 |
| ~~乱来~~ | **本场不用这个词**。上游把失败分成两侧（**上游缺口** ① ② ③ ⑦ / ④ ⑤ ⑥），本场**不展开分侧**，避免多一层术语 | `backbone.md` §0.2 |

**「糊涂」不是本场新造的框架**——它是听众自己的词。开场先让听众认领症状（第一段的五种），再给名字。
**上游的「乱发挥」在本场并入「糊涂」**：听众不需要知道这两侧的区别。

### 2.2 答案：harness（模型外面那一圈）

| 说法 | 用途 |
|---|---|
| **模型外面那一圈** | **全场的工作说法**——除下面两处外，一律用这个 |
| **harness** | **只在两处出现**：（a）**P5** 核心命题 `Agent = Model + Harness`（含原文 "If you're not the model, you're the harness."）；（b）**P19** 收尾正名 **harness engineering**。**其余各页出现即违规；上屏标题亦不得含此词** |
| **`Agent = Model + Harness`** | 全场核心命题，**P5 给出**（动机已在 P3 建立）。**逐字使用，不拆开改写** |
| **「身体」（口播比喻，不上屏）** | **只作 P5 口播一次**：**"脑子继续换，身体不用每次重新造"**——帮听众抓住"模型能换、那一圈留下"。**不上屏，也不替代「模型外面那一圈」** |
| **harness engineering** | 收尾正名：搭这一圈是一门工程手艺。**不上屏定义**，一句话带过 |

**为什么给名（2026-09-22 用户定）**：给听众一个能带走的词，本场同时成为进阶内容的入口。
**为什么只给两次**：本场听众不靠这个词理解；给多了就变成术语课。

### 2.3 两个基础词

| 词 | 定义 | 一句话区分 |
|---|---|---|
| **智能体** | 能自己决定下一步的东西 | **下一步是谁定的** |
| **工作流** | 步骤被事先定好的东西 | （同上，就这一句） |

**这句区分句是四档的派生源**，四档全部由它派生。不要用「自主性」「agentic」这类词替代。

### 2.4 术语引入表（v6 · 循序渐进：一页最多命名一个新词）

**这不是"零术语场"，是"术语按序入场"。** 每个专业词走**三段式**：

> ① **先给现象**（大白话，先不用这个词）→ ② **当场命名**（上屏一次，写清"这叫 X"）→ ③ **之后沿用**（巩固）。

**命名必须在该页的概念讲完之后**，不许提前抛词。**一页最多引入一个新词。**

| 页 | ① 先给的大白话 | ② 在这一页命名 | ③ 之后怎么用 |
|---|---|---|---|
| **P5** | 「模型外面那一圈」（P4 已建立） | **`harness`**（写进 `Agent = Model + Harness`） | 其余各页仍说「那一圈」；P19 正名 **harness engineering** |
| **P8** | 桌面 / 抽屉（放在它眼前的、要用再拿的） | **上下文** | 之后可说「上下文」 |
| **P12** | AI 的判断每次不一样 ／ 写好的程序每次都一样 | **代码** | 落点用「**能让代码查的**」 |
| **P15** | 下一步谁定、同时有几个在跑 | **工作流**（你定步骤）/ **智能体**（它定下一步） | 之后可说这两个词 |
| **P19** | — | **harness engineering** | 收尾正名 |

**全场上屏术语总量 = 5 个**（`harness` / 上下文 / 代码 / 工作流 / 智能体）+ 收尾正名 1 个。
听众走的时候应该**带走这几个词**——这是本场作为"培训型分享"的一半价值。
**不许因为"听众不懂"就整场回避术语，也不许一次性抛一堆**（后者就是术语课）。
注意 §4 仍禁的是**复合行话**（context engineering / 多智能体 / 工具调用…），不是这几个单字词。

> **为什么要引入术语（2026-09-22 用户定，本条的根据）**：术语不只是"方便"，它是**让人认真对待这件事的凭据**——
> 说法含糊，听众会把它当成"又一个 AI 概念"，**不会认真审视**；
> **只有准确的那个词才能把那件事说清楚，而说清楚了，他们就记得住**。
> 所以判断标准**不是**"听众听不听得懂"，而是：
> **换一个更通俗的说法，这件事还说清楚了吗？** 说不清楚，就必须引入那个词（并按三段式引入）。
> **推论**：上屏可以出现"版本、上下文、代码、工作流、智能体"这类**单字/单词术语**，
> 但**必须当场命名、只命名一次、之后沿用**；被禁的始终是**没解释过的复合行话**。

**主线比喻（不是术语，无需命名仪式；v9 新增）**：

| 比喻 / 说法 | 用在哪 | 说明 |
|---|---|---|
| **信噪比** | **P6 就是主线页（在那里点名）**；P8 / P9 / P10 / P11 / P12 / P17 / P19 各沿用一句 | **大众词**（音响、摄影里就有）。**上屏时紧跟一句大白话**：「**有用的多、没用的少**」。**它是本场的统一道理**——五件事都在调高它 |
| 桌面 / 抽屉 | P8 | 见第三节固定说法 |
| 身体（脑子换、身体不换） | P5 口播 | 见 2.2 |

**为什么用信噪比当主线（2026-09-22 用户定）**：面向普通大众，**"信息管理"听着像技术，"信噪比"听着像常识**；
而且它一句话就把上下文、知识、工具、步骤、检查全串起来了——**都是同一件事：让给它的东西更准**。

## 三、固定说法（全场一字不改）

| 概念 | 固定说法 | 不要写成 |
|---|---|---|
| 全场主轴 | **同一个模型，为什么在别人手里好用，在你手里糊涂？** | 「AI 智能体入门」「如何搭建智能体」 |
| 全场结论 | **模型决定上限；那一圈决定你能拿到多少——搭对了，它就不糊涂** | 「选对模型」「用好提示词」「选完大家都一样」 |
| **五件事** | **看到什么 / 懂什么 / 会什么 / 怎么做 / 怎么验** | 宪法 / 工件 / 回路 / 节奏（母版内部词） |
| 五件事的顺序 | 先看到 → 再懂 → 再会 → 再按路走 → 最后经得起检查（**与五种症状一一对应，不许换序、不许合并**） | 「五大支柱」「五层」「五个能力」 |
| **① 的比喻（可上屏）** | **什么该一直放桌面，什么应该收进抽屉**（要用的时候再拿出来） | 「分层存储」「上下文管理」「记忆分层」 |
| 两句判据 | **错了赔得起吗？错了多久能发现？** | 「风险评估」「成本收益分析」 |
| 每件事的结论句 | **一句话** | **「判词」「金句」「slogan」——「判词」本场禁用**，与「判据」一字之差、含义完全不同 |
| **核心命题的英文原句** | 保留英文原文，**紧跟一句大白话**：**说白了：你不做模型，你做的就是那一圈。** | 硬译成中文（译了就丢术语） |
| **② 的做法（内部名）** | **隐性知识显性化**：把老手脑子里"这件事我们这儿怎么做 / 为什么 / 什么情况不能"写下来 | 「知识管理」「文档化」 |
| **② 的上屏说法** | **把老手脑子里的东西写出来** | 「隐性知识显性化」**不上屏**（内部名，听众没有这个词） |
| **⑤（续）那段检查谁写** | **现成的 / 找工程同事加一条 / 让 AI 写，但你自己审它检查什么** | 「你得学写代码」「让 AI 自己检查」 |
| **贯穿主线（v9）** | **让它看到的、拿到的，都「有用的多、没用的少」——这就是信噪比** | 「信息量」「数据量」「资料越多越好」 |
| 四档的关键句 | **这一圈是现成的，还是你自己搭** | 「自主性等级」「成熟度模型」 |
| 验证的可信度排序 | **它自己就能查的核对 > 你看一眼 > 它说它做好了** | 「验证闭环」「可观测性」 |
| 划圈怎么说（③） | **它能读什么、能对谁发东西、能不能花钱** | 沙箱 / 权限边界 |
| 核对怎么说（⑤） | **一个机器自己能查的检查** | 门禁 / CI / 断言 |
| 留痕怎么说（⑤） | **事后查得到它每一步做了什么、用了哪份数据** | trace / 可观测性 / provenance |
| **代码的角色** | **不是拿来干活的，是拿来做质量把关的**；P12 当场命名：**代码就是写好的程序，每次跑出来都一样** | 「脚本」「程序逻辑」「要学编程」「传统代码」 |
| 为什么能把关 | **它每次跑出来都一样** | 确定性 / computational / deterministic |
| AI 判断的边界 | **AI 的判断每次可能不一样** | 概率性 / inferential / 「幻觉」 |
| 代码当检查怎么说 | **一段跑起来会给出明确对错的检查** | 测试 / 断言 / 门禁 / lint |
| **P12 的落点** | **能让代码查的，别让 AI 自己说** | 「确定性优先」「分层验证」 |
| 要不要会写 | **写不用你写；你要知道的是它能拿来把什么定死** | 「零基础也能学」「不用懂技术」 |

> **「判据」与「一句话」不许混用**（v3 立，v4 复核）：
> **判据** = 那两句（错了赔得起吗 / 多久能发现），回答**"这一圈搭多厚"**，全场只有一处（**P14**）；
> **一句话** = 五件事各自的结论句，回答**"这件事记住什么"**，共五处（**P8–P12**）。
> 旧稿里的「判词」一词**已废**，见第四节禁用词。
> **v4 复核发现**：② 一度把它的结论句写成了「判据」，已改回「一句话」——**内部名（隐性知识显性化）
> 与上屏说法（把老手脑子里的东西写出来）也在此分开登记**，不许混。

## 四、禁用词（上屏与讲稿都不出现）

| **harness**（P5 与 P19 之外，含上屏标题） | 只在 P5 核心命题与 P19 正名出现**两次**（见第二节 2.2）。**其余各页一律说「模型外面那一圈」** |

| 公司名 / 产品名 / 工具名**上屏** | 上屏只留**作者或机构 + 年份**（如 "Trivedy, 2026"、"Anthropic, 2026"、"UC Berkeley 等, NeurIPS 2025"）；公司名只出现在本目录的工作文档里 |

## 五、讲法纪律（写稿时逐条过）

1. **五件事的每一件必须给四段：症状 → 它是什么 → 你要做什么 → 一句话。不给形容词。**
   写不出对应症状的那一件，说明它还没想清。**⑤ 允许拆成两页（P12 / P13），但四段结构不变。**
2. **开场先让听众认领症状，再给名字。** 五种症状（P3）念完必须停一下问「你中过哪一条」，
   不要念完就往下走——听众不认领，后面五件事就没有地方挂。
   **房间里有上级在时，认领用"不用说出来"的问法**（v4 补）。
3. **症状与五件事必须一一对应、同序**：看到 → 懂 → 会 → 走 → 验。**不许换序，不许合并。**
4. **五件事连续讲完，中间不插停顿页**（P6–P13，含主线页 P6）。切开就散成五条孤立技巧。
5. **不教工具操作，也不教编程。** 不出现「点哪里、怎么配置」，也不出现语法、函数、部署。
   讲代码只讲一件事：**它是拿来把「对不对」这一步定死的**。
6. **不把「不会写代码」当门槛，也不当卖点。** 两句话都不说——「这你学不会」（劝退）和
   「零基础也能学会」（跑题，本场不是编程课）。正确说法：**写不用你写，你要知道的是该要求什么**；
   **并回答"那段检查谁写"（P13）**——不回答，这一页对不写代码的听众就是空的。
7. **四档收着讲。** 第 3–4 档是听众最容易上头的地方，必须紧跟「什么时候别折腾」。
8. **P4 必须回答「等下一代模型不就行了」这个反驳**——这是听众最可能的抵抗点，
   也是本场唯一的趋势判断：**这一圈不会消失，只会移动**（每个组件都编码了一个"模型做不到"的假设）。
   **不回答它，整场的必要性就立不住。** 依据：Anthropic, 2026（**一手**）。
9. **每一页让听众拿走一个东西。** 拿不到的页 = 删或合并；**页数预算是 21 张（19 正文 + 2 停顿；v10 起）**。
   **v8 起区分两层**：`04_drafts` 是**内容池**（每页给的材料多于能装的，按 `[必上] / [可选] / [例]` 分档，
   由下游按版面容得下挑）；**渲染成页之后仍是一页一件事**——**池子大不等于幻灯片堆满**，
   讲的时候一页只讲一件事。
10. **任何一页都不许讲成「越复杂越高级」。** 四档是这一圈归谁，不是成熟度；停在 第 1 档 完全没问题。
11. **外部结论一律回 `../02_evidence/00-sources.md` 取**，不在稿里另行摘录；上屏只留作者 / 机构 + 年份
    （上屏署名计划见 storyline 末节：**只有 P4 / P5 署名**）。
12. **上屏文案必须是中文口语（v4 补，v6 加严）**：**基准读者 = 文职岗、略懂科技的人**。
    不许被动句、不许「…的是…」句式、不许抽象名词堆叠、不许把英文直译过来，
    **也不许出现研发圈行话**——版本 / 字段 / 全局 / 传统代码 / 可靠性 / 一手 一类。
    **还包括（v17 补）**：**表单腔标签**（"你要摆清楚："→"摆什么："）、**单字不加引号**、
    **指代要统一**（五个地方一律说"哪个地方"，不许格/样/个混用）、**别缺虚词**
    （"全堆一个文件夹"→"全堆在一个文件夹里"）、**别用"是…的"判断句**、
    **引它的心理话用第一人称**（"它在哪儿？"→"我在哪儿？"）、**僵搭配换中文说法**
    （在这里→在这儿 ／ 对它就等于不存在→它就当没有）。
    **判据是念出来像不像中国人说话、要不要解释一遍才懂；别扭或要解释的，一律重写。**
    反面例子与改法清单见 `../01_storyline/01-narrative-check.md` 第三节「说人话自检」。
    **英语只在术语本身精确时才上屏**，全稿允许的英文只有 5 类（同节）。
13. **专业术语循序渐进引入（v6 补）**：每个词走**三段式**——① 先给现象（大白话）→ ② 当场命名
    （上屏一次，写清"这叫 X"）→ ③ 之后沿用。**命名必须在概念之后；一页最多命名一个新词。**
    清单见第二节 2.4。**既不许因为"听众不懂"就整场回避术语，也不许一次性抛一堆。**

## 七、记号约定（v7 · 给下游渲染 Agent 的接口）

**先划文件职责——各写各的，不混：**

| 文件 | 只装什么 | 是渲染输入吗 |
|---|---|---|
| `04_drafts/ppt-text-v5.md` | **只有上屏文案** | ✅ **talk 的渲染文案来源** |
| `04_drafts/手册-页版-v5.md` | **手册的页版**：一页一个提醒（与 04 同一套字段与记号） | ✅ **手册的渲染文案来源** |
| `04_drafts/实战手册-v5.md` | **手册的长版**（讲义，可发可读，含填空模板与一页清单） | 否（不是幻灯片） |
| `03_outline/00-page-structure-v4.md` | 页序 / 时长 / 上屏元素 / **讲法（不上屏）** | 页序与时长是；讲法不是 |
| `01_storyline/00-storyline-map.md` | 内容与推导 | 否（文案以 04 为准） |
| `01_storyline/01-narrative-check.md` | 自查与质检痕迹 | 否 |
| `02_evidence/00-sources.md` | 证据与口径红线 | 否 |
| `CONTEXT.md`（本文） | 术语 / 红线 / 记号约定 / 英文白名单 | 否 |
| `05_output/` | **未建**——等 talk review 过再渲染 PPTX | — |

**两种记号，各管一件事：**

1. **标签 `[不上屏]`**——给人看、给 LLM 看的**词元**，可 grep：
   `grep -n '\[不上屏\]' <file>` 一次拿到全部不上屏段落。
2. **硬隔离 HTML 注释**——给渲染器的**硬保证**：

   ```
   <!-- off-screen:begin -->
   （不上屏的内容）
   <!-- off-screen:end -->
   ```

   HTML 注释是 CommonMark 自带语法，**所有渲染器一律隐藏**，零插件依赖。

**为什么不用别的**（2026-09-22 查证结论）：

- `> [!XXX]` 自定义类型：GitHub 只认 NOTE / TIP / IMPORTANT / WARNING / CAUTION 五种，
  **自定义类型不会变成结构**，只是普通引用块——只能"提示"，不能"隔离"。
- `:::directive`：要渲染管线装 remark-directive（Docusaurus / Astro 那类）；纯 MD 视图里会露出 `:::off-screen` 噪声。
- **幻灯工具自己就是这么干的**：Marp 的演讲者备注就是 HTML 注释，reveal.js 用 `<aside class="notes">`——
  "内容在源里、不在屏上"是这个生态的既有惯例。

**规则**：**成段**的上不了屏内容**必须**用硬隔离包起来，**并且**在段落标签里带 `[不上屏]`（两者叠加）；
只带标签、不包注释的，允许用在"本身就是工作文档"的文件里（如本文件、`01-narrative-check.md`）。
**例外**：**文件顶部的 `[INTERFACE]` 声明块不要包进注释**——它是给下游读的契约，包了反而读不到。

**内容池与优先级记号（v8）**：`04_drafts` 给的**材料多于一张幻灯片能装的**，下游**按版面容得下挑选**：

| 记号 | 含义 |
|---|---|
| `[必上]` | 缺了这一页就不成立——没地方就挤别的 |
| `[可选]` | 装得下就上，装不下就丢 |
| `[例]` | 具体例子——**优先上**，比抽象说法好懂 |

- **挑选不得违反红线**：数字零上屏 / 无行话 / 产品名不上屏 / **术语一页只命名一次** / 英文只那 5 类。
- **池子大 ≠ 幻灯片堆满**：挑选完**渲染成页之后，一页仍然只讲一件事**。

**页块怎么切（v18 定；下游按这个解析）**：
- **页块 = 以 `### ` 开头的那一块**（`### P1…`、`### B1 / B2`）；**`## ` 开头的是分段，不是页**；
  **第一个页块之前的头部不是页**。`04_drafts` 两个渲染件都遵守这条。
- **方括号里只放优先级记号**（`[必上] / [必给] / [可选] / [例]`），其他说明一律用**圆括号**。
- **`[必上]` 在手册页版里专指"那一页的提醒"——每页恰好一条**；材料用 `[必给]`（可多条、可含表）。
  演讲件没有 `提醒` 字段，它的 `[必上]` 表示"该页必给内容"，可多条。
- **两个渲染件共用同一套记号约定，但字段表各自独立**，不声称"同一套字段"。
- **页块编号两套前缀，故意不撞号**：演讲件 `### P1`…`### P19` ＋ `### B1 / B2`；
  **手册页版 `### HP1`…`### HP20`**（`HP` = handbook page）。正文里提"第几页"**一律写中文"第 N 页"并指明是哪个件**。
- **手册页版自带一套叫法**：它说**五个地方**（工作空间 / 知识 / 能力 / 流程 / 规矩与约束），
  演讲说**五件事**（看到什么 / 懂什么 / 会什么 / 怎么做 / 怎么验）——**同一件事、两套叫法**；手册里已声明这层对应。
- **字号指令与空槽**：`（大字）`／`（小字）` 是**字号指令**（写在演讲件的 `L2 主视觉` 里）；
  `讲者`／`场次`／`日期` 是**空槽**（按需填或留空）；**演讲件另有 `脚注` 字段**（小字）；
  停顿页用独立字段 `大字`／`小字`。**手册页版不用字号指令。**

**页面分隔线（2026-09-22 用户定；不得改动）**：`04_drafts` 里**每两页之间必须有一条 `---`**
（独立成行、前后留空行）——作用就是让下游**能按页切分**。
**`ppt-text-v5.md` 21 个页块 → 21 条分割线**（页块之间 20 条 ＋ 头部之后、第一个页块之前 1 条）；
**`手册-页版-v5.md` 20 个页块 → 20 条分割线**（同理）。
**一条不许删、不许合并、不许挪位置。**
（本节、`03_outline` 与 storyline 的规格/内容表**不用**这种分隔线——**它只属于 `04` 的页块**。）
