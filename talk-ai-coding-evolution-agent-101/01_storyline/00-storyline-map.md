## 一句话主线

**Agent = Model + Harness。模型决定上限，那一圈决定你能拿到多少——差别就在模型外面那一圈。
那一圈搭对了，它跑起来就不糊涂；这门手艺叫 harness engineering。**

## 全场主轴：只追一个问题

> **同一个模型，为什么在别人手里好用，在你手里糊涂？**

**为什么是这个问题**：

1. **听众已经在被它折磨**——它忘了你说过的话、不懂你的业务还不问、反复绕圈、说做完了其实没做完。
2. **它把答案逼到唯一的地方**：不是模型不行（模型你也没法改），是**模型外面那一圈没搭**。
3. **它天然推出五件事**：那一圈要搭的，就是让它**看到什么 / 懂什么 / 会什么 / 怎么做 / 怎么验**。

> **术语约定（本文件全篇）**：`①②③④⑤` 指**症状与五件事**（一一对应、同号）；
> **四档一律写「第 N 档」**，不用圈码——避免三套编号撞车。

## 第二段：核心命题（为什么不在模型）

### P4 · 不是模型不行，也不是"等下一代就好了"

- 你**只能选**模型，选完就没法改了。同一个模型，在不同人手里表现不一样——
  所以差别不在模型，在**模型外面那一圈**。
- **一定会有人问：那等下一代模型不就行了？**
  模型变强，这一圈**会变，但不会消失**：**每一个组件都编码了一个"模型做不到"的假设**；
  模型学会了，那个组件就退休——**但新的天花板又要新的组件**。
- **落点**：**你等不到一个不需要搭这一圈的模型。**

> **依据（v4 改正）**：**Anthropic《Harness design for long-running application development》，2026-03-24，
> 一手（官方工程博客）**——原文 "every component in a harness encodes an assumption about what the model
> can't do on its own"，以及 "the space of interesting harness combinations doesn't shrink as models improve.
> Instead, it moves"。见 `../02_evidence/00-sources.md` §3。
> （v3 曾把这两句记在 Osmani 名下并只评趋势级，属转引误记；v4 已直接引一手源。）
> **同方向·行业侧（v5）**：2026-09 有厂商干脆把那圈单独做成产品开源，官方口径是"**一行代码 + 随便换模型**"——
> 见 `../02_evidence/00-sources.md` §5（⚠️ 厂商自述，只作方向）。

### P5 · `Agent = Model + Harness`

> **"If you're not the model, you're the harness."** —— Vivek Trivedy

- **模型**：给能力。你只能选，控制不了。
- **harness（模型外面那一圈）**：**管稳不稳**。**你拥有它、你能搭它、它决定它跑起来糊不糊涂。**
- **命名**：**模型外面那一圈，有个名字，叫 `harness`。**
- 一句话：**模型决定上限，那一圈决定你能拿到多少**（原意：模型给智能，那一圈让智能真的能干活）。

**旁证（口播，不上屏，见 §7 红线 2）**：**上个月有家厂商干脆把这一圈单独做成了产品开源出来——
官方卖点就是"一行代码 + 随便换模型"。**
（⚠️ 厂商自述；**不点产品名、不报数字**，见 §5。此前"同一个模型从 Top 30 进 Top 5"仍可作备选口播，
但那个榜在本场观测时已换代、原名次表为空，既无法独立回源又已漂移——**数字一律不上屏**。）
（**比喻（只口播）**：**"脑子继续换，身体不用每次重新造"**——注意这句是中文界的提炼，不是官方原话。）

**命名纪律**：`harness` 这个词**只在本段与收尾正名出现**；其余各页一律说「**模型外面那一圈**」。
理由与例外见 `../CONTEXT.md` 第二节 2.2。

## 第三段：那一圈要搭的五件事（本场主体 · P6–P13）

> **五件事不是拍脑袋分的**：它们既对应 harness 的组件面（`../02_evidence/00-sources.md` §1），
> 也对应第一段的五种症状（同号一一对应）。
> **排序依据是"它需要什么"**：先看到 → 再懂 → 再会 → 再按路走 → 最后经得起检查。
> **每件事固定四段**：症状 → 它是什么 → 你要做什么 → 一句话。
> **⑤ 因为要回答"那段检查谁写"，拆成 P12 / P13 两页**（拆页不是合并，顺序与编号不变）。
>
> **贯穿主线（v9）**：这五件事其实在干**同一件事**——**把它看到的、拿到的，都调成高信噪比**
> （**有用的多、没用的少**）。**P6 就是主线页（在那儿点名），P8–P12 与 P17 各沿用一句**。
> 听众记住这一条，比记住五个词有用。

### P6 · 那一圈到底在调什么（全片主线页）

- **它做对的前提，是它看到的、拿到的都是"准"的**
- **有用的多、没用的少**——这个比例，就叫**信噪比**（大众词：音响、摄影里就有）
- **少即是多**：它不需要知道很多，它需要知道得**准**
- **按图索骥**：不一定要把资料都搬过来——**给它一张索引，让它自己去找**
  （索引长什么样：一份目录 ／ "这个在共享盘哪个文件夹" ／ "遇到 X 就去查 Y"的对照）
- **一句提醒**：它现在缺的，往往不是信息，是**"哪条算数"**
- **落点**：**它不是知道得不够多，是拿到的里面"没用的"太多。**

> **为什么单独给一页（v10，用户定）**：面向普通大众，**"信息管理"听着像技术，"信噪比"听着像常识**；
> 而且它一句话就把上下文、知识、工具、步骤、检查全串起来——**都是同一件事：让给它的东西更准**。
> 用掉 20 页预算的余量，插在五件事之前当**主线页**；P8–P12 与 P17 各沿用一句。

### ① 让它看到该看的东西（上下文）

- **症状**：它忘了你后来说的；它还在用早先那份；关键那份它没看见
- **它是什么**：模型能用的，**只有此刻放在它眼前的东西**（就是"桌面"上的那些）——你给它的，就是它知道的全部
- **你要做什么**：
  - 把该给的给到位（规矩、背景、这次要用的资料）
  - **告诉它哪份是最新的**——它分不清"现在这么做"和"以前这么做"
  - 别一次塞太多：**塞得越满，中间越容易被漏掉**——**抽屉里的，用到再拿**
- **命名**：**这些"放在它眼前"的东西，专业上叫「上下文」。**
- **一句话**：**你以为它知道，其实它没看见。**

<!-- off-screen:begin -->
> **底稿（不上屏，v5 补）** [不上屏]：成熟做法是**分层的**——工具结果太长就截头尾、**原文外置到磁盘、需要时再取回**
> （不是删掉）；用到八成就把旧的压缩掉、只留最近几条；技能启动只装名字和一句话、**用到才加载**。
> 核心一句：**不要因为"可能会用到"，就把所有东西提前塞进去**。见 `../02_evidence/00-sources.md` §5。
<!-- off-screen:end -->

### ② 让它懂你的业务（把老手脑子里的东西写出来）

- **症状**：它按通用套路干；不懂你们这行的规矩和黑话；**不懂也不问，自己猜**
- **它是什么**：模型懂的是**通用套路**；你们这行真正管用的东西，大多**还在老手脑子里，没写下来**
- **你要做什么**：把老手脑子里的东西写出来——不是写手册，是写"这件事我们这儿怎么做 / 为什么这么做 /
  什么情况不能这么做"
- **一句话**：**脑子里的东西不写下来，它就只能猜。**

<!-- off-screen:begin -->
> **底稿（不上屏，v5 补）** [不上屏]：把"它记住的东西"分三层——**此刻能看的 / 这一段干过什么 / 跨会话还值得知道的**。
> 前两层产品可以给默认策略，但**"什么该被永久记住"仍然要人来定**——这正是 ② 为什么是人的活。
<!-- off-screen:end -->

### ③ 让它有该有的本事（工具与边界）

- **症状**：它干不了（够不着你的系统）；用了笨办法；**碰了不该碰的**
- **它是什么**：模型只会**写给你看**；**真能动手的，是你给它的工具**
- **你要做什么**：
  - 给它够得着的工具（查资料、读表、发消息）
  - **同时划圈**：它能读什么、能对谁发东西、能不能花钱
- **一句话**：**给能力的时候，顺手把圈划上。**

### ④ 让它按对的步骤走（工作流）

- **症状**：**它反复绕圈**（最高频）；跑偏；**提前收工**；说的和做的不是一回事
- **它是什么**：你给一个目标，它自己决定下一步——**步骤对不对，它自己不知道**
- **你要做什么**：
  - 把关键步骤写下来：先做什么、后做什么、**什么时候必须停下来问你**
  - 长活要能**接着上一段往下干**（不然每换一段就重来）
- **一句话**：**它不迷路，是因为你先把路画出来了。**

<!-- off-screen:begin -->
> **底稿（不上屏，v5 补）** [不上屏]：那一圈管的不只是"它能调用什么"，还包括**以什么顺序行动、什么时候停下来确认、
> 什么才算完成**（成熟产品的默认策略里就写着：先摸清环境再动手、不可逆的先问、收工前重新验一遍）。
<!-- off-screen:end -->

### ⑤ 让它经得起检查（代码把关）★ 全场最重要的一页

- **症状**：它说做完了其实没做完；检查只做了表面；**自己评自己总说好**
- **它是什么**：**AI 的判断每次可能不一样**——所以它**不能当最后的对错判官**
- **你要做什么**：**AI 负责干，写好的程序负责查**
  - **写好的程序每次跑出来的结果都一样**，所以能替你把「对不对」这一步**定死**
  - **你要提的要求就三条**：会给出明确对错 / 每次都一样 / **卡在最容易出错的那一步**
  - **留痕**：事后查得到它每一步做了什么、用了哪份数据——不是为了追责，是为了出错时找得到断点
- **命名**：**这种"写好的程序"，就叫「代码」——它不是拿来干活的，是拿来做质量把关的。**
- **一句话**：**能让代码查的，别让 AI 自己说。**

<!-- off-screen:begin -->
> **底稿 [不上屏]** 直接支持这一页（v4 改正数字口径）：验证错误 + 验证不完整合计 **13.48%**，
> 且"有验证者也不够"——现有验证大多只做表面检查。**加一层高层目标验证，ChatDev 成功率 +15.6%（绝对改进）。**
> **行业侧（v5）**：成熟 harness 的默认策略里就写着"**收工前重新验证一遍**"，而且**在循环内恢复**而不是等它崩掉——
> 与 P12"卡在最容易出错的那一步"同向。见 `../02_evidence/00-sources.md` §5。
<!-- off-screen:end -->

### ⑤（续）那段检查谁写（P13）

- **它不是你的活，但它是你的要求**——写不用你写，**要知道该要求什么**。三条路，任选：
  1. **现成的**：你们平台上本来就带着的检查（金额对不对得上、字段有没有空、格式合不合）；
  2. **找工程同事加一条**：你能说清"哪一步最容易错、错了长什么样"，他就能把它变成一段会报错的检查；
  3. **让 AI 写，但检查什么由你定**——它能替你写，**检查什么得你说了算**。
- **附带一条（不可省）**：**干活的和验收的，不能是同一个人**——自己评自己，一定说好。
  （一手依据：Anthropic 2026-03-24，"Separating the agent doing the work from the agent judging it"。）

## 第四段：搭多厚、归谁（P14–P16）

### P14 · 先定"搭多厚"：两句判据

> **错了赔得起吗？错了多久能发现？**

| | **马上能发现** | **很久才发现** |
|---|---|---|
| **赔得起** | 改一封内部通知的措辞 → **放手，随便试** | 整理内部知识库 → **加一个「每周扫一眼」** |
| **赔不起** | 给客户发报价单 → **发出去之前必须有人看一眼** | 动客户数据 / 对外自动回复 → **划圈 + 核对 + 留痕，一样不能少** |

**这一页回答的是"搭多厚"，不是"搭不搭"**：五件事在**任何一档**都得有，只是厚薄不同。

### P15 · 再定"归谁"：四档

**定位的两个问题**：**下一步谁定**（你 / 它）× **同时有几个在跑**（一个 / 多个）。

| 档 | 上屏名 | 这一圈归谁 | 它的风险 |
|---|---|---|---|
| **第 1 档** | 你问一句，它答一句 | **现成的**——你自己就是那一圈 | 几乎没有：你全程在场，代价最小 |
| **第 2 档** | 你定好步骤，它照着走 | **现成的**——但步骤和检查要你写进去 | **一步烂，后面全烂，而且错得很整齐，看起来很像对的** |
| **第 3 档** | 你给个目标，它自己跑 | **你自己搭**——你只在开头和结尾出现 | 跑偏没人知道 / 碰了不该碰的 / 该停不停 |
| **第 4 档** | 你定好分工，它们自己配合 | **你自己搭，还要定谁验收** | 互相甩锅 / 重复劳动 / **一条线出了错，全都跟着错** |

<!-- off-screen:begin -->
> **口径 [不上屏]**：第 3–4 档的风险描述**借自多 agent 场景**，只作"多一层就多一类风险"的**方向提示**；
> **不引"多 agent 更容易失败"**（见 `../02_evidence/00-sources.md` §2 口径警告）。本场多数听众在 第 1–2 档。
<!-- off-screen:end -->

**两条关键句**：

- 第 3 档：**它自己能验证的活，才敢让它长跑。**
- 第 4 档：**多找一个人干活之前，先问一句：这一步是不是真的需要另一个脑子？**

**落点**：**越往下走，五件事越不能省；但停在 第 1 档，完全没问题。**

**命名**：**下一步由你定，叫「工作流」；下一步由它定，叫「智能体」。**

### P16 · 两页合起来用

> **先定厚薄，再看归谁。**
>
> - **判据回答"搭多厚"**（错了赔得起吗 / 多久能发现）；**四档回答"这一圈归谁"**（现成 / 自己搭）。
> - **合起来只有两句话**：
>   1. **现成的，别自己重搭**——第 1–2 档里那些检查是产品自带的，**你要做的是把它用起来**；
>   2. **自己搭的，别忘了定谁验收**——走到第 3–4 档，**能碰什么 / 什么时候停 / 谁来验收**这三样必须写下来。

> **为什么单独一页**：P14 的四个格子与 P15 的四个档位紧挨着，听众会看到两个"四"。
> 圈码纪律解决了**编号**撞车，解决不了**认知**撞车——这一页只做"两页怎么一起用"这一件事。

## 第五段：收尾（P17–P19）

### P17 · 什么时候别折腾（对这批听众最重要的一页）

- 一句话能说清的事，别写流程
- 一周做一次的事，别搭自动化
- **还没想清楚"什么样算做对"，别交给它自己跑**
- 先跑最简单的，不够再加。加之前先问：**谁维护它？它坏了谁发现？**

### P18 · 今天就能做的两件事

1. 挑一件你正在让 AI 干的事，对一遍五件事——**哪一件你根本没做？**
2. 如果是第 3 或第 4 档，先把这三条写下来：**它能碰什么**、**什么情况必须停下来问你**、
   **有没有一段代码能替它说"这步没问题"**（没有就按 P13 的三条路去弄一条）

### P19 · 回到开场 + 正名

**回到 P2 那个场景**：现在再看它为什么糊——**答不出的那一条，就是你那一圈缺的东西。**
**这一圈有名字**——`Agent = Model + Harness`，搭它的这门手艺叫 **harness engineering**。
