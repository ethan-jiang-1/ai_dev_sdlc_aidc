# talk-ai-coding-evolution-agent-101

**定位（2026-09-22 用户定；v23 换听众口径）**：面向「**业务熟、AI 有初步理解、技术一般、已经在动手搭 Agent**」
的人的实战场——**他们亲身感受过 Agent 时好时坏，但不知道该怎么把它搭稳**。
（**听众的完整定义在 `CONTEXT.md` §〇，本节不重复定义。**）
**20–30 min · 19 页正文 + 2 张停顿页 = 21 张 ≈ 28 min**。全场只追一个问题：

> **同一个模型，为什么在别人手里好用，在你手里糊涂？**

**核心命题只有一条**：

> ## `Agent = Model + Harness`
> **模型决定上限；那一圈决定你能拿到多少。**
> **那一圈搭对了，它跑起来就不糊涂。这门手艺叫 harness engineering。**

**这是一场独立成篇的 talk，不是任何其他场的删减版。** 它从 `talk-ai-coding-evolution-harness/` 与
`03_practice/harness_governance/` 取素材，但**换了主轴、听众与概念量**：

| | 母版（harness talk） | 本场 |
|---|---|---|
| **主轴（同一个问法）** | **这次改动，凭什么可以上线？**——面向研发交付 | **同一个模型，为什么在别人手里好用，在你手里糊涂？** |
| 听众前提 | 知道 prompt／context，做过团队交付（产品 + 程序员，质量门槛高） | **业务熟 ＋ AI 有初步理解，已经在搭 Agent**；技术一般，但**知道什么错了要命** |
| 失败面 | 追责链断在哪一步（圈住／拦住／看清） | **五种症状**（学术底稿：MAST 的 14 种失败模式，13 归位 + 1 未采用） |
| 概念量 | 五层工程 + 20 余个机制词 | **一条公式 + 五件事 + 四档** |
| 规格 | 37 页正文 + 5 停顿页 = 42 张／75–90 min | 19 页正文 + 2 停顿页 = 21 张／20–30 min |

> **两场的组织原则其实是同一个**（母版 v2 起的规矩：**全场只追一个问题，每一幕是这个问题的一步推导**）——
> 差别不在"问题轴 vs 时间轴"（母版的时间轴只是它的第一幕），而在**主轴问题本身、听众前提、概念量与规格**。

**为什么不能靠删页做出来**：母版的概念量是**结构性的**（五层工程 + 20 余个机制词），
它的推导链砍任何一环就断；而且母版的听众是研发 + PM、篇幅是本场的三倍。
所以本场是**按新主轴重新组织**，不是压缩。

## 一、核心结构（一句话版）

**五种症状**（听众先认领）→ 一一对应 **五件事**（那一圈要搭的）：

| # | 症状（听众的话） | 五件事 | 一句话 |
|---|---|---|---|
| ① | 它忘了你后来说的；**还在用早先那份** | **让它看到该看的东西**（上下文） | 你以为它知道，其实它没看见 |
| ② | 它按通用套路干，不懂你的业务**还不问** | **让它懂你的业务**（把老手脑子里的东西写出来） | 脑子里的东西不写下来，它就只能猜 |
| ③ | 它干不了；用了笨办法；**碰了不该碰的** | **让它有该有的本事**（工具与边界） | 给能力的时候，顺手把圈划上 |
| ④ | 它**来回兜圈子**；跑偏；提前收工 | **让它按对的步骤走**（工作流） | 路先画出来，它就不迷路 |
| ⑤ | 它说做完了其实没做完；**自己评自己总说好** | **让它经得起检查**（代码把关）★ | **能让代码查的，别让 AI 自己说** |

**四档**只回答一件事——**这一圈是现成的，还是你自己搭**：
**第 1 档 你问一句它答一句／第 2 档 你定好步骤它照着走**（现成）→
**第 3 档 你给个目标它自己跑／第 4 档 你定好分工它们自己配合**（自己搭）。

**搭多厚**由**两句判据**决定（**错了赔得起吗？错了多久能发现？**）——它回答"搭多厚"，不是"搭不搭"。
**P14 的判据与 P15 的四档怎么一起用，由 P16 单独回答**（先定厚薄，再看归谁）。

**全场最重要的一页（P12）**：**AI 负责干，代码负责查**——写好的程序每次跑的结果都一样，
所以能替 AI 把「对不对」这一步定死；这一页**当场把「代码」这个名字给听众**。
**检查由谁写不关键**（听众的强项是判断，不是手艺）；
**P13 专门回答"那段检查谁写"**——不回答，这一页对技术一般的听众就落不了地。

**P4 必须回答听众最可能的反驳**：「等下一代模型不就行了？」——
**这一圈不会消失，只会移动**（每个组件都编码了一个"模型做不到"的假设）。
**依据已回源到 Anthropic 官方工程博客（2026，一手）**。不回答它，整场必要性立不住。

**P2 必须先给一个场景**（30 秒：旧模板 → 不懂规矩也不问 → 悄悄兜了两圈 → "做好了"但数字是错的），
再上 P3 的五种症状让听众认领——清单直上，认领不会发生。

> **编号纪律**：`①②③④⑤` 指**症状与五件事**（一一对应、同号）；**四档一律写「第 N 档」**，
> 不用圈码；**两句判据不用编号**。
>
> **页数预算 21 张**（v10 起）：宁可加一张轻页，不要在一页上堆（讲法纪律第 9 条）。
>
