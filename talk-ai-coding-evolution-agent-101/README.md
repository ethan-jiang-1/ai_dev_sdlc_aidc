# talk-ai-coding-evolution-agent-101

**定位（2026-09-21 用户定）**：面向「**会用 AI 工具、但不写代码**」的人（产品 / 运营 / 设计 / 管理者）的普及场，
**20–30 min · 15 页正文 + 2 张停顿页 ≈ 27 min**。全场只追一个问题：

> **同一个模型，为什么在别人手里好用，在你手里糊涂？**

**核心命题只有一条**：

> ## `Agent = Model + Harness`
> **模型你只能选，选完大家都一样；差别在模型外面那一圈。**
> **那一圈搭对了，它跑起来就不糊涂。这门手艺叫 harness engineering。**

**这是一场独立成篇的 talk，不是任何其他场的删减版。** 它从 `talk-ai-coding-evolution-harness/` 与
`03_practice/harness_governance/` 取素材，但**换掉了组织原则**：

| | 母版（harness talk） | 本场 |
|---|---|---|
| 组织原则 | **时间轴**：这五年答案一层层往外挪 | **问题轴**：同一个模型，为什么在别人手里好用 |
| 听众前提 | 知道 prompt / context，做过团队交付 | 会用 AI 干活即可；**会不会写代码不影响用** |
| 失败面 | 追责链断在哪一步 | **五种症状**（学术底稿：MAST 的 14 种失败模式） |
| 概念量 | 五层工程 + 20 余个机制词 | **一条公式 + 五件事 + 四档** |

**为什么不能靠删页做出来**：母版的逻辑链是一条完整推导，砍任何一环就断；它的概念量是结构性的。
所以本场是**重新组织**，不是压缩。

## 一、核心结构（一句话版）

**五种症状**（听众先认领）→ 一一对应 **五件事**（那一圈要搭的）：

| # | 症状（听众的话） | 五件事 | 一句话判词 |
|---|---|---|---|
| ① | 它忘了你说过的话；拿到的是旧版本 | **让它看到该看的**（上下文） | 你以为它知道，其实它没看见 |
| ② | 它按通用套路干，不懂你的业务**还不问** | **让它懂你的业务**（隐性知识显性化） | 隐性知识不写出来，它就只能猜 |
| ③ | 它干不了；用了笨办法；**碰了不该碰的** | **让它有该有的能力**（工具与边界） | 给能力的时候，顺手把圈划上 |
| ④ | 它**反复绕圈**；跑偏；提前收工 | **让它按对的步骤走**（工作流） | 它不迷路，是因为你先把路画出来了 |
| ⑤ | 它说做完了其实没做完；**自己评自己总说好** | **让它能被验证**（传统代码把关）★ | **能让代码查的，别让 AI 自己说** |

**四档**只回答一件事——**这一圈是现成的，还是你自己搭**：
**① 你问一句它答一句 / ② 你定好步骤它照着走**（现成）→ **③ 你给个目标它自己跑 / ④ 你定好分工它们自己配合**（自己搭）。

**全场最重要的一页（P10）**：**AI 负责干，传统代码负责查**——代码每次跑的结果都一样，
所以能替 AI 把「对不对」这一步定死。**会不会写不影响用**（写不用听众写）。
