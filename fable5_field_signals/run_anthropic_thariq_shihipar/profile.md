# Thariq Shihipar

- 身份：Anthropic，Claude Code 工程师
- 角色定位：最系统地讲“怎么和 Fable 协作”的方法论人物之一
- 为什么值得单列：很多人讲 Fable 很强，Thariq 讲的是“你该如何不把这种强浪费掉”
- 核心贡献：提出 `map vs territory`、`unknowns`、`blindspot pass` 等一整套与强模型协作的方法论
- 最重要的判断：Fable 5 是第一个让“澄清未知项的能力”成为工作质量瓶颈的模型
- 目录现状：现在已经补进长文线索和 AI Engineer World's Fair 演讲笔记，不再只有人物卡

## 这人到底说了什么

- 他把 prompt、skill、上下文比作地图，把真实代码库和现实约束比作领地。
- 他认为模型出错，常常不是因为模型不够强，而是因为你没有先识别自己的 unknowns。
- 他给出了一套很实用的手法：盲区扫描、四个差异原型、反问、参考实现、实现笔记、测验。
- 他后续还补了 `capability overhang`、`砍掉 80% 系统提示词`、`多给上下文少给约束` 等关键判断。
- 这说明他不是只发过一条观点，而是在 2026 年围绕 Fable 5 持续输出同一套方法论。

## 最值得记住的句子

> “地图与疆域之间的差距，就是未知项。”

> “Fable 5 是第一个让澄清未知项的能力成为工作质量瓶颈的模型。”

> “多给上下文，少给约束。”

## 我的判断

- Thariq 的价值在于，他把“怎么用强模型”从零散技巧升级成了协作方法论。
- 如果你要把 Fable 的经验迁移给 Opus 或以后别的模型，最值得沉淀的就是他这一套。
- 在这批人物里，他最适合转译成 Skills、模板、工作流。
- 现在这条目录已经更像“方法论样本库”而不是单薄的人物名片了。
