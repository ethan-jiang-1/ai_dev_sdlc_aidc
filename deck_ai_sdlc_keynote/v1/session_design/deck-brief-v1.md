# Deck Brief v1: AI 时代的信息加工变革

## PART 0: OPENING

### S0.1: 开场

**L1 — META**
- VISUAL TYPE: Title Opener
- KICKER: THREE YEARS
- CLAIM: AI 正在从"帮人写代码"变成"帮人做一切信息加工的事"
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 时间压缩感——三年从补全一行代码到接管整个项目
- MUST NOT: 机器人、大脑、电路板等 AI 陈词滥调
- Bridge: 全场第一张。建立 speaker credibility，定调"这不是 hype，是真实加速度"

**L3 — IMAGE PROMPT**

一条水平时间轴从左到右：2024 → 2025 → 2026。三个时间节点上各有一个不同大小的光点——2024 的光点如烛火（"补全一行代码"），2025 的光点如灯泡（"写一个函数"），2026 的光点如太阳升起（"接管整个项目"）。光点越来越大、越来越亮。时间轴下方是极简的代码片段演化：一行补全 → 一个函数 → 整个项目结构。背景是深邃的灰蓝渐变，暗示"夜晚到黎明"的时间流逝感。整体构图干净、极简，没有人物，只有光和时间。标题区域留白给 Header-Lock。

**L4 — SPEAKER NOTE**

我在 AI 行业做了很多年。经历过很多次"AI 要改变世界"然后没改变的周期。

但这三年不一样。

2024 年，AI 能帮你补全一行代码。2025 年，AI 能帮你写一个函数。2026 年，AI 能接住整个项目——你自己去睡觉，它干一夜，早上起来东西好了。

这个加速度不是 hype。是真实发生了的。而且它不是只发生在编程——它在往所有"信息加工"的领域蔓延。办公室白领做的事——看文档、写邮件、填报表、走审批——AI 都开始能做了。

### S0.2: 为什么 AI 先颠覆了软件开发

**L1 — META**
- VISUAL TYPE: Concept Split
- KICKER: WHY SOFTWARE FIRST
- CLAIM: 软件的强逻辑性和海量训练数据让它成为 AI 第一个"学透"的领域，资本涌入加速了溢出
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 两个要素——逻辑性（编译器的即时反馈）+ 数据量（GitHub 的代码海洋）——构成 AI 的完美训练场
- MUST NOT: 过于技术化的图表，保持非技术观众能懂
- Bridge: 承接"三年变化"→ 解释为什么是编程先被颠覆

**L3 — IMAGE PROMPT**

Split 构图。左侧：一个简化的代码编辑器界面，AI 写的代码在屏幕上实时被编译器检查——绿色的勾（通过）像瀑布一样落下，极少数红色的叉（失败）立刻被修正。这个反馈循环用发光的环状箭头表示——"写→编译→修正→再编译"，速度快到环变成了一个连续的光圈。右侧：GitHub 的章鱼猫图标演化成数据海洋——无数微小的代码片段像雨滴一样汇入一个巨大的知识库。两边的共同终点是画面中央：一个正在加速的光点，标注"资本涌入 → 模型越训越强 → 溢出到其他领域"。配色：深蓝灰底，绿色（通过）和暖金色（突破）为主色调。

**L4 — SPEAKER NOTE**

为什么是编程先被颠覆？

两个原因。第一，代码有编译器。AI 写的对不对，编译器 0.1 秒就告诉你。这个反馈循环快到离谱——人类学编程要四年，AI 学编程可以一天跑几十万次试错。第二，GitHub 上有几十亿行代码。StackOverflow 上有几千万个问答。AI 有读不完的教材。

所以 AI 在编程上进步最快。进步快就吸引了资本。资本涌进来，模型越训越强。模型强了……就开始溢出。那些没那么有逻辑、但同样需要信息加工的领域——看文档、写报告、填报表——AI 也开始能做了。

### S0.3: 同一批工具，两种模式

**L1 — META**
- VISUAL TYPE: Evidence
- KICKER: ONE TOOL, TWO MODES
- CLAIM: Claude Code 和 Codex Desktop 不区分"编程工具"和"办公工具"——开发者和白领第一次共用同一套 Agent 基础设施
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 同一个界面分裂成两个场景——左边写代码，右边写报告。底层是同一个 Agent
- MUST NOT: 产品截图/logo——用概念化的视觉
- Bridge: 从"为什么软件先被颠覆"过渡到"这对你有什么关系"

**L3 — IMAGE PROMPT**

画面中央是一个发光的菱形核心（代表同一个 Agent 引擎）。从核心分出左右两条光路。左路通向一个深色终端风格的面板——代码、PR、测试覆盖率百分比在面板上流动。右路通向一个明亮的文档风格面板——邮件、表格、审批流在面板上流动。两边的界面风格不同（暗 vs 亮），但中间的核心是一样的。一个人物剪影站在左边（程序员），一个人物剪影站在右边（白领），两人看向同一个菱形核心。底部一行小字："上午写代码。下午写报告。同一个 Agent。" 构图对称、冷静、概念化。

**L4 — SPEAKER NOTE**

2026 年出现了一批强悍的 Agent 工具——Claude Code、Codex Desktop。它们有一个共同特点：不区分"编程工具"和"办公工具"。

同一个界面，上午你让它写代码、跑测试、提交 PR。下午你让它读邮件、写报告、分析表格。模式切换一下就行了。

工作方式完全一样：你给任务和上下文，它执行，你验收。

这意味着什么？软件开发者已经在这条路上跑了三年了。办公室白领才刚刚开始。软件开发行业是一个先行样本——今天讲的，你会发现跟你的行业一模一样。

**L3 — IMAGE PROMPT**

一条简洁的三段式路径从左到右。第一段标"1"，深蓝色，图标是一行代码被拆解（SDLC）。第二段标"2"，过渡到蓝绿色，图标是一条链连接办公楼和代码符号（BPM = SDLC）。第三段标"3"，暖金色，图标是一个金字塔正在变成平的网格（组织重构）。三段路径由一条连续的光线连接。背景是深灰，路径是唯一的光源。整体感觉像一张极简的地铁线路图——只有方向，没有废话。

第三，退一步看大局。AI 最根本的冲击不是技术——是生产力、沟通方式、组织结构。这三个东西变了，一切都要重来。

### S1.1: SDLC 被掀翻——每次都是参数调整，这次前提被挖了

**L1 — META**
- VISUAL TYPE: Framework
- KICKER: THE PREMISE IS GONE
- CLAIM: 瀑布、V 模型、敏捷都是同一个前提（人先想清楚）下的参数变体。AI 挖掉的是这个前提本身
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 三种方法论在同一地基上——地基裂了，三个都在晃
- MUST NOT: 三个方法论分开来讲，必须体现出"它们是同一栋楼"
- Bridge: 第一张内容 slide，为三条 storyline 搭台

**L3 — IMAGE PROMPT**

一座古典建筑（代表 SDLC）建在一块巨大的基石上。基石上刻着："人必须先想清楚"。建筑有三层——底层是瀑布（1970s），中层是 V 模型（1980s），顶层是敏捷（2001）。三个楼层用不同的建筑风格表示（古典→装饰艺术→现代），但都建在同一块基石上。现在，基石下方出现了一道发光的裂缝——裂缝里透出 AI 的光（暖金色）。裂缝标注："程序不再需要人完全想清楚"。建筑没有倒塌，但整个结构在微微倾斜。构图：正面视角，建筑居中，裂缝在底部。深蓝灰背景，裂缝的金光是唯一暖色。

**L4 — SPEAKER NOTE**

软件工程有一个管理复杂性的方法——SDLC。它演化了很多次。瀑布：想全部、拆全部、做全部、验全部。V 模型：每个阶段加验证。敏捷：想一点、做一点、验一点、再想。

看起来变化很大。但它们有一个共同前提从来没变过——人必须先想清楚。程序是确定性的，它不会自己"想"，所以人必须替它想。

瀑布和敏捷的区别，只是"想多少再做"的参数不同。本质上是同一件事的不同节奏。

AI 出现后，这个前提被挖了。程序不再需要人完全想清楚——AI 可以填中间。输出的正确性从"符合人的设计"变成"符合人的验收标准"。如果前提变了，整个 SDLC 大厦需要从地基重建。

### S1.2: 5 个月，从犹豫到确信 — Deer Valley → Engelberg

**L1 — META**
- VISUAL TYPE: Evidence
- KICKER: FROM MAYBE TO PRODUCTION
- CLAIM: Martin Fowler 召集的两次 retreat——5 个月内从"可能有点东西"变成了"所有人都在生产环境里做"
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 时间压缩——5 个月从犹豫到确信的速度感
- MUST NOT: 两个事件分开讲，必须是对比
- Bridge: 第一条 storyline，承接"前提被挖"，提供真实证据

**L3 — IMAGE PROMPT**

Split 构图。左侧：2026 年 2 月 Deer Valley。白雪覆盖的犹他山脉。篝火旁一群人在讨论，桌上散落着笔记。画面色调偏冷——蓝灰、未确定的朦胧感。文字标注："可能有点东西……但我们不确定是什么"。右侧：2026 年 7 月 Engelberg。瑞士的绿色山谷，同一个圈子的人。但这次他们面前是发光的屏幕——production dashboards，实时数据在流动。色调偏暖——金色的自信感。文字标注："不是 slides——是 production。" 中间一个巨大的箭头连接两边，标注"5 个月"。箭头的颜色从冷到暖渐变。

**L4 — SPEAKER NOTE**

这不是理论推演。有一群世界上最牛的软件工程大脑，用 5 个月亲身经历了一遍。

2026 年 2 月，犹他州 Deer Valley。25 年前同一片山上，17 个人写出了 Agile Manifesto。25 年后，Martin Fowler 把新一代最优秀的大脑召回来。没有宣言。只有一堆问题。"不确定性多于确定性。"但几个关键概念诞生了：Rigor Relocation——严苛没消失，从写代码迁移到了 spec 和测试。Supervisory Engineering——一个新工种，指挥 Agent、评估输出、校准信任。

5 个月后。瑞士 Engelberg。语气彻底变了。"Deer Valley 是犹豫。Engelberg 是自信——价值就在这里。""房间里所有人都在做。在生产环境里交付。不是 slides——是 production。"

问题从"是否"变成了"如何"。Harness Engineering——这个词在 Deer Valley 时根本不存在——在 Engelberg 成了核心议题。5 个月。从不确定到生产环境。这不是渐进改进——这是 disruption 的速度。

### S1.3: Beck + Fowler 同台 — Agile 的原班人马怎么说

**L1 — META**
- VISUAL TYPE: Evidence
- KICKER: THE ORIGINAL CREW SPEAKS
- CLAIM: AI 量级大于之前所有变革总和。TDD 不可协商。中层最危险。
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 两个老人（不是贬义——是权威感）在舞台上，说出的话比任何 hype 都有分量
- MUST NOT: 过于热闹的大会场景，聚焦在对话本身
- Bridge: 第二条 storyline，跟 Deer Valley 同一个月但视角不同

**L3 — IMAGE PROMPT**

温暖的舞台光。两个人物剪影面对面坐着——不是 PPT 演讲，是炉边对话。背景是大屏幕，上面不是 slide，是三个发光的关键词从上到下排列："MAGNITUDE > ALL PREVIOUS SHIFTS"、"TDD NON-NEGOTIABLE"、"MID-PACK AT RISK"。三个词像宣言一样挂在空中。舞台下方是观众席的模糊轮廓——暗示这是公开大会，不是闭门 retreat。色调：暖琥珀色舞台光 + 深蓝黑背景。构图：对话者在下半部，宣言在上半部。

**L4 — SPEAKER NOTE**

同一周，旧金山。Gergely Orosz 主办的首届 Pragmatic Summit。跟 Deer Valley 同一个月，但这是公开售票大会——有硬数据、有 CTO 圆桌。

Agile Manifesto 两个合著者——Kent Beck 和 Martin Fowler——25 年来第一次以 AI 为主题联合公开对话。

Fowler 开场："Nothing has hit with the magnitude of AI." Beck 补充：AI 的量级大于微处理器 + OOP + 互联网 + Agile 的总和。

但 Beck 最担心的是 Re-Soloing——一个人管 6 个 Agent 关起门来干活，跟真人 pair programming 不是一回事。他的方案：Two humans + one agent 可能好过 one human + six agents。

三个独立声音——Beck、Fowler、Willison——得出同一个结论：TDD 不可协商。不是"TDD 还重要"——是"没有 TDD，你根本驾驭不了 AI 产出的代码"。Tests are free now.

Laura Tacho 的 12 万开发者数据：AI 是放大器——好团队用 AI，incidents 降 50%；差团队用 AI，incidents 翻倍。

### S1.4: Fable 5 来了 — 瓶颈从机器变成了人

**L1 — META**
- VISUAL TYPE: Evidence
- KICKER: THE BOTTLENECK FLIPPED
- CLAIM: Fable 5 把人与 AI 的关系从"操作者→工具"变成了"委托人→执行者"。瓶颈第一次从机器变成了人
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 翻转——以前的瓶颈（机器不够聪明）变成了现在的瓶颈（人跟不上）
- MUST NOT: 机器人/人脸对峙的 cliché
- Bridge: 第三条 storyline。前面讲了"前提被挖"和"原班人马怎么说"，现在讲"具体是什么东西改变了关系"

**L3 — IMAGE PROMPT**

画面被一条水平线分为上下两半。上半是"以前"——色调暗沉。一个巨大的齿轮（代表"机器瓶颈"）卡在中间，人的剪影在齿轮后面等待。文字："瓶颈 = 机器不够聪明"。下半是"现在"——色调暖金。齿轮缩小成了背景里的一个小点，人的剪影被放大到前景，但人的轮廓里有问号和闪烁的光——代表"判断力跟不上"。文字："瓶颈 = 人能不能驾驭一个比自己聪明的东西"。中间那条分界线是一行代码演化成的光流。三个微型引语漂浮在画面中：Mollick "I no longer steer; I commission." Krieger "Teammate I can delegate to." Willison "Relentlessly proactive."

**L4 — SPEAKER NOTE**

2026 年 6 月，Fable 5 发布。一线开发者的反应不是"哇，好快"——是"我不知道我还是不是那个 wizard"。

Ethan Mollick："I no longer steer; I commission. The unnerving part was how little I did."

Mike Krieger——Instagram 联合创始人——说："I'll wish Claude a good night, set it off on a complex task, and wake up to find it's done."

Simon Willison："Claude Fable is relentlessly proactive." 它自己拼了一条截图工具链——你没给它这个工具，它现场做了一个。

Boris Cherny——Claude Code 创建者——说："Claude has stepped up from being a coding agent to a thought and design partner. It has judgment, taste, and dimensionality."

这些不是夸模型聪明。这些是在描述一种新的人机关系。Kieran Klaassen 把它叫 AI Sandwich——人设定任务 + 上下文，AI 自主执行，人 review 验收。Jesse Vincent 更极端："Specs are the thing that matters now. The code does not matter anymore."

最关键的变化：瓶颈从机器变成了人。以前瓶颈是机器不够聪明。现在瓶颈是你——能不能给出清晰的上下文、能不能发现 AI 产出里那些看起来正确但实际有问题的东西。

### S1.5: 软件开发本质是信息加工——现在加工的不是人了

**L1 — META**
- VISUAL TYPE: Concept Split
- KICKER: THE CHAIN
- CLAIM: AI 接管了信息加工链的中间环节后，人只有两个方向：往上游（做什么）或往下游（验收治理）
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: ITO 链——Input → Transformation → Output。以前每个 T 环节都是人，现在 AI 占了中间
- MUST NOT: 过于复杂的工作流图
- Bridge: 从"关系变了"过渡到"角色怎么重写"

**L3 — IMAGE PROMPT**

一条水平的信息加工链从左到右：需求 → 分析 → 设计 → 编码 → 测试 → 部署 → 产品。链条上的每个节点以前都有一个发光的人形剪影（代表人在做这个环节）。现在，中间的三个节点——设计、编码、测试——的人形剪影被替换成了 AI 光核（暖金色、几何形状）。AI 光核比原来的人形转得更快，发出脉冲。最左边的节点（需求、分析）和最右边的节点（部署、产品）仍然是人形——但人形的姿态变了：左边的人往上指（"决定做什么"），右边的人往下指（"验收做得对不对"）。两个箭头从中间的人形指向这两个方向："往上走——架构师、产品"，"往下走——Harness Engineer"。

**L4 — SPEAKER NOTE**

软件开发本质上就是把需求一步步加工成代码。

以前，这条链上每个环节都是人做的。一个程序员一天写几百行代码。一个 reviewer 逐行看 PR。

现在，AI 接管了中间的加工环节——编码、测试、甚至部分设计。那人往哪走？

两条路。往上走——定义做什么。什么需求值得做？tradeoff 怎么判断？系统架构怎么设计？往下走——验收和治理。验收标准怎么设？护栏怎么建？Agent 的判断什么时候能信任？

Simon Willison 说的最透："Build is cheap. Argument is expensive." 写代码变便宜了。真正贵的是判断。

### S1.6: 反馈周期炸了——人的信息吞吐是瓶颈

**L1 — META**
- VISUAL TYPE: Concept Split
- KICKER: TOO FAST TO REVIEW
- CLAIM: AI 时代的核心瓶颈不是"写不够快"，是"人审不过来"。反馈从人-paced 变成 AI-paced
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 速度差——AI 产出如瀑布，人 review 如吸管
- MUST NOT: 焦虑感画面——这是客观事实，不是恐慌
- Bridge: 从"加工链"过渡到"反馈速度"——链条加速了，但人的带宽没变

**L3 — IMAGE PROMPT**

Split 构图。左侧是一个巨大的漏斗，上方涌入密密麻麻的代码行、PR、测试结果——像瀑布一样倾泻（"AI 产出"）。漏斗的出口却极窄，只能一滴一滴流出（"人 review"）。右侧是 Martin Fowler 的引用以大字漂浮："Verified used to mean 'read by you.' Now it has to mean 'checked by tests, by type checkers, by automated gates, or by you where your judgment matters.'" 背景深色。AI 瀑布是冷蓝色，人 review 的出口是暖金色（暗示人的判断仍然稀缺和有价值）。构图强调比例失调——入口和出口的尺寸差至少 10:1。

**L4 — SPEAKER NOTE**

传统 SDLC 有一个设计前提：人的信息吞吐速度是恒定的。一天写几百行代码。review 一个 PR 花半小时。一个 sprint 两周——因为人需要这么多时间。

AI 把这个前提也炸了。Fable 5 一晚上写几千行代码。Jesse Vincent 的 agent 一晚上跑 25 个实验，录了假设，写了 backlog。

但人还是那个速度。

Martin Fowler 重新定义了 Verified 这个词——"以前 verified 的意思是'你读过了'。在 agent 时代，verified 必须意味着'被测试、类型检查器、自动门禁检查过——或者由你在判断关键的节点检查过'。"

反馈周期从人-paced 变成了 AI-paced。人跟不上——所以必须从一对一盯着的模式，变成一对多设护栏的模式。

### S1.7: 从 human-in-the-loop 到 human-on-the-loop

**L1 — META**
- VISUAL TYPE: Framework
- KICKER: ON THE LOOP
- CLAIM: 人不再逐个检查 AI 产出，而是建护栏让 AI 在框内自主。新工种诞生——Supervisory Engineer, Harness Engineer
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 两种模式的对比——in the loop（盯着每行）vs on the loop（建护栏）
- MUST NOT: 过于机械的流程图
- Bridge: 从"反馈周期炸了"过渡到解决方案——怎么应对

**L3 — IMAGE PROMPT**

上下对比构图。上半是"IN THE LOOP"——一个人坐在一串 AI agent 旁边，逐个检查每个 agent 的输出。视觉上像质检员站在流水线旁一个一个翻看产品。标注："不可扩展——agent 输出速度远超人类"。下半是"ON THE LOOP"——同一个人坐在中央控制台前，面前是一圈发光的护栏（像激光围栏）。多个 AI agent 在护栏内自主运行。人的手不在每个 agent 上——而是在控制台的参数旋钮上。标注："agent 产出不满意时，修的是 harness，不是 artifact —— Kief Morris"。底部出现三个新的职业标签，像名牌一样排列：Supervisory Engineer / Harness Engineer / Middle Loop。配色：上半偏暗红（瓶颈感），下半偏绿金（赋能感）。

**L4 — SPEAKER NOTE**

Kief Morris 提出了一个关键区分。In the loop——人逐个 review AI 产出的每一行。不可扩展，agent 输出远超人类。On the loop——人建立和维护护栏，AI 在框内自主运行。当 agent 产出不满意时，in the loop 的人修的是 artifact；on the loop 的人修的是 harness——lint rules、type checkers、CI 阻断脚本。

这催生了全新的工种。Supervisory Engineering——指挥 Agent、评估输出、校准信任。Harness Engineering——设计护栏和沙箱。

Ryan Lopopolo 在 OpenAI 做了一个极端实验：3 个工程师，5 个月，100 万行代码。零人手写。零人 review。人能这么干，是因为把 80% 的时间花在了建 harness 上。他说："Agents aren't hard. The Harness is hard."

**L2 — CONCEPT**

- Bridge: 从"角色重写"过渡到"组织冲击"

三个水平层次，像地层剖面。最上层——初级开发者。浅绿色，标注"意外安全"。视觉：一个年轻的人形剪影旁边有一个发光的 AI 导师剪影——AI 在教，人在学。标注"AI-native 一代，24/7 导师"。中间层——中层开发者。红色/警告色。视觉：一个人形剪影被上下两股力量挤压——上方是更聪明的人（资深），下方是更快的 AI。标注"技能被 AI 商品化，但还没积累足够的架构判断力"。最下层——资深开发者。金色。视觉：一个人形剪影站在控制台前，面前是多个 AI agent 的编排面板。标注"转型为 Harness Engineer、Agent 编排者。1/3 最初抵制的人动手后变成非常支持。" 右侧漂浮 Kent Beck 的引语："中层是我最担心的。"

并排两条信息加工链。上链标注"SDLC"：需求 → 分析 → 设计 → 编码 → 测试 → 产品。下链标注"BPM"：业务信息 → 汇总 → 分析 → 审批 → 执行 → 决策。两条链的结构完全对齐，用垂直虚线连接对应的节点。链条的背景是时间轴——上链从 1970s 到现在（瀑布→敏捷→AI-SDLC），下链从 1980s 到现在（泰勒→BPR→BPM→Agentic BPM）。两条时间轴在 2026 年交汇——同时被 AI 冲击。标注："不是类比——是学术和工业界双重验证的同构。" 构图对称、冷静、像教科书插图但更简洁。

### S2.2: Framed Autonomy — 人定边界，AI 在框内自主

**L1 — META**
- VISUAL TYPE: Framework
- KICKER: FRAMED AUTONOMY
- CLAIM: Framed Autonomy = AI Sandwich。人定义边界和验收标准，Agent 在框内自主执行。BPM 侧和 SDLC 侧在说同一件事
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 框（frame）的概念——不是牢笼，是边界。框内 AI 自由，框外人控制
- MUST NOT: 过于技术化的 BPMN 图
- Bridge: 从"BPM 存在"过渡到"BPM 的新范式是什么"

**L3 — IMAGE PROMPT**

画面中央是一个发光的几何框——不是牢笼，更像一个透明的力场。框内，多个 AI agent（光点）在自由移动、执行任务。框的边缘有清晰的边界——Operational Frame（实线，代表"必须按这个序列执行"）和 Normative Frame（虚线，代表"不能做的事情"）。一个人形剪影站在框外，手放在框的边界上——不是阻挡，是调节。旁边标注："人定义框。Agent 在框内自主。人在关键节点策展。" 底部并排两个标签，中间有等号：Framed Autonomy = AI Sandwich。右上角小字："Dagstuhl Seminar, 18 位作者, 2026"。色调：框是暖金色光，背景是深蓝灰。

**L4 — SPEAKER NOTE**

Dagstuhl 18 位作者的正式定义："确保流程感知和目标对齐的主要机制——通过对 Agent 的知识和目标施加限制来约束其自主性。"

两种框。Operational Frame——规定具体执行序列，比如 CI 管道 lint → test → build → deploy。对应 SDLC 的 CI/CD 管道。Normative Frame——规定允许和禁止的行为，比如编码规范、安全策略。对应 SDLC 的 coding standards。

已经在真实世界验证过了——德国能源网公司，meter-to-cash 流程。Frame Agent 生成约束，Operational Agent 在约束内自主执行。预定义规则下 99% 成功执行率。

BPM 侧叫 Framed Autonomy。SDLC 侧叫 AI Sandwich。同一个东西。人定义边界和验收标准，Agent 在框内自主。

- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 历史的重量——2000 年没变的组织逻辑，在 AI 面前松动了
- MUST NOT: 组织架构图的 cliché——用更概念化的方式呈现层级
- Bridge: Part 3 开场——从"两个领域的具体变化"拔高到"组织理论"

**L3 — IMAGE PROMPT**

画面中央是一个巨大的金字塔，但不是石头砌的——是人的剪影叠成的。每一层的人剪影姿态相同：手向上传递信息，手向下接收信息。他们都是"信息节点"。金字塔底部标注："罗马军团时代至今，2000 年。"画面右侧，一个 AI 光核出现在金字塔旁边。光核发出涟漪——每圈涟漪碰到金字塔，就有一层人的剪影开始变透明。旁注："AI 把沟通成本打到接近零 → 信息搬运工不再需要。" 最底部一行大字："Dunbar 数的管理版本——一个人能有效沟通的人数是有限的。所以需要层级。AI 不受这个限制。" 色调：金字塔是古老的石头灰褐，AI 光核是暖金色。

**L4 — SPEAKER NOTE**

为什么公司要有层级？为什么不是 CEO 直接管所有人？

因为人的沟通带宽有限。一个 manager 能直接有效沟通的人数大概 7 到 15 个人。所以必须分层——CEO、VP、Director、Manager、IC。每一层的作用是汇总信息、过滤噪音、上传下达。

这个结构不是因为"这样效率高"。是因为人是信息流动的瓶颈，所以必须用层级来管理带宽。

罗马军团时代就是这样了。2000 年了，没变过。

AI 打破了这个前提。当 Agent 可以自动汇总信息、跨层级同步上下文、把沟通从"人传人"变成"Agent 传 Agent"——中间层的信息中转功能开始变得多余。

### S3.2: 中层如果只做上传下达——没用了

**L1 — META**
- VISUAL TYPE: Evidence
- KICKER: MEASURERS, NOT BUILDERS
- CLAIM: Cloudflare 的 Builder/Seller/Measurer 框架——纯测量/报告/协调的岗位需要重新定义，不是裁掉，是从"做测量的人"变成"管理 AI 测量输出并决策的人"
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: Measurer 不是贬义词——是客观分类。关键不是裁掉他们，是重新设计工作
- MUST NOT: 裁员/失业的悲惨画面——重点是"重新定义"，不是"淘汰"
- Bridge: 从"为什么层级松动"到"具体哪些角色受影响"

**L3 — IMAGE PROMPT**

三列角色分类图。左列"Builders"——绿色，一个人形剪影站在产品/代码旁边。标注"创造产品的人 → AI 是他们的工具"。中列"Sellers"——蓝色，一个人形剪影面对客户。标注"获取客户的人 → 人际关系不可替代"。右列"Measurers"——琥珀色，一个人形剪影拿着一把尺子在量。标注"测量、报告、协调的人 → AI 可替代测量动作，但人需要变成 AI 测量输出的决策者"。右列有一个箭头指向新的形态——同一个人形剪影，但尺子变成了一个发光的 AI 助手在旁边做测量，人变成了审查 AI 报告、处理异常的角色。底部标注箭头变化："质检员 → AI 质检异常处理员。排产员 → AI 排产决策审查员。成本会计 → AI 成本分析决策者。"

**L4 — SPEAKER NOTE**

Cloudflare 的 Prince 提出了一个框架——Builder、Seller、Measurer 三分法。

Builder——创造产品的人。Seller——获取客户的人。Measurer——测量、报告、协调的人。

AI 对前两类是工具。对第三类——Measurer——是替代。因为测量、报告、分析、协调，正是 LLM 最核心的能力。

但关键不是裁掉 Measurer。是重新设计这些岗位。质检员不是被替代——是变成 AI 质检异常处理员。排产员不是被替代——是变成 AI 排产决策审查员。成本会计不是被替代——是变成 AI 成本分析决策者。

从"做测量的人"变成"管理 AI 测量输出并根据输出决策的人"。在中国尤其重要——法院已经裁定 AI 不能作为裁员的合法理由。但用 AI 工具提升员工的工作价值——这完全合法，也完全合理。

**L1 — META**
- VISUAL TYPE: Concept Split
- KICKER: CONVERGENCE
- CLAIM: SDLC 和 BPM 不再是"可以互相借鉴"——它们在同一个 Agent 基础设施上收敛
- IMAGE TYPE: normal

**L2 — CONCEPT**
- MUST communicate: 两条河汇成一条——不是交叉，是融合
- MUST NOT: 过于抽象的"融合"画面——需要具体的锚点（同一个工具界面）
- Bridge: 从"组织冲击"过渡到"最终结论"——这一切的终极意义

**L3 — IMAGE PROMPT**

两条发光的河流从画面左右两侧流过来。左侧河流标注"SDLC（软件）"，河水里漂浮着代码符号、PR、CI pipeline、Deer Valley→Engelberg 的时间线碎片。右侧河流标注"BPM（企业）"，河水里漂浮着 BPMN 符号、工单、审批流、Dagstuhl 论文碎片。两条河在画面中央汇合——汇合处是一个发光的 Agent 界面（终端风格 + 文档风格融合在一起）。汇合后的河流更宽、更亮，标注："同一个 Brief → Agent 执行 → 人验收 的工作模式"。底部一句话："这不是 future trend。这是 2026 年正在发生的事。" 色调：左侧蓝，右侧绿，汇合处金。

**L4 — SPEAKER NOTE**

回头看一遍。

软件开发经历了什么？SDLC 的前提被挖了。人的角色从操作者变成委托人。方法论转向 Harness Engineering。组织从中层密集转向极端扁平。

企业 BPM 经历了什么？完全一样。Framed Autonomy 等于 AI Sandwich。Agentic BPM 等于 Agentic SDLC。四层架构每一层都有精确映射。

而且，两边现在用同一套工具。Claude Code 上午写代码，下午写报告。飞书和钉钉的 CLI 化让 office 变成 Agent 的 terminal。

这不是"两个领域可以互相借鉴"。这是两个领域在同一个基础设施上收敛。SDLC 和 BPM 的边界正在消失——因为它们被吸进了同一个 Agent 工作模式。
