# v0.14 逐页 REVIEW 账本

> 对象：`../05_output/v0.14/AI-Native软件研发组织-SDLC转型-v0.14.pptx`
>
> 审查方式：以 v0.14 为唯一对象，核对 P1-P50 的页面职责、当前上屏文案、speaker notes、全尺寸渲染和全篇总览；重新运行 `slides_test.py`，无画布溢出。本账本只记录 REVIEW 结论，不把 v0.14 宣称为正式版。

## 总体判断

v0.14 已经具备完整故事线、稳定视觉母语和可交付的技术质量。下一版不应再做全局视觉重定调，也不需要改变 50 页容器。修改应集中在少量会影响可信度、现场理解或后续维护的页面。

- **可直接保留：39 页**。页面职责、主关系和视觉层级已经成立，只需在完整彩排中确认节奏。
- **观察：5 页**。页面本身成立，但需要目标听众或现场距离验证；未验证前不主动重做。
- **建议修改：6 页**。其中 4 页涉及可被误解为真实数据或未完成内容，2 页涉及术语入口或核心闭环表达。
- **技术 QA**：50 页渲染完整；`slides_test.py` 通过；未发现画布溢出。

## 优先级

### P0：进入下一候选版前必须处理

1. **P12 空表语义不清**：页面说“四个问题”，但当前只在“门禁”列出现“已填写 / 待补齐”，容易被看成未完成页面。应把它明确改成后续六阶段的阅读模板，四列同时给出填写提示，或只展示一条示范行。
2. **P16 的 68% / 32% 没有可见口径**：speaker notes 虽说明为 illustrative visual，但观众会自然把精确百分比当作实测数据。应移除数字、改成指标名称，或在页面上明确标注“示例数据”。
3. **P28 的 `PASS >= 95%` 像通用标准**：当前没有来源，也不应把某个固定阈值讲成所有团队的推荐值。改成“团队定义的合并阈值”或明确标作示例配置。
4. **P36 的 `1 sigma / 2 sigma / 3 sigma` 像规范建议**：这是一种说明分级授权的示例，不是通用运维标准。页面应加“示例分级策略”，或改成 `T1 / T2 / T3` 并让团队自行定义阈值。

### P1：建议随下一候选版处理

1. **P35 的闭环节点无标签**：左侧多个空圆点会被理解为占位符，削弱“事实 -> 诊断 -> intent -> 受控处置 -> 经验回写”的主关系。应补齐少量必要标签或简化为空间上更明确的一条闭环。
2. **P41 的 DSH 首次上屏未展开**：内部文档定义清楚，但首次听众只看到缩写。标题或副标题首次写作 `DSH（DeepSeek Harness）`，同时继续强调它只是参考实现。
3. **外部来源可移植性**：P3 的 Anthropic 观点应在 notes 中保存完整标题、作者、日期和公开 URL；Image 2 来源目前多为本机绝对路径，正式外发版应改成项目内相对资产标识或可移交的来源记录。

### P2：彩排后再决定

1. **P4 五层入口**：逻辑正确，但首次听众可能尚未建立“六阶段主轴 / 五层镜头”的区别。先通过口头桥接和彩排验证，不先删页或重画。
2. **P21 锁图标**：当前彩色锁形与全篇工程素描和原生图元体系略有差异，可在最后视觉精修时换成同源线性符号。
3. **P39 信息密度**：全尺寸可读，但现场距离下不应要求观众逐项阅读全部重复符号。彩排时按五层从上到下讲；若仍显拥挤，再加强逐层高亮，不拆页。
4. **P46 视觉强度较弱**：关系精确且可编辑，当前可保留。只有当 P41-P48 连续播放时明显掉节奏，才增强 Definition 的“稳定合同”视觉，而不是换成生成图。
5. **P50 可填写框**：这是有意设计的行动页。需要通过真实讲述验证观众能否在 30 秒内理解“从最慢交接开始”，不把留白误读为未完成。
