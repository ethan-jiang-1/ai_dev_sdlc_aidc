## 混合生产模型

- 每页先判断最需要讲清的是场景、关系、过程、对比还是证据，再在原生主体、生成主体和混合主体中选择。
- GPT Image 2 负责它擅长的整体表达：把图像、空间、材质、视觉隐喻和主体内嵌文字合成为丰富的图文主体。原生图元难以自然表达复杂定性关系时，优先比较 Image 2 方案。Packy 是当前主入口，MICU 是备用；服务入口验证见 [`experiments/imagegen-v0.8/`](./experiments/imagegen-v0.8/README.md)，当前成片资产见 v0.13/v0.14/v0.16 实验目录。
- PowerPoint 负责全篇统一的页面文案：主标题、副标题、眉题、强调句、页码和固定术语。生成资产必须为这些文字留下明确安全区。
- 主体内嵌文字可以承担局部解释，但必须逐字校对；工件顺序、门禁位置、责任归属、因果方向、数字、引用、日志和复杂拓扑保持可编辑。
- 当原生图元会变成框、箭头、卡片和标签堆积时，主动比较生成式图文主体；Image 2 不是“PowerPoint 实在做不了”之后的补救工具。
- Image 2 不设页数配额。逐页只按表达收益和精确关系要求选择实现；当前 32 页生成主体、18 页原生主体的清单见 `../CURRENT.md`。
- 生成资产默认透明或边缘匹配地无缝嵌入固定纸白画布；满版底图只作例外，任何图片矩形、残留底色或页间色差都不通过。
- 所有生成主体共享同一套「工程素描 + 编辑标注」Visual Master Language：石墨与技术墨线构成主体，珊瑚红、青绿和金黄只作克制批注；允许使用结构剖面、连续叙事和工件拼贴三种方言，不允许切换成 3D 物件语言。

## 为什么选这个方向

- **系统蓝图**对应内容性质：六阶段、工件链、控制面、运行边界和责任接口本来就是系统问题。
- **技术编辑**保证 Keynote 节奏：结论标题、大尺度信息层级、少量高价值文字，不做架构文档截图式堆砌。
- **克制而不官僚**：保留 CTO / 平台 / QA / 安全 / SRE 所需的可信度，但不落入咨询报告式卡片海洋和密集表格。
- **工程感而不赛博**：用真实工件、状态变化、路径与证据表达 AI-native，不借机器人、脑神经、霓虹代码或紫蓝渐变制造“AI 感”。

## 视觉语法

### 1. 基础画布

- 16:9，**50 页统一纸白或极浅冷灰底**，石墨黑为正文与结构线。
- 转折页和首尾呼应也不切换黑底；高对比改用大号石墨标题、局部深色控制块、线宽和留白建立。
- 不使用渐变、玻璃拟态、发光边缘、圆角卡片阵列或仪表盘式 UI。
- 留白服务于层级和现场可读性，不追求“极简到只剩一句话”。

### 2. 色彩职责

- **主色**：纸白 / 冷灰 / 石墨黑，提供稳定、可信的系统底座。
- **运行色**：青绿色，用于当前路径、反馈与正在流动的事实。
- **控制色**：朱红或珊瑚红，仅用于门禁、风险、阻断与不可绕过的边界。
- **工件色**：偏金黄，用于已提交工件、版本与证据。
- 六阶段用克制的阶段标记区分，颜色只作定位，不把每一章染成独立主题。
- 所有含义同时依赖文字、图形或线型，不只依赖颜色。

### 3. 三条贯穿视觉线

1. **SDLC 轨道**：规划 → 设计 → 构建 → 测试 → 发布 → 运维。早期呈现按人的速度运行的线性交接，P13 后闭合成反馈回路；后续页面只高亮当前阶段。
2. **工件链**：`intent → spec → plan → diff+tests → PR+review → incident`。工件以带版本与责任签名的“工程文档”出现，P39 再叠加身份、证据、审批与门禁。
3. **控制面**：圈住 / 拦住 / 看清。用边界、关卡和事实轨迹表达，不画成云平台产品架构总览。

这三条线需要保持同一套符号语义，不能每次出现都重新发明图形。

### 4. 四问符号

- **工件（Artifact）**：文档 / commit 形态，强调可交接、带版本。
- **门禁（Gate）**：垂直关卡或断点，强调执行、允许 / 询问 / 阻断。
- **责任人（Owner）**：明确签名或责任标记，避免泛化人物插画。
- **反馈（Feedback）**：回流箭头与度量，强调结果重新进入下一轮意图。

六个阶段收口页复用同一语法，但版面不做六张完全相同的模板页；稳定的是阅读路径，不是机械复制。

## 页面节奏

- **P1–P5 开场**：白底、高对比、低密度。P1 用生成式单线价值流剖面建立从产品意图到生产运维的全程暗线；不使用通用 AI 人物或抽象发光网络。
- **P6–P12 诊断**：以比较、容量失配和控制迁移为主；图形从线性、拥塞逐步过渡到四问框架。
- **P13–P38 六阶段**：浅底主场。每阶段使用“镜头页 → 机制页 → 四问收口”的节奏；真实工件片段、路径图、前后对比优先于装饰性图片。
- **P39–P48 控制面**：结构更精密、颜色更克制；展示合同、门禁、seam 和事件日志怎样支撑追溯与替换，不画成产品功能菜单。
- **P49–P50 收尾**：保持白底，以高对比大字与更少结构收束；P50 保留可现场思考和填写的四个位置，不以 Thank you 结束。

## 图像与图表策略

- 主要视觉来自**真实或仿真的软件工件片段**、少量原生 PowerPoint 结构图、路径与比较图。
- 每页先判断 GPT Image 2 是否能显著改善视觉主体、场景、材质、空间关系、视觉隐喻或整体构图；它不只用于封面，也不要求每页都生成。
- 生成图必须主动为文字层留出安全区。标题、副标题、kicker、callout 和其他面向听众的关键文字由 PowerPoint 统一渲染，保持字体、字号、位置、颜色和节奏一致。
- v0.9 的 P1 原生主体是视觉语言形成过程中的历史样片；P8 使用生成式图文主体与精确出口叠加的混合主体；P20 使用执行单元剖面与“圈住、拦住、看清”精确层叠加的混合主体；P42 保持原生主体。
- 当前 P1 与 P49 都由 Image 2 承担完整视觉主体：P1 建立可执行的软件价值流，P49 把“更多代码”经过工件、门禁、责任人与反馈转成“可靠运行”。包含精确拓扑、日志、数字和引用的页面仍以原生主体为基线。
- 不为每页强行配图。对这场 talk，可信的工件、门禁和证据本身就是视觉资产。
- 复杂关系图只有在比文字明显更容易理解时才使用；节点标签短，连接语义统一。
- 外部非平凡主张和外部视觉资产在 speaker notes 中保留 `[Sources]`。

## 明确不采用

- `-opc` 的 CLAWTIME / 航海隐喻：个人冒险感与本 talk 的跨职能控制系统性质不符。
- 传统咨询报告风：标题 + 四卡片 + 小字表格重复 50 页，会把演讲变成阅读材料。
- 黑底霓虹 / cyberpunk / terminal 风：会把主题误读成开发工具或 agent demo。
- 蓝紫 AI 渐变、机器人、脑神经、发光电路和通用团队 stock photo。
- 3D 玩具、黏土或塑料模型、实体纸模、微缩建筑、等距模型、棚拍柔光、景深和悬浮阴影。
- 六阶段六套独立视觉主题：会破坏“同一条价值流”的连续感。

## 制作路线

- 采用**自定义视觉方向，从零建立母版与布局系统**；不套现成模板，不混用 Codex Grid。
- v0.11 四张关键样片已通过，完整稿已迭代到 v0.16。当前只围绕 v0.16 做用户 REVIEW 与完整彩排；收到具体证据后再进入下一小版本。
- 每个新版本都逐页渲染，分别做文字 REVIEW 与视觉 REVIEW，并重新检查溢出、重叠、错误换行、连接线和来源问题。
