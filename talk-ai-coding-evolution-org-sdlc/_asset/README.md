# `_asset/` —— 表现设计方向（v0.8）

> **当前推荐已定：系统蓝图式技术编辑风（Systems Blueprint Editorial）。**
> 这是一场面向软件 SDLC 决策者的转型深度 talk，不是 AI 科普、产品发布、开发者工具演示或一般企业汇报。
> 视觉任务是让价值流、工件、gate、owner、feedback 与共享控制面变得可读、可比较、可追踪。

## 为什么选这个方向

- **系统蓝图**对应内容性质：六阶段、工件链、控制面、运行边界和责任接口本来就是系统问题。
- **技术编辑**保证 Keynote 节奏：结论标题、大尺度信息层级、少量高价值文字，不做架构文档截图式堆砌。
- **克制而不官僚**：保留 CTO / 平台 / QA / 安全 / SRE 所需的可信度，但不落入咨询报告式卡片海洋和密集表格。
- **工程感而不赛博**：用真实工件、状态变化、路径与证据表达 AI-native，不借机器人、脑神经、霓虹代码或紫蓝渐变制造“AI 感”。

## 视觉语法

### 1. 基础画布

- 16:9，纸白或极浅冷灰为主画布，石墨黑为正文与结构线。
- 深色只用于少量转折页和首尾呼应，不让 50 页整体变成黑底开发者大会。
- 不使用渐变、玻璃拟态、发光边缘、圆角卡片阵列或仪表盘式 UI。
- 留白服务于层级和现场可读性，不追求“极简到只剩一句话”。

### 2. 色彩职责

- **主色**：纸白 / 冷灰 / 石墨黑，提供稳定、可信的系统底座。
- **运行色**：青绿色，用于 active path、feedback 与正在流动的事实。
- **控制色**：朱红或珊瑚红，仅用于 gate、风险、阻断与不可绕过边界。
- **工件色**：偏金黄，用于 committed artifact、版本与证据。
- 六阶段用克制的阶段标记区分，颜色只作定位，不把每一章染成独立主题。
- 所有含义同时依赖文字、图形或线型，不只依赖颜色。

### 3. 三条贯穿视觉线

1. **SDLC 轨道**：Plan → Design → Build → Test → Deploy → Maintain。早期呈线性人速交接，P13 后闭合成 loop；后续页只高亮当前阶段。
2. **工件链**：`intent → spec → plan → diff+tests → PR+review → incident`。工件以带版本与 owner 的“工程文档”出现，P39 再叠加身份、证据、审批与 gate。
3. **控制面**：圈住 / 拦住 / 看清。用边界、关卡和事实轨迹表达，不画成云平台产品架构总览。

这三条线需要保持同一套符号语义，不能每次出现都重新发明图形。

### 4. 四问符号

- **Artifact**：文档 / commit 形态，强调可交接、带版本。
- **Gate**：垂直关卡或断点，强调执行、允许 / 询问 / 阻断。
- **Owner**：明确签名或责任标记，避免泛化人物插画。
- **Feedback**：回流箭头与度量，强调结果重新进入 intent。

六个阶段收口页复用同一语法，但版面不做六张完全相同的模板页；稳定的是阅读路径，不是机械复制。

## 页面节奏

- **P1–P5 开场**：高对比、低密度。P1 可使用一张全幅定制位图，表现“软件价值流从线性管道向受控闭环转变”；不使用通用 AI 人物或抽象发光网络。
- **P6–P12 诊断**：以比较、容量失配和控制迁移为主；图形从线性、拥塞逐步过渡到四问框架。
- **P13–P38 六阶段**：浅底主场。每阶段使用“镜头页 → 机制页 → 四问收口”的节奏；真实工件片段、路径图、前后对比优先于装饰性图片。
- **P39–P48 控制面**：结构更精密、颜色更克制；展示合同、gate、seam、事件日志如何支撑可追溯与替换，不画成产品功能菜单。
- **P49–P50 收尾**：回到高对比大字；P50 保留可现场思考和填写的四个位置，不以 Thank you 结束。

## 图像与图表策略

- 主要视觉来自**真实或仿真的软件工件片段**、少量原生 PowerPoint 结构图、路径与比较图。
- 只在 P1 或少数转折页使用生成式位图；一张图只承担一个概念，不重复复用。
- 不为每页强行配图。对这场 talk，可信的 artifact、gate 与 evidence 本身就是视觉资产。
- 复杂关系图只有在比文字明显更容易理解时才使用；节点标签短，连接语义统一。
- 外部非平凡主张和外部视觉资产在 speaker notes 中保留 `[Sources]`。

## 明确不采用

- `-opc` 的 CLAWTIME / 航海隐喻：个人冒险感与本 talk 的跨职能控制系统性质不符。
- 传统咨询报告风：标题 + 四卡片 + 小字表格重复 50 页，会把演讲变成阅读材料。
- 黑底霓虹 / cyberpunk / terminal 风：会把主题误读成开发工具或 agent demo。
- 蓝紫 AI 渐变、机器人、脑神经、发光电路和通用团队 stock photo。
- 六阶段六套独立视觉主题：会破坏“同一条价值流”的连续感。

## 制作路线

- 采用**自定义视觉方向，从零建立母版与布局系统**；不套现成模板，不混用 Codex Grid。
- 先完成生产事实稿，再建立 6–8 个可复用布局族与核心视觉母图，然后生产 50 页。
- 生产完成后逐页渲染，分别做文字 REVIEW 与视觉 REVIEW；修复所有溢出、重叠、错误换行、连接线和来源问题后交付。
