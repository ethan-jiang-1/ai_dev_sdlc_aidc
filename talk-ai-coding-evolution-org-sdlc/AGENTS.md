## 两阶段门禁

### A. 内容 REVIEW（已通过）

先回答「为什么讲、对谁讲、听完要发生什么改变」，再考虑「一页怎么长」。REVIEW 固定按以下顺序：

1. **沟通任务**：用一句话写清「听众应该理解 / 相信 / 决定 / 行动什么，因为什么」。
2. **核心命题**：一个中心结论，由 3–5 个必要主张支撑；所有术语、边界与因果口径一致。
3. **累进故事线**：每一幕回答上一幕留下的问题，同时产生下一幕的必要性；议程、素材目录不算故事线。
4. **论据与意义**：每个关键主张都有可追溯论据，并说清「它对这批听众意味着什么」；外部观点明确归属，未证实内容进 open questions。
5. **开场与收束**：开场建立值得听的张力，收束必须解开它，并把听众带到明确的组织决策或下一步。

**内容锁定标准**：上述五项在 `01_storyline/` 中均有明确、互不矛盾的答案；
核心主张在 `02_evidence/` 中均有来源或被标为待验证；从开场到收束可以用 5–8 分钟口述且无逻辑跳转。
未达标时继续改上游；50 页提供稳定边界，不代表页面职责已通过内容锁定。

### B. 表现设计与 PPTX 生产（当前阶段）

1. 先定每页的叙事职责和主要结论，再决定版式、图像、图表、节奏与动画。
2. 一页一个叙事任务；标题直接说结论，证据要与当页结论同屏咬合。
3. **先过中文编辑门**：页面结论、上屏文字、图中标签和讲稿都要按中文原生句法重写并通过朗读检查；英文只作必要术语或代码标识，不拿英文句法套中文词。
4. **视觉样片门已通过**：P1/P8/P20/P42 的历史验证过程保留在 `_asset/samples/v0.8–v0.11/`，用于解释视觉语言为何这样形成。当前不重新执行样片阶段；只有用户要求改变全局视觉语言时，才回到样片门重新验证。
5. 进入 PPT 规划或生产时必须启用 `presentations:Presentations` skill；采用本目录已定的自定义视觉方向，不套模板、不混用 Codex Grid。
6. **逐页选择主体实现**：按 `CONTEXT.md` 在原生主体、生成主体和混合主体中选择。Image 2 的采用只看表达收益；当原生图元会退化成框、箭头、卡片与标签堆积时，主动比较生成式图文主体，不按封面或普通页身份分配图片。
   先应用“图源分界”：纯文字、数字、表格、日志和少量精确关系页由 PowerPoint 直接呈现；一旦页面借助场景、对象、空间、材质或视觉隐喻来解释，就优先把完整主体交给 Image 2，不用 PowerPoint 基础图元假扮图像。
7. **页面文案保持统一**：主标题、副标题、眉题、强调句、页码和固定术语由 PowerPoint 文字层渲染；生成资产必须为这些页面文案预留明确安全区。
8. **主体内嵌文字允许承担局部解释**：Image 2 可以把标签、短语或一句简短说明与场景合成为丰富的图文主体，不把它降格为无字插画工具。连续段落由文字层承载；所有主体内嵌文字逐字核对，有错字、歧义、术语漂移或演示距离下不可读时，重新生成或改由文字层承载。
9. **有空间依赖时内生图文优先**：文字、引线、标注若会与生成主体覆盖、穿插、贴合或共同占位，由 Image 2 在同一次构图中处理；PowerPoint 不再往生成主体上补丁式盖字。PowerPoint 只在主体之外承载页面级标题、副标题、眉题、强调句、页码与固定术语。
10. **生成文字必须与 PPT 字体同源**：中文标签以 PowerPoint 的 `Hiragino Sans GB` 为视觉参照，英文以 `Helvetica Neue` 为参照；一级标签使用半粗无衬线，二级说明使用常规无衬线。素描感由图形线条承担，不用手写体、书法体、漫画体或每页不同的字体制造。
11. **精确关系保持可编辑**：工件顺序、门禁位置、责任归属、因果方向、数字、引用、graph、log 和关键论证使用 PowerPoint / Graphviz 可编辑结构。若这些关系必须落在生成主体内部，就不要再叠一层 PowerPoint；应重构页面主体边界，或让 Image 2 完成一体化表达并通过逐字、逐关系校对。
12. **生成资产无缝嵌入画布**：默认使用透明或边缘匹配的独立主体；只有确需覆盖整页时才使用底图。任何可察觉的矩形边界、残留底色或页间色差都必须修复。
13. **逐页完成标准**：能回答「为什么采用这种页面主体、Image 2 的表达收益是什么、页面文案与主体内嵌文字怎样分工、哪些关系必须保持精确、文字安全区在哪里」，并证明生成资产已无缝嵌入画布；答不清时不进入渲染。
14. 中文编辑门和视觉样片门都通过后，先建立 P1-P50 页面主体账本，逐页记录表达收益、主体实现、文字分工、精确关系与安全区；再按既定布局容器压缩 audience-facing 生产事实稿并进入完整 PPTX。Image 2 不设页数配额。
15. 每个外部非平凡主张和外部视觉资产都记录来源；PPTX 在 speaker notes 中保留 `[Sources]` 块。
16. 最终 PPTX 每页完整渲染并逐页检查；文字 REVIEW 与视觉 REVIEW 均通过后才交付。

表现阶段如果暴露了命题、证据或转场问题，立即退回内容 REVIEW，先修正上游源文件，再重做页面。

## 中文编辑门

这是一场中文演讲。中文负责叙述和推理，英文只负责标识确实需要保留的术语、产品名、文件名和代码。

1. **从意思出发重写**：先确定这句话要说清的判断，再用中文重新组织主语、动作和结果；不按英文原句逐词搬运。
2. **标题能直接讲出口**：标题优先使用完整判断或自然提问，避免名词连续堆叠、斜杠串词、箭头代替因果和机械的「从 X 到 Y」。
3. **术语中文先行**：阶段统一写「规划、设计、构建、测试、发布、运维」，首次需要时在括号中标 Plan / Design / Build / Test / Deploy / Maintain；正文统一使用「工件、门禁、责任人、反馈闭环」。
4. **保留必要英文**：`intent.md`、`spec.md`、`plan.md`、API、CI/CD、DSH、harness、hook、skill、runtime 等没有稳定等价词或承担精确机制含义的词可以保留；它们必须嵌入自然中文句子，不能充当中文谓语。
5. **一句只推进一个判断**：先给结论，再补条件、证据或例外；缩短多层定语和被动句，能用动词就不用抽象名词串。
6. **完成前朗读**：逐页朗读标题、上屏文字和关键转场。凡是需要倒回去才能读懂、像报告翻译稿、或离开英文词就说不清的句子，继续改写。

**通过标准**：P1-P50 的页面结论、上屏文字和图中标签逐页审过；同一术语全篇口径一致；任取一页都能由中文演讲者自然说出口，且不需要先在脑中还原英文原句。

## 规则

- **单一事实来源**：每个事实只写一处——主线在 `01_storyline/`，素材卡片在 `02_evidence/`。
- **术语单一来源**：本 talk 的局部词义只在 `CONTEXT.md` 定义；`AGENTS.md` 规定流程，其他文件消费这些词，不重复定义或悄悄改义。
- **故事线优先**：先通过内容锁定，再写 slide / 讲稿，最后做视觉与 PPTX。
- **素材只摘不搬**：从 `_reference/rawdata_*/` 摘进 `02_evidence/` 时标注来源路径。
- **rawdata 只读**：`_reference/` 下的上游 symlink 只在里面读，不在里面写。
- **对象红线**：对象是「软件 SDLC 上的跨职能研发与交付组织」，范围从产品意图、需求与设计，到 Build / Test / Deploy / Maintain。
  落点始终在 **软件价值流 / 工件链 / gate / owner / feedback / 平台治理 / 合规审计 / 规模化**。
  不滑回「个人技能进阶」的 `-opc` 叙事，也不外推到销售、市场、客服、财务、人力或一般企业组织设计。
- **独立红线**：不依赖、不承接 `04_output/deck_ai_sdlc_keynote`（听众不同）；不把「代码不再是瓶颈」讲成普适事实，标注是 Anthropic 论点。
- **责任红线**：共享的是沙箱、权限、工具准入、门禁、观测与审计基线；产品、架构、服务和政策 owner 继续掌握 intent、context、取舍与例外。不要把五层写成五个团队，也不要把「平台共同基线」写成「所有内容统一」。
- **视觉方向**：采用 `_asset/README.md` 的“系统蓝图式技术编辑风”，从零建立母版与布局系统；不用 `-opc` 的 CLAWTIME，不套咨询报告、黑底霓虹或通用 AI 模板。
- **生成视觉语言**：所有生成主体共享 `CONTEXT.md` 定义的「工程素描 + 编辑标注」Visual Master Language。石墨与技术墨线构成主体，少量构造线、擦除痕迹和剖面线保留推敲感；珊瑚红、青绿与金黄只作克制的彩色铅笔或淡墨批注。结构剖面、连续叙事和工件拼贴只是同一母语的方言。
- **生成视觉禁区**：不使用 3D 玩具、黏土或塑料材质、实体纸模、微缩建筑、等距模型、棚拍柔光、景深、悬浮阴影、复古插画和松散白板涂鸦。即使画面精致，只要产生独立的 3D 物件语言，也不通过视觉门禁。
- **画布红线**：50 页统一纸白/极浅冷灰底，不使用整页黑底章节或深浅交替；节奏由局部石墨结构块、标题尺度、线宽和留白建立。
- **画布衔接红线**：生成资产使用透明或边缘匹配方式无缝嵌入固定纸白画布；可察觉的图片矩形、残留底色和页间色差一律不通过。
- **视觉语义**：青绿只表示 active path / feedback，朱红只表示 gate / 风险，金黄只表示 committed artifact / 版本 / 证据；颜色必须同时配合线型、关卡或文档轮廓，不单独编码。
- **图文分层**：主动用 GPT Image 2 建立原生图元难以表达的丰富图文主体；页面文案由 PowerPoint 统一排版，主体内嵌文字可以生成但必须逐字核对，精确关系与关键论证保持可编辑。
- **图文覆盖红线**：只要主体内文字、引线或标注与图形存在 overlap 风险，就让 Image 2 统一构图；禁止在生成主体上用 PowerPoint 标签、引线和色块做补丁式覆盖。
- **生成字体红线**：主体内嵌文字必须与 PowerPoint 的中英文字体体系同源；生成提示词提供字体参考图，禁用手写批注、书法、漫画和装饰字体。
- **临时目录约定**：所有一次性产物（构建中间体、逐页 inspect、审稿草稿、模板试验）
  一律放在仓库根目录、以 `.tmp-org-sdlc-talk-` 前缀 + 主题命名；工具自动生成的随机名目录（`.ppt-build-*`、`.tmp-xxx.XXXX`）算同类，
  `.gitignore` 覆盖、永不入库。**版本收口时清理**：某一版 PPTX 落进 `05_output/` 并完成 review 后，对应 `.tmp-org-sdlc-talk-vN*` 及散落目录即删。
- **视觉版本约定**：内容锁后的视觉迭代沿用 `v0.x` 连续编号，按十进制小版本递增：`v0.8 → v0.9 → v0.10 → v0.11`。两位后缀不是把版本升为 `v1.0`；只有完整 50 页 PPTX 通过文字与视觉 REVIEW、被明确认定为首个正式发布版时，才允许使用 `v1.0`。
