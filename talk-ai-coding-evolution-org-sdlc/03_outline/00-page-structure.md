# Talk 页面结构（现场版 v0.7 · 固定 50 页 · 75–90 min）

> **A 档单场加长，50 页已锁定**。主轴是 SDLC 六阶段；五层用来观察控制深度，DSH 用作共享控制面的参考实现。
> 六个阶段始终回答四个问题：**留下什么工件 / 哪道门禁必须执行 / 谁作最后决定 / 结果怎样回到下一轮**。
> 每页 play 细则见 `../02_evidence/00-absorption-plan.md`。

## 开场（~6 min · P1–P5）

| 页 | 页面结论 | 引子 |
|---|---|---|
| P1 | 封面 | — |

## 第一幕：为什么整条 SDLC 要转型（~10 min · P6–P12）

| 页 | 页面结论 |
|---|---|
| P6 | 编码不再是主要约束之后，瓶颈、风险和治理成本会同时转移 |
| P7 | 传统 SDLC 的许多控制方式，都建立在“代码稀缺、主要由人执行”这个前提上 |
| P8 | 产出速度超过控制能力，结果不是排队，就是审查不足 |
| P9 | 机器执行可以重复判断的规则，人负责意图、风险、例外和授权 |
| P10 | 工件链只是审计骨架；身份、证据、审批和不可绕过的门禁缺一不可 |
| P11 | 六个阶段都要从“人盯流程”转向“工件交接、规则执行、责任明确” |
| P12 | 后面每个阶段都回答同样四问，五层只帮助判断控制做到了多深 |

## 第三幕：共享控制面 + DSH 参考实现（~20 min · P39–P48）

| 页 | 页面结论 |
|---|---|
| P39 | 工件链只有补齐身份、版本、证据、审批和强制门禁，才真正支持审计 |
| P40 | 机器负责可重复判断的规则，人负责结合语境作判断；两类决定都要留痕 |
| P41 | DSH 说明三项原则怎样进入运行时：知识外置、路径明确、反馈可执行 |
| P42 | 共享控制面必须同时说清“系统现在由什么组成”和“刚才实际做了什么” |
| P43 | 一个事实只认一个权威来源，也要记录为什么没有选择另一条路 |
| P44 | 正确路径应该最省力；不同层级的参与，各有入口、合同和检查范围 |
| P45 | 门禁只有经过负例反复验证，才值得信任 |
| P46 | 共享控制面统一能力合同，不强迫所有团队使用同一种后端 |
| P47 | 输入、工具结果和审批必须写入只追加日志，才能还原当时的事实 |
| P48 | 先让工件可读，再让门禁可信，最后才把反馈闭环自动运行起来 |

## 收尾（~6 min · P49–P50）

| 页 | 页面结论 |
|---|---|
| P49 | 带走一句：代码不再是瓶颈，流程才是 |
| P50 | 从最慢的一次交接开始：选一条价值流，补齐工件、门禁、责任人和反馈指标 |

## 叙事检查

1. P2 提出需要用自身数据验证的张力，P3 引入 Anthropic 诊断，P4–P5 只给深度镜头和共享控制面的必要性。
2. P6–P10 完成因果：瓶颈转移 → 旧控制失配 → 新控制方式 → 工件链只是审计骨架。
3. P12 建立全场四问；P13–P38 沿六阶段累计答案，P16/P19/P25/P29/P34/P38 分别收口。
4. P39 解开 P10 留下的条件，P40–P47 解释共享控制面如何工程化，P48 收成采用顺序。
5. P49 回答开场，P50 把论点变成一个可以在会后启动的试点选择。
