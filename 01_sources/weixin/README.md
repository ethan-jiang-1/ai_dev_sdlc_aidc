# 01_sources/weixin — 微信公众号原文归档

**定位**：公众号一手文章的**原文快照**。文章本身是二/三手信源，价值在于它是「当下外界怎么说」的原始记录；
本目录只做**忠实转录**，不做分析、不做摘要——消化产物放该文章所服务的下游（`02_research/`、
`03_practice/` 或某场 talk 的 `02_evidence/`）。

## 分法

每篇一个目录，命名 `raw_<slug>/`（slug 取厂商/主题的 ASCII 形式）：

```
raw_<slug>/
├── <slug>_<主题>.md     # 原文正文（**文件名用英文 + 下划线**），文首 YAML 交代来源
└── images/
    ├── 图N_<按原文图注拟定>.png     # 正文图
    └── _非正文/                     # 页首横幅、文末广告、编辑器装饰图标
```

**命名铁律**：

- **正文文件名用英文 + 下划线**（例：`aws_strands_harness_change_model_not_body.md`）——
  中文标题只留在 YAML 的 `title` 与本节表格里，**不让空格、全角标点、引号进路径**。
- 图片一律**按原文自己的图注序号与标题**命名（`图1_…`、`图2_…`），
  不保留 `img_01` 这类下载序号——下游引用时能直接和原文对上。

## 转录纪律

- 正文文字**不作改写**；只做结构还原：表格还原为 Markdown 表、文中小标题提级、修断行与合并被拆散的粗体。
- **非正文元素不入正文**：页首「星标引导」横幅、文末广告海报、编辑器装饰图标移入 `images/_非正文/`；
  「往期推荐」链接列表与公众号页脚模板不收录。每篇文末以「抓取说明」交代取舍，保证没有静默丢失。
- 文首 YAML 必须写全 `source_url / source_account / published / captured`——**抓取日期是这条信源的保质期**。
- 微信正文 HTML 用移动端 UA 抓取（桌面 UA 会撞验证码），源码在 `js_content` 容器内。
