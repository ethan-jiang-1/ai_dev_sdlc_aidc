# Simon Willison — "整个 SDLC 是围绕'一天几百行'设计的"

> Django 联合创始人，25 年行业经验。Simon Willison 是 AI 编码时代被引用最多的独立 KOL 之一。他不是 AI 公司员工，不卖 AI 产品——所以他的观点被广泛认为中立可信。

---

## 2025 年 11 月的拐点

Willison 指出了一个精确的时间点：GPT-5.1 和 Claude Opus 4.5 发布时，AI 编码跨过了关键门槛。

> *"Before November 2025, code generated by AI mostly worked but you had to pay very close attention. Afterward, almost all of the time it does what you told it to do — which makes all the difference in the world."*

他现在估计 **~95% 的代码是 AI 生成的**，不是手动敲的。

## SDLC 瓶颈迁移 — Willison 最具影响力的洞察

> *"If you can go from producing 200 lines of code a day to 2,000 lines of code a day, what else breaks? The entire software development lifecycle was designed around the idea that it takes a day to produce a few hundred lines of code. And now it doesn't."*

这个洞察之所以有力，是因为它把问题从"AI 代码质量好不好"转移到了**"整个流程是否匹配新的吞吐量"**。

### 上游影响

引用 Anthropic 设计负责人 Jenny Wen：
- 设计流程之所以存在，是因为"建了 3 个月后才发现建错了"是灾难性的
- 如果构建只需几小时而非几个月，风险计算就变了
- **迭代便宜时，prototype-validate 优于 spec-and-pray**

Willison 现在可以为一个功能 prototype **三种不同的 UI 方案**，因为"一个 UI 原型现在是免费的"。

### 新的质量信号

传统质量信号（commits 多、tests 全、README 好）已经**无意义**——AI 30 分钟就能全搞出来。

Willison 的新质量指标：

> *"Has someone actually used this thing daily for two weeks?"*

一个被每天用了两周的 vibe-coded 工具，比一个文档完美但从未被实战测试的仓库更值得信赖。**使用量是新质量信号。**

## Vibe Coding vs Agentic Engineering — 以及它们在趋同

Willison 最初画了一条清晰的线：

| Vibe Coding | Agentic Engineering |
|-------------|-------------------|
| 不看代码 | 专业的生产级工作 |
| "能用就行，不行告诉它" | 利用 25 年工程经验 |
| 个人工具 OK | 对用户、安全、运营负责 |
| 非程序员可做 | 需要深度专业判断 |

但在 2026 年 5 月的博文 *"Vibe coding and agentic engineering are getting closer than I'd like"* 中，他承认这两者在自己的实践中正在**趋同**——他已经停止审查 Agent 生成代码的每一行，即使是生产系统。

他称之为 **"the normalization of deviance"（偏差正常化）**，并感到真实的内疚。

这也许是关于 AI 时代最诚实的工程师自白。

---

## 并行 Agent 生活方式

Willison 描述了一种新的工作模式：

> *"I can fire up four agents in parallel and have them work on four different problems."*

但这带来了新的认知负担和倦怠：

> *"And by like 11 AM, I am wiped out for the day."*

他描述了上瘾般的行为模式：
- 熬夜"启动更多 Agent"
- 凌晨 4 点醒来检查结果
- "学会新的个人极限"成为了新的专业技能

---

## 黑暗工厂 (Dark Factory) 与"没人读代码"

Willison 讨论了 StrongDM 的"黑暗工厂"实验：
- 规则 1：没人**写**代码（已经可行——他自己 ~95% AI 生成）
- 规则 2：没人**读**代码（StrongDM 的新实践）

他类比：就像你不会在使用另一个团队的内部服务之前读它的每一行代码——他现在把 Agent 输出当做**半黑盒**，信任它直到它坏掉。

> *"It used to be if you found a GitHub repository with a hundred commits and a good readme and automated tests... you could be pretty sure that person put care into that project. Now I can knock that out in half an hour."*

---

## 职业生涯影响：中层在危险区

引用 ThoughtWorks 工程领导 offsite 的观察：

- AI 放大 **资深工程师**（经验 + AI = 巨大杠杆）
- AI 帮助 **初级工程师**（onboarding、学习、更快上手）
- **中层工程师**风险最高——经验足够昂贵但不够资深成为编排者

他的建议：

> *"Lean into this stuff. The only universal skill is being able to roll with the changes. The term that comes up most is agency."*

---

## Agentic 循环模型

Willison 提倡结构化的 agentic 工程循环而非一次性 prompt：

```
Analyze → Plan → Implement → Test → Review → Iterate
```

开发者的工作从"写代码"转变为**设计闭环**——让 Agent 自主推理、测试和完善输出。
