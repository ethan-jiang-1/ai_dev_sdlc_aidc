## 两场活动的关联观察（作者分析，非官方联合声明）

⚠️ **注意**：以下为作者基于两个独立活动材料的**对比分析**，并非两个活动组织者的联合声明。Pragmatic Summit（旧金山，Gergely Orosz 主办，公开售票大会）和 Deer Valley Retreat（犹他，ThoughtWorks 主办，闭门邀请 retreat）——虽同期举行且有关键人物重叠——但格式、受众、规则不同。以下关联为作者观察：

Pragmatic Summit 和 Deer Valley Retreat 的材料中出现了四个可对比的方向：

1. **"严苛去哪儿了？"** — 代码生成变便宜了，判断必须更严格。这是两场活动共同的底层焦虑
2. **"Supervisory Engineering"** — 一个新工种在浮现：指挥 Agent、评估输出、校准信任、编码标准
3. **Agent Experience = Developer Experience** — 对 Agent 好的实践（模块化、命名、文档）也对人好。不是二选一
4. **"不是 Agile Manifesto 2.0"** — Fowler 明确否定了这个说法。但这不意味着什么都没变——他在重新召集同一个圈子，在同一片山，问不同的问题

## 从 2001 到 2026 的对比

| | Agile Manifesto (2001) | Pragmatic Summit + Deer Valley (2026) |
|---|---|---|
| 地点 | Snowbird, Utah | Deer Valley, Utah (同一片山) |
| 召集人 | 17 位独立方法学家 | Martin Fowler + Gergely Orosz |
| 成果 | 4 条价值观 + 12 条原则 | 没有宣言——只有一堆问题 |
| 核心焦虑 | 流程太重，人在流程中消失了 | Agent 太快，人的判断跟不上 |
