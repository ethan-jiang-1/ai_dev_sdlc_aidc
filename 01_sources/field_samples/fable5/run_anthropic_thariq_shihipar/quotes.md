# Thariq Shihipar：洞察摘录

## 关键言辞

> “地图与疆域之间的差距，就是『未知项』。”

- 这是 Thariq 最值得长期保留的一句话。
- 它把 prompt 和真实工作之间的缝隙直接命名了出来。

> “Fable 5 是第一个让『澄清未知项的能力』成为工作质量瓶颈的模型。”

- 这句话非常关键。
- 它把瓶颈从“模型能力”移到了“人的澄清能力”。

> “减少并提前规划未知项，就是智能体式编程的核心能力。”

- 这句适合和上一句一起看。
- 前一句在定义瓶颈转移，这一句在定义新的核心能力。

> “减少并提前规划未知项，就是智能体式编程的核心能力。”

- 这不是抽象观点，而是具体工作方法的总纲。

## 具体方法

> “blindspot pass”

- 动手前先让模型通读相关代码，帮你找 `unknown unknowns`。
- 这招特别适合复杂项目的前置扫描。

> “请一次只问我一个问题，围绕任何存在歧义的地方采访我。”

- 这是把模型从执行器切成 interviewer。
- 目的不是快写代码，而是逼出你脑中没写出来的约束。

> “用假数据做 4 种风格差异很大的设计方向，我先反馈，你再去动真实代码。”

- 这句体现出一个非常强的理念：先用低成本原型发现自己的偏好，再进入高成本实现。

## 演讲补充

> “Capability overhang” / “能力悬余”

- 模型早已有一些能力，只是接口和使用方式还没把它释放出来。

> “Claude Code 最近一个关键变化是砍掉了 80% 的系统提示词。”

- 这说明强模型时代，过度约束可能比无约束更糟。

> “多给上下文，少给约束；告诉它情况，不告诉它不许做什么。”

- 这句很适合直接进你的总方法论层。

> “Be unreasonable.”

- 这句是他在演讲里给出的态度层建议。
- 不是鼓励鲁莽，而是提醒你不要过早接受旧时代的默认边界。
