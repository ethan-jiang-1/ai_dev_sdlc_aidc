## 这篇材料在讲什么

这是 Thariq Shihipar 围绕 Fable 5 的核心长文，主题不是“Fable 5 很强”，而是当模型已经强到足以长时间自主推进任务时，人和模型之间真正的瓶颈会转移到哪里。

他的答案是：瓶颈不再主要是模型能力，而是你能否提前识别并澄清 `unknowns`。

## 核心框架

### 地图与疆域

- 地图：你的提示词、skills、上下文，也就是你交给 Claude 的表征
- 疆域：真正发生工作的地方，例如代码库、现实世界约束、已有系统边界

核心判断：

> 地图与疆域之间的差距，就是未知项。

> Fable 是第一个让我明显感觉到工作质量的瓶颈，取决于我澄清其未知项能力的模型。

### 四类未知项

- 已知的已知：已经写进提示词的部分
- 已知的未知：你知道自己还没搞清楚的部分
- 未知的已知：你觉得理所当然、不会写下，但看到就认得出来的部分
- 未知的未知：你根本没想到、也不知道自己没想到的部分

核心判断：

> 减少并提前规划未知项，就是智能体式编程的核心能力。

## 实现前的方法

### 1. Blindspot Pass

在进入一个陌生模块、陌生任务或陌生领域前，先让 Claude 帮你找 `unknown unknowns`。

代表性提示词：

- “我正在添加一个新的身份认证提供方，但我对这个代码库里的认证模块一无所知。你能不能做一次 blindspot pass，帮我找出相关的 unknown unknowns，并帮助我更好地给你写提示词？”

### 2. 头脑风暴与原型

当你只有模糊偏好、但看见东西才知道自己要什么时，先要求 Claude 产出多个方向，而不是直接实现。

代表性提示词：

- “我想为这组数据做一个仪表盘，但我没有什么视觉品味，也不知道可以做到什么程度。帮我做一个 HTML 页面，给出 4 种风格差异很大的设计方向，好让我根据结果做反馈。”

### 3. 反问

让 Claude 采访你，一次一个问题，逼出你脑子里那些知道但没写下来的约束。

代表性提示词：

- “请一次只问我一个问题，围绕任何存在歧义的地方采访我。优先提出那些我的回答会改变架构设计的问题。”

### 4. 参考资料

当你描述不清楚时，直接给代码、库或现成模块做“参考地图”。

代表性提示词：

- “vendor/rate-limiter 里的这个 Rust crate 实现的正是我想要的回退重试行为。请阅读它，并在我们的 TypeScript API 客户端中重新实现相同的语义。”

### 5. 实现计划

在真正执行前，让 Claude 先给出计划，并优先暴露最容易变动的高杠杆决策点。

## 实现中与实现后

### Implementation Notes

Thariq 建议要求 Claude 在长任务里维护一个 `implementation-notes.md`，记录边界情况和偏离计划的原因。

### 推介 / 解释文档

他强调最后不只是要有代码，还要有帮助评审者理解变更的工件。

### Quiz

他还建议让 Claude 反过来考你，确认你真理解了这次变更，然后再合并代码。

## Fable 发布视频案例

Thariq 说 Fable 的发布视频也是按这套方法做出来的：

- 先问 Claude 转录和剪辑能否可靠完成
- 再用 Remotion 做原型验证
- 最后在调色这种自己不熟的领域，不是盲目要版本，而是先让 Claude 教自己理解未知项
