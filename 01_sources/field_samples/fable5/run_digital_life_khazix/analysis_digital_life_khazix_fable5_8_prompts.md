# 数字生命卡兹克《Fable 5 下线前必跑的 8 个 Prompt》解读

## 背景

Fable 5 即将从订阅计划下线，转为 API 按 token 计费。卡尔在最后 48 小时窗口期内，系统梳理了中英文圈十几篇实战帖，提炼出 8 个高价值提示语模板。

## 核心框架：两类真正值得做的事

卡尔把 Fable 5 窗口期所有用法收敛为两个大类：

| 类别 | 逻辑 | 典型场景 |
|------|------|----------|
| **自主实验** | 你睡觉，它干活，醒来看报告 | 成本优化、性能调优、大规模 A/B |
| **研究你自己** | 把你的工作模式变成可复用系统 | 迁移到 Opus/API 后依然有 90% 体验 |

---

## 逐一拆解 8 个 Prompt

### 1. /goal 目标提示语（第一类·自主实验）

**来源**：Jesse Vincent（Superpowers 作者）实战验证

**核心结构**（Karpathy 三要素）：

```
目标（Objective） → 要什么结果
指标（Metric）   → 怎么判断做完了
边界（Boundaries）→ 什么东西不能碰
```

**关键差异化设计**：
- 每次实验**先写假设**再跑
- **失败路线完整记录**，不丢弃
- 中途发现测量错误**当场修正继续**，不停机等待人类

**实战数据**：$165 → 构建速度 +50%，token 开销 -60%，全程无人介入，Fable 5 自主发现并修正了 3 个测量 bug。

**三个反直觉的失败实验（省钱反而更贵）**：

| 做法 | 预期 | 实际结果 |
|------|------|----------|
| 限制思考字数上限 | 省 token | 车轱辘话来回说，92 轮变 138 轮，输出翻倍 |
| Sonnet 写计划 → Fable 执行 | 省钱 | Sonnet 的思路不是 Fable 的思路，任务结构全乱 |
| 给测试计划设字数预算 | 合理约束 | 测试内容削减 62%，等于删掉一半实验 |

> **关键洞察**：失败实验比成功的更值钱——新项目上不用再花钱重踩一遍坑。

---

### 2. 工作模式提示语（第二类·研究你自己）

**用途**：让 Fable 5 遍历你的全部历史对话，输出一套**可直接使用**的系统（不是报告，是可执行的 Skill）。

**六个核心问题**：
1. 我最常用 Claude 做什么？
2. 哪些任务我总是重复做？
3. 哪些指令我总是手动重写？
4. 哪些工作流应该变成可复用 Skill？
5. 过去哪些方法和思路是错的？
6. Opus 应该知道什么才能给我 90% 的 Fable 5 体验？

**输出物**：Claude Skills + 使用指南 + 工作流模板 + 给 Opus 的系统指令

> **关键洞察**：这是卡尔认为整个窗口期 ROI 最高的 30 分钟。模型会换、会下架、号会被封，但工作模式和错题本不会消失。

---

### 3. 行动规范提示语（给 Subagent 的行为准则）

**来源**：hiromi maeo 从 Anthropic Fable 5 文档反向提炼

**五条铁律**：

| 规范 | 含义 |
|------|------|
| **结论先行** | 第一句话就说发生了什么 |
| **立即行动** | 信息够了就动手，不重新推导已确定的事实 |
| **实证汇报** | 用工具结果交叉验证，没验证就说没验证 |
| **最小范围** | 不做要求以外的功能，不防御不可能发生的场景 |
| **说到做到** | 不说完"这就去做"就停下 |

**使用场景**：贴在每个 subagent 提示语末尾。Fable 5 拆任务时派出的小弟（Opus/Sonnet）不够聪明，需要明确的行为规范约束。

> **关键洞察**：Subagent 是 Fable 5 能力的关键杠杆，但不加约束时，便宜模型会磨蹭、重复劳动、甚至摸鱼。

---

### 4. Subagent 分配提示语（模型路由策略）

**核心逻辑**：让 Fable 5 自己判断什么任务下放给便宜模型，什么留给自己。

```
小任务 → 便宜模型（Sonnet/Codex）
重任务 → Fable 5 全力
```

**延伸实践**：
- 卡尔的开源"搭子 Skill"：在出计划阶段分配哪个阶段用哪个 Agent
- 更极端：所有执行走 Codex subagent，Fable 5 只负责出计划和头脑风暴

> **关键洞察**：API 计费后，多 Agent 分配打法大概率变成主流。这是一种提前适应。

---

### 5. Loop 提示语（自动化工作流）

**来源**：Machina，固化了 25 个可直接用的 loop 工作流

**每个 Loop 的标准结构**：

| 要素 | 作用 |
|------|------|
| 排期表 | 什么时候醒来跑 |
| 状态文件 | 记录做了什么、下一步是什么 |
| 停止条件 | 轮次上限 + 完成/堵住的定义 |

**三色风险标签**：
- 🟢 绿色：完全自动跑
- 🟡 黄色：需人类审批才能发出
- 🔴 红色：涉及生产环境或外发消息，不能无人自动跑

**最有价值的 Loop：Shadow Prompt Loop（影子提示语 A/B 测试）**

```
/loop daily, on real traffic

1. 从真实流量抽 N 条代表性请求（边缘 case + 高频各半）
2. baseline 和 candidate 各跑一遍
3. 只记录有分歧的 case
4. 标注哪个更好、为什么
5. 积累 50 个有效分歧 → 生成"是否切换"推荐报告
```

> **关键洞察**：状态文件是让每次运行比上一次更聪明的关键——模型每轮开始前先读自己上一轮的历史，永远不会重做已完成的工作。

---

### 6. 自治运行 + 自动暂停提示语

**用途**：让 Fable 5 长时间自主运行，只在真正需要时暂停。

**暂停条件（三个）**：
1. 破坏性或不可逆操作
2. 真正的范围变更
3. 只有用户才能提供的信息

**其他情况**：继续推进，完成后汇报。

> **关键洞察**：实测比 auto mode 更少打扰用户，因为排除了大量"可以做但不需要确认"的伪阻断点。

---

### 7. 记忆更新提示语

**用途**：Hook 触发（说"记一下"），持久化学习经验。

**只记录两类东西**：
1. 被纠正过、下次不能再犯的点（错题本）
2. 已验证有效、以后可以复用的方法（武器库）

**规则**：
- 每条记录写清楚为什么重要
- 不重复仓库/文档/聊天记录已有的信息
- 相似记录更新而非新建
- 发现错误就删除或标记废弃

> **关键洞察**：卡尔多次被封号，每次回来都是一片空白。这个 hook 保留了"前世记忆"，让每个新号至少从错题本开始。

---

### 8. 反向面试提示语

**用途**：写需求文档阶段，让 Fable 5 反向问你问题。

```
问我问题，直到你有 95% 的把握可以完成这件任务
```

**搭配 /goal 模板使用**：问清楚 → 开 Plan 模式 → 按 goal 结构化写法出初版。

---

## 贯穿全文的三条金线

### 1. 最好的模型是最便宜的实现路径

Jesse 的实验反复验证了这一点——试图用限制 Fable 5 来省钱，结果全部适得其反。省 token 的正确方式不是约束模型，而是让最好的模型做它最擅长的事。

### 2. 自动化一切重复 ≥3 次的事

引用 Claude Code 工程总监 Fiona Fung：团队已经把"能不能自动化"变成了肌肉记忆。三遍以上的重复性工作，想尽一切办法让 AI 自动化。

### 3. 沉淀比模型更持久

模型会换、会下架、号会被封，但**工作模式、错题本、对话记忆**不会消失。用 Fable 5 把这些沉淀成 Skill 和系统指令，是窗口期 ROI 最高的投资。

---

## 一句话总结

> 趁 Fable 5 还在，让它研究你、跑实验、把你自己变成一套可迁移的 Skill 系统。这些沉淀不会跟着模型一起下线。
