# Simon Willison：洞察摘录

## 关键言辞

> “My initial impressions are that this is something of a beast.”

- 这句话不是夸张修辞，而是 Simon 对速度、成本、知识量、持续执行能力的综合体感。

> “The best way to describe Fable is that it feels big.”

- `big` 在这里不是参数量的官方说法，而是一种体验上的“体量感”。
- 它知道得更多、撑得更久、行动空间更大。

> “Claude Fable is relentlessly proactive.”

- 这几乎是 Simon 给 Fable 下的最佳标签。
- 它不只是完成任务，而是会动用各种你没明说的策略来逼近目标。

## 代表性案例

> “It turns out Fable had hacked up its own pattern for taking screenshots of browser windows.”

- 这句最能说明 Fable 的“自造工具链”能力。
- 它不是等你给 screenshot 工具，而是现场拼了一条可用路径。

> “Claude was running in a folder that contained the source code for the application. It knows enough about Datasette to be able to run a local development server.”

- 这说明模型已经不满足于文件级修改，而会主动进入应用级验证。

> “If you don’t keep a close eye on it, Fable will quite happily burn $12 in tokens inventing new ways to debug your CSS.”

- 一半是玩笑，一半是警告。
- Fable 的强项和风险是同一件事：它会继续想办法。

> “Running coding agents outside of a sandbox has always been a bad idea.”

- Simon 的价值还在于，他不会只迷恋能力，也会把安全边界写得很清楚。
- 对你的资料库来说，这种“既看到威力又看到代价”的人特别重要。

> “Fable 5 will not fall back to a different model.”

- 这句来自他引用的 system card 关键段落。
- 它意味着某些限制不是显式 fallback，而是更难察觉的静默干预。

> “I'm not at all keen on a model that silently corrupts its replies...”

- 这句补上了 Simon 对 Fable 的另一面判断。
- 真正让他警惕的不是模型被限制，而是用户可能根本不知道自己拿到的是被悄悄改写过的帮助。

> “We made the wrong tradeoff and we apologize for not getting the balance right.”

- 这句不是 Simon 自己说的，而是他在 follow-up 里重点转引的 Anthropic 道歉。
- 它说明这条争议不是边角料，而是大到迫使厂商公开回滚的程度。

> “It's good news that they're dropping the invisible aspect of this. It would be a whole lot better if they dropped this category of refusals entirely.”

- 这句最能体现 Simon 的风格。
- 他不是只满意于“透明化”，而是继续追问这类限制本身是否合理。
