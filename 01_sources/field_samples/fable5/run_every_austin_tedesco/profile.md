# Austin Tedesco

- 身份：Every，Head of Growth
- 角色定位：不是模型公司的人，也不是纯工程岗位；他代表的是把 Fable 5 真正塞进增长、研究、执行链路里的 operator
- 为什么值得单列：他给出的不是抽象赞美，而是明确区分了什么任务该交给 Fable，什么任务继续交给更便宜、更快的 agent
- 核心贡献：把 Fable 5 定义成适合四小时以上、可委托、结果导向任务的“rocket launcher”
- 最重要的判断：Fable 5 改变的不是提示词技巧，而是知识工作者分配任务、定义结果、信任执行的方式
- 目录现状：现在已同时保留团队原文和 Austin 专属 workflow 摘录

## 这人到底说了什么

- Austin 反复强调，Fable 5 不是日常每个小任务都要开的默认模型，而是给“大、复杂、可委托”的任务准备的。
- 他把 Fable 5 用在可以跑四小时以上的项目上，比如隔夜增长实验、复杂研究、带执行链路的长任务。
- 他常用 compound engineering 的 LFG 流程来跑 Fable：brainstorm、plan、work、review、repeat。
- 与此同时，他并没有把别的 agent 扔掉，反而很明确地保留了 Codex 处理会后 action items 和当天的小任务。
- 现在这些方法也已经被抽成了人物专属 raw，不再只藏在 Every 团队长文里。

## 最值得记住的句子

> “Fable 5 demands a very different way of approaching knowledge work.”

> “Austin’s reserved Fable 5 for ‘rocket launcher’ projects that can run for four-plus hours.”

## 我的判断

- Austin 的价值在于他来自应用公司，而且不是传统工程领袖视角。
- 他说明了 Fable 5 最真实的一个落点：不是替代所有 AI 工具，而是接管那些你愿意真正放手的长任务。
- 这条线很适合留在 `fable5_field_signals/`，因为它讲的就是 Fable 5 用后 workflow 的变化。
- 现在这条目录已经更像一个“应用侧 operator 样本”，而不只是团队文章摘录。
