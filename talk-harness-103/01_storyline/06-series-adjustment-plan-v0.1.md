# 101—103 系列调整计划 v0.1

> 根据用户最新说明制定：101 是覆盖体系关键概念、可独立满足多数读者的完整入门；102、103 在理解 101 后向前延展。允许概念衔接与适量重复，以核心问题和学习所得不同为边界。用户已批准本计划并设持续目标推进；执行进度见各场CURRENT，本件保留计划与完成标准，不复制动态状态。问题证据见 [联合审阅](<05-series-quality-review-v0.1.md>)。

## 调整目标与范围

保留 101 → 102 → 103。101 提供完整认识及基本做法，102 深入工程执行，103 深入业务判断与反复对齐。修正准确性、突出各场核心任务；不以减少共同概念为目标。

本轮拟保持三场当前页数预算，先在既有页面内调整。材料容量或叙事需要加拆页时再更新本场 03，不提前规定一律不能增页。案例继续分别使用日常产出、工单分流、报价草稿，不统一成复杂大案例。内容修订不包括 PPTX 制作、真实产品实现或教学效果试验。

## 先落实系列分工

执行时把用户的定位澄清记入各场入口，避免只在聊天和审阅报告存在。每场仍以自己的 README／CONTEXT 为权威；系列计划是协调记录，不成为第二套页表或事实源。

| 场 | 必须保留的核心 | 共同概念在本场承担的任务 | 完成后听众能做的事 |
|---|---|---|---|
| 101 | 完整概念地图、五件事、检查与风险判断、基本打磨和维护意识 | 解释这些事为什么需要、最低限度怎样做、有什么限制 | 看懂自己的缺口，挑一件熟悉工作，明确边界、检查与维护责任，开始一次改善 |
| 102 | 执行前拆分、任务粒度、完整小路径、逐轮反馈、状态交接、续停 | 需求与验收支持开工和每轮决策，治理保证下一轮仍有现行依据 | 将需求转成可执行任务，用当前证据决定下一轮，交出可接续状态 |
| 103 | 两头业务能力、隐含标准、直接反馈、共同理解、判断尺度、经验维护 | 工程机制承接已确认的业务理解，保证样本、理由、标准与约束持续有效 | 用具体输出指出偏差与理由，区分问题去向，确认标准变更并重验，保存有效判断 |

不用把三场理解为项目时间上的三阶段。需求与验收贯穿每轮；103 深化其构造与判断，不意味着 102 先执行、最后才补业务标准。

## 第一轮：修 101，使完整入门准确且独立可用

目标是即使只读 101，读者也不会带走需要后续纠正的规则。保留核心公式、五件事及顺序、信噪比、四档识别、两句风险判据和行动收尾；不搬入 102 的完整工程流程或 103 的完整反馈方法。

| 调整位置 | 修改方向 | 保留的教学作用 |
|---|---|---|
| P4／P5，模型与环境关系 | 保留环境的重要性，去掉“稳定全由环境决定”及升级后自动取消约束的充分条件；明确能力补偿变化需复核 | 回答“等下一代模型不就行了”，说明环境值得经营 |
| P8／P9，资料与业务知识 | “不会找／不会问”改为不能假定缺入口、缺流程时会主动查问；写下规则后仍核理解与落实 | 让读者把做法、理由、例外和现行来源表达出来 |
| P12，代码检查 | 说明程序按明确规则核对特定条件，结果只覆盖检查范围；代码定义准确，不把重复性当业务正确性 | 保留“能让代码查的，别让 AI 自己说”，现场给出一个好懂的机械核对例 |
| P13，谁写／谁接受 | 保留现成检查、请工程同事、AI 协助三条路径；自报不能替代证据，指定接受责任，高风险可要求独立人审 | 技术一般的人也能提出检查要求，不误导为人人必须增加第二名人员或第二个 Agent |
| P15，四档风险 | 修“第3—4档风险只在多人出现”的脚注；人在场代表较易观察纠正，业务后果仍按风险判据判断 | 四档用于识别工作方式，与风险厚薄两条轴分开 |
| 长手册报价走读及页版对应段 | 已有有效期要求漏做归为实现未落实；新增期限上限明确业务确认；检查对应实际审批限制；三轮只作过程示例，改后仍复验 | 留下可照做的“跑、看、补、再验”，读者不需继续读后两场才能正确练习 |
| 手册完成判据、收尾行动 | 从“只看绿灯就能交”改为依据当前检查范围与必要人审作接受决定；保留未知／限制及维护责任 | 独立完成入门学习，知道下一步能亲自做什么 |

处理过满句时先用准确、积极、短的表述替换，不能把入门稿改成连续的免责声明。必要限制紧跟相关判断和例子，不堆到末尾。全稿另查同类绝对化句，按事实及适用条件判断，不机械删除所有“必须”或强结论。

维护顺序：定位与词义 → 故事线／来源支持 → 03 讲法 → PPT／长手册／页版 → 现有一致性检查器。只同步受影响内容，不对未变段落作无关改写。若检查器固化了旧错误口径，更新对应条件并执行其 selftest，不能为通过旧检查保留错误句。具体修改前读取相关源文件。

## 第二轮：校准 102，让工程执行主线更鲜明

102 的主体已较完整，预计局部调整。保留 P4—P6 的需求与样本入口、P7—P10 的拆分和粒度、P12—P19 的当前状态与失败反馈、P20—P24 的变更和接续治理。

- 在开场／需求转执行处说明本场任务：当前业务结果与边界明确后，怎样组织开发工作；未知仍须有去向，执行反馈也可以回需求。
- 验证页围绕“这份证据怎样决定下一轮”。保留检查范围与检验检查，避免只有验收原则、没有对下一轮目标和状态的作用。
- 治理页围绕“当前依据怎样找、失败怎样送达、换会话怎样继续”。约束维护／退出保留，作为接续工作所需的环境管理，不扩展独立制度全景。
- 保留开发 Agent、工单 Agent 与人的角色桥，避免让连续听众把业务助手与开发执行者混为一谈。
- 收尾确保听众能从自己的需求写一张任务卡，并用一轮反馈更新下一步；不用为了区分 103 强改主标题或删掉验收内容。

默认以 PPT 为修改中心，尊重 102 当前聚焦 PPT 文案的要求。改的是纯措辞，其他材料不扩修；若实际变更页面职责或关键含义，回改 03／故事线并定点同步对应口播与操作件，避免配套材料教出另一套意思。案例业务规则不因系列调整而变化。

## 第三轮：突出 103 的业务判断，并让治理接住打磨成果

103 保留需求、验收、治理三部分和直接反复对齐主线。预计开场、若干转场与终题局部改动，不作整场重写。

| 调整位置 | 修改方向 |
|---|---|
| P1—P3 开场 | 让听众一开始看见“业务熟仍未必说得清、双方点头仍未必理解一致”；主问题候选偏向业务判断与 AI 对齐，结合实际正文择定，不只为避开102的词而换标题 |
| P4—P8 需求 | 保留查事实、问取舍、决定依赖及同例核理解；突出业务人怎样确认理由和处理例外，示范当前够用的收口 |
| P9—P13 直接对齐 | 保留核心输入／输出／反馈链及历史快照；让已有遗漏、理解偏差、新标准发现的处理动作始终清楚，不继续堆流程标签 |
| P14—P19 验收 | 保留五问、独立业务基线、实际来源及人判；每页连回“业务人凭什么接受”，而不仅复述检查机制 |
| P20—P24 治理 | 继续留住当前标准、样本、反馈理由、变更与证据条件；价格和入口演练保留，明确它们影响哪些业务判断、谁确认、如何重验。必要工程解释有助理解即可，不按重复页数强行删除 |
| P25 终题 | 保留Q2／实际Q1／旧证据闭环；增添或替换一个短问，用已有报价输出和当轮条件让听众判断漏做／理解偏／新标准，写具体反馈理由及重验去向。优先复用前文情境，不在末尾新增一套规则 |
| P26 收尾 | 两头、直接反馈、保存有效判断落到一次亲自实践；确保终题与回去做的事都体现本场核心 |

终题按控时调整，可用“指出已有遗漏＋说出反馈理由”作为必答，新增标准／受影响预期作为主持追问，避免一百秒题页被扩成完整工作坊。题面必须给相应输出和当轮已定条件，答案仍只在03主持卡，不混入PPT。

涉及标题／职责变化时回改故事线和03；涉及标准、输出或规则变化先回案例源，再同步PPT与两份手册。当前长手册、页版仍保留独立可读、空模板与紧邻已填例、一页一核心提醒的组织。

## 第四轮：联合复核与状态收口

分两种阅读方式复核，解决不同风险：

1. **只读 101。** 能否获得完整的概念认识和基本做法？是否正确理解检查、权限、人工判断、反复打磨及维护的边界？不存在“等读后两场才能纠正”的必上结论。
2. **继续读 102／103。** 能否明确说出每场新增能力？共同概念是否帮助本场核心任务？102能否用反馈安排下一轮，103能否用具体片段确认标准与理解？后续是在深化而非推翻入门。

独立复核分两路：一路看内容准确性和案例／标准／检查对应，一路看三场核心、自然中文与学习递进。只报实质问题，不以重复率评分或要求零重叠。修改后定点复验，不反复整套重审凑问题。

结构核验：页块、字段、背景隔离、题面／主持答案隔离、手册核心提醒、本地链接与来源边界；101运行自身检查器，102／103按受影响范围核查。全程明确合成未运行及预算未排练，不生成虚构通过记录。

最后更新各场 CURRENT、开放问题（101按其自身约定记入CURRENT）、README必要入口和根地图的实际变更；既有审阅保留为历史记录，新增修改落实／未落实结论。版本按实际改动与各场约定收口；不先约定统一升版，也不建立重复文案源。

## 执行顺序与交付

**先101，再102，再103，最后联合复核。** 101准确性先稳定，后续无需依赖纠错式讲法；102执行骨架基本不变，103再据其实际重心校准深化与收尾。每一场内部先改事实／主张源再同步文案；同时关注其他会话的改动，不覆盖新文本。

完成后交付：三场修改摘要与关键对照、各场当前唯一稿入口、检查和独立复核结论。页数／规格若需改变给出实际理由及新预算；无变化就沿用当前预算。本计划已获执行授权；内容修改与复核收口在各场CURRENT登记，不启动渲染。
