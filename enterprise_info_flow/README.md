# Enterprise Info Flow — 企业信息加工流研究

> 核心问题：软件行业用 SDLC 体系化管理信息加工流。办公室里的信息处理有没有等价的方法论？AI 在怎么改变它？

## 定位

这是 SDLC 研究的**横向参照系**。两条线的底层是同一个东西：

```
软件开发：  用户需求 → [SDLC 各阶段] → 软件产品
企业办公：  业务信息 → [？？？]       → 决策/动作/文档
                              ↑
                    有体系化的方法论吗？
```

如果企业信息流也在被 AI 重构，SDLC 的变化就不是孤例。如果那边已经出现了方法论——借过来。如果那边还是一片荒地——我们的 SDLC 框架反而可以反向输出。

## 目录

```
enterprise_info_flow/
├── README.md              ← 你在这里
├── findings/              ← 外部发现归档
│   ├── products/          ← 具体产品/功能
│   ├── cases/             ← 企业落地案例
│   ├── vendors/           ← 厂商战略/白皮书
│   ├── methodology/       ← 方法论/理论框架（有没有"SDLC 等价物"？）
│   └── china/             ← 中文世界的产品和案例
└── synthesis.md           ← 综合判断
```

## 研究方法

- 不堆学术论文——找实战和行业上真正落地的东西
- 但也追问：做是做了，背后的方法论是什么？有人体系化地研究过吗？
- 每个发现回答：① 它能做什么（具体） ② 信息加工模型是什么（人/AI 分工） ③ 跟传统信息系统的关系

## ⚠️ 来源铁律（与 KOL 材料同等纪律）

> **本库所有内容必须有可验证的来源。厂商自吹自擂的 PR 稿不算。**

| 情况 | 处置 |
|------|------|
| **有可靠来源** | 放入 `findings/`，文中标注 URL |
| **厂商 PR/营销稿** | 不可用——除非有第三方验证或真实数据背书 |
| **没有来源** | 不入库 |

**什么是可靠来源**：
- 官方产品文档/开发者文档（不是营销 landing page）
- 有数据、有方法论的行业分析报告（Gartner, Forrester, Futurum Group 等）
- 企业自己发布的案例数据（需标注"厂商自报"，可靠性打折）
- 第三方媒体的独立报道（非软文）
- 学术论文/会议论文

**什么不可用**：
- 厂商新闻稿里的"革命性""行业领先"话术
- 没有数据支撑的"XX 企业用了 AI 提效"类软文
- 聚合站转述（除非原文可查）
