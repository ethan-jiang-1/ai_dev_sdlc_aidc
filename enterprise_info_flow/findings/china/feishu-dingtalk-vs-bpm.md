# 飞书/钉钉/企微 — 他们到底是什么？

> 核心判断：他们**不是**传统 BPM。他们是**协作平台 + 轻量流程引擎 + AI Agent 底座**的混合体，正在从下方侵蚀传统 BPM 的中低端市场。

---

## 一句话定位

| 平台 | 基因 | 一句话 |
|------|------|--------|
| **飞书** | 以"事"为中心 | Context, not Control — 信息高效流转 > 流程管控 |
| **钉钉** | 以"管理"为中心 | 老板视角，强管控、强执行、全场景 OA |
| **企微** | 以"客户"为中心 | 连接微信生态，私域流量 + 轻量内部协作 |
| **传统 BPM**（泛微/致远） | 以"流程"为中心 | 流程建模、合规审计、跨系统编排 |

---

## 为什么他们不是传统 BPM

传统 BPM（泛微、致远互联、蓝凌）的基因：
- 流程建模（BPMN 2.0）
- 审批流引擎
- 合规审计
- 跨系统 ESB 编排

飞书/钉钉/企微做的事：
- **飞书**：文档 + 多维表格 + 会议 + 轻审批。流程是"协作的副产品"，不是核心。AI 时代走"龙虾式自主执行"——Agent 跨系统操作，**不依赖传统流程引擎**。
- **钉钉**：三大平台里最接近传统 BPM 的。OA 审批深厚（考勤/报销/采购/合同），宜搭低代码让业务人员自建流程。但 2026 年推出"悟空"平台——把审批/文档/日程拆成 **AI 可调用的原子指令（CLI 化）**，这是传统 BPM 做不到的。
- **企微**：核心价值是连接微信客户。内部流程能力最弱，但客户经营场景最强（客服对话 → AI 自动生成客户档案和销售线索）。

---

## 关键转折：CLI 化改造（2026）

飞书和钉钉在 2026 年**同日开源 CLI**——把产品能力拆解为 AI 可调用的标准化指令。

这意味着什么？传统 BPM 的流程引擎不再是唯一的执行入口。AI Agent 可以直接调用"发审批""查数据""写文档"——不需要经过预定义的流程模型。

## 传统 BPM 的生存空间

| 传统 BPM 仍有壁垒的场景 | 正在被侵蚀的场景 |
|------|------|
| 超大型企业复杂合规流程 | 日常审批（报销/请假/采购申请） |
| 需要 BPMN 2.0 精确建模 | 轻量协作式工作流 |
| 跨系统 ESB 编排（SAP+Oracle+遗留系统） | 部门级流程自动化 |
| 审计追踪的完整性要求 | AI Agent 自主执行的简单流程 |

---

## 飞书在 AI 时代最值得关注

飞书的路线最接近你说的"能处理各种 media、不被传统流程束缚"：
- 多维表格智能体：群聊中 @agent 查数据、填进度、写报告——信息来源可以是聊天、表格、文档，不局限于结构化表单
- 权限继承自表格，不同角色得到不同层级回答——治理内嵌在协作中
- 拿了三个国际评测榜单冠军（TableBench、FDABench、SpreadsheetBench）

> Source: [2026企业协同办公平台深度横评](http://www.cniteyes.com/archives/40732)

## 结论

飞书/钉钉/企微**不是** BPM——他们是比 BPM 更宽的一层：**协作基础设施 + AI Agent 底座**。传统 BPM 的流程引擎在它们这里变成了可被 Agent 调用的原子能力。这个变化跟 SDLC 里"流程不再被完整预定义"是同一个故事。
