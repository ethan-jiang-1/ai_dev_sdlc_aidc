# 听众、时长与核心目的（v0.1 初稿）

## 听众

- **有组织决策权的人**：CTO / 技术 VP / 平台工程（Platform Engineering）负责人 / 研发效能负责人 / 安全合规负责人。
- **不是** hands-on 程序员的进阶课（那是 `-opc` 的听众）。听众关心的是：**建不建平台、怎么分工、怎么治理、
  怎么合规、ROI 在哪**，而不是"个人怎么学 prompt / harness"。
- 推论：五层机制要讲得专业、抓要害（不让决策者觉得被科普），但落点始终回到**组织怎么分工与治理**，
  不滑向个人技能细节。

## 时长与形式

- **45 分钟，硬上限 50**（无 demo；初稿 23 页版预算：41 内容 + 1 收尾页 + 3 弹性，与 `-opc` 同构但逐页内容不同）。

## 核心目的

1. **介绍每个 engineering 背后到底是怎么回事儿**——Prompt / Context / Harness / Loop / Graph
   每一层讲清它工程化的是什么、解决了什么、局限在哪（通俗 + 抓要害）。
2. **把五层翻译成组织的分工问题**：哪一层该放给一线、哪一层该集中建平台、哪一层该归治理。
   这是本 talk 区别于 `-opc` 的核心增值。
3. **用 DSH 说明组织怎样搭共享平台、同时把运行边界收归治理**：可组合 harness runtime 的 registry /
   adapter / capability seam / enforced gate / append-only session log 是组织四项治理决定（准入、替换、放行、重建事实）的机制证据。
4. **更大的主题：组织的规模化 AI Coding**。组织要建成的能力边界在哪？统一平台还是各自为政？
   什么时候必须把 harness 收归平台、把 final say 收归治理？
   → 五层演变 + DSH 都是为回答这个问题服务的素材。

## 一句话 pitch

- 主题：**组织航海指南：组织与 Harness，规模化 AI Coding 之道**（题目待定）
- 听众听完要带走的一个东西：**部件可借，边界归治理**（完整三层：任务归团队，平台归组织，边界归治理）。

## 讲述基调

- 抓要害 + 讲治理 + 引发组织决策者共鸣（不是炫技，不是论文复述，不是个人技能课）。
