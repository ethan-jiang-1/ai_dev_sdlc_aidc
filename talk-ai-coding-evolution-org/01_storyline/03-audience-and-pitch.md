# 听众、时长与核心目的（v0.5）

## 听众

- **研发整体组织的决策者**：CTO / 技术 VP、平台工程（Platform Engineering）负责人、产品负责人、QA / 安全 / 发布 / 运维负责人——从产品一路到底到实施、再到运维这条链上每个环节的 owner。
- **独立成篇**：不依赖、不承接 `04_output/deck_ai_sdlc_keynote`。那边听众是「软件 + 业务」混合的战略听众（讲为什么世界变了），这边是研发组织的操作级听众（讲六阶段怎么一步步转）。
- 不假设听众都懂 prompt / harness 细节，但要讲得专业、抓要害、落到「组织怎么转型」，不滑向个人技能课。

## 时长与形式

- **单场加长 Keynote**：75–90 min，目标 **~45–60 页**（不再受 23 页约束）。
- 无 demo（内容已满）。

## 核心目的

1. 讲清「**代码不再是瓶颈**」——为什么 AI coding 用起来了，交付却没快。
2. 把六阶段 SDLC 的 AI-native 转型讲透：每阶段「传统 → AI-native 转变 + 关键 play + 治理 + 度量」。
3. 用「**工件链 = 审计链 + 人守 gate**」收束治理主线，落到「统一平台 + 治理边界」。
4. 用 DSH 说明组织怎样用可组合 harness runtime 搭出这套平台与治理。

## 一句话 pitch

- 主题（题目候选见 `00-storyline-map.md` 文末）：**AI-Native 研发组织：从产品到实施的 SDLC 转型之道**
- 听众听完要带走的一个东西（候选）：**代码不再是瓶颈，流程才是。**

## 讲述基调

- 抓要害 + 讲治理 + 引发研发决策者共鸣（不是炫技，不是论文复述，不是个人技能课）。
