# 第三幕 + 收尾逐页内容（P39–P50 · v0.5 加厚版）

> 组织视角：把六阶段升维成治理主线——工件链即审计链、人守 gate；DSH 作为可组合 harness runtime，用「三条腿」讲清它怎么帮组织把流程跑起来。DSH 素材见 `../02_evidence/00-absorption-plan.md` §四。

## 第三幕：DSH + 治理收束（P39–P48）

### P39 工件链 = 审计链（收束）
- **页面结论**：`intent → spec → plan → diff → PR → incident` 这条 commit 链就是审计记录。
- **上屏**：工件链；「谁要的 / agent 产出了什么 / 谁批的」。
- **讲点**：组织要的问责，不靠会议和签字，靠**版本库里的工件链**。合规/审计的抓手从「流程」变成「链」。
- **视觉**：工件链 + 审计标注。

### P40 人守 gate + 确定性优先
- **页面结论**：人的注意力守在 gate；能交给确定性门禁的，绝不靠模型自觉。
- **上屏**：computational（测试/lint/类型/schema）> inferential（AI review）。
- **讲点**：组织要审计、要合规，门禁必须可复现、可留痕。Böckeler 两套控制（Guides/Sensors），每套分确定性/概率性两档。原则：确定性优先。**埋一句 DSH 的金句（P45 再点）**：Agents follow enforced gates far more reliably than prose conventions.
- **视觉**：computational vs inferential 阶梯。

### P41 引子：DSH 如何帮助流程——三条腿
- **页面结论**：DSH 不训练「更聪明的 agent」，而是把「怎么正确参与」外置成运行时语法。
- **上屏**：三条腿——**知识外置 / 正确路径 / 可执行反馈**。
- **讲点**：这是「DSH 帮流程」的钥匙：让「读对、改对」成为阻力最小路径，「读错、改错」在离错误源头最近处被机器拒绝。三句话——「不糊涂靠外置，不靠聪明」「不乱发挥靠正确路径」「不乱发挥靠早失败，不靠自律」。**这和整场 talk 的工件链 / 人守 gate / 确定性优先是同一条线。**
- **视觉**：三条腿 → 三个动词。

### P42 DSH = 可组合 harness runtime：插件图 + 事件流 + loop
- **页面结论**：DSH 的基底是两套系统——插件图回答「现在由什么组成」，事件流回答「刚才做过什么」，loop 在两者之间取能力、写事实。
- **上屏**：插件图（live plugin graph）+ 事件流（session event log）+ loop。
- **讲点**：参与一个 harness 需要两类知识——系统外置的（写在哪、怎么写、怎么验证）和读者自带的（行话、部落知识）。DSH 的工程重心是让前者尽可能多、后者尽可能少：**参与规则住在运行时里，不在人脑里**。
- **视觉**：插件图 + 事件流 + loop 三件套。

### P43 知识外置：一个事实一个 owner、负知识外置
- **页面结论**：规则、结构、改哪里、为什么，写进可搜索可检查的文件——不靠资深成员脑子里的部落知识。
- **上屏**：「一个事实一个 owner」「当前状态与决策理由分开」「负知识外置（为什么不做 X）」。
- **讲点**：这是「不糊涂」的地基——agent 遇到问题去权威文件查，而不是在过时故事里猜。**对应第二幕的工件链**：intent/spec/AGENTS.md + ADR + rejected notes，同一个原则。
- **视觉**：知识外置 → 单一事实源。

### P44 正确路径 + 参与阶梯：分层参与、各有门与合同
- **页面结论**：正确做法是阻力最小的路径；参与分层（patch → 扩展点 → seam → loop），每层有门、合同与检查半径。
- **上屏**：扩展点路由四问（事实 / 拦截 / 能力 / loop）+ 参与阶梯。
- **讲点**：这是「不乱发挥」的前半段——**改哪里先问归属**。组织读法：谁能改配置、谁能加能力、谁能换后端、谁能改 loop，各有一道门。这直接引出 P48 的四项治理决定。
- **视觉**：参与阶梯（四层 + 门）。

### P45 可执行反馈 + 门禁：门禁本身被测试
- **页面结论**：能机械判断的规则全部落到执行，而且门禁自己被测试——证明无效案例会被拒绝。
- **上屏**：类型 / load / 测试 / snapshot / invariant / CI；「Agents follow enforced gates far more reliably than prose conventions.」
- **讲点**：这是「不乱发挥」的后半段，也是 DSH 最值得抄的一句话。org 读法 = 确定性优先的最硬实现：文档负责「告诉你往哪看」，系统负责「证明你做对了」。
- **视觉**：门禁清单 + 「门禁被测试」示意。

### P46 定制/替换：capability seam 三角色
- **页面结论**：一条 seam 是「可替换的完整能力」——Definition / Provider / Consumer 三角色齐了才算；「换一个后端，Consumer 不用改」。
- **上屏**：Definition（声明）+ Provider（实现）+ Consumer（使用）。
- **讲点**：这就是「给不同环节定制」的机制——组织换沙箱、换模型、换持久化，业务 Consumer 一行不改。org 读法：**平台团队把「能替换」做成一等公民，业务团队才能按环节定制。**
- **视觉**：三角色图 + 换后端示意。

### P47 审计与重建事实：append-only + asked/decided + fail-closed
- **页面结论**：模型可见 ⟺ 已记录；审批成对、无人可答就失败关闭——这是「敢放手」的底座。
- **上屏**：append-only session log；`asked/decided` 成对；fail-closed；会话格式版本纪律。
- **讲点**：组织读法 = 「谁能重建事实」的运行时保证。三条不变式：① 模型看到的每一件事都能从日志重建（loop 构建期检查，不是文档承诺）；② 审批是成对的审计事件，没有 answerer 时 fail-closed；③ 会话格式有版本纪律、冷读可恢复。**审计对称**：同一张日志也记录 DSH 官方自己的行为。
- **视觉**：append-only log + 成对审批。

### P48 四项治理决定 + 组织怎么落地 + 度量总表
- **页面结论**：准入/替换/放行/重建事实，各对应一个机制；落地顺序 = 先工件链 → 再 gate → 再关 loop。
- **上屏**：准入=registry+knowledge map；替换=adapter+seam；放行=enforced gate+invariant；重建事实=session log。
- **讲点**：把 P44/P45/P47 收成四个可操作的决定。落地顺序：先立工件链 + 单一事实源（知识外置），再补门禁（可执行反馈），最后关 loop（Maintain）。**诚实标尺**：DSH 敢把可替换率摊开（28 条 seam，39.3% 可无痛替换），饱和区 vs 缺口区分明——成熟度诚实本身就是治理的一部分。
- **视觉**：四决定 → 四机制对齐图 + 落地三步。
