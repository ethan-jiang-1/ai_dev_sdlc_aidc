# 开场 + 第一幕逐页内容（P1–P12 · v0.5）

> 组织视角：每页回答「组织该建什么 / 谁负责 / 怎么治理」。口径红线见 `../02_evidence/00-absorption-plan.md` §三。

## 开场（P1–P5）

### P1 封面
- **页面结论**：AI-Native 研发组织：从产品到实施的 SDLC 转型之道。
- **上屏**：题目 + 副题「从产品到实施，整条 SDLC 的 AI-native 转型」+ 讲者。
- **讲点**：对象是**研发整体组织**（CTO/平台/产品/QA/安全/发布/运维），不是程序员个人。定调：组织转型，不是工具课。
- **视觉**：封面；六阶段 loop 作暗线。

### P2 钩子：代码产出翻倍，交付没快
- **页面结论**：组织已用上 AI coding，但交付时间没变。
- **上屏**：「代码产出翻了几倍，交付时间没变。」
- **讲点**：组织的普遍困惑——不是个别团队没用好，是**结构性问题**。抛问题：慢的到底在哪？
- **视觉**：双曲线对比——产出陡升 vs 交付平直。

### P3 转型对象是整条 SDLC，不是编码
- **页面结论**：从产品一路到底到实施、再到运维，整条链都要变。
- **上屏**：「Code is no longer the bottleneck.」
- **讲点**：Anthropic 论点（**标注来源**）。慢的不是写代码，是代码左右两边的流程与治理。组织注意力该从编码移开。
- **视觉**：线性 SDLC——build 塌缩，两边原长。

### P4 引子：五层预告
- **页面结论**：人机互动一直在变——五层会沿 SDLC 逐一亮相。
- **上屏**：Prompt → Context → Harness → Loop → Graph（每层一句话）。
- **讲点**：不展开，只预告。这五层是「人机协作越来越深」的理论；本 talk 会沿 SDLC 六个阶段，看每一层在哪个阶段登场。**五层一个都不缺，但它们是引子，不是独立章节。**
- **视觉**：五层图（预告态，浅标注）。

### P5 引子：harness 先立住
- **页面结论**：模型给能力，harness 给可靠性——五层里组织最该握住的是 harness。
- **上屏**：「模型给能力，harness 给可靠性。」
- **讲点**：先点破临界点，后面 Build/Test/Deploy 再展开。对组织来说，harness 是**唯一该集中建设的那一层**——它一旦各自为政，整条链的审计就散了。
- **视觉**：Agent = Model + Harness（Böckeler）。

## 第一幕：为什么整条 SDLC 要转型（P6–P12）

### P6 代码不再是瓶颈 → 三个后果
- **页面结论**：瓶颈左移右移 / 旧控制失效 / 治理成本上升。
- **上屏**：三张卡片。
- **讲点**：① 慢的移到 plan/review/deploy；② 逐行 review 是「人写代码」时代设计的，agent 一次吐几千行就崩；③ 例外仍走周会/月会委员会。**三个都是组织级问题**。
- **视觉**：三卡片。

### P7 传统 SDLC 的控制假设
- **页面结论**：六阶段靠文档/工单/签字交接，隐含假设「每一步都是人做的」。
- **上屏**：线性六阶段 + 交接物（PRD/工单/签字）。
- **讲点**：传统控制为了问责而流程重——但它的前提是「人执行、人交接」。这个前提被 AI 挖了。
- **视觉**：线性流程 + 交接节点。

### P8 传统控制失效
- **页面结论**：逐行 review 和阶段闸门跟不上 agent 产出。
- **上屏**：「安全团队按人的产出配备——排队，或欠审。」
- **讲点**：playbook 的安全例子：代码产出成倍、安全团队规模没变 → 要么排队、要么欠审。受监管组织两个都不能接受。
- **视觉**：漏斗（产出洪流 vs review 吸管）。

### P9 转型 = 从「人执行」到「harness 执行 + 人守 gate」
- **页面结论**：机械检查下沉到工具链，人在 gate 上做判断。
- **上屏**：「人执行 + 人工闸」→「harness 执行 + 人守 gate」。
- **讲点**：这是整场转型的轴心。确定性检查（测试/类型/lint/evals）交给 harness，人只在 gate 判断意图与风险。**judgment 归人，机械检查归机器。**
- **视觉**：in-the-loop → on-the-loop。

### P10 贯穿主线：工件链 = 审计链
- **页面结论**：每一阶段落一个工件，下一阶段读它；commit 链就是审计链。
- **上屏**：`intent → spec → plan → diff → PR → incident`。
- **讲点**：工件链记录「谁要的 / agent 产出了什么 / 谁批的」。人不再逐行看，而是守 gate。为第二幕、第三幕埋线。
- **视觉**：工件链首尾相接。

### P11 六阶段 shifts 总表
- **页面结论**：传统 vs AI-native，一屏看清六阶段转变。
- **上屏**：六阶段对照表（Plan/Design/Build/Test/Deploy/Maintain，两列）。
- **讲点**：逐行点到为止（细节第二幕展开）。重点：每一阶段从「人执行 + 人工闸」变成「agent 执行 + 工件交接 + 确定性闸」。
- **视觉**：对照表（进货单 §一）。

### P12 引子地图：五层在六阶段的落点
- **页面结论**：一张表看清每个阶段由哪一层点破。
- **上屏**：Plan=Prompt / Design=Context / Build=Harness / Test=Harness+Loop / Deploy=Harness / Maintain=Loop+Graph。
- **讲点**：这是本 talk 的「导航图」——后面每阶段开页都先点破「这一阶段的本质是哪一层」，再讲机制。DSH 到第三幕作为可组合 runtime 收束。
- **视觉**：六阶段 + 五层对齐图。
