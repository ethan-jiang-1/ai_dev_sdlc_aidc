# Nityesh Agarwal：洞察摘录

## 关键言辞

> “...senior engineer Nityesh Agarwal repairing a broken PowerPoint-generation workflow...”

- 这句很重要，因为它不是笼统地说“做了个项目”，而是说在修一个已经坏掉的流程。
- 这类脏活最能检验模型是不是能顶住复杂上下文和多步骤依赖。

> “Tasks that are good candidates for Fable 5 have four qualities...”

- 这句虽然不是 Nityesh 本人的直引，但它定义了他这类任务为什么适配 Fable 5。
- 对资料库来说，这种“任务选择标准”很值得保存。

## 总结判断

- Nityesh 的价值在于把 Fable 5 从“造新东西”拉回“修复杂烂摊子”。
- 这是一类非常真实、也非常有参考价值的应用公司样本。
