# Outline — Loop Engineering（技术/产品场）

27 页，约 75 分钟。听众已在跑循环：不铺「一轮是什么」，开场直接进治理问题。原统一稿加深档的深度全部并进正文；机制页再向下取一层（backbone / manual 有、统一稿未上屏的）。平铺单档；追问材料留备注，指向 backbone 与 manual。

## 听众

工程师与产品经理，正在搭或维护 agent 系统。测试、构建、评审是他们每天的工具，不解释这些词。他们来学的是治理：什么时候敢让循环自己走，人站在哪，哪些账是空的。

「执行方」是正在写改动的那一方，也包括替它确认完成的人。不专指员工，也不专指模型。

A03 先把外延摊开：三个已核对的定义互不兼容，本场的用词不依赖其中任何一个。A10 引入「裁判」一词后，A11 讲怎么保护它。A23 十种翻车各对回一页，是这一场的自查地图。

## 1. 核心判断

系统可以宣告一轮完成。这个宣告只说明完成被提交了。能够相信它，要同时满足三件事：已知错误能使检查失败，停止时已经核过上一轮结果，完成签署不是执行方。

## 2. 核心公式

```text
已知错误能使检查失败 × 停止时已核上一轮结果 × 完成签署不是执行方 = 才可以减少逐轮值守
```

三个因子都是设计，不是模型的品性。缺一个，人就还要留在每一轮。

本场不证明这样做更快、更好、更省人。它只划出可以减少逐轮值守的条件。证明不了的那句放在结论里，不单开一页清单。

## 4. 页面

每页一句主张 = subtitle。title 标这一步讲到哪。只读 title 与 subtitle 应能跟上论证；content 写看得见的场面，分两档：第一档「必须写出」是这页的最小完整版面，第二档 nice to have 版面有余再上。引用块是给做片的补充材料（这页的意思、词解、禁止、版面），不上屏——做片方未必懂这个题目，拿不准时以引用块为准，不要自行发挥。个别难点页加一句 callout 点睛（自造金句，或已回源复核的署名引语；未复核引语不上屏）。

**A01 · Loop Engineering**
由系统替人完成一轮，而不是由人逐轮发起。

**A02 · 名称还不是方法**
这个名称之下没有统一做法。本场只确定何时允许这一转向。

**A03 · 三个外延，互不兼容**
三个已核对的外延互相不兼容。未复核的不出现。

**A04 · 完成宣告不等于完成判断**
系统报告已完成，只说明完成被宣告了。要确认的是已知错误下一次能否使检查失败。

**A05 · 两种容易得到的通过**
一种是不看上一轮结果就再次运行。一种是执行方自己签署完成。

**A06 · 提前宣告完成**
任务尚未完成，却被标为完成。要拦住的就是这一步。

**A07 · 三件事不能并成一件**
检查能否失败、到达上限后是否停止、由谁签署完成，是三件不同的事。

**A08 · 停止是三值**
停止条件是三值：还没到，到了，到不了。不是一句是或不是。

**A09 · 谁来签署完成**
执行方自己签署完成，是最弱的一种。检查若能被执行方修改，就会对执行方放行。

**A10 · 裁判有五型**
裁判有五型。干活的那一方自判，是最弱的一型。

**A11 · 保护裁判**
检查和改动不能放在同一个可写的地方。该做却没做的，检查仍可能通过。

**A12 · 什么样的工作适合**
边界清楚、一次可以做完的事，不必专人安排下一轮。变长之后，未完成项必须写在对话之外，并且下一轮要有触发。

**A13 · 文件即队列**
进度写进一个文件。每一轮重读它，从中取下一件。

**A14 · 触发即节拍**
下一轮由触发拉起：条件到了、时间到了，或一件事发生了。

**A15 · 日志不是在途总账**
任务能够续跑，仍可能不知道：谁批准、谁改了优先级、卡在何处、谁验收。

**A16 · 没有通用轮次**
看不清在途状态时，容易想用轮次代替判断。没有可复核的通用轮次。应看动作是否高风险、意图是否清楚、拒绝之后有没有人接手。

**A17 · 没有第几级**
三套说法不能换算成一把尺子。

**A18 · 何时减少逐轮值守**
循环已经在运行时，用一个已知错误做检验。检查不失败，人就还要留在每一轮。

**A19 · 人仍要在的位置**
高风险动作、说不清的意图、拒绝之后谁接手、最终是否验收。

**A20 · 一次批准只绑一次动作**
一次批准只绑这一次动作、目标和有效期。旧批准不自动继承到新分支、新功能、发布。

**A21 · 拒绝之后**
放行、等人、硬拒绝、升级。升级画在图上，边可能是断的。

**A22 · 判定与人相反时**
裁判与人工验收者对同一产出判定相反时，先停自动升档与自动验收，由人核对。

**A23 · 十种失败**
十种失败都能对回前面某一页，没有第十一种主题。

**A24 · 先不要进入下一轮**
这一轮还不能拦住已知错误，或这件事一次就能做完，就不要自动开始下一轮。

**A25 · 完成条件写不出来**
完成条件写不成一句可检查的话，就交给人。不要靠增加轮次把它跑到通过。

**A26 · 结论**
允许减少逐轮值守的是这些条件，不是一个更聪明的模型。本场没有证明因此更快或更好。

**A27 · 回去的顺序**
先用已知错误检验检查能否失败，再规定停止必须查看上一轮，再把长任务的进度移出对话，最后才讨论人离开逐轮值守。
