# 07 · 它停了

> 它熔断、超时、或自己停了。停止不是失败，也不是完成——是**交接时刻**。

## 本章回答什么

停了之后三件事：先阻止在途动作；分三路处置；分账记录两件事。

## 第一步：阻止待执行动作

- 支持持久化暂停的实现 → **保存当轮状态**；
- 不支持 → 记下请求并停机，**不假装可从原位恢复**。

## 三路处置

| 情形 | 处置 | 红线 |
|---|---|---|
| 策略明确禁止 | 维持硬拒绝 | 不得改名为「待人批准」 |
| 可由人决定 | 有合法审批入口 → 交指定审批者 | 入口不可达或无人接手 → 记 `blocked`，**不自动重试同一危险动作** |
| 入口不可达 | 保持阻塞并记录 | 不把阻塞写成「已升级」 |

交接记录至少带：任务 ID、动作、目标、线程 ID、决定来源、拒绝原因、授权范围、审批人、**恢复指针**（不存在就显式留空）。若是子代理，确认**父线程能看到该请求**。

## 两件事分记（不可互相冒充）

| 记什么 | 记哪些值 | 不能冒充 |
|---|---|---|
| `stop_reason`（为什么停） | 目标门通过而停 / 资源耗尽 / 连续拒绝 / 不可恢复错误 / 人暂停 / 模型自行收尾 | 「已验收」——**没有验收证据就保留未验收** |
| `accepted ＋ 证据链`（谁收了货） | 验收者与测试、PR、日志或人工记录的指针；未验收留空 | 不能从超时、模型消息或测试进程结束推断已交付 |

不可恢复错误四类（触发即清空目标，Claude Code 官方文档，观测 2026-09-26）：认证失败｜额度耗尽｜压缩解决不了的上下文溢出｜模型不可用；其余错误重试若干次后暂停。

## 恢复后重新核对

动作与授权**有效期**重新核对——不继承上次对另一个目标的批准（[02 章铁则一](02-交动作.md)）。

## 退档信号

熔断频发、假把控症状复现（测试被动过、越界实现、未说明的失败）→ 退一档重新稳住再升（见 [05 章](05-升一档.md)）。停止本身不构成退档理由——**正常停与事故停要分得清**：目标门通过而停是设计内；拒绝熔断与无进展熔断频发才是信号。

## 什么时候不要

- 别在没看清 `stop_reason` 前重启循环——重启烧掉的预算和上次一样。
- 别把「它自己收尾了」读成任何一种完成（00 章状态语汇表第 6 行）。

## 交接记录实例（填好的样子，示意）

```text
task_id         = fix-cart-total-42
action          = bash(git push origin fix/cart-total)
target          = repo:shop, branch:fix/cart-total
decision_source = exec_policy: push → Forbidden
denial_reason   = 硬拒绝（push 不在授权面；本次授权只覆盖编辑与测试）
authorized_scope= 编辑 payments/、跑 npm test；不含 commit/push
reviewer        = @xiaoming（审批入口：PR #217）
resume_pointer  = paused_state:88f3      # 持久化暂停；恢复后从断点继续
thread_id       = session-12             # 父线程可见该请求 ✓
```

恢复时第一步：重核 `authorized_scope` 的**有效期**——上次批的是那次评审，这次是新的，重新请求（[02 章](02-交动作.md)铁则一）。

## 两个常见误处置（对照修）

| 误处置 | 正解 |
|---|---|
| 把硬拒绝现场改成「待人批准」 | 策略说禁止就是禁止；要改的是策略本身，走策略变更流程，不在事故现场开口子 |
| 入口不可达时自动重试同一动作 | 正确状态是 `blocked`＋记录；每五分钟再撞一次墙不会把墙撞开，只会烧预算 |
