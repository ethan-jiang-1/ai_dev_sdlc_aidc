# 01 · 要不要交给循环

> 你有个任务，犹豫要不要把它交给自动循环。这章帮你在五分钟内做决定——包括决定「不交」。

## 本章回答什么

三个问题：这个任务配不配循环？配的话交到哪一档？不配的话怎么办？

## 三问诊断（任一答「否」→ 先别上循环）

| 问题 | 答「否」意味着什么 | 下一步 |
|---|---|---|
| 1. 停止条件依赖上一轮的结果吗？ | 不依赖的是重试（retry），不是循环 | 写脚本或手动重跑，不建循环 |
| 2. 单次运行受控吗？ | 不受控时，循环只是把错误复制得更快 | 先治单次运行（约束写进环境：沙箱、审批、测试），再回来 |
| 3. 跨轮状态放在对话外面了吗？ | 没外置（文件 / git / 日志），每轮都在交「对话税」，人退化成催促者 | 先把进度落到文件，再谈多轮 |

## 完成条件体检（第二道门）

三问过了，再看完成条件能不能写成**可观察的句子**：

- ✅ 能写：`npm test 退出码 0` / `Lighthouse 分数 ≥ 92` / `队列清空` → 可以交续跑（03 章）
- ⚠️ 产出可核、外部结果不可见：把自动停止范围收窄到产出（如「PR 已生成且检查通过」），业务结果另行观测（06 章）
- ❌ 写不出（「做到生产就绪」「设计变好」）：拆小、人工标样、或交人——**不靠增加轮次硬跑**

坏目标的典型（署名原话）："a vague goal would be 'keep going until this UI design is good'. What does that mean? Good to who? How is it being evaluated?"（Addy Osmani《Practical Loop Engineering》，2026-08-14）

## 什么时候不要（与正面步骤同权重）

1. **单次小任务不建循环脚手架**——先有真实失控，再上治理；为二十分钟的活配一套循环是过度工程。
2. **存量代码库慎用无限循环**——Ralph 式裸循环作者自己的适用警告："There's no way in heck would I use Ralph in an existing code base"（Jesse Vincent，2025-07；greenfield 专用）。
3. **标准会随样本变化的任务**（品味、审美、法律判断）：保留人工检查点，不塞进自动达成。
4. **别把品味和判断一起委托**——"check yourself, that you are not delegating the taste and the judgment to your agent. You're delegating the task, and then you are actually checking back that it's meeting your bar."（Osmani，同上）

## 判定实例（三个任务过三关，判定过程写全）

**实例 A｜重命名 2,000 张截图**：第一问就死——停止条件不依赖上一轮结果（第 1,733 张和第 1 张毫无关系），这是批处理。判定：**不交**，写十行脚本。错法：为它配循环脚手架——拿大炮修桌子，还得自己擦炮膛。

**实例 B｜修 flaky 测试到三连绿**：三问全过（这次没修好才知道下次改哪＝依赖上轮反馈）；完成条件可观察。判定：**交**，goal 照抄模板四件套：

```text
Fix the flaky cart-total test until `npm test` exits 0 on three consecutive runs.
Do not modify unrelated tests.
Stop after 8 turns.
```

**实例 C｜「把体验改到用户满意」**：完成条件写不成可观察句子。判定：**先拆**——拆出可观察的代理指标：

| 拆出的子目标 | 可观察吗 | 去处 |
|---|---|---|
| Lighthouse 性能分 ≥ 92 | ✅ 可测 | 可交循环（03 章） |
| 支付页崩溃率 < 0.1% | ✅ 可测 | 可交循环（03 章） |
| 用户满意度提升 | ⏳ 外部结果，延迟可见 | 待观测，业务负责人复查（06 章） |

**同一个任务拆完，一部分交、一部分不交——这是常态，不是失败。**「先拆」不是拖着不办，是把「满意」翻译成机器能对照的句子、把翻译不出去的部分诚实留给人。
