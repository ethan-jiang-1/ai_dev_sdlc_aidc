# 03 · 交续跑

> 单轮跑稳了，你想让它**自己跑到目标为止**——交出的是「本轮之后是否再开一轮」。

## 本章回答什么

交出续跑权前配四样：目标怎么写、裁判怎么选、裁判怎么保护、熔断怎么配。目标可枚举时再加进度清单。

## 目标模板（官方三要素＋上限子句）

```text
目标（一个可度量终态）：
  "All tests in test_status.py pass" / "the endpoint returns 200 with the new field"
检查（声明式——怎么证明：哪条命令、哪个退出码、哪份输出）：
  "`npm test` exits 0" / "`git status` is clean"
约束（路径上不许变的东西）：
  "no other test file is modified"
上限子句（推荐常备）：
  "… or stop after 20 turns"（轮次或时间均可）
```

（模板要素：Claude Code /goal 官方文档，观测 2026-09-26）

**教科书级全例**（Addy Osmani，2026-08-14）——一件不少：可度量终态、声明式检查、约束、无进展中止、轮次上限：

> "/goal Refactor the data-fetching layer in Dashboard.tsx until Lighthouse performance score is >= 92 and LCP is under 1.8s as shown by the Lighthouse CLI output. Do not change the public API of any hooks. Each turn must improve at least one reported metric; abort if two consecutive turns show no improvement. Stop after 10 turns."

## 三值判定（续跑的出口）

| 裁定 | 含义 | 下一步 |
|---|---|---|
| Not yet met | 约定条件未达成 | 继续，**评估理由作为下一轮的指导** |
| Met | 条件在裁判可见证据内成立 | 停止本轮——注意：**Met ≠ 验收**（[06 章](06-它说做完了.md)） |
| Impossible | 裁判判条件无法满足 | 停止并交人；「业务结果还看不见」不得误报为 Impossible |

无进展熔断：连续数轮没有工具调用 → 停止并警告、返还控制，目标保留不清除（同上官方文档）。

## 写法红线

1. **含糊目标不配循环**（见 01 章的坏目标例句）。
2. **别把品味和判断一起委托**——委托任务，检查是否达到你的标准。
3. **评估器只核硬规则，不判内容好坏**："It doesn't look at the content to see if it's good or bad in any way, shape, or form. All it does is examine the conversation transcript to see if the hard rules you specified have been met."（Osmani，2026-08-14）
4. **续跑信号可以比入口目标弱**："The harness just needs some signal that lets it continue. It does not have to be objective or binary, it just has to be useful enough to drive another iteration."（Armin Ronacher，2026-09）——入口目标要可核，中间推进信号只要「够用」；两句别混成一句。

## 裁判选型（五式，按场景选一）

| 裁判 | 适用 | 风险 |
|---|---|---|
| 人判（品味） | 探索、清单语义撑不住 | 不可规模化 |
| 文件清单逐条判定 | 目标可枚举（见下节） | 清单本身要保护 |
| 独立小模型每轮判定 | 会话内目标 | 裁判自身可信度要校验 |
| 干活模型自判 | **最弱**——多数产品的默认形态 | 必须配保护＋熔断补偿 |
| 被审批方提出、审批方判定 | 越界动作 | 审批方可能被操纵（红队实证） |

选型次序：优先机器可核；必须人判的，把判断点集中在门上。

## 保护裁判四件

1. **测试不可删改**：强措辞条款＋测试文件钩子硬拦——**写在提示词里的「不许改测试」不算隔离**；
2. **清单选 JSON 不选 Markdown**：模型对 JSON 整文件改写的概率更低（Anthropic 长程 harness 实录，观测 2026-09-26）；
3. **裁判输入防操纵**：分类器只看用户消息与工具调用、剥掉模型自述——"reasoning-blind by design"（Claude Code auto mode 文档，观测 2026-09-26）；
4. **看真实证据不看转述**：带运行 ID、目标版本与原始输出的测试 / 扫描记录。

## 目标可枚举时：进度清单七步

粗目标 → 逐条 feature（JSON 结构，初始全部 `passes: false`）→ 三件套（清单＋进度文件＋初始 commit）→ 每轮固定开场（定位目录 → 读 log 与进度 → **选最高优先级未完成项** → 先过基线：环境留在坏状态时先修它）→ **一次只做一件** → 完成判定要端到端自验证（单测或 curl 过不算）→ 干净收尾（描述性 commit＋进度更新）。**只允许改 `passes` 字段。**

官方反例对照（Anthropic 长程 harness，观测 2026-09-26）："declares victory on the entire project too early" → 设清单；"marks features as done prematurely" → 认真测试后才翻 passing。

## 预算的语义（别读错数字）

预算是**花费暂停阀**，不是「达成」的同义词。真实参数样例：某云托管 agent 服务的预算写 `"max_list_cost": {"amount":"125","currency":"USD"}` 时，**125 是美分，即 $1.25**；触顶返回 `budget_reached`，在途请求可稍超额完成，新消息得 400；提高或移除预算可恢复原会话；**按会话计，不等于跨次总额**（Anthropic Managed Agents，观测 2026-09-30）。

## 什么时候不要

- 完成条件写不成可观察句子 → 01 章分流：拆小 / 人工标样 / 交人。
- 无进展出口和上限子句配不出来 → 没有兜底的续跑是烧钱循环。
- **判停权住在哪一层，要追到驱动代码**——某官方 quickstart 示例里，进度条打印「通过数/总数」，但驱动循环**没有「全部通过就停」的分支**，默认迭代上限是无限、错误还换新会话重试；「不可改测试」只写在提示词里，驱动层并不校验。博客叙事里的「goal 完成」，在配套代码里可能是靠人看进度条实现的（Anthropic 官方 quickstart 源码，观测 2026-09-28）。

## 走一遍（一份 goal 的三轮，教学示意非产品日志）

用上面那个 Lighthouse goal 跑三轮，看每道闸各拦什么：

```text
第 1 轮  改数据层 → Lighthouse 88 分（< 92）
        裁判：Not yet met（评估理由回传：「performance 88, LCP 2.4s」→ 下一轮知道改哪）

第 2 轮  分数 93、LCP 1.7s ——但 diff 显示改了 useCart 的 public API
        约束检查：违例（"Do not change the public API of any hooks"）
        裁判拒判 Met：分数达标、路径犯规——只有盯 transcript/工具输出的约束检查能抓住这种

第 3 轮  恢复 API、改内部实现 → 93 分且 API 未动
        裁判：Met，本轮停
        人还要看一眼：Lighthouse 测的是不是正确的页面（跑错 URL 的假绿是经典事故）
```

**第 2 轮是整套机制存在的原因：分数会达标，犯规不会被分数看见。**

## 清单条目长什么样（目标可枚举时）

（结构样例，Anthropic 长程 harness 实录，观测 2026-09-26；实际项目一例清单 200+ 条）

```json
{
  "category": "chat",
  "description": "a user can open a new chat, type in a query, press enter, and see an AI response",
  "steps": ["render chat page", "submit query", "assert response visible"],
  "passes": false
}
```

铁规则：**端到端自验证后才翻 `passes`**（浏览器自动化 / 真实用户路径），单测或 curl 过不算；执行方只被允许改 `passes` 这一个字段。

## 判停权要追到代码（不看博客看源码）

某官方 quickstart 的驱动循环长这样（源码观测 2026-09-28）：

```python
while True:
    iteration += 1
    if max_iterations and iteration > max_iterations:   # 唯一退出分支
        print(f"Reached max iterations ({max_iterations})")
        break
    # 成功时 run_agent_session 恒返回 ("continue", response) ——没有完成分支
```

进度条打印 `passing/total` 是**给人看的**（`count_passing_tests` 读清单的 `passes` 字段），驱动层没有 `passing == total` 的停机判断；`--max-iterations` 默认 `None`＝无限；「不可改测试」只写在提示词里，驱动层不校验。博客叙事里「goal 会自己完成」，在这份代码里＝跑到你按 Ctrl-C。**交续跑之前，先找到你家驱动循环的 `break` 在哪。**
