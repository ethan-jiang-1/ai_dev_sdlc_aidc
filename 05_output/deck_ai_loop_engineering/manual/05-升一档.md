# 05 · 升一档

> 现在的档位跑稳了，你想把下一个决定也交出去。这章是全书的铰链：**升档不是毕业，是用护栏换放权**。

## 本章回答什么

升档前置检查（三项门禁＋一次演练）；判定冲突怎么办；退档信号。

## 三项门禁（缺一不可）

| 门禁 | 检查什么 | 不过怎么办 |
|---|---|---|
| 1 门会红吗 | **负例控制**：故意引入一个已知错误，看门禁会不会拦住 | 没做过负例的检查视为摆设；门不会红就不配当门 |
| 2 裁判独立且判据可用吗 | 过 03 章五式之一；抽看本任务的人工核对与自动判定是否一致 | 干活模型自判＋无保护＝不升 |
| 3 熔断配了吗 | 至少配了拒绝熔断与硬过期（02 / 04 章） | 没有兜底的升档是把错误复制得更快 |

## 控制路径演练（升档前必做一次）

挑一条**有外部副作用**的动作，写清「动作＋目标＋本次授权有效期」，分别触发三种处置：

- **允许**：只在当前边界内执行；
- **需人批准**：执行前让指定人看到具体参数与风险、作决定、按同一线程恢复；
- **硬拒绝**：停下并暴露原因，**不得用普通审批覆盖**。

演练后任一情形不成立——人不在、父线程看不见请求、状态不可恢复——保持暂停，退回需要人在环的档位。**不要把权限开大来让演练通过。**下一轮换目标或从 edit 变为 commit/push 时，重新请求授权。

## 判定冲突时

裁判与人工验收者对同一产出结论冲突：

1. **暂停自动验收与升档**；
2. 把样例交给有权判定的人；人也无法一致判断 → 先重新明确「成功」的定义，再用固定样本复核；
3. 改过判据或样本集后记录新版本，**新旧分数不直接横比**；
4. 不能靠模型自报或提高轮次上限通过。

## 退档信号（退档不是失败）

- 熔断频发；
- 假把控症状复现：测试被删 / 关 / 弱化、做了未授权的功能、失败测试未说明——先暂停标完成，转独立核对；
- 交接反复丢信息（授权、优先级、验收）。

退一档重新稳住，再升。

## 档位速查（本手册编排）

| 交出的决定 | 章 | 已配护栏 |
|---|---|---|
| 动作审批 | [02](02-交动作.md) | 分级处置＋绑定授权＋拒绝预算 |
| 续跑 | [03](03-交续跑.md) | 三要素目标＋裁判选型与保护＋熔断 |
| 唤醒时机 | [04](04-交唤醒.md) | 触发器＋持久状态＋取消传播＋硬上限 |

三条交接面均为多家独立可观察的机制（Loop Engineering 研究综述，2026-09-30）；**高阶不是毕业要求**——没有任何通用刻度说「跑 N 轮必须人看」，能写成门的是事件：动作类别、拒绝预算、无进展、歧义、升级后是否有人接得住。

## 什么时候不要

- 三项门禁任何一项没过 → 不升。
- 演练三条路有一条走不通 → 不升。
- 说不清「升这一档省下的是什么、换来的是什么」→ 先写下来再决定。

## 演练记录（填好的样子，示意）

| 项 | 值 |
|---|---|
| 演练动作 | `bash(git push origin fix/cart-total)` |
| 目标 / 有效期 | 仅 fix/cart-total 分支，仅本次评审周期 |
| 触发「允许」 | 在边界内执行；日志有 propose → execute → result 三行 ✓ |
| 触发「需人批准」 | 执行前暂停；审批人看到 diff 与目标分支；批准后按同一线程恢复 ✓ |
| 触发「硬拒绝」 | 停止＋原因回传；普通审批不可覆盖 ✓ |
| 人不在场复测 | 请求进入 `awaiting_human`，父线程可见，恢复指针有效 ✓ |
| 结论 | 三路全通 → 可交动作审批（02 档） |

结论栏写「不通过——人不在场时请求不可见」**也是合格产出：它挡住了一次真事故**。演练的目的是暴露断点，不是走个过场。

## 定档实例（三条样例的判定）

- 「agent 改文件、跑测试都在我看着的时候，每个 push 我批」→ 交了**动作**（02），没交续跑（03）；
- 「`/goal` 最多十轮，修到 Lighthouse 达标为止」→ 交了动作＋**续跑**（03），没交唤醒（04）；
- 「`/loop 5m` 值班看部署」→ 三档都交了——但唤醒交出的是**触发权**，不是成果裁决权：CI 绿不是部署成功，放行另查（06 章）。
