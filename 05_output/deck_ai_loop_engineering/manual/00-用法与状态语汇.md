# 00 · 用法与状态语汇

> 第一次拿到这本手册读这章，之后按时刻翻。这章立三条全书约定：怎么翻、参数怎么锚、状态怎么说。

## 一、怎么用

1. **按时刻翻，不按顺序读**。先确认你在哪个时刻——要交一个决定、想升一档、它说做完了、它停了——翻到对应章。每章自足，不依赖其他章。
2. **要抄的东西都在表格里**。模板、清单、步骤、反例，全部表格化；两分钟内找不到要抄的那一行，是我们写坏了，请反馈。
3. **先看「什么时候不要」，再看怎么配**。每章的退回条件与正面步骤同权重。交出去之前先确认自己不在退回区。

## 二、参数锚约定

- 手册里每条具体参数（阈值、时长、费用、命令语法、默认值）都带**「（产品与版本，观测日期）」**。产品会改默认值，抄进配置前先核对你手上的版本。
- **docs 与源码打架时，以源码为准**；手册会显式标出两个值与各自出处。
- 没有锚的参数，手册写「以你所用版本的官方文档为准」——那是提醒你去找，不是省略。

## 三、档位语言

手册说「档」，只指**交出去的决定**是哪一种：动作（02 章）、续跑（03 章）、唤醒（04 章）。档不是成熟度等级：

- 升档不是毕业，退档不是失败；按任务的风险、可逆性、验收成本选位置，随时允许退回。
- 没有任何通用刻度说「跑 N 轮必须人看」。能写成门的是事件：动作类别、拒绝预算、无进展、歧义、升级后是否有人接得住。

每一步交接前，四个问题要能写在纸上：

1. 谁启动下一轮？
2. 谁判断完成？
3. 谁能改变系统？
4. 出了错，谁能及时停下并接手？

写不出来，就是护栏还没配好，先别交。

## 四、状态语汇表（全书唯一权威）

任何状态都有「最多能声称什么」。看到把左列偷换成右列的说法——那是误读，或事故的开始。

| 你看到的 | 它最多说明 | 不能偷换成 |
|---|---|---|
| 检查通过（测试退出码 0、lint 干净、构建成功） | 写在条件里的检查，在该环境、该版本上通过 | 需求无遗漏、无回归、业务会变好 |
| 裁判判「达成」（Met） | 该裁判按**它可见的证据**判约定条件成立 | 人已验收、生产业务已改善 |
| 裁判判「不可能」（Impossible） | 该裁判判断约定条件无法满足，终止 | 所有尚不可见的结果都已证明不可能 |
| 检查失败 / 证据不足 | 该次验证不支持「达成」，进入修复或升级 | 任务本质不可能；也不可静默改判达成 |
| 轮数、时间、预算、成本耗尽 | 资源到边界，必须停或交人 | 任务已完成或已失败 |
| 拒绝熔断 / 人工暂停 / 停止（stopped） | 循环不再运行，状态可交接 | 产出已被接受 |
| 人或专家验收（accepted） | 指明版本、样本、时间窗内的接受 | 自动推广到所有用户和任务 |
| 上线后业务指标改善 | 观测窗口内的外部结果 | 离线检查可替代上线观测；或可归因于循环设计本身 |

三条硬边界（这张表的骨架）：

1. **停止 ≠ 接受**：超时、耗尽、拒绝、模型自己收尾，都只是控制流停了；是否验收另算。
2. **产出 ≠ 结果**：可观察的产物（PR、测试、构建）与外部业务结果分账记录；结果尚不可见时写「待观测」，不写达成。
3. **达成 ≠ 验收**：裁判只核约定条件，不判内容好坏；验收是人或独立检查者对照真实需求做的事。

## 五、一条总警告

**无人值守地跑，和无人值守地对，是两件事。** 授权与调度解决「跑」，不解决「凭什么放行」。每一次交接：护栏先于放权。
