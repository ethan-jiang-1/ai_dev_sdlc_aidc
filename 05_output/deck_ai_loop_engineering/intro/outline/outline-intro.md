# Outline — Loop Engineering（入门场）

## 0. 这场要解决什么

听众不需要先学会搭 loop；他们需要带走一个判断：**系统说做完了，不等于我们有理由接受它。** 本场先展示一条最小控制链，再用提前完成、停机与交接三个失败面说明为什么链条不能省。

吴恩达的三环只作为上位背景：编码环、开发者反馈环、真实用户反馈环解释反馈如何回流；本场不把它当 runtime 操作模型。控制链是本场的研究抽象，不声称是任何 KOL 的原文 taxonomy。

## 1. 核心判断

**Loop 的信任问题不是它能不能行动，而是它每次继续、停止或交还时，是否留下了可审计的依据。**

## 2. 核心链条

```text
Goal / 边界
  → Action / 本轮做什么
  → Environment Feedback / 环境返回什么事实
  → Eval / 谁按什么判据解释事实
  → Continue / Stop / Escalate
  → State / Outcome 分账
```

停止条件三件骨架是这条链的控制内核，不是全场唯一主题：机器闸门拦已知错误，硬上限管资源，验收与干活分离；三者都不能单独代表完成。

## 3. 叙事弧

```text
1. 它说做完了，问题不是“能不能跑”，而是“凭什么信”
2. 先给目标和边界，否则没有完成对象
3. 一轮是目标约束下的行动、环境反馈和裁判
4. 反馈不等于验收，停止不等于接受
5. 继续、停止、升级是三个不同出口
6. 长任务必须把状态和外部结果分账
7. 提前完成、资源停机、执行方自判分别击穿不同节点
8. 只有负例控制、反馈驱动停续、独立验收和可达交接同时成立，才讨论减少逐轮值守
9. 这不是效率保证；回去先审计一条真实链路
```

## 4. 页面

**I01 · 它说做完了**
你离开后它继续跑，回来听到“完成”；真正的问题是这句话凭什么可信。

**I02 · Loop 不是一圈箭头，是一条控制链**
一轮从目标和边界出发，经行动、环境反馈、评估，走向继续、停止或交还。

**I03 · 先给 Goal，再谈完成**
没有可观察的目标、范围和不可变约束，循环没有可以验收的完成对象。

**I04 · Action 不是固定自动化**
系统可以在目标和授权边界内选择下一步；自动触发仍可叠加，不是旧自动化被新东西取代。

**I05 · Feedback 必须来自环境事实**
工具结果、测试、构建或真实路径返回的事实，必须改变下一步；不看上一轮结果的重跑只是重试。

**I06 · Eval 不是 Feedback**
反馈是环境返回什么，评估是按什么判据解释它；检查要事先写好、机器能判，且不能只靠执行方自述。

**I07 · 继续、停止、升级不是同一个出口**
未满足但可继续就继续；满足预设产出才可停止候选；不可判、高风险、拒绝或无恢复路径就交人。

**I08 · Stop ≠ Accepted**
超时、资源耗尽、无进展或模型自己收尾，都只说明控制流停了，不说明产出已验收。

**I09 · 状态和结果要分账**
`running`、`blocked`、`awaiting_human`、`stopped` 是控制状态；`accepted` 是预设产出验收，`outcome_pending` 是外部结果尚不可见。

**I10 · 第一类失败：提前宣告完成**
文件变多、语气很满、能打开的空壳，都不是完成证据；目标敌人是“尚未完成却被标为完成”。

**I11 · 三件停止骨架各管一件事**
机器闸门拦已知错误；硬上限只管资源熔断；验收与干活分离；三件不能合成一句“它停了”。

**I12 · 负例控制决定能不能少守**
把已知错误放进链路；如果门拦不住，普通动作也不能自动放手。负例只证明一个必要条件，不单独证明质量或业务成功。

**I13 · 人要守的是控制关口**
高风险动作、说不清的目标、拒绝后的接手、最终验收和外部结果；人不是被移出循环，而是从机械 QA 转到上下文和责任判断。

**I14 · 什么时候不要自动继续**
一次就能做完的任务不必建循环；完成条件写不成可观察的句子，就拆小、人工标样或交人，不靠增加轮次硬跑。

**I15 · 回去先做控制链审计**
写 Goal/边界 → 定义可观察 Eval 和一个已知错误 → 接入真实 Feedback → 分开 Stop 与 Accepted → 演练升级和恢复；前置失败就保留逐轮值守。

## 5. 公式/系统落点

本场不再用“减少值守”的三因子作为总公式。它作为 I12–I13 的局部判据出现：

```text
已知错误能使检查失败
+ 停止前读取并解释上一轮反馈
+ 完成验收不由执行方独自签署
+ 停止/升级后状态可交接
→ 才有资格讨论减少逐轮值守
```

其中最后一项是控制链新增的必要条件；整场不证明因此更快、更好或更省人。

## 6. 语言与边界

- 首现术语：目标（Goal）、行动（Action）、环境反馈（Environment Feedback）、评估（Eval）、验收（Accepted）、交还（Escalate）。
- 不把 Ng 三环说成 runtime taxonomy；不把控制链说成某位 KOL 的原话。
- 不把 Stop、Blocked、Awaiting human 或 Outcome pending 说成完成。
- 不使用红、绿、灯作为术语；产品参数和具体拒绝次数留备注。
- 技术例子用测试、构建、浏览器路径，但不暗示测试通过就等于业务结果成功。
