# Outline — Loop Engineering（入门场）

19 页，约 45 分钟。平铺单档；追问现场答，材料指针留备注。

这一场面对没跑过循环的人：概念从「一轮是什么」讲起；技术例子（测试、构建）照用，口播补一句白话，不假定听众天天跑流水线。论证顺序不放松：开场说明 Loop Engineering 是什么，随后回答它为何成为问题、技术难点在何处、哪些问题适合、哪些场合允许减少逐轮值守。

## 听众

一个房间，没跑过循环的人居多：听说过「AI 自己干活」，可能见过演示，没有自己把循环跑起来过。业务与管理为主。

开场先让他们看见一轮（I02），再划清与自动化的分界（I03）。I06 第一次正式定义「检查」：事先写好、机器能判定的一句话条件；不满足就叫检查失败。测试不通过、构建不成功只是例子。不使用红、绿——颜色是工具的界面，不是本场的术语；这句话本身不上屏，留在引用块。

「执行方」是正在写改动的那一方，也包括替它确认完成的人。不专指员工，也不专指模型。

I19 是这一场独有的收尾：四步顺序。第一步不过，后面三步都不开始。

## 1. 核心判断

系统可以宣告一轮完成。这个宣告只说明完成被提交了。能够相信它，要同时满足三件事：已知错误能使检查失败，停止时已经核过上一轮结果，完成签署不是执行方。

## 2. 核心公式

```text
已知错误能使检查失败 × 停止时已核上一轮结果 × 完成签署不是执行方 = 才可以减少逐轮值守
```

三个因子都是设计，不是模型的品性。缺一个，人就还要留在每一轮。

本场不证明这样做更快、更好、更省人。它只划出可以减少逐轮值守的条件。证明不了的那句放在结论里，不单开一页清单。

## 4. 页面

每页一句主张 = subtitle。title 标这一步讲到哪。只读 title 与 subtitle 应能跟上论证；content 写看得见的场面，分两档：第一档「必须写出」是这页的最小完整版面，第二档 nice to have 版面有余再上。引用块是给做片的补充材料（这页的意思、词解、禁止、版面），不上屏——做片方未必懂这个题目，拿不准时以引用块为准，不要自行发挥。

**I01 · Loop Engineering**
由系统替人完成一轮，而不是由人逐轮发起。

**I02 · 一轮长什么样**
一轮里有三下：动手、核对、决定收住还是继续。

**I03 · 它和自动化不一样**
自动化到点做固定的事。这一转向多了两件：自己选下一步，自己核这一轮。

**I04 · 名称还不是方法**
这个名称之下没有统一做法。本场只确定何时允许这一转向。

**I05 · 完成宣告不等于完成判断**
系统报告已完成，只说明完成被宣告了。要确认的是已知错误下一次能否使检查失败。

**I06 · 检查是什么**
检查是事先写好、机器能判定的一句话条件。不满足，就叫检查失败。

**I07 · 两种容易得到的通过**
一种是不看上一轮结果就再次运行。一种是执行方自己签署完成。

**I08 · 提前宣告完成**
任务尚未完成，却被标为完成。要拦住的就是这一步。

**I09 · 三件事不能并成一件**
检查能否失败、到达上限后是否停止、由谁签署完成，是三件不同的事。

**I10 · 谁来签署完成**
执行方自己签署完成，是最弱的一种。检查若能被执行方修改，就会对执行方放行。

**I11 · 什么样的工作适合**
边界清楚、一次可以做完的事，不必专人安排下一轮。变长之后，未完成项必须写在对话之外，并且下一轮要有触发。

**I12 · 日志不是在途总账**
任务能够续跑，仍可能不知道：谁批准、谁改了优先级、卡在何处、谁验收。

**I13 · 没有通用轮次**
看不清在途状态时，容易想用轮次代替判断。没有可复核的通用轮次。应看动作是否高风险、意图是否清楚、拒绝之后有没有人接手。

**I14 · 何时减少逐轮值守**
循环已经在运行时，用一个已知错误做检验。检查不失败，人就还要留在每一轮。

**I15 · 人仍要在的位置**
高风险动作、说不清的意图、拒绝之后谁接手、最终是否验收。

**I16 · 先不要进入下一轮**
这一轮还不能拦住已知错误，或这件事一次就能做完，就不要自动开始下一轮。

**I17 · 完成条件写不出来**
完成条件写不成一句可检查的话，就交给人。不要靠增加轮次把它跑到通过。

**I18 · 结论**
允许减少逐轮值守的是这些条件，不是一个更聪明的模型。本场没有证明因此更快或更好。

**I19 · 回去先做什么**
先用已知错误检验检查能否失败，再规定停止必须查看上一轮，再把长任务的进度移出对话，最后才讨论人离开逐轮值守。

## 6. 语言

投影用完整中文。主题在前。title 短，subtitle 是主张。只读二者应能跟上论证。loop、harness、goal、eval 可以出现在备注里，主张句不依赖它们。

第一页 title 就是 Loop Engineering。不解释谁在哪一天起的名。

不说红、绿、灯。检查失败指事先写好的判定没有通过。若提到有的工具用颜色表示结果，先说明那是界面，本场不用——这句话不上屏，留在引用块。

通识补则：测试、构建这类例子出现时，口播补一句白话。例如「构建不成功」补一句「程序没拼成一个能跑的整体」。

「轮数」不进 I09。I09 只说时间或连续拒绝到达上限。某一家自己的上限留在备注。「骨架」「熔断」不进口播。人离开的是逐轮值守。页码只留备注。
