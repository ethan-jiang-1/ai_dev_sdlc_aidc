# Outline — Loop Engineering（入门场）

## 0. 这场要解决什么

听众不需要先学会写 goal；他们需要带走一张阶梯图：**你已经在梯子上，往上每交出一个决定，就配一组护栏；反馈是让循环成为循环的东西——基建和人两路都不能断；最贵的那一级门口才需要 goal/eval 的真功夫；选对档位比爬到顶重要。**

**开场故事**（2026-10-01 用户定）：loop engineering 为什么存在——模型已经强到能知错改错，所以有人喊出「别写 prompt 了，写 loop」。这个故事吸引人且为真，但它的燃料是反馈、它的掌握需要锻炼；本场就是把这两件事讲清楚。

**反馈是贯穿全场的第二根线索**：loop 和抽卡的全部区别，是这一轮有没有被上一轮的反馈改变。反馈有两路——环境反馈要落成基建（工件、退出码、日志，下一轮消费的是工件不是记忆），人的反馈要留在环里（纠偏、品味、拒绝的理由回灌下一轮）。

v2 把「先给 Goal」当全场地基（第 3 页），对站在第一级的通识听众是提前征税。v3 的次序：第一级什么都不用配 → 第一级台阶（交动作授权）很便宜 → 交续跑那一级的门口，把 goal/eval 的全部火力摆出来。要求一点不降，只是搬对了海拔。

**一页一概念**：每页只讲一个概念，承载页（N03 路线图、N10 门票转折）负责呼吸与承接。

吴恩达三环保留一句上位背景。控制链是研究骨架，本场不再单独立页——它作为检查表随档位出现。

## 1. 核心判断

**你已经在阶梯上——往上走，每交出一个决定就配一组护栏；反馈是让循环成为循环的东西，基建和人两路都不能断；最贵的那一级，门票是把「什么叫好」写成机器能对照的句子；选对档位，比爬到顶重要。**

## 2. 系统（定档四问贯穿全阶梯）

四个定档问题贯穿——每一档都要能回答同一组问题，答案随档位变化：

```text
谁启动下一轮？      → 第一级：人 ／ 第三级：目标条件 ／ 第四级：时间表或事件
谁判断完成？        → 第一、二级：人 ／ 第三级：裁判判条件、人守验收
谁能改变系统？      → 每一级的授权面
出了错谁能停下接手？→ 每一级的升级路径
```

四问源自研究层交接面判定的对外措辞（§7）。四问在每一档都有答案，页面给出各档答案；这就是本场的「公式」。

## 3. 叙事弧

```text
1.  你听过那个承诺：你离开，它继续跑，回来告诉你做完了

27. 回去先定档：loop 是手艺，阶梯是练法
```

## 4. 页面

**N01 · 它说做完了**
你离开后它继续跑，回来听到「完成」；真正的问题是这句话凭什么可信。

**N02 · 为什么有人喊「别写 prompt 了，写 loop」**
模型已经强到能知错改错——知道错在哪就能改对，所以有人开始不写 prompt，改写 loop；这个故事的燃料是反馈。

**N03 · 今天的路线图：一张阶梯**
每上一级，交出一个决定，配上一组护栏；今天从你站的位置出发。

**N04 · 你已经在阶梯上**
逐次提示就是阶梯的第一级——人当裁判；这一级什么都不用先配，它是合法驻留，不是失败态。

**N05 · 反馈让循环成为循环**
模型不知道错在哪、要改哪里——除非每一轮都有反馈进来；没有反馈的重跑是抽卡（比喻），不是循环。

**N06 · 反馈要落成基建**
反馈不能只留在聊天里——退出码、日志、产物要落成可复查的工件，下一轮消费的是工件，不是记忆。

**N07 · 交出动作授权**
授权面让它在边界内自己动作，省掉的是打断，不是判断——你仍然逐轮看。

**N08 · 规则要写进策略件**
写了规则不等于有授权面——93% 的权限提示最终被人批准；策略偏好不等于执行隔离。

**N09 · 授权绑三样**
一次批准只绑定动作、目标、有效期；任何一个变了，就是新动作，要重新批准。

**N10 · 下一级的门票贵了**
让它自己跑到目标为止，交出的是「做完没做完」的判断权——这是全阶梯最贵的一级。

**N11 · 门票：一个可测终态＋一条声明式检查**
「把体验做好」不是目标；「Lighthouse ≥92，以 CLI 输出证明」才是——把潜意识里的判断挖出来写成文字，全场最难。

**N12 · 约束与兜底**
约束写「不许变的东西」；无进展出口和轮数上限是兜底——没有兜底的续跑是烧钱。

**N13 · 裁判不是反馈**
反馈是环境返回的事实，裁判是按事先约定判据解释事实的那一位；判好坏的仍是你。

**N14 · 三个出口各管一件事**
未达成带理由继续；达成只算停止候选；不可能就停并交人——三个出口语义不同，不能合成一句「它停了」。

**N15 · 门要覆盖真实的反馈通道**
门存在不等于门覆盖——实际跑的那条路径没被检查住，假通过照常发生。

**N16 · 门要见过血**
没让门红过一次的检查是摆设——负例控制是你决定放手前的必要条件。

**N17 · 事故：提前宣告完成**
交出续跑之后，最大的敌人是提前宣告完成——文件变多、语气很满、测试绿了，都可能不是完成。

**N18 · 防它第一层：清单逐条判定**
把目标拆成逐条清单，完成逐条判——「整个项目做完了」没法判，「第 37 条通过」可以。

**N19 · 防它第二层：端到端验证才翻完成**
真实路径走通才翻「完成」——单测和 curl 过不算。

**N20 · 防它第三层：测试不可删改**
测试删了，绿灯就没有意义——不可删改要写进硬约束，不是提示词。

**N21 · 人的反馈要留在环里**
你不是只在终点验收——方向纠偏、品味判断、拒绝的理由，都要回灌到下一轮；完全静默不是目标。

**N22 · Stop ≠ Accepted**
超时、耗尽、模型收尾，只说明控制流停了；验收是另一件事，由人签。

**N23 · 产出和结果是两本账**
PR 合了、测试绿了，是产出验收；业务有没有变好是外部结果，要等观测——两本账不能合成一句「完成了」。

**N24 · 最后一级的远景：让它自己醒**
交出「何时再起跑」的档位里，定时唤醒只证明「醒来并执行过」，不证明目标达成。

**N25 · 每一级，人守的东西不一样**
人不是被移出循环，是被移到更高处的判断。

**N26 · 什么时候不要往上爬**
完成条件写不成可观察句子就留在低档——驻留是控制决策，不是失败。

**N27 · 回去先定档**
先答四个问题——谁启动下一轮、谁判断完成、谁能改变系统、出了错谁能停下接手——答得出，再决定爬不爬。

## 5. 系统落点

本场的系统是**定档四问**（§2）＋**反馈双路**（§0）：四问在 N04/N10/N25/N27 逐档给答案；反馈双路在 N05/N06（环境反馈基建）、N21（人的反馈）承重，N13/N14/N15 是它们在交续跑档的机器化形态。旧版「三因子减值守公式」在 v2 已降级，v3 移除——「减少值守」不再是本场目标，**定档与配护栏**才是。

## 6. 语言与边界

- 首现术语：档、授权面、策略件、裁判、负例、验收、外部结果、反馈回路。上屏不使用 LE0–LE3 编号（口头可说「第一级／第二级」）；阶梯四级不作成熟度模型、不作人人必经。
- 「抽卡」是教学比喻，上屏可用，首现标注（比喻）。
- 控制链是研究骨架，本场不立页、不说成某位 KOL 的原话；其节点（目标、反馈、裁判、出口、分账）随档位以检查表形式出现。
- 不把 Stop、Blocked、待观测 说成完成；参数（3/20 拒绝、7 天过期等）留备注。
- 支线（多代理编排、改进循环自身）只在 N24 提一嘴「高级内容、非必经」，不展开。
- 反馈措辞纪律：「人的反馈要留在环里」不是说人要做每轮机械检查——是说纠偏、品味、拒绝理由必须能回到下一轮。
- 故事措辞纪律（N02）：「别写 prompt 了，写 loop」作为引子呈现，紧接「燃料是反馈、它需要锻炼」——只立不破，不点名任何人。
