# Outline v1：Loop Engineering

标准档 15 页，约 40 分钟。加深 10 页只在有人追问时用，不插进标准档的中间。

这一版要的是论证顺序，不是第二人称讲故事。开场就说明 Loop Engineering 是什么。随后依次回答：它为何成为一个问题，技术难点在何处，哪些问题适合，哪些场合允许减少逐轮值守。

## 听众

一场，一个房间。动手搭过的人，和要为结果负责的人，坐在一起。标准档不分成两套论述。某一方多问的，才进加深页。

开场两种人都先知道题目：Loop Engineering 是由系统替人完成一轮。动手的人接着关心检查能否失败。负责结果的人接着关心谁签署完成，以及多项工作同时在途时是否看得见。

「执行方」是正在写改动的那一方，也包括替它确认完成的人。不专指编制内的员工，也不专指模型。

S01 的 title 就是 Loop Engineering，subtitle 说明它是什么。不先讲场景再报名字。

S03 第一次使用「检查」。正文要解释：这是事先写好、可以由机器判定的条件；不满足就叫检查失败。测试不通过、构建不成功只是例子。不使用红色和绿色。有的工具把失败显示成红色、通过显示成绿色，那是界面，不是本场的术语。

S08 先讲一件任务变长。S09 才是多项工作同时在途。不要在 S08 就把总账讲完。不把「从文件取下一件」讲成所有循环的做法。触发决定下一轮何时开始。人仍可以改接下来做什么。

S10 只拒绝轮次，并说出用什么代替。S11 说的是循环已经在运行：检查不失败，人就不能离开每一轮。S12 不是把那几项再念一遍。多出来的一处是最终是否验收。S13 不是把上一句收回。它是更早的前提：这一轮还不能拦住已知错误，或这件事一次就能做完，就不要自动开始下一轮。S14 只做一件事：完成条件写不成可检查的语句，就交给人，不要靠增加轮次把它跑到通过。看不见的业务结果不能因此标成业务成功。「探索可以，由人看」留到 E9。S13 的衔接只问写不出来怎么办，不预告下一页会教怎么写。

## 1. 核心判断

系统可以宣告一轮完成。这个宣告只说明完成被提交了。能够相信它，要同时满足三件事：已知错误能使检查失败，停止时已经核过上一轮结果，完成签署不是执行方。

## 2. 核心公式

```text
已知错误能使检查失败 × 停止时已核上一轮结果 × 完成签署不是执行方 = 才可以减少逐轮值守
```

三个因子都是设计，不是模型的品性。缺一个，人就还要留在每一轮。

本场不证明这样做更快、更好、更省人。它只划出可以减少逐轮值守的条件。证明不了的那句放在结论里，不单开一页清单。

## 4. 标准档

每页只有一句能被复述的主张。证据和人名留在讲者备注。

文稿里每页另有上屏。主张就是 subtitle。title 只标这一步讲到哪。只读 title 和 subtitle，应能跟上论证。content 把这一步写成看得见的场面，不写成概念说明。红、绿、灯，以及版面怎么分组，放在引用块里暗示，不上屏。nice to have 可以空。引用块不另起主张。

**S01 · Loop Engineering**
由系统替人完成一轮，而不是由人逐轮发起。

**S02 · 名称还不是方法**
这个名称之下没有统一做法。本场只确定何时允许这一转向。

**S03 · 完成宣告不等于完成判断**
系统报告已完成，只说明完成被宣告了。要确认的是已知错误下一次能否使检查失败。

**S04 · 两种容易得到的通过**
一种是不看上一轮结果就再次运行。一种是执行方自己签署完成。

**S05 · 提前宣告完成**
任务尚未完成，却被标为完成。要拦住的就是这一步。

**S06 · 三件事不能并成一件**
检查能否失败、到达上限后是否停止、由谁签署完成，是三件不同的事。

**S07 · 谁来签署完成**
执行方自己签署完成，是最弱的一种。检查若能被执行方修改，就会对执行方放行。

**S08 · 任务变长之后**
边界清楚、一次可以做完的事，不必专人安排下一轮。变长之后，未完成项必须写在对话之外，并且下一轮要有触发。

**S09 · 日志不是在途总账**
任务能够续跑，仍可能不知道：谁批准、谁改了优先级、卡在何处、谁验收。

**S10 · 没有通用轮次**
看不清在途状态时，容易想用轮次代替判断。没有可复核的通用轮次。应看动作是否高风险、意图是否清楚、拒绝之后有没有人接手。

**S11 · 何时减少逐轮值守**
循环已经在运行时，用一个已知错误做检验。检查不失败，人就还要留在每一轮。

**S12 · 人仍要在的位置**
高风险动作、说不清的意图、拒绝之后谁接手、最终是否验收。

**S13 · 先不要进入下一轮**
这一轮还不能拦住已知错误，或这件事一次就能做完，就不要自动开始下一轮。

**S14 · 完成条件写不出来**
完成条件写不成一句可检查的话，就交给人。不要靠增加轮次把它跑到通过。

**S15 · 结论**
允许减少逐轮值守的是这些条件，不是一个更聪明的模型。本场没有证明因此更快或更好。

## 5. 加深档

不进标准档的顺序。有人追问再翻。

| 页 | 只回答这个追问 |
|---|---|
| E1 | 「loop engineering 这个词不就是定义吗？」三个已核对的外延互相不兼容。未复核的不出现。 |
| E2 | 「是不是先自动化、再自主、然后才有循环？」四个词可以叠在一起，不是一条阶段史。 |
| E3 | 「失败还有哪些？」十种失败都能对回上面某一页，没有第十一种主题。 |
| E4 | 「拒绝之后会怎样？」放行、等人、硬拒绝、升级。升级画在图上，边可能是断的。 |
| E5 | 「角色分开就够了吗？」检查和改动不能放在同一个可写的地方。该做却没做的，检查仍可能通过。 |
| E6 | 「到底哪些已经有办法？」执行、停止、这一下能不能做、这一次会话记得住，已经有公开的办法。空的是多项工作的那四列。 |
| E7 | 「我们的系统不是已经能自己续吗？」能续上，和有总账，不是一回事。 |
| E8 | 「外面那些四级，我们在第几级？」三套说法不能换算成一把尺子。 |
| E9 | 「目标本来就写不清，怎么办？」探索可以，由人看。不能把看不见的业务结果自动标成达成。 |
| E10 | 「回去第一步做什么？」先用已知错误检验检查能否失败，再规定停止必须查看上一轮，再把长任务的进度移出对话，最后才讨论人离开逐轮值守。 |

## 6. 语言

投影用完整中文。主题在前。title 短，subtitle 是主张。只读二者应能跟上论证。loop、harness、goal、eval 可以出现在备注里，主张句不依赖它们。

第一页 title 就是 Loop Engineering。不先用口语场景代替题目。标准档不解释谁在哪一天起的名。有人说这个词已经有定义，才翻 E1。

标准档不说红、绿、灯。检查失败指事先写好的判定没有通过。若提到有的工具用颜色表示结果，先说明那是界面，本场不用。

「轮数」不进 S06。S06 只说时间或连续拒绝到达上限：停止不等于通过。第几轮必须人看，由 S10 回答：没有这个数。某一家自己的上限留在备注。

「骨架」「熔断」不进口播。停止用「到达上限」，接手用「拒绝之后」。人离开的是逐轮值守。页码只留在备注。

## 7. 这一版故意拿掉的

- 用一页罗列「还不能说」。边界收进 S15 的第二句，细节留在备注。
- 用一页做三层架构图。S13 只留依赖：这一轮还不能拦住已知错误，就不要自动进入下一轮。
- 把五类签署强度拆开讲。S07 只留最弱的一种，以及检查不能被执行方修改。
- 产品的次数、天数、默认轮数。备注里被问到再答「那是那一家的参数」。

## 8. 公式落在哪一页

| 因子 | 听众在哪一页听见 |
|---|---|
| 已知错误能使检查失败 | S03 提出问题，S11 用已知错误做检验 |
| 停止时已核上一轮结果 | S04 的第一种通过，S06 里到达上限不等于通过 |
| 完成签署不是执行方 | S04 的第二种通过，S07 |

S01 和 S02 不是第四个因子。它们说明题目是什么，以及名称还不是方法。S08 和 S09 也不是：它们回答哪些问题适合，以及续跑不等于看得见。S13 是第一个因子的前提，也比 S11 更早：这一轮还不能拦住已知错误，就不要自动进入下一轮。S14 是第三个因子落空：写不出可检查的语句，签署只能留给人。S15 把公式说回去，并带上本场证明不了的那一句。
