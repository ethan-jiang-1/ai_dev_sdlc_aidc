# 01. 命名起源、历史时间线与演进光谱

---

## 1. 关键历史时间线（2023 – 2026）

- **2023 年（Prompt Engineering 时代）**：
  - 核心焦点：如何通过 System Prompt、Few-shot、Chain-of-Thought（CoT）诱导单次 LLM 生成最优代码。
  - 局限：单次 Token 窗口受限，无法处理长程任务与外部副作用。
- **2024 年 – 2025 年中（Context Engineering 时代）**：
  - 核心焦点：长上下文窗口（Long Context）、RAG 检索增强、工程代码库向量索引、动态上下文组装。
  - 局限：即便能把整个代码库塞进上下文，“迷失在中间（Lost in the Middle）”与幻觉依然严重，缺乏执行反馈。
- **2025 年底 – 2026 年初（Harness Engineering 时代）**：
  - 核心事件：Engelberg Retreat 2026 正式定调；MCP（Model Context Protocol）标准化工具调用。
  - 核心焦点：把约束写进运行环境。建立沙箱隔离、代码执行门禁、环境状态清理与漂移抹除。
  - 确立原则：模型能力不够，脚手架（Harness）来凑。
- **2026 年 6 月（Loop Engineering 时代）**：
  - 核心事件：2026-06-30 Andrew Ng 公开发帖定名并倡导 Loop Engineering。
  - 核心焦点：从单次触发到自主闭环（Plan-Execute-Verify-Retry）。定义停止条件（Stop Conditions）、机器可核判据与验证分离。
- **2026 年 7 月 18 日（Graph Engineering 爆发点）**：
  - 核心事件：Peter Steinberger（OpenClaw 创作者）在 X 上发出灵魂提问：
    > *"Are we still talking loops or did we shift to graphs yet?"*
  - 行业回响：引发了大规模工程论辩。包括 LangChain 创始人 Harrison Chase、开源 Agent 架构师、各大 AI 实验室工程师纷纷入局讨论。
  - 核心结论：单 Agent 的 Loop 在长流程中面临不可逾越的上下文崩溃；真实生产系统必须从“单循环迭代”走向“异构节点、显式 DAG 与状态机编排（Graph Engineering）”。

## 2. AI 原生工程五层演化光谱

这五层不是互相排斥的替代关系，而是**由内向外的洋葱包裹模型**：

```text
               ┌────────────────────────────────────────────────────────┐
               │ 5. Graph Engineering (系统拓扑、DAG调度、多Agent治理)   │
               │   ┌────────────────────────────────────────────────┐   │
               │   │ 4. Loop Engineering (单节点自主循环、停止条件)  │   │
               │   │   ┌────────────────────────────────────────┐   │   │
               │   │   │ 3. Harness Engineering (环境约束、沙箱) │   │   │
               │   │   │   ┌────────────────────────────────┐   │   │   │
               │   │   │   │ 2. Context Engineering (记忆)  │   │   │   │
               │   │   │   │   ┌────────────────────────┐   │   │   │   │
               │   │   │   │   │ 1. Prompt Engineering  │   │   │   │   │
               │   │   │   │   └────────────────────────┘   │   │   │   │
               │   │   │   └────────────────────────────────┘   │   │   │
               │   │   └────────────────────────────────────────┘   │   │
               │   └────────────────────────────────────────────────┘   │
               └────────────────────────────────────────────────────────┘
```

| 层级 | 出现时间 | 关注焦点 | 解决的本质瓶颈 | 典型产物 |
|---|---|---|---|---|
| **L1. Prompt Engineering** | 2023 | 提示词调优 | 单轮生成的质量与格式合规 | System Prompt, Markdown, Few-shot |
| **L2. Context Engineering** | 2024–2025 | 知识与状态装配 | 上下文超载与长程信息丢失 | RAG, AST 索引, 记忆总结 |
| **L3. Harness Engineering** | 2025末–2026初 | 运行环境与安全 | 幻觉无法自测、环境状态污染 | 沙箱, MCP Server, 漂移清理器 |
| **L4. Loop Engineering** | 2026-06 | 局部自愈与循环控制 | 单次失败即挂、无法迭代修复 | 停止条件, 逐轮验证门禁, 退避重试 |
| **L5. Graph Engineering** | 2026-07起 | 系统拓扑与协作编排 | 单循环死锁、上下文腐败、缺乏并发与确定性业务流 | DAG 状态机, 节点路由, 多 Agent 岗位流 |

## 3. 2026 年夏天的行业大论辩：Loop 还是 Graph？

Peter Steinberger 发帖后，业界主要形成了两大派别与一种整合共识：

1. **“Graph 必然派”**：
   - 主张：单个 Agent 的自主性存在固有的“熵增”。没有显式的图路由与状态机，长任务一定会因为累积幻觉而坠入 Doom Loop（死循环）。必须把控制权夺回，用代码编写的 DAG 或有限状态机（FSM）来规范 Agent 的行为边界。
2. **“过度设计怀疑派”**：
   - 主张：很多所谓的 Graph Engineering 不过是工作流软件（如 Airflow、Camunda）在 AI 时代的包装。真正的通用智能应该由更强的模型自治（自主 Loop）解决，硬编码的图结构会让系统丧失灵活性。
3. **“分层工程整合共识（主流）”**：
   - Harrison Chase 与多数生产落地团队达成共识：**“Graph 与 Loop 不是对立的，生产级 Graph 本身就是由包含循环的子图（Cyclic Graphs）组成的。”**
   - 宏观上是 DAG（前向递进的阶段：需求分析 -> 架构任务分解 -> 并发编码 -> 集成测试 -> 交付）；
   - 微观上是 Loop（编码节点内部遇到 lint 报错自动重试 3 次）。
