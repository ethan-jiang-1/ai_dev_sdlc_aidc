# Paweł Huryn

- 身份：The Product Compass，作者
- 角色定位：偏 operator / PM 视角的硬核实测人物
- 为什么值得单列：他不是只讲感觉，而是拿 effort dial、延迟、token、knowledge layer 做了系统性实测
- 核心贡献：把 Fable 讲成一个会“审计”你的现有规则系统的模型
- 最重要的判断：你的 CLAUDE.md、skills、知识层，很可能是为更弱模型写的，它们会反过来拖住更强模型

## 这人到底说了什么

- 他最抓人的开场是：`Fable 5 is the first model that's made me feel audited.`
- 他强调 Fable 会主动发现你的规则冲突，而不是机械执行所有旧指令。
- 他对 effort dial、首 token 延迟、in-flight token 使用做了测量，而不是只讲主观体验。
- 他也很早强调 safeguard / reroute / silent degrade 这些迁移风险。

## 最值得记住的句子

> “Fable 5 is the first model that's made me feel audited.”

> “Previous models followed my rules. This one evaluated them.”

> “A system maintained by model N tends to preserve the errors model N can't see.”

## 我的判断

- Paweł 是很典型的“不是超级大 V，但确实有硬货”的人物。
- 他最有价值的地方是把 Fable 放进真实知识层和规则层里测试，而不是只跑 demo。
- 对你现在这套人物资料库来说，这种人正是最该被单列的 Bob/Joe 型样本。
