# Outline — Loop Engineering（入门场）

## 0. 这场要解决什么

听众不需要先学会写 goal；他们需要带走一张交接面地图：**从基线看起，每交出一个决定就配一组护栏；反馈要参与后续决策，环境结果可复查，人的纠偏与接手有入口；决定交续跑时才需要目标与检查的门票；选对档位比爬到顶重要。**

**开场故事**（2026-10-01 用户定）：loop engineering 为什么存在——模型已经能根据环境反馈反复尝试并修正，所以有人开始「写 loop」。Addy Osmani 将其定义为：用系统替代人逐轮提示 agent；本场把反馈、判断和边界讲清楚。

**反馈是贯穿全场的第二根线索**：下一步是否依据上一轮反馈决定，是本场区分反馈循环与盲目重跑的判断；证据可以支持修正、重查或停止，不要求每轮动作不同。反馈有环境和人两路，也可包含 Eval 回传理由；环境结果可落成工件，服务恢复与审计，人的纠偏、标准变更和拒绝理由要能回到后续动作。落盘是可审计实现，不是 loop 的定义条件；两路都要有可达入口，不等于每轮都要人介入。**全场使用同一本场虚构示意：PM 离开前授权 Agent 在 `agent/search-pagination` 分支加分页；Agent 产出 PR 与测试结果，浏览器返回丢查询，随后按反馈修正、触及出口或停止，最后把控制、验收、业务结果分账。字段、状态、分支名与事件均为教学设计，不是事故、真实运行或收益证据。**

v2 把「先给 Goal」当全场地基（第 3 页），对站在基线的通识听众是提前征税。v3 的次序：基线无需先配续跑机器，但按风险守范围、权限和检查 → 动作档先交动作授权 → 到续跑档门口，再讲 goal/eval 的门票。要求放到对应交接面，不把低档写成无需治理。

**一页一概念**：每页只讲一个概念，承载页（N03 路线图、N10 门票转折）负责呼吸与承接。

Andrew Ng 的三环作为备注里的上位背景；N21 用上下文优势承重。控制链是研究骨架，本场不再单独立页，它作为检查表随交接面出现。

## 1. 核心判断

**从基线看起，每交出一个决定就配一组护栏；下一步要依据反馈决定，必要时调整，环境结果与人的纠偏都要有可达通道；交续跑的门票是写清终态和证明方式，条件成立仍不等于验收；选对档位，比爬到顶重要。**

## 2. 系统（定档四问贯穿全阶梯）

四个定档问题贯穿——每一档都要能回答同一组问题，答案随档位变化：

```text
谁启动下一轮？      → 基线：人 ／ 动作：人 ／ 续跑：目标条件 ／ 唤醒：时间表或事件
谁判断完成？        → 基线、动作：人 ／ 续跑：裁判判条件、人守验收 ／ 唤醒：仍需回到验收
谁能改变系统？      → 每个交接面的授权范围；执行方不自行改判据或权限
出了错谁能停下接手？→ 每个交接面的停止、指定责任人与恢复入口
```

四问是本场把研究判定翻成听众可用语言的教学映射，不是某位 KOL 提出的统一等级。每个交接面都要回答它们，页面给出基线与各档答案；这就是本场的检查表。

## 3. 叙事弧

```text
1.  它说做完了：从自动工作的承诺，转到完成声称为何可信
2.  为什么有人开始写 Loop：系统接替人逐轮提示 Agent，但不保证每次修对
3.  一张阶梯：动作、续跑、唤醒分别交决定，不按成熟度排名
4.  基线：人发起下一轮，也判断结果；留在这里是合理选择
5.  Feedback 参与下一步决策：可支持修正、重查或停止；无视结果固定重跑才像抽卡
6.  留存证据：支持恢复与审计，不是 Loop 的定义条件
7.  交动作授权：少点允许，人仍逐轮判断
8.  规则能否限制执行：提示要求、偏好与隔离不可混同
9.  一次批准：绑定动作、目标范围、有效期
10. 门票变贵：系统决定是否续轮，人仍守验收
11. Goal：分页终态与真实路径证明一一对应
12. 约束与兜底：限制路径、无效重复和预算
13. 环境结果作证据，Eval 按判据判断；判定理由可成为下一轮 Feedback
14. 三出口：继续带理由，达成是停止候选，不可能停并交人
15. 实际路径：检查有无被绕过，上限和原有失败是否可解释
16. 负例：先证明会拒绝这一类已知错误，不承诺全覆盖
17. 提前宣告完成：追证据与驱动，不信数量、语气或局部通过
18. 第一层：同一分页案例，从笼统完成拆成逐条证据
19. 第二层：单测保留，用户路径另证
20. 第三层：修分页行为，不削弱断言
21. 人的反馈：补业务信息，纠偏与拒绝理由进入下一轮
22. Stop 与 Accepted：停止原因和验收依据分别记录
23. 产出和业务结果：签认之后，还要设观测窗与责任人
24. 唤醒：自己起跑，不证明达成或持久运行
25. 人的责任：位置变化，不等于退出 Loop
26. 按任务选范围：完成条件不清楚，就保留人判断
27. 回去答四问：从当前真实答案出发，决定交到哪一步
```

## 3.1 六章的认知节奏（不增加章节页）

章节名是听众可见的小标，不是内部分类。各章首沿用现有页面，在 title 上方显示章名；其余页保留 chapter 元数据，章末用一句口头回扣。页号、练习嵌点不变。

| 可见章节名 | 页范围 | 核心问题 | 理解收获 | 章末回扣与转场 |
|---|---|---|---|---|
| 第一章｜为什么要写 Loop | N01–N03 | 它说完成，凭什么信？ | Loop Engineering 用系统接替逐轮提示；阶梯表示交出的决定，不表示人的高低。 | 我们先不讨论爬多高，先看看你现在怎样判断每一轮。 |
| 第二章｜从人的判断到反馈 | N04–N06 | 下一步为什么这样做？ | 基线里人发起和判断；Feedback 参与下一步决策，留存证据让别人能恢复、复查。 | 反馈接得上，才开始谈第一个可以交出的决定：动作授权。 |
| 第三章｜先交动作，不交判断 | N07–N09 | 允许它动手，究竟允许了什么？ | 授权要有执行边界，并绑定动作、目标、有效期；自动动手不等于自动续跑。 | 少点几次允许之后，每轮看不看、继续不继续，仍由你决定。 |
| 第四章｜续跑之前，先配判据 | N10–N16 | 你不逐轮看，系统凭什么继续或停？ | Goal 写清终态，Eval 按证据判条件；出口、覆盖和负例共同检验这条判定路径。 | 我们验证了检查能拦住已知错误，还不能因此相信所有完成声称。 |
| 第五章｜它说完成，还要查什么 | N17–N23 | 条件通过是否足以认定交付成功？ | 清单、真实路径和判据保护约束完成声称；人的反馈、产出验收与业务结果分别保留。 | 一次停下的含义弄清了，最后再看谁能让它下次自己起跑。 |
| 第六章｜决定交到哪一步 | N24–N27 | 哪些决定值得交，哪些要留在人手里？ | 唤醒不是达成；逐面回答四问，按任务选交接范围，留在低档也是合理选择。 | 回到开场：不靠一句完成，而靠决定、边界、证据和接手人。 |

六章不是六套新术语：前三章把“谁决定”讲清，第四章交出续跑前先配条件，第五章核查完成含义，第六章把唤醒与任务选档收回来。60 分钟预算仍以 §8 为准；章节边界不要求时间平均。

## 4. 页面

每页章节归属按 §3.1 的连续范围确定；文稿逐页提供 chapter 字段，不能由做片方另分章节。

### 第一章｜为什么要写 Loop

**N01 · 它说做完了**
你离开后它继续跑，回来听到「完成」；真正的问题是这句话凭什么可信。

**N02 · 为什么有人开始「写 Loop」**
Osmani 将 Loop Engineering 定义为用系统接替人逐轮提示 Agent；系统再根据反馈组织下一步。

**N03 · 今天的路线图：一张阶梯**
从基线看起，每交出动作、续跑或唤醒的决定，就配相应护栏；这是一条教学路线，不是人人必经的等级。

### 第二章｜从人的判断到反馈

**N04 · 你已经在阶梯上**
逐次提示是基线：人发起下一轮，也判断这一轮的结果；留在这里是合理选择，不是失败。

**N05 · 反馈让 Loop 成立**
下一步依据环境或人的反馈决定，才形成反馈循环；无视上一轮结果的固定重跑，才是抽卡（比喻）。

**N06 · 把反馈留成可复查的证据**
需要恢复或审计时，留存退出码、日志、产物和版本；留存让反馈可复查，但不是 Loop 成立的必要条件。

### 第三章｜先交动作，不交判断

**N07 · 交出动作授权**
让 Agent 在授权范围内动手，省掉的是逐条打断，不是结果判断；每一轮仍由你查看。

**N08 · 规则要能限制实际执行**
要求模型遵守规则，不等于运行时能阻止越界。

**N09 · 一次授权，绑定三项边界**
一次批准绑定动作、目标范围和有效期；其中任何一项改变，都要重新批准。

### 第四章｜续跑之前，先配判据

**N10 · 下一级的门票贵了**
交出续跑权，是让系统按约定条件决定是否再开一轮。

**N11 · Goal 要写清终态与证明**
Goal 要写清可观察终态，以及证明它的检查路径。

**N12 · 约束与兜底**
约束写清不能改变什么，无进展出口和资源上限限制无效续跑；系统不能只有目标，没有兜底。

**N13 · 环境结果作证据，Eval 按判据判断**
Eval 按判据解释环境证据；判定理由也可以成为下一轮的 Feedback。

**N14 · 三个出口各管一件事**
只有未达成、可重试且未触出口时才继续；其他状态按原因停止或交人。

**N15 · 检查要覆盖实际执行路径**
有检查，不等于实际执行经过了检查；要确认真实路径确实经过它。

**N16 · 先证明检查能拒绝错误**
放手前，先用一个已知错误验证检查会拒绝；这只证明该类错误能被拦住，不证明覆盖了所有风险。

### 第五章｜它说完成，还要查什么

**N17 · 风险：提前宣告完成**
文件数量、肯定语气或局部检查通过，都不足以单独证明目标达成。

**N18 · 第一层：清单逐条核查**
把分页目标拆成逐条条件；打开、返回、查询保留分别有证据，才更新对应的完成标记。

**N19 · 第二层：走完真实用户路径**
单测和接口检查各有价值，但不能单独证明完整用户路径；分页是否可用，还要从用户入口走一遍。

**N20 · 第三层：不能靠削弱测试过关**
保住判据，检查通过才有原本的意义；Agent 应修分页行为，而不能自行删断言或跳过测试。

**N21 · 人的反馈要能改变下一轮**
人的业务信息和纠偏理由，应参与后续行动的决定。

**N22 · Stop ≠ Accepted**
超时、资源耗尽或模型收尾，只说明控制流停止；验收要由有权的人依据证据另行签认。

**N23 · 产出和业务结果是两本账**
PR、测试和日志支持产出验收，不自动证明业务变好；采用率、满意度等外部结果，要另设观测与责任人。

### 第六章｜决定交到哪一步

**N24 · 让它自己起跑，不等于目标达成**
唤醒只安排何时起跑，不证明目标达成。

**N25 · 每一档，人守的责任不同**
交出的决定不同，人要守的标准、权限和接手责任也不同；人不是被移出了 Loop。

**N26 · 什么时候不要往上爬**
完成条件还写不成可观察的句子，就保留人工判断；留在低档是按任务作出的控制选择，不是失败。

**N27 · 回去先定档**
先写清当前四问的答案，再选择把哪项判断交给系统。

## 5. 系统落点

本场的系统是**定档四问**（§2）＋**反馈双路**（§0）：四问在 N04/N10/N25/N27 逐档给答案；反馈双路在 N05/N06（环境反馈基建）、N21（人的反馈）承重，N13/N14/N15 是它们在交续跑档的机器化形态。N03 的阶梯是本场教学映射，不是行业成熟度标准。旧版「三因子减值守公式」在 v2 已降级，v3 移除——「减少值守」不再是本场目标，**定档与配护栏**才是。

## 6. 语言与边界

- 重要英文保留并首现解释：Loop/Loop Engineering、Agent、Feedback、Harness、Goal、check、Eval/evaluator、Stop/Accepted。用中文讲因果，不机械全翻，也不把英文句法搬成中文。术语实质区别集中在文稿头部，逐页首次口播补解释。
- 基线、档、授权范围、可执行策略件、裁判比喻、负例、验收、外部结果逐页白话说明。上屏不使用 LE0–LE3 编号；口头用「基线／动作档／续跑档／唤醒档」。这是一张交接面教学地图，不是成熟度模型。
- 单稿交付：最终 PPT Agent 只收文稿；全场背景、六章问题与转场、逐页知识、练习最小题面、证据边界都在稿内。大纲是维护权威，不是制作补课资料。
- 「抽卡」是教学比喻，上屏可用，首现标注（比喻）。
- 控制链是研究骨架，本场不立页、不说成某位 KOL 的原话；其节点（目标、反馈、裁判、出口、分账）随档位以检查表形式出现。
- 不把 Stop、Blocked、待观测 说成完成；参数（3/20 拒绝、7 天过期等）留备注。
- 支线（多代理编排、改进循环自身）只在 N24 提一嘴「高级内容、非必经」，不展开。
- 反馈措辞纪律：人的反馈不是每轮机械检查；纠偏可包含判断，拒绝后若仍允许继续，理由应进入下一步。硬拒绝或停止不承诺再开一轮。
- 故事措辞纪律（N02）：使用 Addy Osmani 已核一手定义，不用 Boris/Peter 名句；不把“根据反馈修正”说成“知道错就必然改对”。署名 callout 限 N02/N05/N21/N24 四页，中文转述显式标明。
- 交接面纪律：教学按基线→动作→续跑→唤醒累计阅读；真实系统须分别审计三个授权轴，`/loop` 只证明唤醒，不保证前两面成立。
- N18–N20 使用同一分页教学案例，只上屏短前后对照，清单字段、测试保护实现及源码边界全部留备注。
