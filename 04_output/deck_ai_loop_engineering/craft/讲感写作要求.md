# 讲感写作要求 — manuscript 怎么写才容易被讲出去

> 2026-10-02 立。来源：入门场成稿（`../intro/final-deck/`）与 `../intro/manuscript/manuscript-intro.md` 的对照复盘——原稿概念都对，成片后「很难讲」，最终按讲感重排为 25 页成稿。逐条证据在 `../intro/final-deck/README.md`，本文件只放要求。
>
> **地位**：这是讲感层的宪章，适用于两场及今后所有 manuscript。各场 `AGENTS.md` 管结构与系统的硬线（页数预算、定档四问、自洽），与本文件冲突时以 AGENTS.md 为准；本文件也不取代 AGENTS.md 的知识交付要求——讲感裁的是**上屏的量**，稿内知识层不减（见判断四、五）。`WORKFLOW.md` Phase 3 的叙事性考核，按第三节过检执行。

## 一、五个根本判断

条款随排练反馈不断改；判断轻易不动。遇到本文件没覆盖的新情况，先回这五条找答案；判断不够用了才新增判断，然后才长出新条款。

**判断一：新概念只能踩在听众已有的经验上传。**
概念都新，听众没有我们词汇所指向的经验；术语先要有经验锚点，再进定义。所以案例必须是**该场听众**母语的工件（入门场是投标书这类业务工件；技术场面对工程师，工程工件就是母语），例子必须让听众在心里**自己**得出结论——自己得出的才消化，消化了才转述给没来的人。
*（落到：定案例三条；定页·先现象后机制、每页一句场景行。）*

**判断二：页是记忆单位，不是知识单位。**
听众每页带得走的新东西很少；「content ≤3 条」管的是行数，管不住负荷。一页是否成立，判据是**听众一口吃得下吗**。这不是机械数数（2026-10-02 用户澄清）：互为对照的同一拍子可以同页，独立新东西堆多了就拆或下沉。
*（落到：定页·每页一句场景行、一页一个视觉任务、轻重交替；过检 2。）*

**判断三：台面只负责带走，覆盖是手册的事。**
一场 talk 的成功标准不是讲全，而是听众带走的那几句是真的、记得住、转述得出去。发现某页在教操作规程或堆产品细节，这页就不该站在台面上——规程归《循环交接手册》，承重的知识沉进稿内层（判断五），台面只留带得走的东西。**砍的是台面位置，不是知识本身。**
*（落到：过检 7「规程细节零上屏、数字与产品细节进页底」；下沉路径见判断五。）*

**判断四：精度不上屏，不等于精度消失。**
讲感和准确不冲突，冲突的只是「都想占上屏」。解法是分层：钩子上屏，限定、证据边界、适用范围下沉到场景行、页底注或口播——**每一层都不许丢，丢哪层都是错**。全上屏是讲不动的页，全下沉是无凭的页。
*（落到：定句·subtitle 主张正句、导航与页底注职责；交稿前·spoken-only 登记。）*

**判断五：上屏瘦身，稿内不减（2026-10-02 用户定）。**
与判断四同一逻辑：分层不是减量。manuscript 有两类读者：台下听众读上屏层，PPT Agent 与讲者读稿内层。稿内那些不上屏的承重内容——稿头背景与全案案例约定（哪些虚构、批准边界、继承禁区）、术语表（首现解释＋使用边界）、章节地图与节奏、逐页知识说明（认知变化、因果关系、案例前提、表达必需、**易错画法**）、现场判断串、追问卡、附录实战样本——是做片不出错、讲者讲得深的保证：做片方未必懂 loop engineering，少一节就乱发挥。讲感只裁上屏的负荷；稿内层的质量标准是**自足**——PPT Agent 不读其他文件能做对，讲者只读稿内能讲深、被追问能现场拆。
*（落到：过检 8；讲感条款一律不适用于稿内层的取舍。）*

## 二、做法（按写作时序：定调 → 定案例 → 定页 → 定句 → 交稿前）

### 定调（动笔前）

- **调性：冷静的较真**。不贩卖焦虑、不喊口号，每页都落在「把关」这个动作上；句子口语化、主谓宾短句。调性全场一致，不因页而变。

### 定案例

- **概念槽选案例**：先列全场要教的概念槽（验收人、红线、停止、待观测、覆盖缺口、削弱检查……），再挑一个该场听众日常工件**天然全有**的。靠类比硬接的概念，讲一个悬一个。入门场投标书全有这些槽位；站内搜索分页只有工程师那一半——这才是换案例的真实理由。
- **例子过转述检验**：听众能不能不看屏，把例子讲给没来的人、还得出一句话结论。转述不出的例子只是插图。好例子有时间、有动作、有看得见的对象（周五下班前让 Agent 起草投标书；周一它说完成；你敢盖章吗？）。
- **能问不陈述**：要听众自己作答的事，写成对他的问句，不写成关于案例角色的陈述。共鸣发生在他作答的那半秒。

### 定页

- **先现象后机制**：新机制之前，先让听众在问题或代价里卡一下（「周末你不在，谁来决定要不要继续改下一版？」）。上来就定义术语是俯视。
- **全场无落后感**：引入新东西前先承认听众现状有道理（留基线是选择不是失败、先别爬）。平视打开耳朵，俯视关上耳朵。
- **每页一句场景行**：把案例的这一拍写成一行上屏——第二人称、有画面、转述得出。它是判断一的落点，也是冷启动测试的第三根支柱（见交稿前）。
- **一页一个视觉任务**：听众的眼睛只做一件事——一次对比、一张表、一个阶梯。
- **轻重交替**：密页（机制、矩阵）后给比喻页或场景页，让听众有喘息；具体节奏排练说话。

### 定句

- **subtitle 是可讲的主张正句**：听众能顺着它接上你下一句的那种句子。「不等于／不证明」连环出现是防御信号——钩子留下，限定移下去。
- **金句预埋与回响**：每章一枚金句，在本章首现页出现（告示不是门锁），在收尾「带走」页回收。金句是设计出来的，不是讲的时候碰上的；自造，或用已回源复核的署名引语。
- **人称与角色**：上屏用该场听众母语里的称谓——你／它／人，及案例工件自带的自然角色（评标人、盖章的人）；内部角色代号（PM、Eval、评审人编号这类要解释才懂的命名）不进上屏，只在口播和稿内层出现。
- **导航印在页上**：过渡短线与跨页指针写进页面，不全靠讲者记；页底注承担限定、教学数字声明与证据边界。

### 交稿前

- **冷启动测试**：只读 title＋subtitle＋场景行、不看备注能讲一分钟，才是给讲者的页；需要读完备注才知道说什么的页，是给读者的。
- **朗读测试**：出声读一遍，需要换气两次的句子拆掉。
- **spoken-only 登记**：只在口播成立的精度（如「基线不算已交动作」）逐条列在稿头，标明由讲者口播承担。不让做片方在「画得准」和「好讲」之间替我们猜。

## 三、交稿过检（逐条可执行）

1. 概念槽核对：全场每个概念在案例工件里有原生槽位。
2. 逐页问「听众一口吃得下吗」：吃不下的页，已拆或已下沉。
3. 逐页场景行：第二人称、有画面、转述得出。
4. 机制页之前有现象页；全场没有让听众落后的暗示。
5. 逐页冷启动、朗读测试通过。
6. subtitle 无防御性否定连环；每章金句首现＋回收；收尾带走页在。
7. spoken-only 清单已登记；规程细节零上屏；数字与产品细节进页底注。
8. 稿内层自足（判断五）：背景与案例约定、术语表、章节地图、逐页知识说明与判断串、追问卡、实战样本全部在位，PPT Agent 不读其他文件能做对。

## 四、维护

- 本文件从**排练与复盘反馈**演化：现场讲暴露新问题，先回五个判断找归属；判断不够用了才新增判断，然后才长出新条款。只堆条款不动判断，这份宪章会烂掉。
- 条款与判断的增删由用户定；复盘证据只进对应复盘件（如 `../intro/final-deck/README.md`），不在本文件复制。
- 改动本文件后，回头核对各场 AGENTS.md 与 `WORKFLOW.md` 对应条目是否需要同步措辞。
