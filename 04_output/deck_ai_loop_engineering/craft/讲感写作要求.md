# 讲感写作要求 — 让 manuscript 容易被讲出去

> 2026-10-02 立。来源：入门场 final deck 与 `intro/manuscript/manuscript-intro.md` 的对照复盘（证据与逐条判读见 [`../intro/final-deck/README.md`](../intro/final-deck/README.md)——那稿成片后「很难讲」，被讲感重写成了 25 页成稿）。
> 适用：本场两份稿及今后所有 manuscript。与各场 `AGENTS.md` 冲突时以 AGENTS.md 为准——本文件只管「怎么写才好讲」这一面。

## 定调：三个根本判断

1. **台阶从听众的地面量起，不从材料内部量起。** 概念都新，听众没有我们词汇所指向的经验；新概念必须踩在听众已有的经验上传过去。例子就是那块跳板——它负责把新概念接到听众自己身上。
2. **页是记忆单位，不是知识单位。** 听众每页只带得走一两件新东西；「content ≤3 条」约束的是行数，不是认知负荷。行数合规、负荷超标的页照样讲不动。
3. **台面只负责带走，覆盖是手册的事。** 一场 talk 的成功标准不是讲全了，而是听众带走的那几句是真的、记得住、能转述给别人。规程细节归《循环交接手册》，研究层边界归备注。

**调性**：冷静的较真。不贩卖焦虑、不喊口号，每页都落在「把关」这个动作上；句子口语化、主谓宾短句。写完朗读一遍，一句需要换气两次就拆。

## A. 听众与台阶（共鸣层）——2026-10-02 用户补

1. **先选「概念槽全」的听众母语案例。** 选案例先列全场要教的概念槽（验收人、红线、停止、待观测、覆盖缺口、削弱检查……），再挑一个听众日常工件天然全有的。入门场的投标书全有这些槽位，站内搜索分页只有工程师那一半——这就是换案例的真实理由。软件词汇只留工具名（如 /goal）。
2. **例子要打动思考，不止演示概念。** 好例子让听众在心里自己得出那页的结论；自己得出的才算消化。检验法：听众能不能把例子转述给没来的人、还得出一句话结论——转述不出的例子只是插图。
3. **第二人称＋可视细节。** 场景行写「你」：周五下班前、周一早上、你敢盖章吗。有时间、有动作、有看得见的对象，听众脑中出画面；画面是记忆的钩子。案例角色名（PM／Agent／Eval）不上屏，人称用你／它／人。
4. **能问不陈述。** 把成立的陈述改成问听众自己的问句（「你敢盖章吗？」「拦不住，就只是告示？」）。问句让听众变成当事人，共鸣发生在他自己作答的那半秒。
5. **新概念之前先给现象。** 机制页之前，让听众先在问题或代价里卡一下（「周末你不在，谁来决定要不要继续改下一版？」）。问题页→机制页是默认台阶顺序；上来就定义术语是俯视。
6. **全场不给听众落后感。** 引入新东西前先承认听众现状有道理（留基线是选择不是失败、先别爬、不往上走不需要理由）。平视打开耳朵，俯视关上。

## B. 页面节奏（记忆层）——2026-10-02 用户补

7. **数新东西，不数行数。** 「一页一个概念、出现第二个概念就拆页」**不是机械原则**（2026-10-02 用户澄清）：本义是一页概念量不要太多，听众吃不下去。执行时按负荷与消化判断——第二个概念与第一个互为对照、属同一拍子（告示 vs 门锁），可以同页；听众要同时消化的独立新东西过多，就拆页或下沉备注。「一两个」是手感参照，不是触发器；拆页的判据是「这页听众吃得下吗」，不是「出现第二个了」。
8. **一页一个视觉任务。** 左右对比、填三格、看阶梯——听众的眼睛只做一件事；两张图加一段字等于没人看。
9. **轻重交替。** 密页（机制／矩阵）后跟比喻页或场景页；章首问题页轻，章内机制页重，章末回收页轻；全场不出现连续三页同重。
10. **冷启动测试。** 只读 title＋subtitle＋场景行、不看备注能讲满 60 秒的页才合格。需要读完备注才知道说什么的页，是写给读者的，不是写给讲者的。

## C. 句式与上屏（表达层）

11. **subtitle 是可讲的主张正句。** 一行以内，至多一个否定式；出现两个「不等于／不证明」就把限定移到页底注或口播。钩子上屏，限定下移。
12. **每章一枚金句，章内预埋、收尾回响。** 金句在本章首现页出现（告示不是门锁 →／goal 不是许愿是合同），在收尾「带走」页回收；自造，或用已回源复核的署名引语。收尾必有「带走」页：每章一句，一张照片带走全场。
13. **过渡线印在页上。** 「→」形式的短导航和跨页指针（「见第 10–11 页」）写进页面，不全靠讲者记；页底注承担限定、教学数字声明与证据边界。

## D. 精度与覆盖（纪律层）

14. **spoken-only 清单。** 只在口播成立的精度（如「基线不算已交动作」「教学路线不是人人必经的等级」）逐条登记在稿头，标明由讲者口播承担；不让做片方在「画得准」和「好讲」之间替我们猜。
15. **覆盖下沉。** 发现某页在教操作规程细节，就是该砍的页——规程给手册，边界给备注，台面只留带走的东西。
16. **数字与产品细节进页底。** 教学数字上屏必须带「仅为教学示意」；产品参数、源码快照、issue 编号一律页底注，上屏只留一句结论。

## 写完一稿的过检清单

- [ ] 案例概念槽核对：全场每个概念在案例工件里有原生槽位；案例是听众母语
- [ ] 逐页问「听众一口吃得下吗」：吃不下就拆页或下沉（手感判断，不数数）
- [ ] 逐页场景行：第二人称、有画面、≤60 字
- [ ] 能改问句的陈述都改了；机制页之前有现象／问题页
- [ ] 全场无让听众产生落后感的语句
- [ ] 逐页冷启动测试通过（不看备注可讲 60 秒）
- [ ] subtitle 一行内、否定式 ≤1
- [ ] 每章金句首现＋回收；收尾「带走」页在
- [ ] 过渡线与跨页指针印在页上
- [ ] spoken-only 清单已登记
- [ ] 规程细节零上屏；数字与产品细节进页底
