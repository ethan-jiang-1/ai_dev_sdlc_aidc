# craft/ — 可讲的 manuscript 写作要求

**定位**：本目录只放一件事——manuscript 怎么写才容易被讲者讲出去、被听众带走。2026-10-02 立，来源是入门场 final deck 与原 manuscript 的对照复盘：那稿成片后「很难讲」，被讲感重写成了 25 页成稿，对照出的是写稿手艺，不是叙事骨架问题。

| 文件 | 说明 |
|---|---|
| [`讲感写作要求.md`](讲感写作要求.md) | **唯一权威**：定调（三个根本判断＋调性）＋四组要求（听众与台阶／页面节奏／句式与上屏／精度与覆盖）＋写完一稿的过检清单 |

**何时读**：写新 manuscript 之前；改稿后自检时；`WORKFLOW.md` Phase 3（叙事性＝调性把控）考核时。

**分工**：
- 本目录管「怎么写才好讲」这一面；各场 `AGENTS.md` 管该场的做完标准、红线与流程，冲突时以 AGENTS.md 为准。
- 对照复盘的**证据**（final deck 改了什么、为什么）在 [`../intro/final-deck/README.md`](../intro/final-deck/README.md)；本目录只放**要求**，不复制判读正文。
- 改本目录要求时，回头核对各场 AGENTS.md 与 `WORKFLOW.md` 对应条目是否需要同步，不复制正文。
