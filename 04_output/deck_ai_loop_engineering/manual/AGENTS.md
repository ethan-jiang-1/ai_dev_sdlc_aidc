# AGENTS.md — 循环交接手册的纪律

> 2026-09-30 立项。本目录是 Loop Engineering 三件套的第三件：两场 keynote 负责「凭什么信」和「链怎么治理」，本手册负责读者回去**做**——把哪个决定交给循环、交之前配什么护栏、它说做完了凭什么放行。

## 体裁（这是手册，不是课、不是 talk）

1. **单文件双篇（2026-09-30 用户定合册）**：全部正文在 `循环交接手册.md` 一个文件——卷首（语汇权威）＋入门篇（判断层，顺序读）＋高级篇（操作层，按时刻翻）。不开散文件；新增内容并入对应篇节。
2. **高级篇按时刻组织，不按叙事组织**。每一节是一个使用时刻（交动作 / 交续跑 / 交唤醒 / 升一档 / 它说做完了 / 它停了 / 可选方向）；读者从任何一节翻进来都能用，不依赖读过前一节。论证不进正文——为什么这样做，两场 talk 讲过了；手册最多保留三行以内的「为什么」。
3. **每节自足**：本节要查的问题、照做的步骤、模板与反例、出错了怎么办。
4. **表格、清单、模板为主**，段落最少化。判断标准：读者能不能在两分钟内找到要抄的那一行。**可抄之物优先**：填好的表、配置片段、走一遍的日志、代码样例——只有原则没有实物的节不算成节。
5. **「什么时候不要」是一等公民**。每节的反过度工程与退回条件和正面步骤同权重，不缩成脚注。

## 参数纪律（手册会被照抄进生产配置，这条最高）

6. **每条具体参数**（阈值、时长、费用、命令语法、默认值）必须带**版本锚＋观测日期**，写法统一为「（产品与版本，观测 2026-XX-XX）」。
7. **docs 与源码打架时以源码为准**；分歧处显式标注两个值与各自出处。
8. **无锚不上**：找不到版本锚的参数宁可不写，写成「以你所用版本的官方文档为准」。

## 主张与溯源

9. **主张不超出三个上游**：研究层 `result/landscape.md`（判定）、实践层 `loop_governance` 的 `backbone.md`＋`manual.md`（操作）、`capability_ladder/00-map.md`＋`result-reliability-interface.md`（交接面判定与放行链）。
10. **编辑合成显式标注**。凡本手册自己做的组合（LE 交接面 × 实践层构件的映射、各节的步骤编排），标注「本手册编排」；上游各自有一手的，写明是谁的一手。
11. **对外自足**：正文不出现仓库内部路径、层级名（研究层/实践层）、姊妹项目或 talk 代号。溯源以「来源注」形式呈现：产品官方文档名＋观测日期，或署名原文。内部 evidence 指针只写在正文文末的 HTML 注释 `<!-- 来源映射 -->` 里，供维护者回溯，不进正文。
12. **产品参数不通用化**：任何一家的拒绝次数、超时分钟、默认轮数只属于那一家，不写成行业阈值。

## 状态语汇（全手册统一，不得各节自造）

`Not yet met`／`Met`／`Impossible`／检查失败／预算耗尽／`blocked`／`awaiting_human`／`stopped`／`accepted`／`outcome_pending` 的「最多可声称什么、不能偷换成什么」以 [循环交接手册.md](循环交接手册.md) **卷首·状态语汇表**为唯一权威。

## 完成标准（每节成稿的自检三问）

1. 零上下文读者单节可用，不需要先读别的节或听过 talk？
2. 每条参数带版本锚与观测日期？
3. 每条主张能指到上游（landscape / backbone / manual / 00-map / 交接页），编辑合成处已标注？

三问有一个答「否」，该节不算成稿。
