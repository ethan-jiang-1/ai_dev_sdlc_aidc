# 技术场练习 · 构造档（三题）

> 每题 7–8 分钟。三题做完，你手里有三件自己写的工件：一份 goal、一个负例、一张新增授权检查表。写不完的模板直接带走当作业。

---

## 练习 1 · 给你的任务写一份合格的 goal（8 min）

拿你带来的真实任务，填满五件（缺一件都是不合格的 goal）：

```text
目标（一个可度量终态——环境里能观察到的状态，不是主观感受）：
  ____
检查（声明式——哪条命令、哪个退出码、哪份输出能证明）：
  ____
约束（路径上不许变的东西——文件、接口、行为）：
  ____
无进展出口（连续 N 轮没有改善/没有工具调用就停）：
  ____
上限子句（最多 N 轮 / M 分钟）：
  ____
```

**对照全例自检**（Addy Osmani《Practical Loop Engineering》，发布 2026-08-14、观测 2026-09-26，[作者原文](https://addyosmani.com/blog/practical-loop-engineering/)）：这是作者示例，92 分、1.8s、两轮与 10 轮均不是通用门槛，不可原样抄生产。

> "Refactor the data-fetching layer in Dashboard.tsx until Lighthouse performance score is >= 92 and LCP is under 1.8s as shown by the Lighthouse CLI output. Do not change the public API of any hooks. Each turn must improve at least one reported metric; abort if two consecutive turns show no improvement. Stop after 10 turns."

**自检五问**：终态是可观察的吗（换成别人，他能用你的检查语句判吗）？检查是声明式的吗（写的是「怎么证明」不是「认真做」）？约束有吗？无进展出口和上限**都**带了吗？你的业务结果看得见吗——看不见的话，goal 只能写产物终态，外部结果另行观测。

## 练习 2 · 设计一个负例：已知错误能被检查拦住吗（7 min）

**前提**：没有验证过负例的检查，不能据此声称覆盖了该错误路径。

步骤（在可回滚分支上）：

1. 挑你的机器闸门里**最自信的一条**（某个测试、某条 lint、某个退出码断言）；
2. 在正确版本、通过的基线上改坏被测行为或 fixture，保留原断言；先写下预期哪项检查失败。测试保护另做一组：尝试删/跳过检查，预期策略或轮末差异核对能拦；
3. 只执行针对该错误的检查：**预期的失败被拦住了吗？**
   - 被拦 → 记录错误、运行版本、原始输出及触发检查；仅说明覆盖了这个负例，不是通用安全证明；
   - 未被拦 → 记录检查漏在哪条路径，修检查再做一次；不能据此断言它从未覆盖任何路径；
4. 只还原本题引入的改动，保留原有未提交工作；核对 diff 和基线检查恢复，别用全仓重置。
5. **反馈闭环补一行（2026-10-04 增）**：把你刚才拦住的失败当成一条真实反馈，现场补一行去向——**正确版本的原始结果在哪、谁消费它（进哪个分支）、预期处置是什么（修复/重查/有界重试/停止/交人）**。完整闭环（红灯送达正确消费者并产生预期处置）作为回去演练项；纸面填完不记已部署。

**追问自己**：这个负例落在哪一层——测试文件被删？基线本来就失败？检查看的是转述还是真实输出？「缺失的测试没有失败」不能算通过。只贴日志、或只说「模型读过」，不能证明反馈闭环已演练。

## 练习 3 · 新增授权前置检查表（8 min）

对着你的任务，三步：

**第一步：定档。** 三个交接面，你现在交了哪个？

| 交接面 | 交了吗 | 证据是什么（写下来） |
|---|---|---|
| 动作审批（授权面内的动作不再逐个批） | 是/否 | ____ |
| 续跑（本轮结束后它自己决定是否再开一轮） | 是/否 | ____ |
| 唤醒（定时/事件自己起跑） | 是/否 | ____ |

**第二步：写出本次拟交出的决定，选择适用检查。** 三个交接面分别核对，不从一个命令推断其他面已配齐；不适用项写明理由。

| 交接面 | 必查项 | 过/不过/不适用及理由 | 证据或差什么 |
|---|---|---|---|
| 动作 | 授权变异失效；允许／需人批准／硬拒绝三路可达 | | |
| 续跑 | 目标负例被拦（练习 2）；裁判校验；无进展出口与资源上限；反馈准入与实际消费（结果适用当轮＋有指定消费者与去向） | | |
| 唤醒 | 取消到 worker；重复事件去重；状态恢复、预算总账与接手可达 | | |

**控制路径演练记录**（本场练习编排，非产品配置）：

```text
动作/目标/本次授权有效期：____
允许：____（真实执行记录）
需人批准：____（谁看到什么；批准后从哪恢复）
硬拒绝：____（拒绝原因；普通批准不能覆盖）
无人响应/取消/预算耗尽：____（停在哪；谁接手；恢复指针）
未实做时：标待演练，不写通过。
```

**第三步：四问写在纸上。** 谁启动下一轮？谁判断完成？谁能改变系统（含判据）？出了错谁能及时停下并接手？——**写不出来，或适用演练未通过，先别多交决定。**

**产出**：一张升级申请单（或一张「现在不升」的理由单——两者都是好答案）。

---

> 三题的判定标准与常见错误，讲者现场对答案。回去逐项配齐的操作规程：《循环交接手册》高级篇——交动作、交续跑、交唤醒、升一档；它说做完了之后的放行检查，在「它说做完了」一节。
