# Outline — Loop Engineering（技术/产品场）

## 0. 这场要解决什么

听众已经在跑循环——但「在跑」不等于「知道自己在哪一档、每一档的护栏配齐了没有」。v2 以控制链为脊柱，把 goal/eval 的要求当天基先铺；v3 以阶梯为脊柱：**先定档，再逐档讲「交出什么决定、配什么护栏、怎么验证」**。控制链不删——它降为每一档的检查表（B04/B37）。

**反馈是贯穿全场的第二根线索**：反馈必须改变下一步，落盘工件使它可审计而不是定义循环的唯一方式（B13）；裁判按判据解释反馈、先核证据归属（B15–B19）；人的业务上下文也要进入下一轮（B29）。「高手的错觉」放在尾巴（B36）：能复制的是显性护栏，不是他人心里的判断。

**贯穿案例（教学故事，虚构示意，非产品日志）**：全场只讲一件开放的事——「夜间回归值守」：你把站内搜索的夜间回归交给 Agent，每晚构建后它自己跑回归、自己修到绿，早上你看报告。故事按七个阶段推进：开场闪回（B01，第 2 周末深夜它说「完成」——悬念留给全场）→ 第 1 周回溯你逐轮指挥（B02–B04）→ 授权日给处置表与会过期的 token（B05–B11）→ 第 2 周末第一次无人续跑，写清「绿」的定义、裁判与出口（B12–B21）→ 第 3 周复盘与分账（B22–B29）→ 第 1 个月末夜间值守上线（B30–B33）→ 第 3 个月它成了值班同学、两条岔路与高手错觉（B34–B38）。每页的场景行从当前阶段取材，让听众看见故事推进到哪一天。技术事实层：固定 `branch=agent/search-pagination`，token 绑定 `principal/action/target/branch/expiry/run`；B12–B20 是「返回丢 query→原始 trace→Eval→修复/重测」的修复主线；B17 是故事里的「旧版通过结果晚到」分支——旧 tree 的全绿结果在本次续跑中途送达，先核归属再消费；B18 与 B27–B32 是放权前演练事件（外层 retry、资源耗尽、硬拒绝、唤醒与 cancel）——每多交一个决定前先演练一次坏路径，这是故事建立信任的方式。B08 约束 worker 改动范围；B12 写出第二页可打开、可返回的目标；B23–B25 核对清单、真实路径与测试差异；B26 分三账、由验收者签认产物，用户采用率另行观测；B37 按交接面门禁升级。所有字段、状态和阈值均为教学设计，不是产品日志、事故或收益证据；不加第二套故事。

一页一概念（2026-10-01 用户定）：38 页是拆分结果；承接/转折由各节首页承担。

## 1. 核心判断

**治理关注的是决定如何交出去：先识别交接面，再配授权、Goal/Eval、停止与交接机制；是否多交一个决定，要看演练证据，而不是已跑多少轮。**

## 2. 系统（定档四问＋逐档检查表）

```text
谁启动下一轮？      → 基线、动作：人 ／ 续跑：目标条件 ／ 唤醒：时间表或事件
谁判断完成？        → 基线、动作：人 ／ 续跑：裁判判条件、人守验收 ／ 唤醒：不另授予判停权
谁能改变系统？      → 每一级的授权面
出了错谁能停下接手？→ 每一级的升级路径与交接单
```

四问在 B03/B04 提出，B37 收束回扣。基线/动作/续跑/唤醒是本场教学映射，不是各 KOL 共同提出的成熟度等级；调度能独立配置，不能由唤醒命令推断动作审批或续跑判停也已交出。控制链节点只在对应交接面成为检查项，仅交动作时，不要求先建立整套 Goal/Eval 完成判定。

## 4. 页面

**B01 · 你离开后，它说做完了**
难的不是让它干活，而是它说「做完了」——你凭什么信。

**B02 · 为什么有人开始「写 loop」**
Osmani 一句话说清：让系统接替你，逐次去提示 agent；今天要工程化的，是里面的反馈、判断和边界。

**B03 · 你在哪一档**
动作、续跑、唤醒，三件事分开核查：交出哪个决定，就装哪道护栏。

**B04 · 定档四问**
每次交出控制权，先问四句：谁发起、谁判定、谁能改、出错谁接手。

**B05 · 授权面是分级处置表**
交出动作审批，交的不是开关，是一张表：允许直行、沙箱内跑、必须人批、硬拒绝。

**B06 · 限制要落在执行层**
提示词和审批偏好都拦不住动作；执行层的策略件和沙箱才拦得住。

**B07 · 批准会自己长大**
一份公开报告里，窄窄的推送授权被用成了大发布许可——批准是会过期的对象，不是一句意图。

**B08 · 一次批准绑三样**
批准必须限定动作、目标与有效期，不能把窄授权扩成广授权。

**B09 · 审批要可达**
人看不见、批不了、恢复不了，就别叫「已升级」——审批这件事，得让人够得着。

**B10 · 拒绝是引导信号**
拒绝不是死路：连理由一起送回 agent，让它找安全路径；拒绝预算是熔断，不是轮数上限。

**B11 · 变异测试验证授权**
把 edit 换成 commit、分支换成 main、时间推过期——旧批准必须次次失效；有一次能溜过去，就不能扩权。

**B12 · 续跑目标：Goal 三要素**
要让系统自己决定要不要再来一轮，先把三样写清：终态长什么样、怎么检查、什么不能动。

**B13 · 反馈是循环的燃料**
检查结果要到达做决定的地方，才会影响下一步。
备注（2026-10-04 增）：补完整反馈路径——环境产生 → 关联/投递 → 模型输入或控制分支 → 谁消费结果；「有工件」不能替代「实际使用」。CLAIM 与 subtitle 已同步为上句（原主张句「下一步得由反馈说了算；证据留下来，这条路才查得回去。」保留在本备注备查）。不是每轮必须改动作。

**B14 · 续跑出口：无进展与资源上限**
续跑要有兜底——无进展出口避免原地打转，上限约束资源，两个都不替代质量验收。

**B15 · Eval 选型：谁按什么判**
Eval 按任务定：谁来判、按什么判；让干活的自己判，就得外加独立复核和硬刹车。

**B16 · 保护裁判输入**
裁判只读可信输入，接口缺字段就拒绝放行；保护的是判定边界，不是再加一条提示词。
备注（2026-10-04 增）：本页只讲**输入防操纵**（分类器/接口缺字段拒绝；promptfoo 反例保留在本页）。**结果准入**已按一页一概念拆出下一页 B17；原「旧 tree 的成功结果不能作为当前 tree 的放行证据；投递错误与裁判误判分开」两句随迁。

**B17 · 旧结果不能替当前工作放行**
裁判先核证据属于谁、哪一版，再判断条件。
备注（2026-10-04 增）：自原 B16 拆出。旧 tree/旧版本的成功结果不能作为当前版的放行证据；投递错误与裁判误判分开——投递错误回投递侧修，裁判误判才动裁判；迟到的结果先核归属（tree/run）再消费。故事落点：夜间回归值守中「旧版通过结果晚到」分支——上一版旧 tree 的全绿报告在本次续跑中途送达，不能替当前版放行。

**B18 · 检查要覆盖真实反馈路径**
内层有上限，外层未必兜得住——重试和唤醒的每一条路，都要单独看住。
备注（2026-10-04 增）：核所有回路**有结果消费者**——预算覆盖真实路径之外，每条回路的出口要有人/分支读它。

**B19 · 裁判也要单独校验**
裁判分开了，不等于判得对——拿样题考它、盯住判据版本，缺证据就不放行。
备注（2026-10-04 增）：不把反馈异常都归于 judge 能力——**反馈通道校验与裁判校准分开**：通道问题（没送达/错版本）回投递侧修，判得不对才动裁判；不重讲 Eval 构造。

**B20 · 逐轮判断要指导下一步**
先判这条反馈能支持什么，再决定修、查、停或交人。
备注（2026-10-04 增）：明确每种去向消费哪份有效反馈；缺失、工具异常、目标失败有不同处置。CLAIM 与 subtitle 已同步为上句（原主张句「判完得有去向：接着修、够条件就停，还是停了交人。」保留在本备注备查）。

**B21 · 续跑面的四问答案**
续跑面配齐的标志：发起、判定、改动、接手，四问各有答案。
备注（2026-10-04 增）：回收本次反馈路径——燃料、通道、裁判、去向在续跑面各归各位。

**B22 · 续跑风险：提前宣告完成**
它能自己续跑了，更要防它抢着说「完成」——检查结果到底有没有让程序停下，得追到代码里看。

**B23 · 完成检查一：清单逐条判定**
「做完了」拆成一张清单：每一项，有证据才准打勾。

**B24 · 完成检查二：走通用户路径**
单测过了、接口通了，只证明各自那一段——用户的路，要真走一遍。

**B25 · 完成检查三：不能削弱检查**
删掉断言换来的「通过」不算数——改检查这件事，得别人批。

**B26 · Stop ≠ Accepted；三本账**
控制状态、产出验收、外部结果三本账分开记——谁停的、谁验收的、结果谁在何时复查。

**B27 · 资源上限限制消耗，不证明质量**
资源上限只管花费，不替代质量判定；耗尽先保全状态并交接。

**B28 · 停止之后，还要把状态交清楚**
停止后要说明原因、责任人和恢复位置；硬拒绝记 blocked，请求送达、还在等决定，才记 awaiting_human。

**B29 · 人的反馈要留在环里**
人的纠偏要更新工作依据，也要到达正在执行的人与程序。
备注（2026-10-04 增）：从「写回目标与样例」走到**变更生效**——旧证据与在途工作如何处置：人的纠偏要更新工作依据，也要到达正在执行的人与程序；消息发出≠worker 已停。采用率不使用与功能检查通过仍分账。CLAIM 与 subtitle 已同步为上句（原主张句「把模型不知道的上下文与纠偏理由写回系统，人的判断仍要有入口。」保留在本备注备查）。

**B30 · 两种运行边界**
定时跑和常驻跑是两回事——醒了，不代表干成了。

**B31 · 取消要传播到 worker**
面板关了不等于停——取消要一路传到跑着的进程，重复发也不能出乱子。

**B32 · 跨次预算：不能只看单会话**
按会话计不等于跨次总额；被遗忘的循环要有过期时间。

**B33 · 多交决定前，逐面验证**
想多交权，先把那一面的坏路径演练一遍——跑的轮数不算数，演练过了才算数。
备注（2026-10-04 增）：续跑面的适用门补一条——**负例反馈到达消费者并产生预期处置**；只核已交的决定，不把所有档都要求完整持久协议。

**B34 · 支线 A：多主体编排**
多 Agent 怎么协作，业内还没有定论——但冲突、合并、验收这三件事，哪种分工都躲不掉。

**B35 · 支线 B：改进循环本身**
Agent 可以提案，批准另说——让它自己改核心判据，这条路还没成熟。

**B36 · 高手的错觉**
「他全放手也做得好」——人家挑活儿的眼光、他的环境、随时插手的判断，你可能都没看见。

**B37 · 先看交接面，再决定交多少**
四问答不清，就保持原有控制方式；只为本次交出的决定配相应检查，并留下演练证据。

**B38 · 带走：逐面门禁三行**
每交一个决定，先拿出它拦得住坏路径的证据。

## 6. 语言与证据边界

中文句法讲机制，保留 Loop、Agent、Harness、Goal、Eval、Feedback 的辨识度。标题和主张不用模糊的“门票”“包络”代替条件与资源限制；阶梯只用于解释教学顺序，不暗示配置必然累积。章节导航按 §3.1，不额外加章节页。

- 首现术语：基线、档、授权面、策略件、裁判、负例、验收、外部结果、交接单、反馈回路。上屏不使用 LE 编号，口头统一说「基线／动作档／续跑档／唤醒档」。教学阶梯不等于三个交接面必然累积，必须分别核证据。
- 控制链是研究抽象，不说成 KOL 原话；`stop_conditions` 的「双环三层」仍是专项提炼，未回流判定层前不当行业架构。
- 不把 Stop、Blocked、待观测 说成完成；3/20、7 天、59 分钟、125 美分等参数只属对应产品，留备注。
- 支线 A/B（B34/B35）如实标注「局部已证、成熟度未证」；不写成必经之路或行业方向共识。
- 「高手的错觉」（B36）不点名真实人物；抽卡为教学比喻。
