# Outline — Graph Engineering（技术与架构场：确定性状态机与拓扑自愈体系）

## 0. 这场要解决什么

听众已经不满足于通识概念，他们正在一线经历多 Agent 系统的各种深水区灾难：
单上下文爆掉、两个 Agent 互相反驳死锁、大模型动态编译图导致 Checkpoint 崩溃、单节点失败引发全图推翻抖动、模型偷跑篡改测试文件。

本场放开讲底层硬核机制与工业终局：
**如何通过固定元图与动态任务数据解耦、Session 外持久化状态机、强类型工件契约与 Git Worktree 物理隔离、两层分级自愈协议（L1 微循环 + L2 受限子图切片）、以及针对 2026 SOTA 模型五大病态行为的机器级防御体系，构建工业级高可用的 Agentic SDLC 流水线。**

---

## 1. 核心判断

**单体 Loop 无法承担长程工业研发，现场动态编译图已被工业落地证伪；生产终局是“固定元图硬编码 + 动态任务数据 DAG”双轨解耦，通过 Session 外持久化状态机与强类型工件黑板实现物理隔离，以 L1 有限微循环与 L2 局部子图切片构建两层自愈闭环，并以非模型依赖的机器级 Hook 阻断顶级模型的一切病态越权冲动。**

---

## 2. 贯穿全场的系统脊柱：图治理四问（架构技术版）

```text
依赖怎么定？  → 固定元图（Meta-Graph）静态编译一次，动态数据（Task DAG as Data）按拓扑派发
工件怎么交？  → 零自然语言对话，仅交接强类型 Schema 工件；Git Worktree 物理沙箱绝对隔离
失败怎么治？  → L1 沙箱内 Hard Cap <= 3 退避重试；L2 绝对冻结成功节点，仅做局部子图切片突变
人在哪里看？  → P0/P1/P2 三级确定性状态机挂起门禁；熔断完好保留 Worktree 案发现场并导出诊断包
```

### 第 1 章：长程任务困境与图工程思潮发端（B01–B04）
- **核心问题**：为什么单体 Agent 和早期 Multi-Agent 框架无法胜任生产级任务？
- **带走判断**：单体 Loop 存在物理极限，而自由群聊模式已被 2026 工业落地彻底抛弃。
- **转场理由**：既然自由聊天不行，真正的工程破局点在哪里？

| 页码 | Title | Subtitle (CLAIM) |
|---|---|---|
| **B01** | 长程研发任务的单体物理极限 | 单上下文在超长跨度任务中必然遭遇注意力稀释、上下文腐朽与死锁反驳 |
| **B02** | 2026-07 Peter Steinberger 发问 | 生产级系统必须从单上下文死循环走向显式 DAG 状态机编排 |

### 第 2 章：工业终局架构：固定元图 vs 动态任务数据（B05–B10）
- **核心问题**：大模型究竟该不该在运行时现场编写并编译图代码？
- **带走判断**：外层状态机是 100% 确定性的静态程序，模型只动态生成与修改状态中的任务数据。
- **转场理由**：双轨解耦确立后，这个确定性状态机究竟应该驻留在哪里？

| 页码 | Title | Subtitle (CLAIM) |
|---|---|---|
| **B05** | 现场动态图编译的生产破产 | 运行时拼接图代码会导致 Checkpoint 断裂、APM 崩溃与全图推翻抖动 |
| **B06** | 工业终局标准：双轨解耦架构 | 固定元图静态编译一次，大模型只在局部生成和修改动态任务数据 |
| **B07** | 元图硬编码：铁打的流程骨架 | 外层由固定的编排器、调度器、执行算子与聚合门禁构成确定性有限状态机 |
| **B08** | 动态任务数据：流动的工单拓扑 | 模型输出符合严格 Schema 的 Task DAG 数据，调度器依据入度算法并发派发 |
| **B09** | 生产实证：字节 DeerFlow 2.0 架构解剖 | 极简两节点元图外控流程，内层按需调度独立 Docker 沙箱实例 |
| **B10** | 拓扑双轨光谱：显式 DAG vs 动态委派树 | 确定性流水线用声明式 Task DAG，探索性排错用 Lead 动态委派树 |

### 第 3 章：状态机分层治理与持久化运行时（B11–B15）
- **核心问题**：为什么只靠内存里的 Python 进程管不住企业级长程研发流水线？
- **带走判断**：必须将 Session 内短期执行与 Session 外持久化状态机严格解耦。
- **转场理由**：有了可靠的状态机底座，节点之间的数据如何干净交接？

| 页码 | Title | Subtitle (CLAIM) |
|---|---|---|
| **B11** | 内存幽灵状态机的致命缺陷 | 将图状态保存在瞬态内存进程中，遇宿主重启或超时即导致任务全死 |
| **B12** | Session 内外状态机职责分界 | Session 内专职短期只读执行，Session 外独立持久化引擎掌控全局生命周期 |
| **B13** | Session 外持久化引擎的不可替代性 | 基于 Temporal 或数据库 Checkpointer 实现事件溯源与崩溃后原位重放 |
| **B14** | 长程挂起（Durable Wait）的工程价值 | 状态机可无代价挂起数天等待架构师审批，不消耗任何内存驻留线程 |
| **B15** | 呼吸页：状态机的确定性闭环 | 确定性的编排工作流调度非确定性模型执行，是生产高可用的唯一正道 |

### 第 4 章：强类型工件契约与共享黑板物理隔离（B16–B21）
- **核心问题**：如何彻底防止节点之间的自然语言污染与并发写冲突？
- **带走判断**：强类型 Schema 契约校验 + 全局黑板单写多读 + Git Worktree 物理沙箱隔离。
- **转场理由**：每个节点都规整隔离了，如果执行中遭遇不可抗力失败，如何自愈？

| 页码 | Title | Subtitle (CLAIM) |
|---|---|---|
| **B16** | 节点间交互铁律：零自然语言对话 | 彻底消灭文本传话，节点间仅通过强类型 Schema 工件进行交接 |
| **B17** | 静态契约校验门禁 | 上游产物进入下游前必须通过 JSON Schema 机器校验，破损工件绝不入流 |
| **B18** | 全局共享黑板（Blackboard）模式 | 需求蓝图、工件字典与不可变事件日志统一上板，遵循单写多读纪律 |
| **B19** | Git Worktree 物理沙箱隔离 | 并发代码 Worker 必须在独立的物理 Worktree 中执行，杜绝文件脏写入 |
| **B20** | 工件语义版本控制与级联失效 | 工件不可就地覆盖写，前置契约变更强制沿 DAG 反向失效未冻结下游 |
| **B21** | 呼吸页：工件流转四步法 | 最小上下文白名单注入，节点消费完工件即销毁沙箱，杜绝历史包袱 |

### 第 5 章：两层分级自愈协议与受限切片突变（B22–B27）
- **核心问题**：节点出错时，如何避免“局部重试死循环”或“整图推翻重新生图”两大极端？
- **带走判断**：L1 Worker 局部有限退避微循环，升级后 L2 编排者做受限的局部子图切片替换。
- **转场理由**：算法机制完善了，但实际跑在里面的 2026 顶级大模型会老老实实听话吗？

| 页码 | Title | Subtitle (CLAIM) |
|---|---|---|
| **B22** | 异常升级协议：Loop 治理与 Graph 治理的缝合点 | 单节点内部有限重试是 Loop 职责，跨节点升级与拓扑重排是 Graph 职责 |
| **B23** | L1 局部微循环：沙箱内有限退避 | Worker 内部重试设 Hard Cap ≤ 3 次，以客观命令退出码为绝对闸门 |
| **B24** | 升级信封（Failure Envelope）规范 | L1 耗尽时抛出结构化错误诊断信封，携带 AST 切片禁止盲目重试 |
| **B25** | L2 全局自愈第一铁律：绝对冻结成功节点 | 状态为 SUCCESS 的节点及其工件不可变，绝不允许重新调度与篡改 |
| **B26** | 三大受限原子图变异（Sub-graph Splicing） | 编排者仅能执行前置注入、分裂降级与回滚修订，严禁自由捏造图结构 |
| **B27** | 汇聚冲突治理协议（Fan-in Protocol） | Git 文本冲突交专职 Worker 解决，语义冲突由独立集成回归门禁裁定 |

### 第 6 章：2026 SOTA 顶级模型五大病理的机器级防御（B28–B33）
- **核心问题**：顶级模型（Opus 5.5 / Sonnet 5 / Sol / Astra）有哪些天然破坏图执行的病态行为？
- **带走判断**：不相信模型的自我约束，必须建立外部非模型依赖的机器级硬核防御。
- **转场理由**：防住了模型的越权冲动，系统最后如何平稳交付给人类？

| 页码 | Title | Subtitle (CLAIM) |
|---|---|---|
| **B28** | 顶级模型的反叛：模型能力增强并不自动带来工程可靠 | 2026 前沿模型在图环境中表现出更强烈的自主破坏确定性冲动 |
| **B29** | 防御病态①与②：汇报风暴与反驳死锁 | 强制 Hook 中间件拦截非工件输出，物理单向管道消灭对话反驳 |
| **B30** | 防御病态③：偷跑虚假完成与篡改测试 | 测试目录挂载只读，最终验收由独立无模型原生容器执行影子门禁 |
| **B31** | 防御病态④：越权架构侵占与全局破坏 | AST 差异白名单锁强制拦截超出当前 Task Spec 声明范围的任何文件修改 |
| **B32** | 防御病态⑤：长程注意力腐败与幻觉残留 | 编排者每次唤醒实行无状态算子化重置，仅喂入不可变蓝图与状态快照 |
| **B33** | 机器级防御矩阵全景总结 | 真正的系统安全性建立在代码 Hook 与沙箱隔离上，绝不建立在 Prompt 劝说上 |
