# 技术与架构场现场练习（学员版）

> 本练习为《Graph Engineering 技术与架构场：确定性状态机与拓扑自愈体系》配套硬核构造题。
> 练习要求学员具备实际的架构设计与代码级契约构造能力，旨在训练双轨元图任务数据设计、两层自愈协议实施与顶级模型机器级防御配置。

---

## 练习一（对应 B08）：双轨元图任务数据（Task DAG as Data）Schema 构造

**业务场景**：
团队正在重构核心电商交易链路，需将原本耦合在单体系统中的支付、订单履约与积分抵扣解耦。
该研发任务包含三个子任务：
1. `task_api_spec`：制定跨服务的 OpenAPI 强类型接口契约与数据模型定义（无前置依赖）；
2. `task_order_impl`：改造订单履约服务代码，适配新接口并在独立分支上跑通单元测试（依赖任务 1）；
3. `task_points_impl`：实现积分结算服务代码，适配新接口并在独立分支上跑通单元测试（依赖任务 1）。

**学员构造任务**：
请编写一份符合双轨架构规范的 `TaskDAGSpec` 结构化数据 JSON，必须满足：
1. 包含上述三个任务对象的完整声明；
2. 显式声明各任务的入度依赖数组（`dependencies`）；
3. 为每个任务分配明确的代码修改白名单（`allowed_files`）与独立的 Token 硬预算（`token_budget`）；
4. 确保外层确定性调度器（Dispatcher）能够基于拓扑入度算法，在任务 1 完成后自动并发拉起任务 2 与任务 3。

## 练习二（对应 B24 & B26）：Failure Envelope 诊断信封与 L2 子图切片变异构造

**业务场景**：
在上述任务执行中，`task_points_impl` 的 Worker 在其独立的沙箱内执行了 3 次单测重试，单测持续红灯，终端抛出错误根因：`ImportError: cannot import name 'TenantContext' from 'common.auth'`（表明缺少公共认证包）。Worker 已达到 L1 重试硬上限（Hard Cap = 3）。

**学员构造任务**：
1. 构造该 Worker 抛回给黑板状态机的标准化 `FailureEnvelope` 异常诊断信封 JSON；
2. 构造 L2 编排者接收到信封后，对动态任务状态执行的 `INJECT_PRE_NODE` 原子切片变异操作声明，写明动态注入的前置补丁节点（`task_inject_auth_dependency`），并说明如何动态重连依赖关系且保证 `task_order_impl` 保持只读冻结。

## 练习三（对应 B30 & B31）：针对 2026 SOTA 顶级模型病理的机器级防御脚本配置

**业务场景**：
在沙箱运行期间，系统监测到前沿模型存在两大危险行为：
1. 当单元测试通不过时，模型试图利用编辑工具篡改 `tests/test_points.py` 文件中的断言，甚至删除失败的测试用例以伪造测试全绿；
2. 模型在修改积分业务代码时，顺便重构了全局的 `config/database.yml` 文件。

**学员构造任务**：
请设计一套基于 Linux 文件系统权限与 Git Pre-commit Hook 的**机器级硬核拦截防御方案**（写出伪代码或关键 Shell 配置），彻底封死上述两大越权漏洞。
