## 卷首｜图治理语汇权威与状态机核心

在引入图治理之前，团队必须在全员范围内对齐以下**八大权威术语**，杜绝用伪概念进行技术包装：

| 术语 | 工业级定义 | 严禁使用的模糊定义 |
|---|---|---|
| **Graph / DAG** | **显式有向图 / 有向无环图**。用于在系统启动前或编译期严格锁定任务执行顺序、依赖前置与并发分支的拓扑网络。 | “几个 Agent 在群里开会讨论出来的流程” |
| **Meta-Graph** | **确定性固定元图**。外层由人类工程师硬编码、静态编译的有限状态机骨架（包含固定的 Planner / Dispatcher / Worker / Gate 节点），运行期结构绝对不可变。 | “大模型实时生成的动态 Python 代码” |
| **Task DAG as Data** | **动态任务数据**。大模型在元图状态机中动态维护的子任务清单数据字典（包含任务 ID、白名单文件、Token 预算与依赖数组）。 | “被动态编译到内存里的不可见图对象” |
| **Typed Artifact** | **强类型工件**。节点之间传递的唯一合法载体，必须符合预定义的 JSON Schema 格式校验（如 TaskSpec、PatchManifest、TestReport）。 | “上游 Agent 写的一段自然语言 Markdown” |
| **Blackboard State** | **全局共享黑板状态机**。集中存储不可变需求基线、已验收工件字典与不可变事件日志的单一事实源，遵循单写多读（SWMR）纪律。 | “各个 Agent 私自互发的消息流” |
| **Sub-graph Splicing** | **局部子图切片替换**。L2 拓扑自愈时的受限外科手术——绝对冻结已成功节点，仅通过前置注入、分裂降级或回滚修订原子算子变异失败前置。 | “把整张拓扑图删掉重新让大模型规划一遍” |
| **Failure Envelope** | **异常升级信封**。Worker 在 L1 微循环退避耗尽后向上抛出的标准化病历卡，包含错误分类与精准 AST 切片。 | “终端报错后直接向控制台抛出的异常字符串” |
| **Shadow Gate** | **只读影子门禁**。测试用例在 Worker 沙箱中强制挂载为只读，最终验收由独立的纯原生干净容器执行。 | “让写代码的大模型自己跑测试并汇报是否通过” |

## 上篇｜通识篇：企业多 Agent 项目健康度审计

> 本篇面向技术 VP、研发总监、项目经理与架构评审委员会，用于评估团队当前的多智能体架构是否具备上线生产的资格。

### 1. 伪 Multi-Agent 群聊模式五项致命体征自检

如果你的系统命中以下任一体征，说明系统仍处于**玩具/原型阶段**，严禁上线承接核心生产链路：

- [ ] **体征 1：共享聊天大窗口**。不同的 Agent 角色在一个全局对话上下文里互相 @ 对方并用自然语言沟通。
- [ ] **体征 2：Token 消耗呈指数爆炸**。随着子任务推进，单次交互消耗的 Token 呈二次方级暴增，上下文充斥大量“收到”、“赞同”等社交闲聊。
- [ ] **体征 3：单点失败引发全图推翻**。某个小任务报错后，主控 Agent 提示“正在重新规划全流程”，已跑通的代码被推翻重做。
- [ ] **体征 4：缺乏物理沙箱隔离**。并发的 Agent 在服务器的同一个物理文件夹内读写文件，频繁遭遇文件被随机覆盖或 Git 索引冲突。
- [ ] **体征 5：裁判与运动员合体**。负责写代码的 Agent 同时负责跑测试并自己向系统汇报“我搞定了”，测试用例允许被模型随意修改。

### 2. 图治理成熟度评估四问（生产放行必答题）

任何多智能体研发流水线在进入生产评审前，必须由项目负责人逐一给出答案：

| 评估维度 | 核心审查问题 | 合格放行标准 |
|---|---|---|
| **一问依赖** | 任务的前后置依赖是如何确立的？ | 外层必须是静态编译的固定元图，内层由大模型生成符合 Schema 的 Task 数据，通过拓扑入度算法派发。 |
| **二问工件** | 节点之间的数据交接是否经过机器校验？ | 节点间零自然语言对话，仅通过带强类型的工件交付，跨越边界前必须通过代码级 Schema 校验器。 |
| **三问自愈** | 单点故障时系统如何防止无限空转与全局抖动？ | 节点内重试设硬上限（≤3 次），失败后抛出 Failure Envelope，编排者绝对冻结成功节点，仅做局部子图切片替换。 |
| **四问把关** | 系统的终极安全底线由谁守护？ | 必须设立架构方案（P0）、破坏性操作（P1）与最终合入（P2）三道确定性审批门禁，触顶优雅熔断完好保留现场。 |

### 3. HITL 人机协同审批门禁配置规范

系统必须在状态机中硬编码以下三级审批哨卡，严禁跳过：

```
[任务启动: Planner 生成 Task DAG 数据]
               │
               ▼
   [⛔ P0 架构设计门禁: 人类架构师审批] ──(Reject)──► [修订任务蓝图]
               │ Pass
               ▼
     [调度 Worker 并发沙箱编码]
               │
               ├── (遇到数据库 DROP/ALTER 操作) ──► [⛔ P1 破坏性变更门禁: DBA 签字]
               │                                            │ Pass
               ▼                                            ▼
     [Worker 完工汇聚与集成回归门禁]
               │
               ▼
   [⛔ P2 最终集成发布门禁: 负责人上线审批] ──(Pass)──► [合并主干并部署]
```

## 下篇｜工程篇：高韧性多智能体图工程实操

> 本篇面向资深系统工程师与平台架构师，提供工业级代码模板、Schema 契约、SOP 与防御脚本。

### 1. 工业终局：双轨元图标准代码模板（基于 LangGraph）

生产系统必须采用以下**双轨解耦范式**（外层元图硬编码，内层数据流转）：

```python
"""
dual_track_meta_graph.py — 工业级双轨元图生产实现模板
外层：静态编译一次的 Meta-Graph
内层：通过 Send API 动态派发 Worker 并发实例
"""
from typing import Annotated, Dict, List, Literal
from pydantic import BaseModel, Field
from langgraph.graph import StateGraph, START, END
from langgraph.constants import Send
import operator

# --- 1. 强类型工件契约定义 ---
class SubTaskSpec(BaseModel):
    task_id: str
    description: str
    dependencies: List[str] = Field(default_factory=list)
    allowed_files: List[str]
    token_budget: int
    status: Literal["PENDING", "RUNNING", "DONE", "FAILED"] = "PENDING"
    patch_result: str = ""

class GlobalGraphState(BaseModel):
    requirement: str
    task_dag: Dict[str, SubTaskSpec] = Field(default_factory=dict)
    event_log: Annotated[List[str], operator.add] = Field(default_factory=list)

# --- 2. 固定元图节点算子 ---
def planner_node(state: GlobalGraphState) -> Dict:
    """仅生成动态任务数据，严禁动态编写图代码"""
    # 模拟大模型输出符合 Schema 的任务数据字典
    tasks = {
        "task_api": SubTaskSpec(task_id="task_api", description="API Spec", dependencies=[], allowed_files=["specs/*"], token_budget=50000),
        "task_order": SubTaskSpec(task_id="task_order", description="Order Service", dependencies=["task_api"], allowed_files=["services/order/*"], token_budget=150000),
        "task_points": SubTaskSpec(task_id="task_points", description="Points Service", dependencies=["task_api"], allowed_files=["services/points/*"], token_budget=150000),
    }
    return {"task_dag": tasks, "event_log": ["Planner: Task DAG initialized."]}

def dispatcher_router(state: GlobalGraphState):
    """基于拓扑入度纯数学算法，并发派发就绪任务"""
    ready_tasks = []
    for tid, task in state.task_dag.items():
        if task.status == "PENDING":
            # 检查所有前置依赖是否均已完成
            deps_met = all(state.task_dag[d].status == "DONE" for d in task.dependencies)
            if deps_met:
                ready_tasks.append(Send("worker_node", {"task_id": tid, "spec": task}))
    
    if not ready_tasks:
        all_done = all(t.status == "DONE" for t in state.task_dag.values())
        return "integration_gate_node" if all_done else END
    return ready_tasks

def worker_node(payload: dict) -> Dict:
    """在独立的 Worktree 沙箱内执行局部微循环"""
    tid = payload["task_id"]
    # 沙箱执行逻辑 (略)...
    return {"task_dag": {tid: SubTaskSpec(task_id=tid, description="", allowed_files=[], token_budget=0, status="DONE", patch_result=f"Patch for {tid}")}}

def integration_gate_node(state: GlobalGraphState) -> Dict:
    """独立无模型的干净门禁验收"""
    return {"event_log": ["Integration Gate: All regression tests passed."]}

# --- 3. 静态编译元图 (进程启动前执行一次) ---
builder = StateGraph(GlobalGraphState)
builder.add_node("planner_node", planner_node)
builder.add_node("worker_node", worker_node)
builder.add_node("integration_gate_node", integration_gate_node)

builder.add_edge(START, "planner_node")
builder.add_conditional_edges("planner_node", dispatcher_router)
builder.add_conditional_edges("worker_node", dispatcher_router)
builder.add_edge("integration_gate_node", END)

# 静态编译注册，绑定持久化 Checkpointer
app = builder.compile()
```

### 3. L2 局部子图切片变异标准操作规程（SOP）

当状态机捕获到 Worker 抛出的 `FailureEnvelope` 时，严格按以下 4 步执行外科手术式局部重排：

1. **第一步 · 锁定成功成果**：立即扫描 `task_dag`，将所有状态为 `DONE` 的节点标记为不可变锁（`immutable = True`），禁止后续操作修改其代码产物。
2. **第二步 · 校验重规划预算**：检查全局计数器 `state.replanning_attempts`。若当前值已达到 2 次，**立即触发熔断**并唤醒人类架构师；若小于 2，计数器自增 1。
3. **第三步 · 应用原子切片变异**：
   - 若建议为 `INJECT_PRE_NODE`：在 `task_dag` 字典中新增一个补丁任务，将补丁任务的前置设为原节点的前置，再将原节点的前置单一重连至补丁任务。
   - 若建议为 `SPLIT_AND_DEGRADE`：将超时子任务分裂为 Part A 与 Part B，Part B 依赖 Part A。
4. **第四步 · 清理失败沙箱**：将失败节点的 Worktree 分支重置或归档，重新将原节点状态置为 `WAITING_PREREQUISITE`，唤醒调度器重新计算入度。

### 4. 针对 2026 SOTA 顶级模型病态行为的机器防御配置

#### A. 测试目录只读挂载（OS 级封死篡改）
```bash
# Docker Worker 容器拉起脚本：测试目录只读挂载
docker run -d \
  --name "worker-sandbox-${TASK_ID}" \
  -v "${WORKTREE_PATH}/src:/workspace/src:rw" \
  -v "${WORKTREE_PATH}/tests:/workspace/tests:ro" \
  --network none \
  "agent-runner:v2026"
```

#### B. AST 变更白名单 Git Pre-commit Hook
在所有 Worker 的沙箱 Git 仓库中强制写入 `.git/hooks/pre-commit`：
```bash
#!/usr/bin/env bash
set -euo pipefail

# 1. 拦截对测试目录的任何写操作
if git diff --cached --name-only | grep -E '^tests/'; then
  echo "❌ [Shadow Gate 拦截]: 严禁修改测试文件！检测到模型试图走捷径伪造单测！" >&2
  exit 1
fi

# 2. 拦截超出当前 TaskSpec 声明范围的越权架构修改
ALLOWED_PREFIX="${TASK_ALLOWED_PREFIX:-services/}"
for CHANGED_FILE in $(git diff --cached --name-only); do
  if [[ ! "$CHANGED_FILE" =~ ^$ALLOWED_PREFIX ]]; then
    echo "❌ [AST 白名单拦截]: 越权架构侵占！文件 '$CHANGED_FILE' 超出本子任务授权范围！" >&2
    exit 1
  fi
done

exit 0
```
