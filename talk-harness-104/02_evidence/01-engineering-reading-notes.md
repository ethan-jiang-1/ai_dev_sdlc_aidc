# 104 工程阅读笔记

## 先分清建设对象

本笔记消化用户指定playbook全文，并结合仓库现有agent工程研究与实践入口；没有新增外部调研或产品试跑。来源ID、强度与行号均回[来源台账](<00-sources.md>)，这里不另设证据权威。

| 对象 | 需要验证什么 | 不能偷换成什么 |
|---|---|---|
| 开发Agent：帮助设计、实现、测试工单助手 | 变更符合要求；构建/代码测试/接口测试通过；开发规则、skill/hook配置变更未退化；有计划、差异和审阅证据 | 开发Agent在编码任务通过，不代表工单助手分类正确、授权有效或可安全处理客户数据 |
| 工单助手：被建设的业务Agent | 规定权限下分流、依据检索和提出建议；创建任务符合授权与副作用约定；正常、缺资料、异常、中断、重复操作都有预期 | 代码绿灯不代表业务行为稳定；语气流畅、工具成功返回或评估器通过不代表问题解决 |

playbook主要讲第一行的交付链，不是完整业务Agent工程教材。104吸收“要求落成工件、验证在链上、动作有边界、运行反馈进入变更”；业务权限、幂等、状态原子性和补偿责任须另作设计（S01–S08、T01）。

## 核心工程动作

以下是本场教学转化，不是厂商产品默认能力声明。合成案例事实由104案例源维护；这里规定每段要讲清的工程接口。

| 工程面 | 可吸收的主张 | 104应展示的动作与证据 | 失败去向 / 责任 |
|---|---|---|---|
| 最小架构 | 流程与模型自主路径分开，复杂性按需要增加（S07）；graph研究提供依赖/状态视角而非必然升级路线（S12） | 输入校验→模型分流→检索→建议→人工批准→创建内部任务；程序控制允许状态、权限与副作用，模型负责有限内容判断。每步写输入、输出及分支 | 不确定、缺资料或规则冲突进人工待处理；业务负责人判断规则正确性，工程负责人维护执行控制 |
| 要求与交接 | 工件供下一阶段读取，人纠正和批准（S01、S02） | 变更写允许/禁止动作、验收样例、风险与未决项；指定权威记录和版本；对照计划、实现与检查输出，不按文件齐全验收 | 偏离要求登记并重新批准，开发Agent不能自行弱化标准；业务/变更负责人决定 |
| 工具契约 | 工具说明、边界与使用测试同样重要（S08） | 每个工具列输入约束、输出结构、错误、权限、副作用、超时及重复调用行为；程序做schema和权限校验，结果带操作标识 | 非法或越权执行前拒绝；工具异常有界恢复/交人，不猜成功 |
| 幂等与结果未知 | 原文无完整事务方案；反馈研究提示重复、迟到、缺失风险（S09、T01） | 创建任务用稳定操作标识；服务端以唯一约束或等价原子机制绑定标识与业务结果。说明保存位置及重复请求返回同一结果的范围，不只靠提示词 | 超时按标识查询：已执行复用；确认未执行且安全才授权内重试；未知暂停/交人。工程负责人保证原子性，业务负责人批准补偿 |
| 持久状态与恢复 | 状态、交接与反馈消费者需显式设计（S09、S12） | 保存任务ID、状态、版本、操作标识、批准引用及结果；先保存待执行记录，再发起副作用，并可核对结果；状态转移防并发冲突 | 重启读持久记录，不用聊天猜测；检查点不保证外部效果恰好一次，恢复须对账；未知不标完成 |
| 指令与强制 | skill advisory，检查和权限各有范围（S02、S03） | 指令讲规则，skill复用方法，程序校验机检条件，服务端权限限制业务动作，沙箱限制运行能力；用禁止动作验证真实执行点阻断 | 未覆盖路径不假定安全；规则/权限冲突交授权负责人 |
| 协作与隔离 | 独立任务适合并行，共享文件顺序处理（S04）；图机制按需采用（S12） | 开发分工写清写入范围、工作区、依赖与合并负责人；业务任务分别保存状态和权限，共享对象另作并发控制 | 合并负责人处理冲突；共享存储/凭据不随上下文分离而隔离，多Agent非默认升级 |
| 检查与行为评估 | 可执行反馈、配置eval、事故回归（S04–S05、S11） | 分开代码/接口测试与业务样本；检查分类、依据、缺信息、禁止动作、创建结果及重复/中断；留正常和失败样本，重复运行观察波动 | 未执行、测试失败、工具故障、判断冲突分账；未通过暂停发布；专家审判据，工程负责人审执行证据 |
| 裁判与控制 | 预算、质量与审批分开，记录参与控制（S09–S11） | 控制器读明确结果，决定继续/停止/交人；裁判说明依据，执行者不能改基准；预算耗尽写未完成/部分结果 | 人与裁判冲突暂停自动放行；预算、无进展和拒绝各有接手渠道；独立模型不独占批准权 |
| 发布与运行 | 发现与批准分开、先只读再扩权、演练回滚、事故入回归（S06） | 发布关联代码、模型、提示、工具、规则、数据及eval版本；记录状态/操作/证据引用并最小化敏感数据；异常触发诊断与受控变更 | 发布负责人决定放行/回滚；获授权者决定业务补偿；阈值按数据与风险约定，不照抄σ |

## 六个必须讲清的限制

### 1. Hook与Skill不是绝对保证

S02已承认skill是advisory；S03的hook只在配置匹配且行动实际经过的事件执行。配置是否受保护、替代工具/入口是否覆盖、脚本故障放行还是拒绝、权限与沙箱如何补位，都会影响结果。程序可重复不等于规则正确或覆盖完备。

可说“把关键约束落到业务助手不能自行改写的执行校验和权限层，再测试禁止动作”；不能说“装了hook绝对不可绕过”，也不能把提示/技能文件当服务器权限策略。

### 2. 短语匹配不是有效发布授权

S03示例在命令文本查 `deploy` 和 `production`，只检查 `RELEASE_APPROVAL` 非空。别名、包装脚本、其他表达或工具路径可能漏掉，无关命令也可能误中。环境变量不证明批准者身份、对象、范围、版本、时效或撤销状态。

本场设计应由执行层接收结构化操作请求，核验有权者批准记录与本次对象/动作/版本/范围匹配，拒绝过期、撤销或不匹配批准。普通文本和模型自称批准均不作授权。这是机制提案，不是声称示例已实现。

### 3. 示例CI没有逐任务隔离

S05一次checkout后在同一工作区循环eval，允许Edit，结果写同一 `result.json`；未展示逐题clean/reset、独立容器、数据重建或外部服务隔离。前一题改动可能污染后一题，结果文件可能覆写；不能称各题独立能力实验。

两类Agent评估都须明确起始工件、数据、权限与环境版本；写操作每题用干净副本/独立状态，留每题每次结果。有意共享状态测试连续任务时，明确这是另一类评估而非独立样本。

### 4. 固定样本数和σ阈值不是通用规范

S05的20–50是起步建议，不是代表性或统计置信度保证，稀有高危失败可能不在其中。按任务、风险和故障路径选择样本，报告覆盖范围、重复次数、缺口及波动，不凭单一总通过率批准敏感动作。

S06的1σ日志/2σ诊断/3σ提案是控制带示例。偏态、低频、季节性、基线漂移或相关样本会改变告警意义；σ不是模型正确性的置信度，不授予业务权限。窗口、指标、检测规则与动作权限分别审定，先检验误报/漏报及接手容量。

### 5. 冻结测试不证明全局可靠

S04先复现、固定测试再修实现，是更强的特定回归证据；“proof the bug is gone”必须缩为“记录环境下，原先失败的覆盖场景现在通过”。测试可能选错、漏规则、oracle有误或仅覆盖一个输入；冻结不阻止篡改运行器、依赖、环境或其他评价入口。

保留修复前后输出、保护范围与版本，并查邻近行为及业务样本；不把固定一条测试、全部绿灯或连续几次成功变成整体可靠。判据合理变化须负责人批准并换版，执行者不能为了过关改弱。

### 6. 回滚与恢复不撤销业务副作用

S06的部署回滚不撤销已创建内部任务，也不撤销外部承诺或发送。状态恢复不等于工具未执行，超时只能表明未收到结果。

区分暂停自动化、恢复运行、回滚版本和补偿业务动作。副作用按操作标识对账，补偿另定动作、授权、确认及记录，不宣称自动恢复一切。幂等唯一约束、存储原子性、崩溃间隙与并发处理须实现验证后才称成立。

## 证据与讲法收口

可用主张：最小够用结构；要求、工具、状态及批准有明确接口；检查产生真实证据并被控制器消费；不同对象分别验证；失败回流成受控变更。没有材料证明所有系统必须多Agent、固定重试/样本数普遍安全或某配置消除全部错误。

每个建设动作保持五问：输入是什么、在哪执行、交付什么证据、失败去哪、谁负责。来源说“厂商建议/仓库研究归纳”，案例说“本场设计/预期”。合成案例未实现、未运行，台账不是验收报告。
