# CONTEXT — 102 的听众、词义与讲法

## 一、听众基准

**用户已定**：AI 已经用起来，正在写智能体，但工程能力还没跟上来的人。

他们能叫 Agent 写出东西，却对需求怎么落地、任务怎么拆、颗粒度多大、怎样验收和逐轮推进缺少手感。既不假定他们是程序员，也不把他们定位成不会碰代码的人。用业务结果解释工程动作，再给必要的准确术语。

## 二、角色与术语

| 词 | 本场含义 | 讲法与边界 |
|---|---|---|
| **开发 Agent** | 协助澄清、拆分、编写代码、执行检查的 coding agent | 流程主视角。案例中始终叫“开发 Agent” |
| **业务 Agent** | 开发出来、处理业务任务的智能体 | 案例中称“工单 Agent”；不与开发 Agent 混称“它” |
| **人** | 需求与取舍的负责人、授权者、指定验收者；可能是同一人 | 不必手写每个任务和测试，但要确认业务规则与关键边界 |
| **清醒／不糊涂** | 能从可访问且现行的材料确定目标、边界、进度、证据、下一步与续停条件 | 工程工作状态；流程降低迷失风险，不保证模型永不出错 |
| **需求** | 希望在特定场景得到什么结果、受什么限制、什么算满足 | 与验收相互校对；发现未知可以有边界地探索，不假装全能预先写清 |
| **拆分** | 把需求加工成有依赖、有边界、有结果和验证办法的工作单元 | 不等于列代码文件，不等于一次预定所有实现细节 |
| **颗粒度** | 单个工作单元承担的结果、决策与改动范围 | 以可检查、失败可定位、风险可控制判断；不是代码行数或固定耗时 |
| **任务** | 一个有边界的工作单元，可以跨多轮完成 | 不等于一次模型调用；必要时再拆，也可以合并过细任务 |
| **一轮迭代** | 读当前状态、选择本轮目标、执行、验证、依据结果作决定并更新状态 | iteration by iteration。下一轮消费上一轮结果，而非原样再试 |
| **验证／验收** | 验证产生证据；验收由指定的检查机制或人据此作通过决定 | 执行者可跑检查、提结论；它的自报不构成唯一验收依据 |
| **Harness** | 支持并约束 Agent 工作的外部环境：信息、工具、权限、规则、检查、状态读写等 | 持久化状态可由文件或系统保存；不要求一定使用某产品 |
| **Harness 治理** | 持续维护外部环境，让现行事实可找、规则有执行点、反馈可达、过期材料退出 | 不只是加文档；不声称本场讨论的一切都属于 Harness 层 |
| **循环控制** | 根据有效反馈决定下一轮目标、是否继续、暂停或交人 | 内部与 Harness 环境治理区分；对客先讲“下一轮怎么定”，再视需要命名 |
| **交付** | 当前约定范围的结果有证据，风险与未完成项明确，并由指定验收者接受 | 不等于发布上线，更不等于业务效果已经达成 |

## 三、表达纪律

1. **一条问题轴，一个贯穿案例。** 每个流程动作先呈现 Agent 此刻缺什么，再说明补什么和如何检查。
2. **每个模板都要填一份。** 一张空表不能代替实战；每个关键步骤展示输入、输出、失败去向。
3. **先做现象，后给名字。** 术语可以使用，不沿用 101 的词表与出现次数；不以术语密度制造进阶感。
4. **两类改进分开讲。** 修交付物和修工作环境有不同触发；只有可复现的环境缺口才考虑升级约束，新增后复核有效性与适用范围。
5. **现行与历史分开。** 变更使部分证据过期，先检查适用范围，再重新验证；不是全部归零，也不是全部继承。
6. **完成与停机分开。** 达到预算、遇到授权阻塞或未知都可以停止，不能因此标完成。阈值由任务风险和资源决定，不给通用轮数。
7. **机器检查不是万能裁判。** 业务含义、未知、外部效果可能需要人判断；新模型或独立审稿同样不是保证。
8. **流程是最小充分的。** 短任务可共用一份简短工作单；长任务、跨会话或有风险时才增加持久化记录和检查点。不规定每任务一堆文件。
9. **对客正文独立成篇。** 不出现仓库路径、内部项目名、姊妹 talk 的页号或“参考另一场”。本工作区内部可以用来源指针。
10. **案例身份明示。** 合成演练、观察到的事实、来源转述、教学建议分别标记；没有运行证据，不写“实测通过”。
