# 让 Agent 接着做，而不糊涂

**先把需求加工成可执行、可验证的工作，再一轮一轮推进。** 不必每个字段单独建文件；一份共享工作单即可起步，复杂或跨会话任务再增加记录。

## 1．开工前：先加工，再拆分

先确认谁需要什么结果、哪些动作不能做、什么证据算满足。然后：

1. 按结果找一条最小完整路径，不先按文件列操作。
2. 单列未知：业务取舍问负责人，技术未知做有预算的探索。
3. 按结果和风险切块，写清每块不负责什么。
4. 排依赖，决定先让哪件事成立。
5. 给每块配检查与失败出口：做完能验、失败能定位、风险能控。过粗再拆，过细合并。

## 2．当前工作单（复制后填写）

| 项目 | 填写 |
|---|---|
| 需求与当前范围 | 谁在什么场景需要什么结果？本次不做什么？ |
| 当前依据与负责人 | 哪份需求／规则生效，谁确认；哪些旧资料已失效？ |
| 任务与依赖 | 当前工作单元是什么，前提是否成立，下一项为什么在它后面？ |
| 本轮目标与边界 | 这一轮只让什么成立，可以改什么，禁止什么动作？ |
| 验证与验收者 | 检查什么，谁确认业务意义；哪种坏例应当失败？ |
| 本次关联与证据入口 | 哪个实现／规则／输入版本；实际结果存哪里，能否重查？ |
| 实际状态 | 通过、失败、未验证分别记录；未执行不能算通过；旧版通过不能直接用于当前版 |
| 决定与下一步 | 继续、再拆、重查、交人还是完成？下一轮会读哪条结果，先做什么？ |
| 预算、授权与接手 | 时间／轮次等上限是什么，哪些事必须停，谁能接手？批准是否只适用于本次动作？ |

一项任务可以跨多轮。**每轮开始重读当前单，结束更新当前单；让前轮结论真的进入下轮目标。** 决策理由和历史证据可以保留，但不要淹没唯一的现行状态。

## 3．失败别都处理成“再改一下”

| 发现 | 先做什么 |
|---|---|
| 人也说不清应该得到什么 | 澄清需求或规则，不让 Agent 替人作业务取舍 |
| 结果明确，实现没做到 | 定位实现错误，修后复验相关行为与回归 |
| 一步牵连太多，失败分不清 | 再拆或限界探索，不继续一口吞 |
| 错结果被放过，或检查没运行 | 修检查／环境，让已知坏例失败；暂停自动通过 |
| 结果属于旧版或其他工作 | 核关联和适用范围，重新验证当前版 |
| 需要新授权、预算到限或没有进展 | 暂停、保留状态并交人；不自动加预算，不标完成 |

## 4．一份已填单：规则更新后的接续

> **合成教学演练，未运行。** 这里示范记录方法，不代表功能已经通过检查。场景是开发 Agent 维护一个只给坐席分流建议的工单 Agent，不发消息、不改订单、不退款。

| 项目 | 示例填写 |
|---|---|
| 需求与范围 | 当前只维护坐席建议；规则更新后，旧判断不能冒充新规则下的结果；外部动作仍不在范围内 |
| 当前依据与负责人 | 业务负责人确认 R2：已取消订单即使未收货也转人工；R1 转历史，开发维护者负责加载入口与开轮核对 |
| 任务与依赖 | T3 规则更新任务还未验证；预设入口已纠正，接手仍要核目标与加载版，再验证当前行为 |
| 本轮目标与边界 | 先核实际加载版与 R2，再补当前实现回归；不扩功能、不获得发送或退款授权 |
| 验证与验收者 | 先核负责人确认的目标版与加载器实际返回版；故意保留旧入口应触发暂停。入口恢复后再跑当前样本，负责人核业务预期 |
| 关联与证据入口 | R2／演练实现丁／确认的输入集 A–F；EV3 目前是脚本索引，没有实际工具结果 |
| 实际状态 | **未验证**；有旧版通过记录，不足以标本版通过 |
| 决定与下一步 | 不标完成；下一轮先核入口再复验。核对失败就转环境修复，检查不可用则报告阻塞，不重新乱改实现 |
| 预算与接手 | T3 资源上限由负责人在实际开轮前确认，当前未给具体数值；需要新权限、检查不可恢复或达到约定上限就交业务负责人和开发维护者，不自行续加 |

## 5．收尾前只问四句

- 这次通过对应当前哪个目标与版本，有什么证据？
- 哪些只是未验证、还有歧义或范围外的事？
- 换一个会话，能否找到当前状态与下一步，而不用重读全部聊天？
- 这次是有据完成，还是因为预算、权限或阻塞而停下？

**开轮有目标，执行有边界，收轮有证据，下轮有依据。**
