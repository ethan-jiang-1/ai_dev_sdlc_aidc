# AGENTS — 102 工作入口

## 按顺序做

1. 每次进入先读 [CURRENT](<CURRENT.md>)，从“下一步”选择工作；首次进入再读 [README](<README.md>)。
2. 写故事线、案例或对客文字前读 [CONTEXT](<CONTEXT.md>)。修改主张时先查 [来源台账](<02_evidence/00-sources.md>)对应条目；来源不支持就降级为教学提案或登记缺口。
3. 在 [故事线](<01_storyline/00-storyline-map.md>)校对推导，在 [案例走读](<01_storyline/02-case-walkthrough.md>)维护案例事实；未决选择只记 [开放问题](<01_storyline/04-open-questions.md>)。每个新动作必须能说明 Agent 缺什么、提供什么、怎样判结果、失败后去哪。
4. 上游获 review 后才进入逐页结构和对客文案。review 改变主张时先回改源，不在下游堆补丁。
5. 收尾核下面的完成门，更新 CURRENT 和开放问题。旧轮次不堆热区；积累后移入历史件。

## 本轮完成门

- 用户定调与 agent 提案可区分；页数、时长、案例未获批准时保留提案状态。
- 需求澄清、执行前拆分、颗粒度、逐轮反馈、状态交接、变更处理、续停与验收都能在案例中找到具体动作。
- 开发 Agent 与工单 Agent 不混称；执行者的自报不等于验收证据。
- 任务不是轮次；停机不是完成；检查未执行不是通过；历史通过不是当前通过。
- 来源分级准确；合成案例没有伪装成已运行产品；教学模板没有伪装成行业统一标准。
- Markdown 文件链接能解析，根地图已登记；下一会话只读本文件与 CURRENT 就知道从哪里继续。
