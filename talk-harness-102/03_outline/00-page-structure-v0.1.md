# 102 逐页职责 v0.1

> **提案**：27 页内容，约 53 分钟，含两页现场练习；尚未经用户确认。这里是逐页职责、时长与讲法的唯一维护处，不是 PPTX 或已测试的排练结果。
>
> 上游：[故事线](<../01_storyline/00-storyline-map.md>)、[案例事实](<../01_storyline/02-case-walkthrough.md>)。术语与听众以 [CONTEXT](<../CONTEXT.md>)为准。下游讲述稿将按同一页号写作；内部来源和导演指令不进入对客正文。

## 页表

每页只追一个 Agent 此刻的问题；“展示材料”给后续编稿／渲染者，不要求整表挤在一页。

| 页 | 段落／标题 | Agent 此刻的问题／本页职责 | 展示材料与讲法 | 分钟 |
|---|---|---|---|---:|
| P1 | 开场：把工作组织成一轮轮可推进的任务 | 本场要解决什么 | 封面副标题“Harness 102｜工程执行”；界定工程执行延展：把需求组织成可验证、能接续的工作；不要求先听过其他内容 | 1 |
| P2 | 开场：做出来，下一轮仍可能没方向 | 下一步该做什么 | 三个现象：一口气做多、改着改着忘限制、换会话重猜；落点转向任务、证据与下一步，不要求公开暴露问题 | 2 |
| P3 | 开场：一句需求，藏着几种决定 | “处理完”到底是什么意思 | 同一原始工单需求；明确开发 Agent 和工单 Agent 两角色。先问分类／回复／退款，不急着解释 Harness | 1 |
| P4 | 第一幕：先把结果和边界摆清楚 | 谁用、得到什么、不能做什么 | 从需求小单提取三组：使用场景、结果、禁做动作；不是叫听众背六字段 | 2 |
| P5 | 第一幕：需求和验收一起写 | 什么结果才算对 | A/B 正常、C/D 不确定、E 不越权；先展示代表输入，其他样本口述。预期由负责人确认 | 2 |
| P6 | 第一幕：不知道，先有去向 | 未决业务和实现未知怎么处理 | 业务规则问人；技术可行性限界探索；两者输出不同，不都写成功能完成 | 2 |
| P7 | 第二幕：拆，也有流程 | 怎样从需求得到工作单元 | 五动作：按结果、列未知、切风险、排依赖、配检查／出口。每步落一次案例动作，不只展示箭头 | 2 |
| P8 | 第二幕：先切一条完整的小路径 | 第一块应该是什么 | T1：输入到可查看的建议与依据，纵向闭环。T0→T1→T2 与变更任务的关系在旁用简图，不上全清单 | 2 |
| P9 | 第二幕：太粗、太细、刚好能验 | 粒度怎么判断 | 三种任务描述对照；用“做完能验、失败能定位、风险能控”判断，风险受控才谈回退，不承诺外部副作用都能撤销 | 2 |
| P10 | 第二幕：给任务一张小卡 | 接到任务时必须知道什么 | 已填 T1 卡：结果、前提、边界、检查／验收、暂停。证据入口与案例预算要有具体示例，细节只口播 | 2 |
| P11 | 第二幕：练习——加上自动回复？ | 新要求应该先做还是先问 | 独立想一张任务卡；先识别新增外部动作授权。主持人给建议答案，允许更小的只生成草稿方案 | 3 |
| P12 | 第三幕：开轮先读当前状态 | 这轮该从哪里开始 | 读目标、任务、前轮结果、当前版本和相关基线；核对不吻合时先恢复工作依据 | 1.5 |
| P13 | 第三幕：输出对了，证据可能没对 | 我为什么不能立刻标完成 | T1 队列看着正确、依据却无法定位；预设失败，不用“实测截图”。修引用后仍只验证当前小范围 | 1.5 |
| P14 | 第三幕：用证据决定下一步 | 哪层证据回答什么、据此怎样行动 | 结构与版本、样本业务预期、动作授权三层；开发 Agent 可执行检查，按既定标准／职责判断继续修、补查、交人或接受当前范围 | 2 |
| P15 | 第三幕：检查也要试着让它失败 | 检查是否真能拦错 | 冻结预期，注入坏实际输出；失败送达暂停／修复分支。未执行不是通过，演练夹具不改正式标准 | 2 |
| P16 | 第四幕：失败先分流 | 下一轮该改需求、代码还是检查 | 失败去向用三个代表：业务未决、实现错误、证据失效；剩余分支见工作单，不把六行讲成六种新术语 | 2 |
| P17 | 第四幕：T2 失败轮如何收尾 | 这次失败留给下一轮什么 | 连续卡左侧：D 错分、EV2a、T2 未完成、剩余预算、修判断顺序；结果全是预设脚本 | 2 |
| P18 | 第四幕：下一轮仍做 T2 | 前轮结果怎样改变这轮目标 | 连续卡右侧与左侧对照；R1 不变，实现版变；D 与 A/B/C/E 回归，当前版验收成立才转任务 | 2 |
| P19 | 第四幕：练习——输出有了，能往下走吗 | 哪份绿灯可以用于这次决定 | 两状态：本版没运行检查且环境不可用／同规则旧实现的局部检查绿灯且环境可用；题面填清当前规则 R1、实现丙与证据实现乙，要求选下一目标、状态和接手人。答案要说补哪类检查、核哪版 | 4 |
| P20 | 第五幕：规则变了，先恢复下一轮的依据 | 哪个版本和证据仍适用于本轮 | R2 新增取消订单转人工，F 的旧预期失效；A–E 预期可保留但当前实现仍回归。判断变更影响，为后续执行恢复正确起点 | 2 |
| P21 | 第五幕：新目标，旧入口 | 为什么“记得读新版”还不够 | 已确认目标版 R2，实际加载入口 R1；不是靠模型自报；环境缺口与产品判断错误分开 | 2 |
| P22 | 第五幕：让错误入口真的被拦住 | 谁维护规则，失败由谁接 | EV3 环境修复：目标版对加载版→不符暂停→修入口→同坏路径复验→功能检查。以动作展示后再命名 Harness 治理 | 2 |
| P23 | 第五幕：把当前状态交给下一轮 | 接手者怎样恢复工作 | 使用演练三轮次卡，核目标、未验证、版本与下一步；相关检查仍不可用则交人，不能恢复成已完成 | 2 |
| P24 | 第五幕：让有效约束支撑后续执行 | 哪些环境资产仍支撑下一步 | 约束需要 owner、失败锚点、适用范围、坏路径复验、退出；等效校验替代后减重复检查，历史退出现行入口 | 2 |
| P25 | 第六幕：继续、交人、完成是三件事 | 怎样决定续停 | 反馈明确且在授权／预算内才继续；歧义／权限／资源阻塞交人；通过证据与接受当前范围才完成 | 2 |
| P26 | 第六幕：交付一份可接手的结果 | 为什么这次敢交付 | 当前范围、当前证据、未验证／限制、授权风险、接手点；演练过关不是上线与外部业务效果 | 2 |
| P27 | 第六幕：用流程积累可信进展 | 听众如何开始、每轮怎样形成新依据 | 回答主问题，带走最小工作单；从自己判得出对错的一件事开始。总结任务、反馈、续停与接续，不加新框架 | 1 |

- [PPT 文案](<../04_drafts/ppt-text-v0.1.md>)是唯一上屏候选内容池，P1–P27；每页含**不上屏的理解背景**和足量候选材料，以供 PPT Agent 独立理解、按版面取舍。L2／版式指令不成文；背景不能复制到画面。

## review 门

1. 每页职责清楚；PPT 文案每页含足够不上屏背景，但展示内容精简，不复制整张规则表或治理表；开场聚焦工程任务／下一步，验证聚焦行动决策，治理聚焦状态接续。
2. PPT 文案独立可读，每页给足上下文、关键状态与可选具体材料；单一上屏事实只维护在文案源，口播不形成第二版本。
3. P17/P18 连续展示同一 T2，不能合并成“失败后修好”；任务、规则、版本、剩余预算和回归有出处。
4. P21/P22 分开目标版、实际加载版和旧证据关联版；展示预设脚本中的拦截→授权修复→坏路径复验→功能检查，修入口不等于功能通过；明确这些动作怎样恢复继续 T3 的条件。
5. P11/P19 有可直接主持的题面、控时、答案和判据；练习页题面不提前泄露答案；执行者没有改变验收预期的默认权力。
6. 对客稿不带姊妹 talk、仓库路径、审稿过程或无依据背书；内部来源与理解背景不冒充上屏文字。
