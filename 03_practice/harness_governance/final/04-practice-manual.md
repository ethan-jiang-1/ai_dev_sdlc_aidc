## 0. 用法

1. **先诊断后动手**：§1 四问打分（半天），找到最痛的一档再进梯子；
2. **按梯子推进**：§11 P0→P4，每级独立验收，不要跳级上平台投入；
3. **每条规程独立可用**：单条照做即有收益，不必全套齐备才开工；
4. **反过度工程清单（§12）常备**：每加一个机制之前过一遍。

## 1. Phase 0 · 四问打分表（诊断｜操作化：final/03 §0.2｜DSH 三问 + 用户实战补充第④问/缺口⑦）

| 问 | 测什么 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|---|
| ① 规则住在哪里？ | 知识外置 | 人脑 / 聊天记录 | 文档可搜索 | 可执行检查（exit non-zero） |
| ② 正确入口明确吗？ | paved road | 每次猜代码位置 | 有 owner 可查 | 有归属表 + 范本 + 升级条件 |
| ③ 错误何时被发现？ | 反馈延迟 | 生产 / 用户报 | review / CI | 本地秒级 / 编译期 |
| ④ 现行与历史分得开吗？ | 现行共识可辨（缺口⑦） | 概念叠层，靠考古拼"现在做哪一版" | 有日期 / git 可考，但无状态标记 | 现行共识唯一 home，历史带生命周期（proposed→implemented→rejected/archived） |

**产出**：四行打分表 + 每行"最痛的一个真实例子"。**验收**：能指着一个具体 bug / 返工说出它是哪一档缺口造成的——说不出来就是没诊断透，先别动手。

## 2. 棘轮操作规程（操作化：宪法 2 / 节奏 1｜Hashimoto / Osmani / HumanLayer / Böckeler / Cloudflare + DSH 分流）

**触发**：同一类 agent 失败出现**第二次**（第一次只记录，进失败案例库）。

**分流**（错误类型 → 落点）：

| 错误类型 | 判定 | 落点 | 动作 |
|---|---|---|---|
| 可机械判定（格式 / 架构 / 命名 / 风格） | 能写成规则让机器判 | lint / CI | 固化为 exit non-zero 检查（进 §6 负例控制）；AGENTS.md 里**不写**（guide / enforcement 分工） |
| "不知道"类（命令、路径、环境陷阱） | agent 自己发现不了或发现代价高 | AGENTS.md 加一行 | 固定格式：**现象 → 处置 → 为什么**；链到 home |
| "做不到"类（agent 无法自证） | 缺验证手段 | 验证工具 / 传感器 | 做成脚本 / 命令 + 一条指路告诉 agent 它存在 |
| 语义 / 意图类 | 机器判不了 | review 检查单 / 任务 skill | 写进评审角色清单或 skill，不冒充门禁 |

**验收**：① 零上下文的新 agent 能沿文件找到并遵守这条；② 原失败场景重放不复发。
**转正（快慢双通道）**：棘轮产物当场生效但标记"**新增（待复核）**"——当场修的不一定修对（错根因 / 过宽过窄 / 与既有规则冲突），进下次周期清扫（§7 第 6 条）的优先校对清单；校对通过 → 转正。**棘轮提议、清扫转正**（Vercel 准入双闸门同构）。
**退出（拔枯枝）**：模型升级后重放原失败案例，新模型不再犯 → 删这条规则 / 组件（进 §10 复检清单）。
**反例**：不 /init 自生成；不预防性加规则（无真实失败锚点不加）；不写 agent 读代码就能自己发现的信息；入口文件保持 <60 行量级（HumanLayer）。

## 3. 入口文件规程（操作化：工件 1/2/6｜OpenAI / HumanLayer / ghostty / openai-cookbook + next.js / goose / Shopify 实物）

**模板**（AGENTS.md 骨架）：

```markdown
# <repo> Agent Guide
## 常驻规则          # 每条 1–3 行、链到 home；每行对应一次真实失败（棘轮产物）
## 布局              # 每个顶层区域一句话 + 指到该区 README
## 命令              # build / test / lint / validate 精确命令 + 提速例外开关
## 红线              # 不可协商项（越权操作 / 安全 / 发布门槛）
## Recent Learnings  # 追加式失败日志，每条固定三段：现象 → 处置 → 为什么
```

**规则**：

- **尺寸判据**：每行是否充当**路由或红线**，而非行数本身；常驻层设**硬预算**（词数 / 字节，CI 校验——DSH doc-budgets 式机器兜底）；实态参照：旗舰 repo 5–7k tokens 已是上限区（逼近 Codex 32KiB 截断线，见 research/01a B8.1）；
- **单源化**：`CLAUDE.md` 用 symlink 指向 `AGENTS.md`（或一行 `@AGENTS.md` 引用）——一个目录一份事实，改规则只有一个动作；
- **嵌套克制**：只在"该子树有专属常驻规则"时放子树 AGENTS.md；大多数目录只有 README 是正确结果，不是缺口；
- **嵌套语义按目标工具实测**：三家不同——Codex 32KiB 截断 + 逐目录至多一份、Cursor 与父级合并更具体者优先、Claude Code 祖先链全拼接（详见 research/01a B4/B6/B7）。

**验收**：任一规则 10 秒内能指出唯一 home；同一规则不存在两处各写一版；根文件无教程 / 历史 / 该 link 出去的细节；`CLAUDE.md` 是 symlink 非副本。

## 4. 按需披露规程（操作化：工件 3｜Anthropic 官方预算 + Cursor / next.js / airflow 实物）

- **三层预算**：L1 常驻元数据 ~100 tok/skill；L2 正文 <5k tok / <500 行，description 匹配才加载；L3 附属文件 / 脚本零直到读取（脚本只回传输出，代码不进上下文）；
- **触发设计**：description 用第三人称、写清"做什么 + 何时用"；引用只一层深；>100 行的 reference 文件顶部放目录；
- **降级协议**（airflow 式）：runtime 不支持 skill 发现 → 直读 SKILL.md；skill 不可用 → 明文红线（如"不得做远端动作"）——依赖披露的链路要有 fallback；
- **README 链路由**（next.js 式）："改子目录前读沿途 README 链"写进入口文件——第 2 层按编辑路径触发。

**验收**：新 agent 命中任务时先读全文、不从摘要猜；未命中的 skill 不占常驻预算。

## 5. 归属表 + 参与阶梯规程（操作化：工件 8｜DSH）

**归属表模板**：

| 目标（想做什么） | 首选入口 | 何时升级 | 范本 |
|---|---|---|---|
| 换实现 / 改参数 | 配置 | 配置表达不了新行为 | `<链接>` |
| 新增能力（工具 / 命令 / 拦截） | 扩展点 | 需要一项完整可替换能力 | `<链接>` |
| 新后端 / 新子系统 | seam（如适用） | 扩展点表达不了所需驱动 | `<链接>` |
| …（按你项目的机制补行） | | | |

**面对新行为的五问**（照搬，把"扩展点 / seam / loop"换成你项目的对应物）：①只是配置组合吗 → L0；②现有扩展点能表达吗 → L1；③是需要可替换实现 + 稳定接口消费的完整能力吗 → L2（设计完整 seam，不为局部工具造多包结构）；④（横切义务，无论选哪层都要查）新增模型可见事实吗 → 同步事件 / 日志契约；⑤都不行，才论证 L3 改核心循环。
**纪律**：阶梯不是价值排序——L0 是完整能力，L3 只是影响半径最大；"本可 L0/L1 表达却爬到 L3"是乱发挥的典型形态，必须在升级条件处显式拦下。
**验收**：新任务先查表就能回答"改哪里"；升级条件写明且被遵守。

## 6. 门禁准入规程（负例控制）（操作化：回路 1/2/7｜Stripe / HumanLayer / OpenAI + DSH）

1. 每条可机械判断的规则 → 一个 `exit non-zero` 命令；写一个聚合脚本一键跑全集；
2. **负例控制三步**：引入对应回归 → 看它变红 → 还原。**没做过负例的检查 = 摆设，不许上线**；
3. 反馈信息三要素（写给 agent 读）：失败对象 + 违反的规则 + 修正入口——不是一句无上下文的"检查失败"；
4. 分工：本地 <5s 只跑受影响范围（Stripe shift-left），CI 跑穷举 + 平台矩阵；stop-hook 式"成功静默、失败才回注"（HumanLayer）；
5. 反馈分层纪律：编译 / load / 局部测试 / 组装 / invariant / 语义 review 各层只拥有自己能观察的性质——绿一层不代表层层绿。

## 7. 保鲜与现行共识规程（操作化：回路 4 / 缺口⑦｜OpenAI / Cloudflare + DSH + 用户实战补充）

1. **verify 脚本**：严格 UTF-8 / 单结尾换行 / 相对链接与锚点可达；上线时先做一次负例（故意改坏一个链接看它红，再还原）；
2. **基线钉**：依赖外部基线的文档，头部注明"结论以 X commit 为准"；上游变更后**只复核被引文件**，不全文重写；
3. **改事实只改 home**：一条规则变更 → 改 owning 文件 + 同步所有指向它的引用（漏一处漂一处）；
4. **生成类文档**：必须新鲜或明确标 stale；`git diff --exit-code docs/generated` 类命令兜底——陈旧的生成物比没有更糟，因为 agent 会信它（Cloudflare："A stale AGENTS.md can be worse than no file at all"）；
5. **现行共识唯一 home**（防概念叠层 A→A′→B→A″）：所有"当前怎么做"只在一处维护（steering / 当前实践文档）；历史决策——含**被否方案**——全部进 ADR/notes 并带状态标记（proposed→implemented→rejected/archived）；每次方向变更时旧版**显式降级**（标 superseded 并链到新 home），而不是留着不管——agent 按机器速度生产沉积，不降级就淹没现行（⑦；Ronacher 之塔为其在团队理解层的无度量极端形态）；
6. **规则审计（快慢双通道的慢通道）**：每次周期清扫**优先校对自上次以来的新增规则 / 组件**——校根因（是否只治了症状）、查冲突（与既有规则是否矛盾？有无 escape hatch？）、删错的（修错的规则回滚或重写）；顺带校对"从未触发"的存量规则（结合用量遥测判断：无触发且无理由 → 候选删除）。

## 8. 评审外置规程（操作化：回路 5｜OpenAI / Anthropic）

- agent review 从 **advisory** 起步（不阻塞合并），分角色（正确性 / 架构 / 安全），findings 强制分类，author 有 pushback 权利（防 review 噪声死循环）；
- **evaluator 必须外置**：agent 自评必然自信地自夸（Anthropic 负结果）——验收证据要"verify the world, not the self-report"：重读文件、重跑命令、看持久状态，不信 agent 的自我报告。

## 9. 运行时查询最小实现（操作化：回路 6｜OpenAI + DSH）

| 成本 | 做法 | 何时做 |
|---|---|---|
| 低 | 一条命令 dump 最终生效配置（`config dump` / `make show-config` 级） | 立刻做 |
| 中 | 声明面索引（工具 / 配置 / 接口清单）+ freshness 检查防漂移 | 声明面变多时 |
| 高 | 活进程 inspect（当前生效的 provider / service 是谁） | 确有多 profile / 动态装卸压力才做 |

**边界**：查询 ≠ 安全沙箱（bash-equivalent trust），不要当授权边界用。

## 10. 模型升级复检清单（操作化：节奏 3｜Anthropic / LangChain / Osmani / Ronacher + DSH）

**执行方式（2026-09-21 用户复核定）：模型升级日 = 大扫除日**——本清单与周期清扫（§7 第 6 条规则审计 + final/03 节奏 2）合并执行：拔枯枝 + 用新模型做一轮深度 pressure washing（Teleport："in a way that we can repeat as newer, better models are released"）；触发频率低不是缺点，绑定到清扫日程即免维护第三种节奏。

模型 / 依赖 / 基线升级时逐项过：

- [ ] **重放失败案例库**（棘轮的副产品：每条规则锚定的那次失败）——新模型不再犯的规则 → 删（拔枯枝）；
- [ ] **组件假设盘点**：每个 harness 组件都编码了"旧模型做不到"的假设，逐个问"新模型还需要它吗"；
- [ ] **工具 schema 兼容**：模型升级可能不再忠实遵循第三方 schema（Ronacher："tool schemas are not neutral"）——跑一遍工具调用回归；
- [ ] **依赖 / 基线升级**：按 change log 只复核被引文件（DSH），不全文重写。

## 11. 统一落地梯子 P0→P4（操作化：全五段｜worldmonitor 实证 + research/02 §4.3 / §5.2 统一版）

> **统一说明**：本表合并 research/02 §4.3（worldmonitor 顺序：P0 lint/测试 → P1 可观测 → P2 review → P3 自愈 → P4 全自主）与 §5.2（SDD 团队路径）两版差异：P0 取两版基础项并集；lint / 新鲜度在 P1；可观测性 + 评审在 P2——平台投入最重的项排后，但**重要性不排后**（worldmonitor 实测模仿者普遍在 P2 项掉队、只做快赢的 lint 类——投入梯度与重要性倒挂是最普遍的失真形态）。

| 级 | 内容 | 投入 | 验收 |
|---|---|---|---|
| P0 | 短 AGENTS.md + symlink + `make validate` 硬命令 + 规则变更走 PR + Recent Learnings 节 + 归属表 v1 | 零平台投入，2 周级 | §3 验收全过；零上下文新 agent 能沿文件干活 |
| P1 | 可机械条款逐条升格为 lint（§6 负例控制）+ 文档新鲜度检查 + verify 脚本（§7） | 低 | review 评论里不再重复出现同一条规则 |
| P2 | per-worktree 可启动 + 最小运行时证据（§9 低成本档）+ agent review advisory（§8） | 中 | agent 能自证视觉 / 运行时修复 |
| P3 | gardening / cleanup agent 开 fix-up PR + 用量遥测（找过热 / 欠触发） | 中高 | gardening PR 真有用（非 churn） |
| P4 | 低风险类目自 merge（须 P0–P2 安全网 + 高风险类目保留人审 + 回滚矩阵） | 高 | 自 merge 类目返工率不升 |

## 12. 反过度工程清单（操作化：组织与边界 5/7｜Teleport / Vercel / HumanLayer / Upsun + DSH）

**不做**：

- 预装几十个 skills"以防万一"；每次改动跑全量测试（HumanLayer 失败清单）；
- 预防性堆 verifier / 复杂多 agent harness（Teleport 实测："The more complicated the harness, the worse the overall performance"）；
- 为局部工具造多包结构；没有组合压力就建插件图 / 完整 seam / 活进程 inspect（DSH："确有压力才做"）。

**加任何机制前三问**：谁维护它？漂移了谁发现？确有组合压力吗？
**四个边界**：可读 ≠ 简单；Skill ≠ enforcement；清理 ≠ 回滚；查询 ≠ 沙箱。
