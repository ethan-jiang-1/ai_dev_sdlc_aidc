# result/ —— 定稿层

> **为什么叫 result（2026-09-21 用户复核定名，原 final/）**：对齐仓库分层惯例（根 AGENTS.md：研究主题按 raw / digested / result 分层）——本主题 research/ ≈ raw+digested，result/ 即定稿产物，"research → result" 正是信息流那句话。不沿用 final 的三个理由：① final 暗示冻结，而 manual 是高变更频率的活文档；② 与 `requirements_engineering/final/`（对客交付物）撞名异义；③ final 是状态词，与 research（内容词）配对不对称。（备选 distilled/ 亦记录在案，用户可否决。）

**定位**：本主题过筛后的结论与操作规程只住这里。调研堆料（证据档案 + 分篇判读 + 未采纳线索）在 [`../research/`](../research/)；当前态在 [`../CURRENT.md`](../CURRENT.md)；主题地图与信息流规则在 [`../README.md`](../README.md)。

## 进层规则

1. **只收过筛结论**：入层判据 = 多源 KOL 共识或真实规模化采用（全文见 [`backbone.md`](backbone.md) §0）；
2. **单一事实来源**：定稿只放判读与指针，证据正文一律在 `../research/`，不复制；
3. **反向同步**：review 改变定稿结论 → 同步 research/ 对应分篇（信息流三规则见主题 README）。

## 命名与生长规则（2026-09-21 定稿层去序号——用户复核定）

- **语义命名，不用序号**：序号在 research/ 是封存历史序列的锚（旧编号映射表管着）；定稿层内容是**并存的类别**（总纲 / 手册），不是先后序列，序号是无义冗余——原 03-/04- 前缀已去除；
- **不用字母后缀**（01a 式 = research/ 证据档案专属惯例）；
- manual 超 ~1000 行按域拆 `manual/` 子目录（artifacts / loops / rhythms……，具名不用号）；模板类内容先以代码块进 manual，需要独立文件时立 `templates.md`；
- **引用写法**：跨层必须带层前缀（research/01 §2.2、result/manual §6）；同层可短引（backbone §2.3）。

## 工作流
