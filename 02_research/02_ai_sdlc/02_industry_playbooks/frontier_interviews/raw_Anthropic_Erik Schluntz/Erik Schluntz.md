## 背景

Erik Schluntz 在一次事故中手部骨折，打了两个月石膏。这期间他被迫将全部编码工作委托给 Claude，从而"被迫 vibe code"。这段经历让他系统化了一套方法论，被社区称为"比 100 个付费课程都有价值"。

## 四大核心策略

### 1. 做 Claude 的 PM（产品经理）

花 15-20 分钟做前置工作：让 Claude 探索代码库 → 找到相关文件 → 共创执行计划 → 把所有上下文压缩成一条 prompt → 放手让 Claude 执行。

> "不要问 Claude 能为你做什么，问你能为 Claude 做什么。"

### 2. Leaf Nodes 策略

把 AI 的改动范围限制在"叶子节点"——不被其他模块依赖的终端模块。这些节点可以吸收一定的技术债。核心架构（主干）仍然需要人类深度保护其可扩展性。

```
核心架构（人类深度保护）
  ├── Leaf Node A（AI 生成，可接受一定技术债）
  ├── Leaf Node B（AI 生成，可接受一定技术债）
  └── Leaf Node C（AI 生成，可接受一定技术债）
```

动态边界：随着模型进步，"叶子节点"的边界会向下移动。核心架构的信任范围在缓慢扩大。

### 3. 核心逻辑人工审查

触碰系统主干的部分，人类逐行审查不可妥协。

### 4. 可验证的检查点

设计长跑压力测试和 I/O 标准，让人无需逐行读代码也能判断对错。

> "忘掉代码存在，但永远别忘了产品存在。"

## 22000 行内部案例

Anthropic 内部的强化学习代码库，一次变更 +22,160/-0 行，一天内合并。同样工作量人类工程师需要两周。四条策略同时施加，缺一不可：前置几天人类规划 → 严格 leaf node 范围 → 核心人工审查 → 压力测试验证。

## 实用战术

**TDD × Vibe Coding**
强制 Claude 只写 3 个 E2E 测试（1 个 happy path + 2 个 error path）。Erik 说他读的唯一代码就是测试。

**上下文压缩**
在自然"午饭断点"压缩。让 Claude 把计划写进文档，然后 compact。~10 万 token → ~几千。

**工具组合**
Claude Code 做重型框架搭建，VS Code/Cursor 做 review 和精确小修。

**学习加速**
问 Claude"为什么选这个库？说说它。"架构决策验证从 2 年变 6 个月。

**关键指标**
AI 任务能力每 ~7 个月翻一倍（METR 数据）。人类逐行 review 终将成为瓶颈——必须找到不读代码的验证层。
