> 嘉宾：Rody Davis，Google 顶级 agentic 工程师
> 主持：Shir Meir Lador，Google Cloud 开发者关系 AI 工程负责人

---

## 核心论断：Skills 就是上下文作弊条

> *"Skills are literally a cheat sheet for the agent."*

Rody 的核心理念：把特定设计系统/API 文档/SDK 用法压缩成精简的 Skill 文件，agent 需要时加载。这比让它自己在海量文档里搜索**更快、更准**。

他写了一个 Go CLI，自动把网站解析成 Markdown，批量生成数百个 Skills。

---

## 四大方法论支柱

### 1. Skills as Context Cheat Sheets

| 传统做法 | Rody 的做法 |
|---|---|
| 让 agent 搜索整个文档网站 | 提前把文档压缩成精准的 Skill |
| 依赖模型对"流行库"的训练知识 | 给最新的、项目专属的 API 参考 |
| 每次对话重复解释偏好 | Skill 文件一次写好，永久复用 |

**效果**：模型速度显著提升，幻觉减少，因为不再需要猜测 API 签名。

### 2. Bonsai（盆景）代码审查法

> *"像盆景艺术家一样持续修剪代码库。"*

- **扁平架构**：state / UI / data 严格分离 → 架构违规一目了然
- 持续修剪，不让复杂性累积
- 代码库健康度 > 任何其他因素

### 3. 分层 Review 策略

| 代码类型 | Review 方式 |
|---|---|
| 营销网站/前端展示 | **看视觉输出**（截图对比） |
| 后端逻辑/API | **深度审查合约和 schema** |
| 重复性模式代码 | 人工写第一个示例，agent 复制模式 |

> *"写第一个例子自己来，剩下的让 agent 抄。"*

### 4. 代码库健康才是真瓶颈

> *"AI 速度的最大瓶颈不是上下文窗口——是糟糕的代码库健康度。"*

- 扁平的、agent 可读的架构 → agent 产出质量高
- 混乱的高度耦合代码 → agent 也乱写
- 投入在清理代码库上的时间，会通过 agent 产出质量数倍回报

## 100X 工程：AI 加速完整生命周期

AI 不只是写代码更快，它改变了每个阶段：

| 阶段 | 加速方式 |
|---|---|
| **原型** | 同一需求出多个框架版本对比 |
| **测试** | 测试套件丰富度远超人工时代 |
| **审查** | Bonsai 法：视觉审 UI，合约审后端 |
| **部署** | 一键多环境 + 自动回滚 |
| **维护** | agent 持续扫描、自动发起清理 PR |

## 核心教训

> **"Skills 不是文档——是给 agent 用的作弊条。信息密度越高，agent 表现越好。"**
>
> **"像盆景艺术家一样对待代码库：持续修剪。你越不清理，agent 越不会帮你清理。"**
>
> **"写第一个例子自己来——然后 agent 会把模式复制一千遍。你的品味会通过那第一个例子，传播到全库。"**
