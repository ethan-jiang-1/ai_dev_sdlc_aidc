# OpenAI “治具工程”与 Anthropic “Agent Teams” 的路线之争

在探索大模型如何重塑软件工程（即 PPT 提到的人均调度千万行代码的第四次跃迁）时，OpenAI 的 **Harness Engineering（治具工程）** 和 Anthropic 的 **Agent Teams（集群/群智智能体）** 表面上都在解决“如何让 AI 写出巨大代码库”的问题，但经过深度比对，它们代表了两种**截然不同甚至对立的技术哲学和组织实验路线**。

它们并非一类东西，而是当前 AI 编码走向深水区的“两条路线之争”。

---

## 1. 核心定义与背景事实对比

### 🔵 治具派：OpenAI - Harness Engineering（治具工程）
*   **爆发案例**：OpenAI 内部的一个秘密实验。3 名人类工程师（后扩展至7人），带领基于最新 Codex 或内部原生大模型的 Agent，在 5 个月内交付了一个百万级代码量级的 Beta 级产品。人类在这个过程中 **“0 手写代码”**。
*   **核心打法 / 四大治具**：
    1.  **Context Engineering（上下文工程）**：精心控制 AI 能看到什么代码。
    2.  **Architecture Linter（架构约束拦截器）**：强校验，一旦 AI 写的代码不符合人类早期的预设架构规划，直接在沙箱里打回重写。
    3.  **AGENTS.md**：全局的最高法则，定义系统的输入输出边界。
    4.  **GC Agents（垃圾回收/扫地僧 Agent）**：专门跟在写代码的 Agent 后面重构、删减多余代码，防止代码库膨胀溃烂。
*   **技术哲学**：**“戴着镣铐跳舞”**。OpenAI 相信模型再聪明也会产生幻觉和漂移，因此人类工程师的角色必须变成**“工厂建造者（Tooling & Sandboxing）”**。给 AI 建立极其完备的约束流水线（治具）。

### 🔴 激进集群派：Anthropic - Agent Teams
*   **爆发案例**：由著名安全研究员 Nicholas Carlini 主导。16 个 Claude 子智能体（历时两周、消耗约 2 万美金 API 成本）在几乎无干预环境下，并行编写了 **10 万行的 C 编译器**。该编译器不仅通过了极限测试，还成功编译了 Linux 内核（6.9版本）和跑通了《DOOM》。
*   **核心打法**：
    1.  **Lead & Sub-Agent 拓扑**：主控智能体像总监一样拆解任务，孵化出不同的子智能体分配到不同的子目录去并行开发。
    2.  **全自助工具连**：允许 Agent 自己写 Bash 脚本去探查环境，甚至自己写测试脚本来互相验证，而不是依赖人类提前搭好的强力 Linter。
    3.  **极端大上下文依赖**：不刻意筛选上下文，而是让多个独立拥有 200k+ Context 的 Agent 们各自理解系统，并在中间通过消息通信。
*   **技术哲学**：**“算力自适应与并发暴力美学”**。Anthropic 相信模型的原生上下文理解力和自我通信能力。与其人类去建复杂的脚手架和测试流水线（这反而会成为技术债），不如发配多倍的算力，让机器在内部涌现出解决冲突的方案。

## 2. 两者的底层分歧：人类该把时间花在哪里？

这两种路径的分歧，恰巧映射了 PPT 里“治具派”与“激进集群派”的终极对抗：

| 维度对比 | OpenAI (治具工程派) | Anthropic (集群激进派) |
| :--- | :--- | :--- |
| **对系统自由度的态度** | **限制自由解空间**：不允许 AI 发挥“创意”，必须在 AGENTS.md 和 Architecture Linter 框定的狭窄管道里产出。 | **释放自由解空间**：给出一个宏观的 Spec，让一堆 Agent 互相协作去摸索实现路径。 |
| **预防代码崩塌的手段** | 靠外部强植入的系统级守护机制（如 GC Agents 和 静态拦截器）。 | 靠 Agent Team 内部的 Reviewer 角色和互相的交叉校验通信。 |
| **人类工程师的转型终局** | 转型为 **工厂架构师 (Factory Builder)**：人类 80% 的时间在写测试框架、CI/CD 拦截规则、和全局架构文档。 | 转型为 **算力包工头 (Micro-outsourcing CEO)**：人类 80% 的时间在分配计算资源、拆解宏观意图（Ticket化）、审查群智最终结果。 |
| **技术债的定义** | “如果缺少强有力的边界约束，AI 每天产生的几万行代码就是最大的技术债。” | “如果你今天为 AI 花一个月搭建了一套死板的脚手架代码，下个月模型智力翻倍，你这套测试用例本身就是最大的技术债。” |

## 3. 结论：没有合并的必要，但有明确的适用边界

这两个方向**不仅不一样，而且是对立的**。因此，你的 PPT 里不仅有必要分开表述，还可以把这种冲突作为核心看点（这也是第 16 页四宫格分立和第 18 页冲突的魅力所在）。

对于真实企业的采用建议：
*   **治具派（OpenAI 路线）**：适合金融、医疗、大型企业核心骨干系统。它牺牲了一部分 AI 的自主创造力，换取了系统绝对的**可预测性和安全性**。
*   **集群派（Anthropic 路线）**：适合初创公司、新产品 0-1 孵化、前沿开源重构。它利用**并发算力极速拉高产出边界**，赌的是大模型智力的进化速度能盖过系统熵增的风险。
