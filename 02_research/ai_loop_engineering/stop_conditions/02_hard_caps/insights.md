# ② 硬性资源上限兜底 — 思考洞察与失败模式

> 初盘 2026-09-28。每条带来源指针；判定级表述以 [`digested/03`](../../digested/03-构件.md) 为准。

1. **上限是资源熔断，不是质量分**。所有已知数字（20 turns、3 连拒/20 总拒、7 天、59 分钟）没有一个是质量判据——它们防的是失控、空转、被遗忘、上下文耗尽这四类**资源性事故**，不判"做完没有"。把任何一个数字写成通用刻度（如"跑 N 轮必须人看"）都越界（digested/03 §三；evidence-i Source 8 明说 59 分钟"是资源熔断，不是质量判据"）。

2. **②与①的分工**：①判每轮"过不过"，②判整个循环"还让不让活"。②触发不携带任何质量信息——熔断停下来的东西可能是好的也可能是坏的，这是它和①的本质区别。

3. **上限触发后的"去向"是被低估的设计点**。至少四种不同语义：升级给人（auto mode 熔断）/ 终止进程（headless）/ 单动作改人工、熔断重置（Codex 未合并 PR）/ 整档自删（`/loop` 7 天过期）。恢复语义也不同：`/goal` 无进展熔断**保留 goal**、四类错误**清空 goal**。同一件事（"到上限了"）在四家手里是四个不同的状态机迁移（evidence-b §4a–§4c、evidence-f）。

4. **deny-and-continue 与熔断是两层结构**：单次拒绝设计为**可恢复反馈**（带理由回给模型、"find a safer path"，auto-review 自述过半场景能自寻安全路径），连续/累计拒绝才熔断。拒绝预算是渐进消耗品，不是开关——这是②里最精巧的一处（evidence-b §4b/§4d）。

5. **"被遗忘的循环"是被官方当一等风险命名的**——`/loop` 7 天过期的存在理由原文就是 "This bounds how long a forgotten loop can run"（evidence-b §4c）。循环自主度越高，这个风险越真实：无人看管的东西必须有死期。

6. **内建 vs 外置两极**：Ralph 故意无限（上限留给人：看 TODO、`git reset --hard`、换 prompt）↔ Claude Code 把上限做成产品原语。两极都活着，说明②的实现位置仍开放（evidence-b §1；digested/03 判定总览"循环终止的内建 vs 外置"行）。
