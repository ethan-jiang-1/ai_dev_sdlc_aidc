# 07 · 控制问题矩阵：A–I1 已回源做法、I2 候选与仍然空着的字段

> **性质**：格子里的公开做法以已复核的 `raw/evidence-*` 为依据；I2 的 `【侦察回源】` 只作为候选指针，不填入已确认格子。J 路是一条本地 session 的事后编码，不是新的公开原句，也不是 P-outcome。没有对照结果的格子不得读成“这样做有效”。
>
> **证据**：[`evidence-a`](../raw/evidence-2026-09-26-a-originators.md) · [`b`](../raw/evidence-2026-09-26-b-stop-and-scheduling.md) · [`c`](../raw/evidence-2026-09-26-c-autonomy-and-convergence.md) · [`e`](../raw/evidence-2026-09-27-e-cross-feature-observability.md) · [`f`](../raw/evidence-2026-09-27-f-autonomy-gates.md) · [`g`](../raw/evidence-2026-09-27-g-dsh-control-surface.md) · [`h`](../raw/evidence-2026-09-27-h-automation-to-autonomy.md) · [`i`](../raw/evidence-2026-09-27-i-high-influence-control.md) · [`i2`](../raw/evidence-2026-09-27-i2-teams-evals-outcome.md) · [`j`](../raw/evidence-2026-09-27-j-local-goal-session.md)（本地日志）。构件收敛的票数仍以 [`03`](03-构件.md) 为准，本篇不改票。I2 中标为 `【侦察回源】` 的条目只作候选线索，未用于关闭空字段或增加独立票。
>
> **读法**：同一机构的多篇文档只算一票。Anthropic（feature_list、Managed Agents、Claude Code）一票；OpenAI（auto-review、Codex policy、harness 文）一票。案例、活文档、团队自述分开标。

## 一、先看空格

跨 feature 的业务控制面，**在已复核的公开材料中**仍然没有一张同时带着下面四列的表：

| 空字段 | 已有的邻近物 | 邻近物停在哪 |
|---|---|---|
| **授权史** | 工具级 allow/ask/deny（Codex、Claude、Managed Agents）；workspace 里的 approval gate（OpenClaw）；人说 go / 人决定何时开 PR（Beck、Copilot）；DSH 上创建和恢复目标要有人的消息 | 没有「谁提出、谁批准、批准的是哪次范围、何时撤回」的 feature 记录 |
| **priority 变更** | feature_list 约定「选最高优先级未完成项」（Anthropic）；Beads 能查询未阻塞项（Yegge，单人案例）；OpenClaw `tasks list` 的 newest-first | 没有 priority 字段、变更前后值、变更人、理由，也没有抢占是否打断在途工作 |
| **业务阻塞原因** | session `idle`、工具确认、flow `waiting`、task delivery `blocked`、DSH goal `blocked` | 原因码混在一起。OpenClaw 的 task `blocked` 是结果送不出去，不是业务依赖卡住。没有「等人 / 等依赖 / 环境坏 / 权限拒绝」加持续时间 |
| **跨 feature 验收总览** | 单项目 `passes`、单 session rubric、PR 交接、测试与 lint | 没有跨 feature 的统一验收者、证据链接、部分通过和发布门 |

这四格在公开材料里是空的。J 路把它们放到一条真实 goal 上再看，仍然是空。其余控制问题已经有机制，只是尺度比 feature 小。

**交接面读法（2026-09-30 增）**：八问按「控制什么」横切；[`capability_ladder/00-map`](../capability_ladder/00-map.md) 把同一批问题按「把哪个决定交给循环」纵切为主线 LE0–LE3 加 A/B 支线，并逐档判定交接面是否已有一手机制（LE1 授权、LE2 续跑、LE3 唤醒已证；支线局部已证）。纵切不改变本篇任何格子的判定，只给下游（landscape §3.5、教学件与手册）提供按交接面引用的入口。四列空格在 LE3 档最疼——人不在场时，它们是「回来还能不能接上」的全部依据。

## 三、分问

### 取题

工作从四处来，优先级几乎都不留痕。

- **人当场指定**：Cursor 从 IDE、Slack、issue 评论、Linear 或 API 启动；Copilot 由人交给云端 agent；OpenAI harness 文里工程师用 prompt 描述任务。活文档或该团队自述。证明有触发器，不证明队列排序。
- **文件中的未完成项，模型自选**：Anthropic 长程 harness 写「选最高优先级尚未完成的 feature」；Huntley 让 Ralph 按 `fix_plan.md` 选最重要的事。这是项目内约定。evidence-e 已写明：没有优先级变更事件。
- **到点或事件再跑**：Claude Code `/loop`、LangChain 的 cron/webhook/channel、OpenClaw automation。回答「何时再启动」，不回答「多个 feature 谁先做」。
- **DSH**：`dsh-goal` 写明 stores goal state but does not schedule work。`todo` 是 session 任务列表。跨 feature 的下一项若存在，只可能在插件自建的 roadmap/queue 里，原生合同没有这一列（evidence-g）。

### 授权

公开机制集中在**这一次动作能不能做**。

- Codex 源码按危险命令、沙箱、项目可信度映射 `Allow / Prompt / Forbidden`（evidence-f，固定 commit 上的机制）。
- Claude auto mode：拒绝并带理由继续，3 连拒或 20 次拒绝后停（evidence-b）。这是拒绝预算，不是授权台账。
- Horthy：在工具选定和工具执行之间打断，高风险动作退出循环等人（evidence-i）。客户向 agent 的设计主张。
- LangChain：工具级 `interrupt_on`，`approve / edit / reject`，可恢复（evidence-f）。
- Spec Kit / OpenSpec：关键歧义、reviewer 拥有的 checklist、任务分解确认（evidence-f）。问的是意图，不是动作风险。
- DSH：`create / edit / pause / resume` 要求当前回合有人的直接消息；`complete / blocked` 可以在自主回合里发生；resume/fork 之后默认解除武装，要人再次授权（evidence-g）。
- 反例：Claude issue 里，一次很窄的 push 授权被沿用到后来更大的功能并直接推上 main；另一则是分类器拒绝之后没有人在环的接手路径（evidence-f）。单次报告，不外推发生率。

**空着的**：feature 一次授权的对象、动作、有效期、撤回。evidence-f 把「授权要绑定目标、动作和有效期」标成判据候选，并写明这还不是公开规范。

### 执行

三层都有，互不顶替。

- **一轮之内**：模型选工具、环境执行、结果回到上下文。Willison、Anthropic 2024、Aider 的编辑环都在这层。
- **同一会话续轮**：Claude `/goal`；DSH `goal-round-driver` 只在目标 active、armed、agent idle 且还有轮次额度时塞入下一轮。driver 明文不做新 agent、不做 Ralph 式独立尝试、不做异常自动重试（evidence-g）。
- **隔离环境里跑完再交接**：Cursor 云端 VM、Copilot 的一次性 Actions 环境、OpenAI 的 per-worktree 应用。恢复接口是 Managed Agents `wake`、DSH 的 session 事件日志、OpenClaw resume。

Copilot 一次会话 59 分钟、一个仓库、一个分支、一个 PR（evidence-i，活文档）。这是执行边界，不是跨 feature 的 owner 表。evidence-e 仍缺：哪个 feature 正在被哪个 session 执行、是否互斥、依赖谁。

### 验证

硬门和裁判已经分开出现，行为面仍空。

- **硬门**：测试、类型、lint、非零退出码。Huntley 叫 back pressure；Aider 默认 lint、测试要显式打开；Copilot 在临时环境里跑测试和 linter；OpenAI 用自定义 linter，错误信息里写修复说明。
- **另一角色来裁判**：Claude `/goal` 用新的小模型看 transcript 里的硬规则，Osmani 写明它不判断内容好坏；Managed Agents 有 rubric 和独立 grader；LangChain 把 grader 分成确定性与 LLM-as-judge；OpenAI auto-review 强调审批角色与干活角色分离。LLM 裁判一律标不确定。
- **人看交接物**：Spec Kit 的 checklist 勾选权在 reviewer；Cursor 用截图、视频、日志说明自己如何验证。
- **行为面反例**：Beck 把关测试、删测试写成作弊；Yegge 写下「缺的测试就是通过的测试」。这与 Anthropic 点名的提前宣告完成同向，仍是案例。

没有来源给出「质量置信度达到某值就免人工」。动作被批准，推不出行为做对了。

### 停止

骨架仍是 [`03`](03-构件.md) 的三件：机器可核闸门、硬上限、验收与干活分离。I 路只是把硬上限的产品实例补全（Copilot 59 分钟、DSH 默认 256 轮），没有新的轮次刻度。

完成权的设计空间保持原样，不合并：

| 谁说停 | 出处 | 限制 |
|---|---|---|
| 人的 taste | Huntley | 故意不把 TODO 耗尽做成内建停止 |
| 清单上的 `passes` | Anthropic feature_list | 单项目文件，不是跨 feature 验收总览 |
| 独立小模型的三值 | Claude `/goal` | 只核硬规则 |
| 干活模型自己 | Anthropic 2024 的默认终止；DSH driver 没有独立 evaluator | 与「提前完成」失败模式直接冲突 |
| 审批 agent | OpenAI auto-review；harness 文里的「reviewer 都满意」 | 后者是该团队自述，并写明不可外推 |
| 人说 go 才做下一条 | Beck | 单人案例 |

Horthy 的因子 8 是另一极：高风险动作不要留在「直到目标」的循环里。这和「循环要有停止条件」同向于控制，方向相反于把循环交给模型。

### 记忆

按尺度排，避免把小尺度记忆叫成 feature 账。

| 尺度 | 已回源 | 下一轮怎么读到 |
|---|---|---|
| 会话 | DSH append-only session log；Managed Agents session | resume / `wake` |
| 单项目文件 | feature_list、progress、fix_plan、loop.md；OpenAI `docs/exec-plans`（active/completed）加 doc-gardening | 冷启动重读；短 `AGENTS.md` 只当目录 |
| 多条 detached 执行 | OpenClaw task/flow | `tasks list/show` |
| issue 图 | Beads：git 中的 JSONL，做完一条就杀掉会话 | `bd ready`（Yegge 自述，附录里的模型评价不作证据） |
| 失败形态 | Yegge：605 份 markdown 计划，外层阶段在压缩后消失 | 会话内计划不能冒充跨会话记忆 |

DSH 的 `todo` 整表替换、归创建它的 session 所有。session 日志能回答「上一轮发生了什么」，不能回答 feature 的授权和优先级。

### 升档

位置词已经够用，刻度仍然空白。

- Morris 的 outside / in / on the loop，以及 Osmani / Claude Code 的四级运行模式，是分类，不是成熟度（[`03`](03-构件.md) §三）。
- 能写成门的是事件：动作类别、沙箱与网络、关键歧义、拒绝预算、工具级 interrupt、授权是否绑定目标（evidence-f 的候选，尚未进实践层）。
- OpenAI harness 文写「只在需要判断时升级给人」。这是一个仓库上的自述，没有放行曲线。
- 升级可达性：拒绝、暂停、要求人工，都不等于人接得住。Claude 的软边界无 fallback、窄授权漂移，以及子 agent 的拒绝传不回 parent，是反例（evidence-f）。

### 复盘

看到了「把失败写回环境」的设计，没有看到「规则改动被评估、可回滚」的闭环。

- Huntley 把坑写成环境里的牌子；Anthropic 长程文把提前完成写成表。
- Runkle 的 hill-climbing 主张用 trace 改 harness。Osmani 把这一层放在 harness，不放在 loop。两说并存，不合并。
- OpenAI：曾经用周五 20% 时间清 slop，然后改成把原则收成 linter，并由后台任务开重构 PR。自述。没有写出规则的版本、回滚和「这次改规则是否放大了错误」。

## 四、DSH 落在哪一行

DSH 原生覆盖的是**单 session 的执行、续轮、轮次上限、恢复和人重新武装**。它不覆盖取题排序、feature 授权史、priority 变更、业务阻塞原因码、跨 feature 验收。所以「跑得动但看不清」对应矩阵里取题、授权、记忆、验证的 feature 列为空，而执行和停止的 session 列已有机制。插件仓若自建 roadmap，是在补这些空列，不是在使用 DSH 已经提供的合同（evidence-g）。

一次本地 session 里，goal 被 create/resume 四次，`roundsStarted` 一直是 0，对话靠人的消息和子代理事件往下走（[evidence-j](../raw/evidence-2026-09-27-j-local-goal-session.md)）。这不推翻上面的机制说明：有 goal 对象不等于 driver 已经计轮。

## 五、若要做一次观察，记哪些字段

字段定义如下。第一次本地观察已做完，表在 [evidence-j](../raw/evidence-2026-09-27-j-local-goal-session.md)，不要在这里再抄一遍。那次只事后编码了一条已经发生的对话内 goal：四列仍空，`roundsStarted` 为 0，催问 2、续轮 0，返工和人工分钟未测。外置行已写在 [`ledger-row-2026-09-27-k.md`](../raw/ledger-row-2026-09-27-k.md)，goal 没创建，那一行的工作没开始。本段仍不是实践规范。设计仍是一次只改一个变量：同一个小 feature，对照「只有对话内 goal」和「外置一行工作记录 + goal 引用这行」。

外置的那一行至少有：

1. `source`：下一项从哪来（人指定 / 文件未完成项 / 定时器）。
2. `authorized`：谁批准、批准的动作和目标、是否一次有效。空着就标空，不要推断。
3. `priority`：当前值；若中途改过，记下前后值和理由。没改过就写「未变更」。
4. `blocked_reason`：等人、等依赖、环境、权限、其他。不要只写 blocked。
5. `stop_reason`：测试门、硬超时、熔断、模型自称完成、人停。模型自称完成单独计。
6. `accepted_by`：测试、独立清单、人。没有验收者就不要记成完成。
7. 计数：催问次数、续轮次数、返工次数、人工分钟。这四项才可能变成以后的 P-outcome；本篇仍是 0。

## 六、本篇改变了什么

不确定性缩小在两处。feature 缺口不再是「还缺一个记忆产品」。记忆产品已经有好几类。缺的是授权史、priority 变更、业务阻塞原因、跨 feature 验收这四列，而且它们在已回源材料里是稳定的空，不是还没搜到的人名。J 路把这四列放到一条真实 goal 日志上再看了一次：还是空。同一条日志还说明，goal 被 resume 不等于 driver 计了轮。

没有改变的：停止条件三件骨架、外层调度不是最小 loop 的必要条件、没有通用轮次阈值、harness 不是 loop 的单向原因、外置行会不会减少催问（对照臂没跑）。2026-09-27 用户要求将可操作项补入实践层：[`loop_governance/manual §5`](../../../03_practice/loop_governance/result/manual.md) 仅试行工作行模板，不把本篇的缺口观察或 J 单例升格为通用效果结论。
