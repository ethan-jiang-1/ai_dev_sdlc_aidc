## 判定一：三层的分工（一句话版）

| 层 | 管什么 | 证据 |
|---|---|---|
| **Harness 治理**（`03_practice/harness_governance/`） | **单次运行受控**：约束写进环境（门禁/传感器/漂移清理），诊断轴＝"agent 缺哪句话" | 该主题 result/backbone（用户已确认） |
| **Loop 治理**（`03_practice/loop_governance/`） | **多轮的治理**：停止条件（跑到哪算完）、外层调度（下一轮跑什么/何时跑）、自主度分档（人在哪一站） | 本主题 evidence-b/c，构件判定见 [`03-构件.md`](03-构件.md) |
| **SDD 工具**（`03_practice/spec_driven_development/`） | **变更的产物链**：proposal/specs/design/tasks 的工件与阶段 | 该主题 debate/ 权威 |

**依赖方向**：loop 层的硬前提是 harness 层（单次运行不受控时，loop 只是把错误复制得更快——主线 talk P9 的判据，与 Ralph 的 greenfield 限定、Anthropic "先过基线再干活"三方同向）。SDD 与 loop 是**同一控制问题的两种工件形态**，不是上下层。

## 判定二：收敛成立，且是双向的（全部可溯源到官方一手动作）

- **SDD 侧在拆人门**：OpenSpec v1.0.0 官方拆刚性阶段（"No more rigid phases"、"Dependencies are enablers, not gates"），人工确认收缩为 "only when context is critically unclear"（v1.13.2）；README 仍保留 "Agree before you build"（产物链没丢，只是门变窄）。
- **SDD 侧在吸收 loop 原语**：Spec Kit 官方社区目录收录 **Ralph Loop extension** 与 **Autonomous Run Governance preset**；v1.0.4 官方接入 DSH（#4336）。
- **loop 侧在吸收 spec**：Böckeler 把 spec 降格为 **feedforward guide**（guides/sensors 模型——指引归文件、执行归门禁）；Anthropic playbook 的 intent.md/spec.md 工件链就是 spec 担任 loop 的检查点。
- **loop 侧在吞并 SDD 的功能位**：marmelab 明说 "Most coding agents already have a plan mode and a task list. In most cases, SDD adds little benefit."（⚠️ 出处 2025-11-12《The Waterfall Strikes Back》，C 路已修正归属）。
- **"取代"不成立**：SDD 工具 2026-09 仍活跃发版（spec-kit 1.0.x 每 2–4 天一版、OpenSpec 每 1–2 周一 minor——库内 [signals-2026h2](../../../03_practice/spec_driven_development/debate/signals-2026h2.md)）。

**收敛的目标形态（≥3 家独立同向）**：**机械门 + 少量真人判断点**。两侧各有一面"假把控"的镜子——SDD 侧 "False Sense of Security"（agent 把 verify implementation 标 done 却零单测，marmelab 2025-11-12）；loop 侧没有进度盘时退回人的工作记忆与对话催促（姊妹仓 FAQ 15 的 owner 案例，外部研究·转引）。真实把控＝机器可查的门 ＋ 少量真人在环点。
