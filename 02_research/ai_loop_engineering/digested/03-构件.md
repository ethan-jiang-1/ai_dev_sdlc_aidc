## 一、停止条件：三件骨架 + 一个目标敌人

**目标敌人被官方点名**：Anthropic《Effective harnesses》（2025-11-26）把两种头号失败模式写成表格——"Claude declares victory on the entire project too early" 与 "Claude marks features as done prematurely"；LangChain verification loop 的存在理由同源；Huntley 的对应物是占位实现（"inherent bias to do minimal and placeholder implementations"）。**停止条件设计的全部意义，就是对抗"提前宣告完成"。**

三件骨架（每件 ≥2 独立一手同向）：

1. **机器可核判据做逐轮闸门**——测试/类型/linter/静态分析/安全扫描（Huntley 称 back pressure，LangChain 称 grader，分 deterministic 与 agentic 两类）。判据的可核性来自环境 ground truth；编码域天然适合（"Code solutions are verifiable through automated tests"，Anthropic 2024）。
2. **硬性资源上限做兜底停止**——最大迭代/轮数/时间/拒绝计数（Anthropic 2024 原句 "stopping conditions (such as a maximum number of iterations)"；`/goal` 的 `or stop after 20 turns` 子句；auto mode 3 连拒/20 总拒停机；`/loop` 7 天硬过期——官方明说这是给"被遗忘的循环"设的上界）。
3. **验收与干活角色分离**——五处一手同向跨三家（evaluator-optimizer、只许改 `passes` 字段、"/goal adds a separate evaluator… completion is decided by a fresh model rather than the one doing the work"、"The separation of roles matters"、grader 与 agent 分置）。

**未收敛点——裁判权归谁**：人判（Huntley：taste）／文件清单逐条判定（Anthropic feature_list）／独立小模型每轮判定（`/goal` 三值）／干活模型自判（Anthropic 2024 默认）／被审批方提出、审批方判定（auto-review）。**这不是缺陷，是设计空间**——实践主干把它做成选型表（见实践层 §1）。

**保护条款族**（"保护裁判不被当事人改写"）：测试不可删改 + JSON 选型防整文件改写（Anthropic 2025，单源但机制成型）；评估器输入防操纵（auto mode 分类器 "reasoning-blind by design"）；Ralph 的防作弊条款（测试当场写明为什么存在，因为"future loops will not have the reasoning in their context window"）。

## 二、外层调度：文件即队列 + 触发器即节拍

**主导形态一：进度外置成持久化文件**。三件套＝进度规格（feature_list.json / fix_plan.md / loop.md）＋叙事日志（claude-progress.txt）＋git 历史；每轮**冷启动重读**（固定开场序列：pwd → 读 git log/progress → 选清单最高优先级未完成项 → 先过基线再干活）。**决定"下一轮跑什么"的不是人、不是定时器，是规格文件里第一个 `passes: false` 的条目。** Huntley 与 Anthropic 两家独立、句式同构（"choose the most important thing" / "choose the highest-priority feature that's not yet done"）。Managed Agents 把这一形态推到接口级：session log 独立于 harness 存活，`wake(sessionId)` 从最后事件恢复。

**主导形态二：定时/事件触发**。Claude Code 三档调度面（云 Routines / 桌面 cron / 会话内 `/loop`，间隔可固定、可模型自选、可 loop.md 定制）；LangChain event-driven loop（cron/webhook/channel）。`/loop` 的内置维护 prompt 是"下一件工作"的清单化变体（固定优先级：未完工作 → PR 偶发维护 → 清理），且明确"**不在该范围外开新动作**"。

**旁论（收敛结论，≥2 独立厂商一手）**：**人工同步审批已退出调度回路**。Anthropic 2024 还把 "pause for human feedback at checkpoints" 写进定义；2025 长程 harness 里人工门禁完全退出（只剩 git 提交与进度文件）；OpenAI auto-review 标题即立场。人留在三处：熔断、ask 规则、显式清除。

## 三、自主度分档：位置有了，刻度没有

- **位置分档（成型：两个独立四级阶梯＋一条官方路径）**：① **Kief Morris 四级阶梯**（outside / in / on the loop → agentic flywheel；Böckeler 的 steering loop 与之同构，但**同属 Thoughtworks——只算一个阵营的一票**，evidence-c 判读）；② **Addy Osmani 四级分层**（agentic loop → `/goal` → `/loop`//`schedule` → proactive 事件触发无人值守，evidence-a——A 路核实完整分层为四级并补齐第四级）；③ **Anthropic 官方升档路径**（逐手 prompt → 门禁审阅 → auto-accept → 并行 worktree → "building and monitoring loops"，含 σ 分层 1σ 记录 / 2σ 只读诊断 / 3σ 限界行动——[`anthropic_ai_sdlc/org/ai-native-sdlc-playbook.md`](../../anthropic_ai_sdlc/org/ai-native-sdlc-playbook.md)）。另：marmelab / Stripe / OpenAI 三家独立同向把"逐行动人审"降级为"阻断式机械门 + 少量判断点"——那是**方向收敛的同向证据**，不是第三个阶梯。
- **量化分档（未成型）**：没有一手源给出轮次判据。现行判据全部**事件驱动**——风险分数门槛（auto-review）、关键歧义触发（OpenSpec v1.13.2 "only when context is critically unclear"）、破坏性动作类别、σ 分层（Anthropic playbook：1σ 记录 / 2σ 只读诊断 / 3σ 限界行动）。
- **已知短板**：Böckeler 点名行为面验证（behaviour harness）是"减监督"路线的公认缺口——门能拦动作，拦不住"没做该做的事"。

## 四、对"2026-06 的命名事件"意味着什么

本词的操作定义（**可核停止条件 + 外层调度**）**不是新发明，是对 2024–2026 已成型构件的一次命名**：两件骨架在 Ralph（2025-07）与 Anthropic 长程文（2025-11）里已经成型并被官方文档化为原语（`/goal` `/loop` auto mode，2026 上半年）。**loop engineering 的增量在"把这两件当作一等工程对象来谈论"，不在机制本身。** ——该预答案**已由 A 路确认**（词源＝热度碎片、定义＝事后工程化，见 [`01-命名谱系.md`](01-命名谱系.md) §一）。
