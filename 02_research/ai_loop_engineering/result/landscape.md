## 0. 三句话

1. **2026-06 的专名是热度，思考在事后。** 核心共识只覆盖「用系统替人把一轮跑完」。层数、验证语义、最外层互不兼容，所以实践层不沿用这个词，叫 loop 治理。
2. **公开机制里反复出现的是设计模式，不是已证最佳实践。** 停止条件有三件骨架；外层调度有两种形态，但不是最小 loop 的必要条件；人站在哪有位置词，没有「第 N 轮必须人看」。
3. **八个控制问题里，执行、停止、动作级授权和会话记忆已有公开机制。** feature 级的授权史、priority 变更、业务阻塞原因、跨 feature 验收，在已复核材料里是稳定的空。

效果、采用率、行业阶段史都不在这三句里。不能说的边界在 §7。

## 2. 控制面是叠加，不是阶段史

判读在 [`../digested/06-automation-autonomy-harness-loop.md`](../digested/06-automation-autonomy-harness-loop.md)。首选解释是接口依赖，不是「先 automation、后 autonomy、harness 引发 loop」的单向史：

> 模型能力、产品原语和失败压力把控制对象逐层外移并叠加。automation 管触发和固定动作；autonomy 管在目标与边界内选下一步；harness 把单次运行托住；loop 再把多轮的取题、反馈、停止、记忆、调度和人介入设计成控制面。

四词正交、可组合。一个定时任务可以没有自主选择；一个单会话 loop 可以没有跨 feature 调度；一个 harness 可以只服务一次调用。

DSH 落在「有执行 loop，没有完整 feature 控制面」：目标可以跨 turn 续上，原生合同不调度工作，也没有 feature 级的授权、优先级、阻塞和验收。体感是跑得动、看不清。这是机制定位，不是效果结论。

## 3. 构件：什么已经成型

票数与强度在 [`../digested/03-构件.md`](../digested/03-构件.md)。本节省略产品名，只留判定。

### 3.1 最小 loop

分析框架，不是任何一位作者的原文定义：**触发 · 反复行动 · 反馈/验证 · 可记忆状态 · 停止或继续。**

两个硬判据：

1. 停止或继续不看上一轮结果，那是重试。
2. 单次运行不受控，循环只是把错误复制得更快。

### 3.2 停止条件：骨架收敛

目标敌人是提前宣告完成。三件同向，各有不少于两路独立材料：

1. **机器可核判据做逐轮闸门**（测试、类型、lint、构建退出码）。可核性来自环境里的 ground truth。
2. **硬性资源上限做兜底**（轮数、时间、拒绝计数、被遗忘循环的过期）。上限是资源熔断，不是质量分。
3. **验收与干活分离。** 完成判定权仍是设计空间：人的 taste、清单、独立模型、干活模型自己、审批方。干活模型自判与「提前完成」直接冲突，是最弱的一极。

### 3.3 外层调度：长程扩展，不是准入条件

单个有界任务可以没有调度器。长程工作里观察到两类形态，不足以写成「所有团队都如此」：

1. **进度放在对话外面**：持久化的未完成项，每轮重读，从中取下一件。
2. **下一轮有触发**：时间、事件或条件，而不是人逐条催。

部分产品把「每一步都问人」挪到风险动作、关键歧义和熔断。这不能证明真实组织里的人工审批已经退出。

### 3.4 自主度：位置有了，轮次刻度没有

有三套位置词，都是分类，不是成熟度等级，也不能互相换算：Morris 的 outside / in / on / flywheel；Osmani 与 Claude Code 的四级运行模式；Anthropic playbook 的升档路径。

没有一手源给出「跑几轮必须人看」。能写成门的是事件：动作类别、沙箱、关键歧义、拒绝预算、工具级打断、升级之后人是否接得住。拒绝预算的具体数字只属于具体产品，不能写成通用刻度。

一次动作的去向按出处分开，不合成一台机器：自动放行、人批准、硬拒绝、升级。图上写了「升级」，不表示那条边在运行里走得通。

## 4. 三层各管什么

分工在 [`../digested/05-边界判定.md`](../digested/05-边界判定.md)。

| 层 | 管什么 |
|---|---|
| Harness | 单次运行受控：约束写进环境 |
| Loop | 多轮：何时算完、下一轮做什么、人站在哪 |
| SDD | 变更的产物链。与 loop 是同一控制问题的两种工件，不是上下层 |

依赖方向：单次不受控时，多轮只是错误复制机。所以 harness 是 loop 可设计、可观察的条件之一，不是 loop 的历史原因。

两侧在互相吸收，不是谁取代谁。收敛的目标形态是：**机械门 + 少量真人判断点。** 假把控有两面：产物链上把「已验证」标完成却没有检查；循环侧没有进度盘时，人退回用对话催。

三条引用归属以 C 路一手链为准，旧记法作废：公式 "Agent = Model + Harness" 的原创是 Viv Trivedy；"False sense of control?" 出自 Böckeler 2025-10-15；"SDD adds little benefit" 出自 marmelab 2025-11-12。

## 5. 八问里什么是空的

矩阵在 [`../digested/07-控制问题矩阵.md`](../digested/07-控制问题矩阵.md)。同一机构多篇文档只算一票。格子里是已回源做法，不是「这样做有效」。

| 控制问题 | 已有公开机制 | 仍然空着或不能证明 |
|---|---|---|
| 取题 | 人指定、文件中的未完成项、到点或事件再跑 | 优先级从哪来、谁改过 |
| 授权 | 这一次动作能否做 | feature 级授权史 |
| 执行 | 一轮之内、同一会话续轮、隔离环境里跑完再交接 | 跨 feature 的 owner 与互斥 |
| 验证 | 硬门、另一角色来裁判、人看交接物 | 门过了不等于该做的事都做了；没有质量置信度放行曲线 |
| 停止 | 三件骨架 | 模型说完成不是证据；没有通用轮次阈值 |
| 记忆 | 会话日志、单项目文件、detached 任务账、issue 图 | 这些都不是带授权史和优先级审计的 feature 账 |
| 升档 | 位置词 + 事件门 | 0 条轮次刻度；有升级入口不等于人接得住 |
| 复盘 | 把失败写回环境的设计 | 没有「规则改动被评估、可回滚」的闭环 |

四列空字段是稳定的空，不是还没搜到的人名：**授权史、priority 变更、业务阻塞原因、跨 feature 验收。** 一条真实 goal 日志再看一次，仍然是空，而且 goal 被 resume 不等于驱动器计了轮。这不是「外置记录更有效」——对照臂没跑。

## 7. 还不能说

1. automation 已被 autonomy 取代。
2. harness 引发了 loop。loop 构件早于命名，没有成熟 harness 的循环也能跑，只是更不可见、更容易复制错误。
3. harness 或 loop 已经证明提升质量、减少返工或提高吞吐。已有的跨场景定量结果没有把 loop 设计当作自变量，方向也不一致。
4. 人已经退出。高风险动作、含糊意图、最终验收和熔断之后的接手，材料里反复留着人。
5. 有持久记忆就等于有 feature 队列。
6. 有一张「第 N 轮必须人看」的通用刻度。
7. 某家产品的拒绝次数、超时分钟、默认轮数是行业阈值。
