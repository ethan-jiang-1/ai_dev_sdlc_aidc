# 维度 01 · 上下文供给与预算

> 角色：加权维。形态适用：A+B（B 下含运行时 harness 资产的供给判据）。判据归族待 checklist-A/B 逐条落。

## 核心问题

Agent 能否在合适时机、以最低 token 成本找到正确指引？

## 为什么独立成维

只关心"**这一次任务**里，指引是否在场、是否低成本到场"。不管指引内容新不新鲜（→ 维度07）、与实现是否一致（→ 维度08）、是否可验证（→ 维度02）。一个结构完美但内容全过时的仓库，本维可以得高分——这正是正交性的体现。

## 边界声明

- 归此维：入口可发现性、层级与就近、文件预算（行数/字节）、渐进披露机制、注入是否真实发生、无矛盾、不复述可推导内容、措辞具体可验证、路径作用域、命名可 grep、distractor、指令文件内的上下文治理规则（T8）。
- 归他维：注意力稀释是本维的理论依据（T2a，context rot 原义）——注意它是**原理**不是判据族；资产腐化与打扫归 07；指引与实现漂移归 08。

## 判据族（草案，checklist-A/B 落条）

1. **入口与层级**：规范指令入口存在；根文件是定位层非百科；嵌套就近生效。
2. **预算与截断**：单文件长度受控；总注入量在主要 harness 预算内；尾部截断风险可知。
3. **信号密度**：不复述可推导内容；措辞具体可验证；结构化排版；无互相矛盾。
4. **作用域与渐进披露**（T3）：路径作用域机制被利用；模块细节放在"会被按需发现的载体"；知识/SKILL/工具三层各自有惰性加载路径；常驻层只留索引。
5. **注入真实性**：tier-1 验证——在目标 harness 内确认指令真的加载（静默失败高发区：被遮蔽、裸 .md、忘 refresh）。
6. **上下文治理规则**（T8）：指令文件自身治理模型上下文（如 codex 式 "no unbounded items / 硬上限 / >1K token 标 P0"）。
7. **命名与消歧**：可 grep 命名；无语义近似 distractor；命名空间前缀一致。
