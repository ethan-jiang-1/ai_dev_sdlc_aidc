# ADR 2026-09-21 · 度量语义定标（映射 / 评级刻度 / 门禁 ⚠️ / agent 时代可复现性）

> 状态：已裁决（v1.4 起生效）。落实 framework §4 与设计约束 3 中挂账的四个待定义项。
> 关联：[`../framework.md`](../framework.md) §2.3、§3.2、§4.1–4.4。

## 背景

框架 v1 定型了聚合结构（门禁+加权、短板制），但留了四个未定义项，实际跑审计前必须闭合：
① ✅/⚠️/❌ 无数值映射，短板制公式 `min(均分, 最低×2)` 无法计算，且若 ❌=0 则单条 ❌ 清零整维；
② "D 级"被引用但 A–D 刻度从没成文；
③ ⑤ 门禁层的 ⚠️ 处置未定；
④ 设计约束写"两个审计者结果一致"，而系统已升级为单 agent 执行仪式，承诺对象错位。

## 裁决

### D1 数值映射：✅=1.0，⚠️=0.5，❌=0.25（❌ 不记 0）

理由：加权层的职责是**梯度排序**（哪个仓库/哪个维更差、差多少，喂效标回归），绝对红线归⑤门禁管。❌ 记 0 有两个害处：单条 ❌ 清零整维，维度分退化成准二值，校准失去信噪；全 ❌ 维与"该维不存在"不可区分。0.25 让单 ❌ 把所在维腰斩到 0.5（min(0.917, 0.5)），保留排序信息又不稀释短板信号。映射为经验设定，随 §4.4 校准可修订。

### D2 评级刻度：A–D，按"门禁 + 最弱维"判定（不依赖权重，校准前可用）

| 级 | 判定 | 语义 |
|---|---|---|
| A 示范 | 门禁 ✅ 且所有加权维 ≥ 0.9 | ≈ 全 ✅，偶发 ⚠️ |
| B 健全 | 门禁 ✅ 且所有加权维 ≥ 0.7 | 无 ❌，⚠️ 受控 |
| C 欠账 | 门禁 ✅ 但存在 < 0.7 的加权维 | 有 ❌ 或 ⚠️ 密集维 |
| D 不合格 | 门禁 ❌（⑤ 任一 ❌） | 红线失守 |

取**最弱维**（min）做刻度依据，与 §4.3 短板制的哲学一致：agent 友好度是约束满足问题，不取均值。刻度不需要权重数值——解除了"权重未校准 → 报告无总分"对交付的阻塞（§4.4 相应放开：A–D 照给，加权数值分与总分列暂缺）。

### D3 门禁 ⚠️：不降 D，但总评封顶 B，且必须进整改清单次段

理由：安全有未闭合警告的仓库不应获评"示范"（A 要求门禁 ✅ 级即零 ⚠️）；但 ⚠️ 是"有条件的护栏"而非红线失守，降 D 会与 ❌ 失去区分度。封顶 B 是介于两者之间、且实现为零成本的规则（评级时多查一项）。

### D4 可复现性承诺改写为 agent 执行语境（按 tier 分档）

| tier | 承诺 | 证据要求 |
|---|---|---|
| 0 | 任意执行者复跑一致（脚本化，模型无关） | 命令/脚本原始输出引用 |
| 1 | 同 harness 同版本复跑一致 | 自检命令原始输出引用（如 `/context` 截图/文本） |
| 2 | 同模型同协议方向性一致；跨模型承认评审差异 | 演练记录 + 抽样清单 |

原"两个审计者"是人工审计时代的措辞；agent 执行后，"第二审计者"角色由**同 manifest 复跑**承担——pilot 阶段对 tier-2 条目做双跑验证协议，一致性数据进效标。spirit 不变：诚实分级地承诺可复现，而不是假装全绿。
