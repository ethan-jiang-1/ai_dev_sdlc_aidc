# 形态 B 评估线 · 智能体代码仓库（B-line）

> 状态：v1（2026-09-21）。体系定义权威链：[`00-framework-v1.md`](00-framework-v1.md) → 本文件（B 线评估面定义）。A 线姊妹文件：[`40-line-a-traditional-repo.md`](40-line-a-traditional-repo.md)。分型权威：[`20-archetypes.md`](20-archetypes.md)。

## 1. 线的定位与评估对象

被测实例：产出的应用**以 LLM 为引擎**（形态 B）的仓库——其自身 harness（系统提示、SKILL、工具面、评估器）是产品本体，正确性靠**统计评估**而非二元断言。

评估有**两条消费路径**（archetypes §2，混评禁止）：

- **开发时路径**：coding agent 开发这个 B 产品时读仓库——照九维评，同 A 线。
- **运行时路径**：产出的智能体运行时读自己的 harness 资产——按产品 harness 工程评，B 线独有的评估面。

成熟度定位：**探索线**。惯例未收敛，判据少而关键；逐条标"共识/探索"，探索级不进硬约束，进观察项，靠试测喂。

## 2. 维度适用面与重心

九维整体迁移（六层 harness 架构映射验证，archetypes §4），但**重心集与 A 线不同**：

| 维度 | B 线地位 |
|---|---|
| ② 可验证性与证明 | **重心**：评估器与生成器分离、评估资产独立来源、统计正确性报告（archetypes §5.2；行业级未解，标探索） |
| ⑥ 失败可恢复性 | **一等**：p^n 衰减使检查点/HITL/干净重启成为结构必需；context reset ≠ compaction |
| ⑦ 新陈代谢 | **加深为 harness 代谢**：组件编码"模型做不到 X"假设，模型升级即过期；清理速度须 ≥ 生成速度 |
| ⑧ 漂移治理 | **B 子族**：行为漂移（行为定义 ↔ 预期行为），evals 基线 + 模型版本变更触发重跑；多一个第三方漂移源（厂商更新） |
| ⑨ 版本控制与协作面 | **升为一等**：多 agent 并行是 B 的常态运行方式，冲突面/交接面/并行度约束是日常问题（非边缘判据） |
| ①③④⑤ | 照评；⑤ 在 B 下**加严**（运行时护栏是产品本体的一部分） |

## 3. 采证特征：tier 结构倒置

B 线与 A 线最大的操作差异：**tier-0/1 覆盖率天然低**。运行时路径的判据多数无法静态扫描——注入策略是否生效、护栏是否结构性、评估器是否真与生成器分离，都要 tier-2 演练与评审。推论：

- B 线审计**不可进 CI 常驻**，单次成本高，按版本/模型升级节奏跑，而不是按 PR 频率。
- tier-2 抽样协议在 B 线是硬要求不是补充；评审协议须写明 harness 版本与模型版本（两者都影响结果）。
- **模型版本变更本身是复验触发器**：实现级判据的复验条件在 B 线除"厂商变更"外再加"被测产品所依赖的模型升级"。

## 4. B 线三条深化判据（权威定义在 archetypes §5，此处只列名）

1. harness 代谢（⑦-B）：假设检验、裁撤冗余、熵治理。
2. 评估分离（②-B）：生成/评估分离、评估资产独立来源、单独调严——标探索。
3. 组合可靠性与重启（⑥-B）：p^n 对冲、context reset、循环检测。

## 5. 与 A 线的分离纪律

- 分型依据是**正确性模型**，不是代码由谁写；混合形态（仓库同时含确定性服务与 agent 产品）按产出物拆开分评，各自定主形态。
- 两线不共用总分；B 线内探索级判据单列观察项，不与共识级混算。
- B 产品的开发时路径评分（九维）可与 A 线同构呈现，但报告须标明"仅开发时路径"，不与运行时路径分数合并。
