# 钉钉悟空 — CLI 化的最完整标本

> 悟空是目前挖到的**最激进、最完整的 CLI 化案例**。不是给旧架构加 CLI——是把整个钉钉底层重写为 Agent-native。

---

## 定位

2026 年 3 月 17 日，阿里正式发布「悟空（WUKONG）」，定义为**全球首个企业级 AI 原生工作平台**。归属新成立 Alibaba Token Hub (ATH) 事业群。

标志性转变：从"人用钉钉工作"到"AI 用钉钉工作"。

## 架构：完整 GUI→CLI 重构

### 底层：Tauri + Rust
- 仅 **122MB** 超轻量
- 跨平台 macOS/Windows/Linux
- 钉钉团队耗时**一整年**，将 8 亿用户体量的底层架构全面打碎重写

### CLI 原子化层
- **1000+ 原子化指令**，覆盖钉钉全场景（AI 表格、AI 听记、视频会议、审批流程、文档协作）
- AI 不需要模拟人类键鼠操作——通过标准化 CLI 指令直接调用能力
- 这是区别于 OpenClaw 等"龙虾"类产品的关键：**不是 AI 模拟人操作 GUI，而是产品本身就是 CLI**

### 多 Agent 引擎路由
| 引擎 | 场景 |
|------|------|
| Spark（自研） | 复杂推理，深度集成钉钉生态 |
| Claude Code | 代码开发 |
| Gemini CLI | 多模态任务 |
| OpenAI 兼容 | 扩展 |

根据任务特性**自动路由**选择最佳 Agent 引擎。

### RealDoc AI 原生文件系统
- 原子级文件操作（按行号定位、关键词锚点、正则批量匹配）
- 每步自动快照 → 秒级回退
- 精准差异追踪 → 全程可追溯

> Source: [悟空技术解析](https://blog.csdn.net/weixin_44262492/article/details/159266464), CSDN, 2026

## 安全架构：六层 + 双层熔断

```
L1: 双层规则体系（基础安全 + 企业自定义）
L2: 统一身份认证（权限 = 用户权限 ∩ 提问人权限）
L3: 专属沙箱（容器级隔离，最小权限）
L4: Skill 生态安全扫描（上架前 + 运行时）
L5: 专属模型（金融/医疗/政务私有化部署）
L6: 网络代理（全请求可追溯可管控）
```

**双层熔断**：
- **意图锁**（CLI 模式）：高危操作需用户确认
- **审批流熔断**（钉钉原生）：敏感操作需团队负责人审批

## 与飞书 CLI 的对比

| | 飞书 Lark CLI | 钉钉悟空 |
|------|------|------|
| 方式 | 开源 CLI 工具（MIT） | 完整底层重构 + CLI 化 |
| 范围 | 2500+ API 暴露为 CLI | 1000+ 指令 + 多 Agent 引擎 |
| 架构 | npm 分发的 Go 工具 | Tauri + Rust, 122MB |
| Agent 模式 | 外部 Agent 调用 CLI | 内建多 Agent 引擎路由 |
| 安全 | OAuth + 权限继承 | 六层安全 + 双层熔断 |
| 开源 | ✅ GitHub (larksuite/cli) | ❌ 邀测，未整体开源 |

## 对 SDLC-BPM 同构性研究的启示

悟空是"Framed Autonomy"的工程实现标本：
- **框** = 六层安全 + 双层熔断 + 权限交集 + 沙箱
- **自主** = 多 Agent 引擎自动路由 + 任务推理引擎自动分解 + 原子化指令按需调用
- **流程**不再被预定义——AI 根据意图自动分解→规划→选引擎→执行。人在熔断点策展。
