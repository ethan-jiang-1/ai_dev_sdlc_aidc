## 判定总览

| 构件 | 是否已有成型做法 | 一手来源数 | 结论 |
|---|---|---|---|
| **停止条件**（跑到哪算完） | ✅ 骨架收敛 | 4–5 条记录（按作者/机构/引用链去重后，独立性不完全相同） | 三件骨架同向：**机器可核判据逐轮闸门 ＋ 硬性熔断上限 ＋ 验收与干活分离**；唯一分歧在**完成判定权归谁** |
| **外层调度**（何时再跑/下一项做什么） | ✅ 已观察到两类可复用形态，但非最小定义必需 | 2 个主要案例族（Anthropic 长程进度文件 / Claude Code 与 LangChain 的时间事件触发；机构内部材料按引用链去重） | ①**进度外置成持久化文件、每轮重读、从未完成项中取题**；②**定时/事件触发**。Osmani 明确 `/goal` 可独立驱动单个 bounded task，故外层调度是长程扩展，不是所有 loop 的准入条件 |

## 一、停止条件：三件骨架 + 一个目标敌人

**目标敌人被官方点名**：Anthropic《Effective harnesses》（2025-11-26）把两种头号失败模式写成表格——"Claude declares victory on the entire project too early" 与 "Claude marks features as done prematurely"；LangChain verification loop 的存在理由同源；Huntley 的对应物是占位实现（"inherent bias to do minimal and placeholder implementations"）。**停止条件设计的全部意义，就是对抗"提前宣告完成"。**

三件骨架（每件 ≥2 独立一手同向）：

1. **机器可核判据做逐轮闸门**——测试/类型/linter/静态分析/安全扫描（Huntley 称 back pressure，LangChain 称 grader，分 deterministic 与 agentic 两类）。判据的可核性来自环境 ground truth；编码域天然适合（"Code solutions are verifiable through automated tests"，Anthropic 2024）。
2. **硬性资源上限做兜底停止**——最大迭代/轮数/时间/拒绝计数（Anthropic 2024 原句 "stopping conditions (such as a maximum number of iterations)"；`/goal` 的 `or stop after 20 turns` 子句；auto mode 3 连拒/20 总拒停机；`/loop` 7 天硬过期——官方明说这是给"被遗忘的循环"设的上界）。
3. **验收与干活角色分离**——五处一手同向跨三家（evaluator-optimizer、只许改 `passes` 字段、"/goal adds a separate evaluator… completion is decided by a fresh model rather than the one doing the work"、"The separation of roles matters"、grader 与 agent 分置）。

**未收敛点——裁判权归谁**：人判（Huntley：taste）／文件清单逐条判定（Anthropic feature_list）／独立小模型每轮判定（`/goal` 三值）／干活模型自判（Anthropic 2024 默认；**候选 K 摘录**把 Codex 2026-01-23 的 assistant message 写成 turn 的终止态，见 [evidence-k](../raw/evidence-2026-09-27-k-unrolling-codex-agent-loop.md)）／被审批方提出、审批方判定（auto-review）。**这不是缺陷，是设计空间**——实践主干把它做成选型表（见实践层 §1）。在 K 摘录完成独立复核前，不把它作为 OpenAI 的新增主验票；候选文本也显示 assistant message 可以是追问，compact 是另一条资源兜底。

**保护条款族**（"保护裁判不被当事人改写"）：测试不可删改 + JSON 选型防整文件改写（Anthropic 2025，单源但机制成型）；评估器输入防操纵（auto mode 分类器 "reasoning-blind by design"）；Ralph 的防作弊条款（测试当场写明为什么存在，因为"future loops will not have the reasoning in their context window"）。

## 二、外层调度：文件即队列 + 触发器即节拍（长程扩展）

**观察到的形态一：进度外置成持久化文件**。三件套＝进度规格（feature_list.json / fix_plan.md / loop.md）＋叙事日志（claude-progress.txt）＋git 历史；部分材料要求每轮重读，并从最高优先级未完成项中取题。Huntley 与 Anthropic 的案例句式相近，但它们是具体实践，不足以推出所有团队都以文件队列工作，也不足以证明跨 feature 在途可见性已经解决。Managed Agents 则把 session log 与 harness 分离，并从最后事件恢复；这是接口设计证据，不等于实际组织使用率。

**观察到的形态二：定时/事件触发**。Claude Code 的云 Routines、桌面 cron、会话内 `/loop`，以及 LangChain 的 cron/webhook/channel，展示了时间或事件作为下一轮触发器。Osmani 的组合建议进一步把 `/loop` 用作 heartbeat/discovery，把 `/goal` 用作单问题闭环；这说明调度与单任务 loop 可以组合，也说明二者不应混为同一必要条件。

**关于人工同步审批的谨慎表述**：部分厂商设计把“每一步都同步问人”移到熔断、关键歧义、风险动作或显式清除等位置；这支持“调度回路可以减少逐行动人审批”的产品方向，但现有材料不足以证明人工同步审批已经从真实组织流程中退出。
## 三、自主度分档：位置有了，刻度没有

- **位置词汇/运行模式（有概念材料，但不是成熟度模型）**：① **Kief Morris 四级阶梯**（outside / in / on the loop → agentic flywheel；Böckeler 的 steering loop 与之同构，但**同属 Thoughtworks，只算一个阵营的一票**）；② **Addy Osmani / Claude Code 四类模式**（agentic loop → `/goal` → `/loop`/schedule → proactive 事件触发无人值守，evidence-a——同时按 trigger、stop、primitive、task fit 分类）；③ **Anthropic 官方升档路径**（逐手 prompt → 门禁审阅 → auto-accept → 并行 worktree → building and monitoring loops，含 σ 分层）。这些材料足以做 taxonomy/术语对照，不足以证明跨团队可复现的等级或可靠决策阈值。
- **量化分档（未成型）**：没有一手源给出轮次判据。现行材料显示的替代方向主要是事件/风险驱动——风险分数门槛（auto-review）、关键歧义触发（OpenSpec v1.13.2）、破坏性动作类别、资源/拒绝上限和 σ 分层；不能把“没有 N 轮判据”写成“没有任何量化可能”。
- **可操作的升档/降档机制已有候选，但不是统一规范**（证据见 [`evidence-2026-09-27-f-autonomy-gates.md`](../raw/evidence-2026-09-27-f-autonomy-gates.md)）：Codex 源码按危险动作/沙箱/项目可信度/policy 映射 `Allow / Prompt / Forbidden`；LangChain 按工具配置 `interrupt_on` 与 `approve/edit/reject`；Spec Kit/OpenSpec 按关键歧义、reviewer-owned checklist、任务分解确认和 converge 缺口介入；重复拒绝可以触发安全熔断或升级给人。它们回答“这次动作是否该自动”，不回答“agent 已达到哪个成熟等级”。
- **升级可达性是自主度的一部分**：拒绝、暂停或要求人工并不等于人真的能接手；Claude/Codex 的公开 issue 暴露软边界无 fallback、窄授权漂移和子 agent 拒绝无法从 parent 进入审批等反例。控制点必须同时记录 action scope、target、decision source、parent/child thread 和 resume pointer。

**动作门的四种处置**（2026-09-27，只综合 [`evidence-f`](../raw/evidence-2026-09-27-f-autonomy-gates.md)，无新抓取）。这四种是一次动作的去向，不是 agent 的成熟度等级，也不是「跑 N 轮必须人看」。各家没有合成一台机器，下面按出处分开。

一次判定要带上的字段：动作类别、沙箱够不够、项目是否可信、当前 approval mode、有没有显式 allow、决定来源（机器还是人）。轮次不在这些字段里。可逆性和质量置信度在 Codex 这个审批函数里没有对应字段。

| 处置 | 已回源的进入条件 | 出处与限制 |
|---|---|---|
| 自动放行 | 命令不危险，并且受限沙箱自己拦得住 | Codex 源码，固定 commit。LangChain 里则是该工具的 `interrupt_on=False` |
| 人批准 | 危险命令，或沙箱不够；不可信项目里又没有显式 allow。人可以批准，LangChain 还允许多一个「改参数再执行」 | Codex 把这档叫 Prompt。`AskForApproval::Never` 不会把这档放成自动，而是改成硬拒绝 |
| 硬拒绝 | 本该问人，但 approval policy 是 Never | 同一套 Codex 规则。没有人的决定 |
| 升级 | 两套，不要并成一条 | ① 未合并的 Codex PR：一轮里 auto-review 拒绝次数碰到熔断，触发那次的动作改交人工，机器拒绝和人的决定分开记账，决定后重置熔断。不是已发布行为。② Microsoft 教学稿：政策例外或歧义直接升级，否则用校准后的置信度对风险阈值。教学场景，不是 coding-agent 的产品政策 |

缺掉的边比新状态更重要。Claude Code 的用户报告里，分类器拒绝了，但没有交互式 prompt，人只能自己退出 auto mode。图上若写了「升级」，这条边在那个报告里走不通。LangChain 的 interrupt 还要求 checkpointer，否则暂停之后无法按 thread 恢复。

拒绝预算的数字只属于具体产品（已归档的 Claude auto mode 是 3 连拒或 20 次总拒后停机）。不能把任何一个数字写成通用刻度。DSH 上这些边是否真的点得通，这轮没有测。
- **已知短板**：Böckeler 点名行为面验证（behaviour harness）是“减监督”路线的公认缺口——门能拦动作，拦不住“没做该做的事”。
## 四、对"2026-06 的命名事件"意味着什么

本词的操作化增量不是凭空发明一套机制，而是把“系统替代人逐轮提示、持续反馈并决定停止/继续”作为一等工程对象来谈论；Ralph（2025-07）与 Anthropic 长程文（2025-11）已先出现相关构件，Claude Code 在 2026 年把部分构件产品化。**外层调度、跨任务记忆和事件触发是长程场景的重要扩展，但不是单个 bounded task loop 的必要条件。** ——该判读由 A/B 路材料共同支持，词源与定义的错位见 [`01-命名谱系.md`](01-命名谱系.md) §一。

## 五、I 路补强：样本扩大，票数不改

[`evidence-i`](../raw/evidence-2026-09-27-i-high-influence-control.md) 把 Aider、Horthy、Beck、Willison、Yegge、OpenAI harness 全文、Cursor、GitHub Copilot 补进控制面。它们**不改上表的收敛票数**——单人案例和活文档产品机制不另计“已收敛的机构票”。它们改变的是样本偏差和两个已知缺口的形状：

- **提前完成 / 行为面**：Beck 把关测试、删测试写成作弊；Yegge 写下上下文将尽时的 “A missing test is a passing test” 和否认既有失败。这与 Anthropic 点名的提前宣告完成同向，来自独立作者，仍然不是跨机构效果证据。
- **硬熔断**：Copilot cloud agent 的 59 分钟是产品级时间上限，不是质量分，也不是“第 N 轮必须人看”。
- **谁拥有循环**：Horthy 要求在工具选定和执行之间打断，明确反对把 “loop until goal” 当生产默认。这加强“控制流要设计”，不支持“循环越自主越好”。
- **外置记忆的新候选**：Beads 的 git issue 图、OpenAI 的 `exec-plans/`、Cursor/Copilot 的分支与日志，都还不是授权史、priority、业务阻塞和跨 feature 验收总览。八问对照与这四列空格的唯一首页在 [`07-控制问题矩阵.md`](07-控制问题矩阵.md)。
