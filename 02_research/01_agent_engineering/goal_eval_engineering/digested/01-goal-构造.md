# 01 · goal 如何构造，loop 才能跑

> 判读。引句在 `raw/`。写法并列，不收成一步。定调在 [`../README.md`](../README.md) §1。

循环要停，得有一句对照物。公开材料里这句话有松有紧。紧的能让另一只模型回答达到没有。松的把品味留在句子里，用旁边的动作撑住。

## 句子

| 写法 | 什么时候用得上 | 出处 |
|---|---|---|
| 可核终态。证据出现在对话或测试里。另一只模型只回答尚未达到 / 达到 / 不可能。另加次数上限 | 怎样算做完已经说得出口，而且环境里看得见 | A、A2。Claude `/goal`，团队博客 2026-06-30 |
| 那句话就是退出条件，最好带一个数。另给测量工具，并写明哪些取巧不算做完 | 有一个可以靠近的数：耗时、通过率、页面指标 | A9。Kundel，2026-06-04 |
| 停的句子仍是「让你满意」。每步实机测、自动审、进度写进文件 | 完成与否靠品味，过程要留下可重复的动作 | A9。Steinberger，2026-06-12 |
| 规格，加上可选的 eval 数据集。同一类问题反复出现之后才建数据集 | 内环先跑。eval 不是开工前写死的 | A4。Ng，2026-06-26 |
| 给干活的模型一条核对通道：测试、浏览器、模拟器。停的句子里可以有「体验好」 | 核对交给干活的那一方。7 月全文仍是这样，并默认自动代码审和安全审 | A4。Cherny，1 月窗边；2026-07-17 全文 |
| 先写成功标准再让它循环。例子是先写测试再通过；或损失尽量低，且不许回退耗时、内存和简洁 | 标准客观，或能先变成会失败的测试 | A10。Karpathy，1 月与 3 月，窗边 |
| 检查说不出口时，先让模型起草，再改掉和本项目不同的几条 | 有几条硬规则，但第一稿写不出来 | A2。2026-07-22 |
| 写之前先问停的是产出还是结果。结果看不见，就不要写成 agent 的完成条件 | 在乎的是系统外面的业务结果 | C。Yeret，2026-05-27，窗边 |

Osmani（2026-08-14）把含糊的「把界面做好」排除在外：裁判只核硬规则。Steinberger 的「架构让你满意」就是那种句子。他没有把它改成硬规则，而是在旁边加了实机测和进度文件。两套都留着。

## 判读

- 能让循环停下来的，是环境里看得见的终态，或一个数，或一条会失败的测试。业务结果还看不见时，材料里的做法是把这一层留在人这边，不是把句子写得更响。
- 否决权在干活模型之外，目前是 Claude 文档和 LangChain 的 grader 这样写的。Ng、Cherny、Karpathy 自己的帖没有这一票。不要把产品文档的裁判算成他们的主张。
