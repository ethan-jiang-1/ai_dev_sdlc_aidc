# 维度 06 · 失败可恢复性

> 角色：加权维。**v1.1 新增维**（自 03 分出）。形态适用：A+B，**B 下升为一等**（组合可靠性使恢复成为结构必需，见 §形态 B 子族）。

## 核心问题

Agent 运行中卡住、失败、绕远时，环境有没有结构性的出口？

## 为什么独立成维

2026-06 后最强的实证信号之一：Amazon 对 6000+ 条 agent 失败 trajectory 的审计显示**死循环与超时合计约占三分之一**，且 harness 决定 agent 是恢复还是越陷越深（[AAIF, 2026-09](https://aaif.io/blog/code-is-cheap-proof-is-the-bottleneck)）。builder.io 的观察同向：agent 会绕过失败、改错文件、带着礼貌 commit message 交付猜测（[AX](https://www.builder.io/blog/agent-experience)）。原五维里没有一维回答"卡住了怎么办"——03 只管冷启动报错可读，02 只管改后判定对错。

## 边界声明

- 归此维：**冷启动之后**的失败面——超时与重试预算、循环检测、逃生舱命令、干净重来路径（幂等重跑、状态复位）、失败上报通道、昂贵操作的分级授权（何时必须先问）、"该跑/不该跑"边界成文。
- 归他维：冷启动路径本身及报错可行动性归 03；验证失败信息的质量归 02；"全量测试先请示"同时涉及 02（验证成本）——**归此维**，因为它是授权/出口规则，不是判定对错的能力；**"需确认"类条目与 ⑤ 的分界**——安全后果型（发布/迁移/删除、凭证、远程写）归 ⑤，资源/时间预算型（长任务、全量套件先问）归本维，分界是**危险后果 vs 成本预算**（与 05 文件互为镜像）。

## 判据族（草案）

1. **预算成文**：长任务/全量套件有显式的先问边界与授权分级（项目级自主、全量先问）。
2. **逃生舱**：每类常见卡点有文档化出路（锁死了怎么清、容器坏了怎么复位、patch 冲突走哪条捷径）。
3. **干净重来**：环境/状态可幂等重置（一键 reset、seed 重建），失败后不必手工考古。
4. **循环与超时**：长命令有预期时长参考；已知慢操作标注；无导致无限重试的静默失败。
5. **上报通道**：卡住时的正确行为成文（停下来报告，而非绕过/猜测交付）。
6. **工作流决策树**：最容易走死路的流程（补丁、迁移、合并冲突）有步骤化剧本。

## 形态 B 子族（组合可靠性与重启，v1.2）

1. **p^n 衰减**：n 个依赖步、单步成功率 p 的端到端成功率为 p^n（0.95^20≈0.36）——长链路 B 产品必须以检查点/HITL/恢复机制对冲，逐点优化单步成功率不解决问题（[arXiv 2606.28791](https://ar5iv.labs.arxiv.org/html/2606.28791) §5.6）。
2. **Context Reset ≠ Compaction**：清空上下文 + 结构化交接文件（handoff artifact）重启新会话，优于原地压缩——压缩不提供干净起点，无法消除上下文焦虑（Anthropic 官方对比）。⑥-B 的"干净重来"判据以此为原理依据。
3. **循环检测中间件**：编辑次数/重试计数达阈值即提示换方法（LangChain LoopDetectionMiddleware 模式）——⑥ 判据族 4 的 B 实例。

## 泛化注意

- 本维判据**双层**（v1.7 定，framework §5）：**成文性条目**（预算/逃生舱/上报通道/决策树成文、reset 命令存在）tier-0 可采，为 A 线主判据；**可达性条目**（出口真实可达、reset 后状态一致）tier-2，经 tier-2 演练的卡点窗口采证（演练卡点映射含⑥）——演练中未出现卡点时，按成文性条目评分并在报告注明"可达性未采证"。
- 新增判据族，raw 清单无对应条目编号，从 raw 06 案例观察 + 上述依据重写。
