# 维度 09 · 版本控制与协作面

> 角色：加权维。**v1.3 新增维**（充分性审查 [`../adr/2026-09-21-dimension-sufficiency-review.md`](../adr/2026-09-21-dimension-sufficiency-review.md) G1 结论）。形态适用：A+B；**B 下升为一等**（多 agent 并行使冲突面成为日常问题）。

## 核心问题

Agent（或多个 agent 并行）产出的改动，能否顺畅进入版本主干——提交、隔离、合并、回退、进入 review——且不与人类或其他 agent 互相踩踏？

## 为什么独立成维

八维的生命周期覆盖在"改动进入主干"一段无主（审查 §2）。⑤只收推送的安全红线，⑥只收合并冲突的逃生剧本，②只收 PR 内的证据义务——"协作旅程"整体无人认领。2026-06 后这段的分量陡增：并行 agent（多 worktree / 多会话分工）、code review agent、AI 产出披露与评审责任，都已从边缘实践变为常态工作方式。原五维时代无此问题，v1.1 扩维时也未覆盖。

## 边界声明

- 归此维：commit 粒度与信息规范、分支/合并模型成文、并行 agent 的结构性隔离（worktree 指引、可并行域声明、文件所有权/锁面）、高冲突文件（lockfile/生成物/changelog）的处理规则、改动可原子回退、review 流程对 agent 产出的适配（模板、披露、评审责任划分）。
- 归他维：推送类**安全红线**（只推 fork、禁 force push、远程操作审批）→ ⑤；合并冲突**卡住后的逃生剧本** → ⑥；PR 内**附证据的义务** → ②；lockfile 的**漂移机器检查** → ⑧。分界口诀：⑨管"改动怎么顺畅地走完协作旅程"，⑤管"走的过程中哪些事绝不能做"，⑥管"走不动了怎么脱身"。

## 判据族（草案，checklist-A/B 落条）

1. **提交卫生**：原子提交惯例成文；message 规范可机判（如 conventional commits）；生成物/临时文件不混入提交（gitignore 卫生）。
2. **分支与合并模型**：分支策略、主干保护规则对 agent 可知（成文或配置可读）；agent 知道该基于哪个基线开枝。
3. **并行隔离**：多 agent 并行有结构性支持——worktree/容器隔离指引、可并行域与不可并行域的声明、文件/模块所有权标注。
4. **冲突面收窄**：高冲突文件（lockfile、生成物、changelog、单点路由表）有显式处理规则或工具化路径（自动再生成、专用命令），而非靠手工合并。
5. **可回退性**：改动可原子 revert；revert/reset 流程文档化；回退不影响共享状态（迁移有 down 或前向修正策略）。
6. **Review 适配**：PR 描述/handoff 格式对 agent 产出可用（改动摘要、影响面、验证记录有固定落点）；AI 参与的披露方式与人类评审责任成文。

## 形态 B 子族（v1.3）

B 形态下本维从"一个人的提交卫生"升为**多 agent 编排的协作面**：

1. **并行度有结构约束**：哪些任务可并行、哪些必须串行（同模块写冲突、共享状态域）有成文声明；并行 agent 间有隔离边界（worktree/命名空间/锁）。
2. **agent 间交接**：一个 agent 的产出作为另一个 agent 的输入时，交接物格式固定且可校验（对应②的证据产出在协作链上的传递）。
3. **主干作为整合点**：合并频率与冲突预算有意识管理（短命分支/主干开发倾向），长分叉的整合成本被显式对待。

## 依据

- **经验判据为主，诚实标注**：本维多数条目来自 2026-06 后并行 agent 实践的社区共识（多 worktree 并行会话、review agent 工作流），一手系统研究尚薄；落 checklist 时逐条标"经验/共识"，有厂商一手文档的（如 Claude Code 官方 git worktrees 工作流文档）标一手 + 观测日期。
- 原子提交/可回退性与经典工程实践同源，但 AX 理由成立：无状态 agent 对"干净基线"的依赖远高于人类（每次会话重建心智模型，脏历史直接变成错误前提）。

## 泛化注意

- 本维与 05/06/08 有四个共享表面（见边界声明），checklist 落条时逐条互相注明归属，防双算——同 ④ 开放问题的处理方式。
- **gitignore 卫生归此维**（v1.4 裁决，与 03 分界）：判据族 1 评 `.gitignore` 文件与提交卫生（生成物/临时文件不混入）；03 判据族 2 只评"新克隆可跑通"的行为后果（模板分离），两边落条时互加指针。
- 单人单 agent 的小仓库：并行隔离判据条件不满足记 **N/A**、不惩罚（规模分档语义见 framework §4.1 / ADR 度量语义 D5；无"加分项"机制，N/A 即不计分）。

## 开放问题

- 提交信息规范的可机判度：要求 conventional commits 算不算过严（不同生态惯例不同）——判据宜写行为描述（"可机判的规范存在"），不绑定具体格式。
- "review 适配"的 tier 归属：模板存在是 tier-0，但"对 agent 产出可用"需 tier-2 演练，落条时拆两条。
